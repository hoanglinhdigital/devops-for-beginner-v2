17. CICD for Kubernetes/EKS / Lab 3: Implement CICD using GithubAction

Mục tiêu

  • Dùng GitHub Actions để dựng pipeline CI/CD cho ứng dụng monorepo, thay thế CodePipeline ở Lab 2.
  • Workflow tự động build Docker image cho frontend & backend, push lên ECR, rồi deploy lên EKS bằng kubectl.
  • Làm quen với GitHub Secrets để lưu credential AWS một cách an toàn.

GitHub Actions chạy khi push code: cấu hình AWS credentials qua Secrets → build image → push ECR → cập nhật kubeconfig và kubectl apply lên EKS.

Yêu cầu trước khi bắt đầu

  • Đã có EKS cluster devops-test-cluster (Lab 1) — hoặc tái sử dụng cluster của Lab 2.
  • Code ứng dụng được đẩy lên GitHub (repo monorepo frontend/backend).
  • Source code bài lab nằm tại sourcecode/section_16_cicd_for_eks/lab3_cicd_github_action/.
Repository ứng dụng mẫu (monorepo) dùng cho bài Lab 3

Các bước thực hành

  1. Bước 1: Đưa code lên GitHub

    Tạo repository trên GitHub (vd todo-app-monorepo), rồi push code lên:

    git add .
git commit -m "Initial commit for EKS deployment via GitHub Actions"
git push -u origin master
  2. Bước 2: Tạo ECR repository (skip nếu đã có từ Lab 2)

    Tạo 2 private repository trên ECR: todo-app-frontend và todo-app-backend.

  3. Bước 3: Cấu hình GitHub Secrets

    Vào GitHub repo → Settings → Secrets and variables → Actions → New repository secret, thêm các secret sau:

    • AWS_ACCESS_KEY_ID — Access key của IAM user.
    • AWS_SECRET_ACCESS_KEY — Secret key của IAM user.
    • AWS_REGION — ap-southeast-1.
    • EKS_CLUSTER_NAME — devops-test-cluster.
    Bảo mật tốt hơn: thay vì dùng access key dài hạn, nên dùng IAM Role + OIDC để GitHub Actions nhận credential tạm thời.
  4. Bước 4: Tạo GitHub Actions Workflow

    Tạo file .github/workflows/deploy.yml với nội dung như file deploy.yml trong thư mục source. Workflow gồm các bước chính:

    • Detect Changes — dùng dorny/paths-filter phát hiện thư mục backend/ hay frontend/ thay đổi.
    • Configure AWS credentials — dùng action aws-actions/configure-aws-credentials.
    • Login to Amazon ECR — dùng aws-actions/amazon-ecr-login.
    • Build, tag, push — build và push image backend/frontend (chỉ chạy khi có thay đổi tương ứng), đồng thời sed cập nhật tag trong aws-eks.yaml.
    • Update kubeconfig + Deploy to EKS — kubectl apply -f aws-eks.yaml.
  5. Bước 5: Kích hoạt pipeline

    Sửa code rồi push lên master để workflow chạy:

    git add .
git commit -m "Update application and workflow"
git push origin master

    Vào tab Actions trên GitHub repo để xem workflow Deploy to EKS chạy và theo dõi log.

Kiểm tra kết quả

✅ Lab thành công khi

  • Workflow Deploy to EKS chạy xong với trạng thái xanh (success).
  • 2 image mới trên ECR (tag theo commit sha).
  • kubectl get deployments/pods/svc thấy ứng dụng chạy trên EKS.
  • Truy cập ứng dụng qua ALB (từ kubectl get ingress) thấy bản mới.

Troubleshoot

Workflow lỗi ở bước Configure AWS credentials
Nguyên nhân: GitHub Secrets nhập sai tên hoặc giá trị, hoặc IAM user thiếu quyền.
Giải pháp: kiểm tra lại tên secret khớp với ${{ secrets.* }} trong workflow và quyền của IAM user.
Lỗi quyền khi kubectl apply
Nguyên nhân: IAM user dùng trong secret chưa có quyền truy cập EKS cluster (access entry).
Giải pháp: thêm access entry cho IAM user/role bằng aws eks create-access-entry và associate-access-policy.
Pod lỗi ImagePullBackOff
Nguyên nhân: tag image trong manifest chưa khớp, hoặc node không có quyền pull ECR.
Giải pháp: kiểm tra tag trong aws-eks.yaml; thêm policy ECR read-only cho node role nếu cần.
