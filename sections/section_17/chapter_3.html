17. CICD for Kubernetes/EKS / Lab 1: Tạo một EKS Cluster và kết nối

Mục tiêu

  • Tạo một EKS Cluster (kèm node group) bằng eksctl.
  • Kết nối tới cluster từ máy local bằng kubectl.
  • Cài đặt các thành phần cần thiết cho các lab sau: OIDC provider, AWS Load Balancer Controller (để tạo ALB) và EBS CSI Driver (để dùng storage cho MongoDB).
  • Kiểm thử nhanh bằng cách deploy ứng dụng mẫu 2048 game và truy cập qua ALB.

Yêu cầu trước khi bắt đầu

  • Máy local đã cài: AWS CLI, kubectl, eksctl và helm (nên dùng chocolatey để cài cho Windows).
  • IAM user có quyền tạo EKS Cluster (kiểm tra bằng aws sts get-caller-identity).
  • Đã tham khảo bài tạo EKS Cluster ở Section 14 – Lab 1 (phần tạo cluster tương tự, bài này bổ sung thêm ALB Controller & EBS CSI Driver).
  • Source code lab nằm tại sourcecode/section_16_cicd_for_eks/lab1_create_eks_cluster/.

Các bước thực hành

  1. Bước 1: Kiểm tra công cụ và quyền 
    aws --version
kubectl version --client
eksctl version
helm version --short

    Xác nhận IAM user đang dùng có đủ quyền:

    aws sts get-caller-identity
  2. Bước 2: Tạo EKS Cluster (mất khoảng 10 phút)

    Chỉnh sửa file cluster-config.yaml nếu muốn đổi tên cluster, region, số node hay instance type, sau đó tạo cluster:

    eksctl create cluster -f cluster-config.yaml

    Chạy lệnh sau để disable extended support cho EKS (giúp tiết kiệm chi phí):

    aws eks update-cluster-config --name devops-test-cluster --upgrade-policy supportType=STANDARD
  3. Bước 3: Cập nhật kubeconfig và kiểm tra node

    Cập nhật file config (Windows: C:\Users\{username}\.kube\config):

    aws eks update-kubeconfig --region ap-southeast-1 --name devops-test-cluster

    Kiểm tra context và thông tin cluster:

    kubectl config get-contexts
kubectl cluster-info

    Đợi khoảng 5 phút rồi kiểm tra node đã sẵn sàng (Ready):

    kubectl get nodes
  4. Bước 4: Cài OIDC provider cho cluster

    OIDC cho phép pod dùng IAM Role for Service Account (IRSA) — cần thiết cho ALB Controller và EBS CSI Driver.

    Tham khảo guide chính thức: enable IAM roles for service accounts.

  5. Bước 5: Cài AWS Load Balancer Controller

    Tham khảo: AWS Load Balancer Controller.

    Tạo IAM policy cho LB Controller (dùng file iam_policy.json trong thư mục source):

    aws iam create-policy \
  --policy-name AWSLoadBalancerControllerIAMPolicy \
  --policy-document file://iam_policy.json

    Tạo IRSA cho LB Controller (thay <AWS_ACCOUNT_ID> bằng Account ID của bạn):

    eksctl create iamserviceaccount \
  --cluster=devops-test-cluster \
  --namespace=kube-system \
  --name=aws-load-balancer-controller \
  --attach-policy-arn=arn:aws:iam::<AWS_ACCOUNT_ID>:policy/AWSLoadBalancerControllerIAMPolicy \
  --override-existing-serviceaccounts \
  --region ap-southeast-1 \
  --approve

    Cài LB Controller bằng Helm:

    helm install aws-load-balancer-controller eks/aws-load-balancer-controller \
  -n kube-system \
  --set clusterName=devops-test-cluster \
  --set serviceAccount.create=false \
  --set serviceAccount.name=aws-load-balancer-controller \
  --version 1.14.0
  6. Bước 6: Deploy ứng dụng mẫu 2048 game và kiểm tra ALB

    Tham khảo: ALB sample application.

    kubectl apply -f https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/v2.14.1/docs/examples/2048/2048_full.yaml

    Kiểm tra ALB được tạo ra (đợi vài phút), lấy DNS của ALB và truy cập thử game 2048 (lưu ý thêm http:// trước DNS).

  7. Bước 7: Cài EBS CSI Driver (cho storage của MongoDB)

    Tạo IAM Role cho EBS CSI Driver:

    eksctl create iamserviceaccount \
  --name ebs-csi-controller-sa \
  --namespace kube-system \
  --cluster devops-test-cluster \
  --role-name AmazonEKS_EBS_CSI_DriverRole \
  --role-only \
  --attach-policy-arn arn:aws:iam::aws:policy/service-role/AmazonEBSCSIDriverPolicy \
  --approve

    Đợi khoảng 3 phút, sau đó cài add-on (thay <AWS_ACCOUNT_ID>):

    eksctl create addon \
  --name aws-ebs-csi-driver \
  --cluster devops-test-cluster \
  --service-account-role-arn arn:aws:iam::<AWS_ACCOUNT_ID>:role/AmazonEKS_EBS_CSI_DriverRole \
  --force
  8. Bước 8: Dọn dẹp ứng dụng 2048

    Sau khi kiểm tra ALB hoạt động, xoá ứng dụng 2048 để giữ cluster gọn gàng cho các lab sau:

    kubectl delete -f https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/v2.14.1/docs/examples/2048/2048_full.yaml

Kiểm tra kết quả

✅ Lab thành công khi

  • kubectl get nodes hiển thị 2 node ở trạng thái Ready.
  • Pod của aws-load-balancer-controller chạy trong namespace kube-system.
  • Deploy 2048 game tạo ra một ALB, truy cập DNS của ALB thấy giao diện game 2048.
  • Add-on aws-ebs-csi-driver ở trạng thái ACTIVE (kiểm tra trên AWS Console hoặc eksctl get addon).

Troubleshoot

kubectl không kết nối được tới cluster
Nguyên nhân: chưa chạy update-kubeconfig, hoặc current context không đúng.
Giải pháp: chạy lại aws eks update-kubeconfig rồi kubectl config use-context devops-test-cluster.
Deploy Ingress nhưng không thấy ALB được tạo
Nguyên nhân: LB Controller chưa được cài, hoặc IRSA/role thiếu quyền.
Giải pháp: kiểm tra pod aws-load-balancer-controller, xem log bằng kubectl logs -n kube-system deployment/aws-load-balancer-controller.
PVC của MongoDB bị Pending (không có volume)
Nguyên nhân: EBS CSI Driver chưa được cài hoặc add-on chưa ACTIVE.
Giải pháp: kiểm tra eksctl get addon --cluster devops-test-cluster và chờ add-on về trạng thái ACTIVE.

Dọn dẹp resource

EKS Cluster có phí theo giờ (control plane) và node EC2 tính phí liên tục. Chỉ giữ cluster khi đang làm các lab tiếp theo; xoá ngay khi hoàn thành toàn bộ chương.
eksctl delete cluster --name devops-test-cluster --region ap-southeast-1
