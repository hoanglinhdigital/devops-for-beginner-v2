17. CICD for Kubernetes/EKS / Lab 2: Implement CICD using CodePipeline

Mục tiêu

  • Dùng bộ AWS Developer Tools (CodeCommit + CodeBuild + CodePipeline) để dựng pipeline CI/CD hoàn chỉnh cho ứng dụng monorepo.
  • Build Docker image cho frontend & backend, push lên ECR.
  • Tự động deploy lên EKS khi có code thay đổi (kích hoạt bằng push lên CodeCommit).

Các bước thực hành

  1. Bước 1: Tạo repository trên CodeCommit và push code

    Tạo repository todo-app-monorepo trên CodeCommit, rồi clone về local và copy toàn bộ code (thư mục frontend/, backend/ và file aws-eks.yaml) vào:

    git clone https://git-codecommit.<region>.amazonaws.com/v1/repos/todo-app-monorepo
git add .
git commit -m "Initial commit for EKS deployment"
git push origin master
  2. Bước 2: Tạo 2 ECR repository

    Tạo 2 repository trên ECR để chứa Docker image của frontend và backend:

    • todo-app-frontend
    • todo-app-backend

    Đồng thời tạo file buildspec.yml ở thư mục gốc repository để hướng dẫn CodeBuild build và push image (xem nội dung trong thư mục source).

  3. Bước 3: Tạo CodePipeline

    Vào CodePipeline → Create Pipeline với tên todo-app-eks-pipeline, cấu hình các stage:

    • Source stage: Provider = CodeCommit, repository todo-app-monorepo, branch main, Output artifact format = Full clone (bắt buộc để dùng lệnh git trong CodeBuild).
    • Build stage: Provider = CodeBuild, Project todo-app-build-stage. Bật Privileged để build Docker image; thêm biến môi trường AWS_ACCOUNT_ID và AWS_DEFAULT_REGION; dùng file buildspec.yml.
    • Deploy stage: Provider = Amazon EKS, chọn cluster devops-test-cluster, Deploy configuration = kubectl, Manifest file paths = aws-eks.yaml, chọn các Private Subnet (KHÔNG chọn public subnet) và Security Group của cluster.
    Lưu ý: ở Deploy stage, chỉ chọn Private Subnet; chọn public subnet sẽ gây lỗi kết nối khi CodePipeline deploy.
  4. Bước 4: Thêm IAM policy cho Service Role

    Thêm các policy sau cho CodeBuild Service Role:

    • AmazonEC2ContainerRegistryFullAccess
    • AWSCodeCommitFullAccess

    Thêm các policy sau cho CodePipeline Service Role:

    • AmazonEC2ContainerRegistryFullAccess, AWSCodeCommitFullAccess, AWSCodeBuildDeveloperAccess, CloudWatchLogsFullAccess, AmazonEC2FullAccess
    • Một custom policy cho phép eks:DescribeCluster.
  5. Bước 5: Gán quyền truy cập cluster cho CodePipeline Service Role

    Tạo access entry và gán policy quyền admin cho CodePipeline Service Role (thay <AWS_ACCOUNT_ID> và ARN của role cho đúng):

    aws eks create-access-entry \
  --cluster-name devops-test-cluster \
  --principal-arn arn:aws:iam::<AWS_ACCOUNT_ID>:role/service-role/<CodePipeline-Service-Role> \
  --type STANDARD

aws eks associate-access-policy \
  --cluster-name devops-test-cluster \
  --principal-arn arn:aws:iam::<AWS_ACCOUNT_ID>:role/service-role/<CodePipeline-Service-Role> \
  --policy-arn arn:aws:eks::aws:cluster-access-policy/AmazonEKSClusterAdminPolicy \
  --access-scope type=cluster
  6. Bước 6: Sửa code để kích hoạt CI/CD

    Sửa nội dung code backend & frontend rồi commit/push lên CodeCommit để pipeline tự chạy:

    git add .
git commit -m "Update TODO app backend and frontend v2"
git push origin master

Cải thiện trong dự án thực tế

Pipeline ở trên đủ chạy nhưng còn khá "thô". Trong dự án thật, người ta thường tách nhỏ và bổ sung thêm để kiểm soát tốt hơn:

Các cải thiện CI/CD trong dự án thực tế
  • Phần CI: tách build Docker image thành 2 pipeline riêng cho Backend và Frontend; thêm biến VERSION (vd v1.0.1) để làm tag cho ECR image; checkout theo git tag thay vì commit hash.
  • Phần CD: tách riêng pipeline deploy cho backend/frontend; thêm biến BE_VERSION/FE_VERSION để biết deploy version nào lên EKS; thêm bước Manual Approve bởi Leader trước khi deploy.
  • Khác: thêm Notification qua SNS/EventBridge để báo kết quả pipeline.

Troubleshoot

CodeBuild không build được Docker image
Nguyên nhân: chưa bật Privileged mode.
Giải pháp: bật Privileged trong cấu hình environment của CodeBuild project.
Deploy stage báo lỗi không kết nối được cluster
Nguyên nhân: chọn public subnet thay vì private subnet, hoặc CodePipeline Service Role chưa có access entry.
Giải pháp: chọn lại private subnet và thực hiện đúng Bước 5 (create-access-entry + associate-access-policy).
Pipeline chạy nhưng pod lỗi ImagePullBackOff
Nguyên nhân: image tag trong aws-eks.yaml sai, hoặc node không pull được image từ ECR.
Giải pháp: kiểm tra tag image trong manifest, đảm bảo node có quyền ECR (thêm AmazonEC2ContainerRegistryReadOnly cho node role).
