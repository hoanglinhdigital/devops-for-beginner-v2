7. Thao tác cơ bản với Git / Lab 6: Git log, show & revert

Mục tiêu

  • Tra cứu lịch sử commit với git log (nhiều định dạng, lọc theo file, tác giả).
  • Xem chi tiết một commit với git show <commit-hash>.
  • Hiểu bản chất git revert: “undo” một commit bằng cách tạo thêm commit đảo ngược, không xoá lịch sử.
  • Thực hành commit một thay đổi lỗi, sau đó revert và push an toàn lên remote.

Kiến trúc tổng quan

gitGraph commit id: "develop" branch feature/F002 checkout feature/F002 commit id: "A: add lab 6 item" commit id: "B: add sale banner" type: REVERSE commit id: "B': Revert B" type: HIGHLIGHT checkout main

Commit B (lỗi) vẫn nằm trong lịch sử. Commit B' có nội dung ngược lại với B, nên code sau B' giống hệt code sau A.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 5: repository demo-git có develop đã cập nhật.
  • Source code: sourcecode/section_7_git_basic_operation/lab6_git_revert/commands.sh.

Các bước thực hành

  1. Bước 1: Tạo nhánh feature/F002 từ develop 
    cd ~/git-labs/demo-git
git checkout develop
git pull origin develop
git checkout -b feature/F002
  2. Bước 2: Tạo 2 commit (commit thứ 2 là thay đổi “lỗi”)

    Mở index.html, thêm 1 dòng vào danh sách <ul>:

        <li>Lab 6: Git revert</li>
    git add index.html
git commit -m "feat(F002): add lab 6 item"

    Tiếp tục thêm 1 dòng ngay dưới thẻ <h1> – giả lập một thay đổi sai cần gỡ bỏ:

      <p class="banner">SALE 90%!!!</p>
    git add index.html
git commit -m "feat(F002): add sale banner"
git push -u origin feature/F002
  3. Bước 3: Xem lịch sử commit với git log 
    git log
git log --oneline
9c1e7f2 (HEAD -> feature/F002, origin/feature/F002) feat(F002): add sale banner
5b4d3a1 feat(F002): add lab 6 item
e8f2c90 (origin/develop, develop) Merge pull request #3 from .../release/v0.1
...

    Một số cách dùng git log hữu ích (nhấn q để thoát khi output dài):

    git log --oneline --graph --all -15
git log --oneline -- index.html
git log --author="Your Name" --oneline
git log --since="2 days ago" --oneline
    LệnhÝ nghĩa
    git logLịch sử đầy đủ: hash, tác giả, ngày, message
    --onelineMỗi commit 1 dòng (hash rút gọn 7 ký tự + message)
    --graph --allVẽ cây branch/merge của tất cả branch
    -- <file>Chỉ các commit có thay đổi file đó
    -pKèm nội dung diff của từng commit
  4. Bước 4: Xem chi tiết commit với git show

    Copy hash của commit add sale banner ở bước 3 và thay vào <COMMIT_HASH>:

    git show <COMMIT_HASH>
git show --stat <COMMIT_HASH>
git show HEAD

    git show hiển thị thông tin commit và diff (dòng + <p class="banner">SALE 90%!!!</p>). HEAD là commit mới nhất của branch hiện tại.

  5. Bước 5: Revert commit lỗi

    Cú pháp: git revert <commit-hash>. Git tạo commit mới có nội dung ngược lại và mở editor (VS Code đã cấu hình ở Lab 1) để sửa message – giữ nguyên message mặc định, lưu và đóng tab để hoàn tất:

    git revert <COMMIT_HASH>

    💡 Bỏ qua bước mở editor: git revert --no-edit <COMMIT_HASH>.

    git log --oneline -3
4a7d9e3 (HEAD -> feature/F002) Revert "feat(F002): add sale banner"
9c1e7f2 (origin/feature/F002) feat(F002): add sale banner
5b4d3a1 feat(F002): add lab 6 item
cat index.html
git push

    Dòng banner đã biến mất khỏi index.html, nhưng cả commit gốc lẫn commit revert đều còn trong lịch sử. Vì chỉ thêm commit mới, git push thành công bình thường – không cần --force.

  6. Bước 6: Revert lại commit revert (khôi phục thay đổi)

    Giả sử sau đó team quyết định vẫn cần banner: revert chính commit Revert "..." (thay <REVERT_COMMIT_HASH>):

    git revert --no-edit <REVERT_COMMIT_HASH>
git log --oneline -5
cat index.html

    Banner xuất hiện trở lại. Để giữ trạng thái không có banner cho các lab sau, revert thêm 1 lần nữa commit vừa tạo (git revert --no-edit HEAD) rồi push:

    git revert --no-edit HEAD
git push
  7. Bước 7: Merge feature/F002 vào develop

    Tạo Pull Request develop ← feature/F002, merge và xoá branch trên GitHub. Sau đó cập nhật local:

    git checkout develop
git pull origin develop
git branch -d feature/F002

So sánh nhanh: revert vs reset

git revertgit reset
Cách hoạt độngTạo commit mới đảo ngược thay đổiDi chuyển branch về commit cũ, các commit sau “biến mất” khỏi branch
Lịch sửGiữ nguyên, có thêm commitBị viết lại
Dùng với branch đã push/chia sẻ✅ An toàn❌ Phải push --force, ảnh hưởng người khác
Khi nào dùngGỡ thay đổi đã lên develop/main/productionDọn commit ở local, chưa push

Troubleshoot

Terminal “đứng” sau khi chạy git revert / git log
Nguyên nhân: git revert đang chờ bạn đóng editor; git log đang mở trình xem trang (pager).
Giải pháp: Với revert: lưu và đóng tab commit message trong VS Code (nếu editor là Vim: gõ :wq). Với log: nhấn q.
CONFLICT (content): Merge conflict in index.html khi revert
Nguyên nhân: Commit muốn revert đã bị các commit sau sửa tiếp cùng dòng.
Giải pháp: Sửa conflict như Lab 7 rồi git add index.html và git revert --continue; hoặc huỷ bằng git revert --abort.
error: commit ... is a merge but no -m option was given.
Nguyên nhân: Revert một merge commit cần chỉ rõ giữ lại nhánh cha nào.
Giải pháp: git revert -m 1 <MERGE_COMMIT_HASH> (giữ nhánh cha thứ nhất – thường là nhánh được merge vào). Trên GitHub có thể dùng nút Revert trong Pull Request đã merge.
