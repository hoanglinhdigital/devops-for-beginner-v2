7. Thao tác cơ bản với Git / Lab 5: Nhánh release, merge vào main & đánh tag

Mục tiêu

  • Tạo nhánh release/v0.1 từ develop và chỉnh sửa nhỏ trước khi release (cập nhật version).
  • Merge release/v0.1 vào main qua Pull Request.
  • Đánh tag v0.1 trên main và push tag lên GitHub.
  • Merge release/v0.1 ngược lại develop để đồng bộ thay đổi; tạo GitHub Release (tuỳ chọn).

Kiến trúc tổng quan

gitGraph commit id: "Initial commit" branch develop checkout develop commit id: "Lab 3" commit id: "PR F001" branch release/v0.1 checkout release/v0.1 commit id: "bump 0.1.0" checkout main merge release/v0.1 id: "PR release" tag: "v0.1" checkout develop merge release/v0.1 id: "back-merge"

Nhánh release/v0.1 “đóng băng” các tính năng đã có trên develop, được merge vào main và gắn tag v0.1, sau đó merge ngược về develop.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 4: main và develop đã được bảo vệ bằng Ruleset, develop có about.html.
  • Source code: sourcecode/section_7_git_basic_operation/lab5_release_tag/ (commands.sh, VERSION).

Các bước thực hành

  1. Bước 1: Tạo nhánh release/v0.1 từ develop 
    cd ~/git-labs/demo-git
git checkout develop
git pull origin develop
git checkout -b release/v0.1
  2. Bước 2: Chỉnh sửa nhỏ trước release

    Trên nhánh release chỉ nên có các thay đổi nhỏ: cập nhật số version, sửa lỗi do tester phát hiện. Copy file VERSION (nội dung 0.1.0) từ source code vào thư mục gốc repository:

    git add VERSION
git commit -m "chore(release): bump version to 0.1.0"
git push -u origin release/v0.1

    💡 Trong dự án thật, đây là lúc CI/CD deploy release/v0.1 lên môi trường Test/Staging để kiểm thử.

  3. Bước 3: Pull Request release/v0.1 → main

    Trên GitHub, tạo Pull Request với thông số:

    • base: main ← compare: release/v0.1
    • Title: Release v0.1

    Merge PR (Create a merge commit). Chưa xoá nhánh release/v0.1 vì còn dùng ở bước 5.

  4. Bước 4: Đánh tag v0.1 trên main

    Cập nhật main ở local, sau đó tạo annotated tag (có người tạo, thời gian, message) tại commit mới nhất:

    git checkout main
git pull origin main
git log --oneline -5
git tag -a v0.1 -m "Release version 0.1"
git tag
v0.1
git show v0.1

    Tag tạo ở local, cần push riêng (lệnh git push thông thường không đẩy tag):

    git push origin v0.1

    💡 Push tag vẫn được phép dù main đã được bảo vệ, vì Ruleset hiện chỉ áp dụng cho branch. Trong dự án thật có thể tạo thêm tag ruleset để chỉ người có quyền release mới được tạo tag v*.

    Loại tagLệnhĐặc điểm
    Annotated taggit tag -a v0.1 -m "..."Lưu người tạo, thời gian, message. Nên dùng cho release.
    Lightweight taggit tag v0.1Chỉ là con trỏ tới commit, không có thông tin kèm theo
  5. Bước 5: Merge release/v0.1 ngược lại develop

    Thay đổi trên nhánh release (file VERSION) cần có trên develop để các release sau không bị thiếu. Vì develop được bảo vệ, tạo Pull Request với thông số:

    • base: develop ← compare: release/v0.1
    • Title: Back-merge release v0.1 into develop

    Merge PR, sau đó Delete branch release/v0.1. Cập nhật local:

    git checkout develop
git pull origin develop
cat VERSION
0.1.0
git branch -d release/v0.1
git fetch --prune

    💡 Nếu nhánh release không có thay đổi gì so với develop, bước back-merge là tuỳ chọn.

  6. Bước 6 (tuỳ chọn): Tạo GitHub Release từ tag

    Trên GitHub, mục Releases → Draft a new release với thông số:

    • Tag: v0.1
    • Title: v0.1
    • Description: dùng Generate release notes để GitHub tự liệt kê các Pull Request trong release

    GitHub Release tự đính kèm file nén source code tại tag đó – hữu ích để khách hàng/đội vận hành tải đúng phiên bản.

Kiểm tra kết quả

✅ Lab thành công khi

  • Branch main trên GitHub có index.html, about.html, VERSION.
  • Mục Tags của repository có v0.1; chọn tag sẽ thấy đúng code tại thời điểm release.
  • develop có file VERSION với nội dung 0.1.0.
  • git log --oneline --graph --all --decorate hiển thị tag: v0.1 trên commit merge của main.

Troubleshoot

Tag có ở local nhưng không thấy trên GitHub
Nguyên nhân: git push không tự đẩy tag.
Giải pháp: git push origin v0.1 hoặc git push origin --tags.
Đánh tag nhầm commit (ví dụ quên git pull trước khi tag)
Nguyên nhân: main ở local chưa có merge commit mới nhất.
Giải pháp: Xoá tag ở local và remote rồi tạo lại: git tag -d v0.1, git push origin --delete v0.1, git pull origin main, git tag -a v0.1 -m "Release version 0.1", git push origin v0.1. Chỉ làm khi chưa ai dùng tag đó để deploy.
! [rejected] v0.1 -> v0.1 (already exists)
Nguyên nhân: Tag cùng tên đã tồn tại trên remote.
Giải pháp: Tag nên là bất biến – dùng version mới (v0.1.1) thay vì ghi đè tag cũ.
