7. Thao tác cơ bản với Git / Lab 7: Giả lập & xử lý conflict trên Git

Mục tiêu

  • Giả lập tình huống 2 developer (Dev A, Dev B) cùng sửa một dòng code dẫn tới conflict.
  • Hiểu vì sao người tạo Pull Request sau bị conflict.
  • Đọc và xử lý các dấu conflict <<<<<<<, =======, >>>>>>> bằng VS Code.
  • Cập nhật lại Pull Request sau khi resolve và merge thành công.

Kiến trúc tổng quan

gitGraph commit id: "test.txt" branch feature/devA checkout main branch feature/devB checkout feature/devA commit id: "A: Hoàn thành" checkout feature/devB commit id: "B: Đang kiểm thử" checkout main merge feature/devB id: "PR devB ✅" checkout feature/devA merge main id: "A resolve conflict" checkout main merge feature/devA id: "PR devA ✅"

Trong sơ đồ, nhánh chính đại diện cho develop. Dev B merge trước nên không conflict. Lúc Dev A merge, develop đã chứa nội dung của Dev B chứ không còn là develop lúc Dev A checkout → conflict. Dev A phải merge develop mới nhất vào branch của mình và resolve.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 4 → Lab 6 trên repository demo-git (develop được bảo vệ, merge qua PR).
  • Dev A làm việc ở thư mục ~/git-labs/demo-git; Dev B dùng một bản clone thứ 2 ~/git-labs/demo-git-devB (giả lập máy tính khác).
  • Source code: sourcecode/section_7_git_basic_operation/lab7_resolve_conflict/ (commands.sh, test.txt).

Các bước thực hành

  1. Bước 1: Chuẩn bị file test.txt trên develop

    Copy file test.txt từ source code vào repository, đưa vào develop qua Pull Request:

    Danh sách chức năng của hệ thống:
Chức năng: Đăng nhập
Trạng thái: Đang phát triển
    cd ~/git-labs/demo-git
git checkout develop
git pull origin develop
git checkout -b feature/add-test-file
git add test.txt
git commit -m "chore: add test.txt for conflict lab"
git push -u origin feature/add-test-file

    Trên GitHub: tạo PR develop ← feature/add-test-file và merge.

  2. Bước 2: Dev A tạo nhánh feature/devA và sửa test.txt 
    cd ~/git-labs/demo-git
git checkout develop
git pull origin develop
git checkout -b feature/devA

    Sửa dòng 3 của test.txt thành:

    Trạng thái: Hoàn thành (Dev A)
    git add test.txt
git commit -m "feat(devA): update status in test.txt"
git push -u origin feature/devA

    Chưa tạo Pull Request – giả lập Dev A làm chậm hơn Dev B.

  3. Bước 3: Dev B clone repository, sửa cùng dòng và merge trước

    Clone bản thứ 2 vào thư mục khác (thay <GITHUB_USERNAME>):

    cd ~/git-labs
git clone git@github.com:<GITHUB_USERNAME>/demo-git.git demo-git-devB
cd ~/git-labs/demo-git-devB
git checkout develop
git checkout -b feature/devB

    Sửa dòng 3 của test.txt (trong thư mục demo-git-devB) thành:

    Trạng thái: Đang kiểm thử (Dev B)
    git add test.txt
git commit -m "feat(devB): update status in test.txt"
git push -u origin feature/devB

    Trên GitHub: tạo PR develop ← feature/devB và merge – không conflict vì Dev B là người merge trước.

  4. Bước 4: Dev A tạo Pull Request → bị conflict

    Trên GitHub: tạo PR develop ← feature/devA. GitHub báo:

    This branch has conflicts that must be resolved – Conflicting files: test.txt. Nút Merge bị vô hiệu hoá.

    💡 Với conflict đơn giản, có thể bấm Resolve conflicts để sửa trực tiếp trên web. Trong lab này ta resolve ở local – cách làm phổ biến và an toàn hơn vì có thể chạy thử code trước khi push.

  5. Bước 5: Dev A lấy develop mới nhất về branch của mình

git checkout feature/devA
git pull origin develop

  6. Bước 6: Resolve conflict bằng VS Code 
    code test.txt

    Git đã chèn các dấu conflict vào file:

    Danh sách chức năng của hệ thống:
Chức năng: Đăng nhập

    Danh sách chức năng của hệ thống:
Chức năng: Đăng nhập
Trạng thái: Hoàn thành (Dev A), đã kiểm thử (Dev B)
  7. Bước 7: Đánh dấu đã resolve, commit & push 
    git add test.txt
git commit -m "merge: resolve conflict with develop in test.txt"
git log --oneline --graph -8
git push

    Quay lại Pull Request của Dev A trên GitHub: trạng thái chuyển thành This branch has no conflicts with the base branch. Merge PR và xoá branch.

Troubleshoot

fatal: Need to specify how to reconcile divergent branches.
Nguyên nhân: Chưa cấu hình cách git pull hợp nhất thay đổi.
Giải pháp: git config --global pull.rebase false (như Lab 1) rồi chạy lại git pull origin develop.
Lỡ commit file vẫn còn dấu <<<<<<<
Nguyên nhân: Chưa xoá hết dấu conflict trước khi git add.
Giải pháp: Sửa lại file, git add, git commit -m "fix: remove conflict markers", push. Dùng git diff --check hoặc tìm chuỗi <<<<<<< trước khi commit.
Rối quá, muốn quay lại trạng thái trước khi pull
Nguyên nhân: Đang trong quá trình merge bị conflict.
Giải pháp: git merge --abort – branch trở về như trước khi chạy git pull, sau đó làm lại từ bước 5.
Hạn chế conflict khi làm việc chung:
  • Hạn chế nhiều người cùng code chung một module/file; chia task theo module rõ ràng.
  • Luôn git pull code mới nhất trước khi bắt đầu thay đổi và trước khi tạo Pull Request.
  • Giữ feature branch ngắn ngày, merge thường xuyên – branch càng sống lâu, conflict càng lớn.
  • Thống nhất format code (Prettier, ESLint, EditorConfig) để tránh conflict do khác định dạng, khoảng trắng.
