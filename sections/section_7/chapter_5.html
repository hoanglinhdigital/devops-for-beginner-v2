7. Thao tác cơ bản với Git / Lab 3: Tạo nhánh develop, commit & push

Mục tiêu

  • Tạo nhánh develop từ nhánh main của repository demo-git.
  • Thực hiện trọn vòng đời: Modify → Stage (git add) → Commit → Push.
  • Sử dụng git status, git diff, git log để quan sát thay đổi.
  • Tạo file .gitignore để không commit nhầm file nhạy cảm.

Kiến trúc tổng quan

gitGraph commit id: "Initial commit" branch develop checkout develop commit id: "feat: add index.html" commit id: "docs: add section list"

Nhánh develop được tạo từ commit đầu tiên của main, sau đó có thêm 2 commit và được push lên GitHub.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 2: đã clone demo-git về ~/git-labs/demo-git bằng SSH.
  • Source code: sourcecode/section_7_git_basic_operation/lab3_develop_branch/ (commands.sh, index.html, README.md, .gitignore).

Các bước thực hành

  1. Bước 1: Cập nhật code mới nhất của main 
    cd ~/git-labs/demo-git
git checkout main
git pull origin main
  2. Bước 2: Tạo nhánh develop từ main

    checkout -b = tạo branch mới + chuyển sang branch đó. Branch mới được tạo từ commit hiện tại của branch đang đứng (main):

    git checkout -b develop
Switched to a new branch 'develop'
git branch
* develop
  main

    💡 Git từ bản 2.23 có lệnh mới tương đương, dễ đọc hơn: git switch -c develop (tạo & chuyển) và git switch main (chỉ chuyển).

  3. Bước 3: Tạo/sửa file

    Mở repository bằng VS Code, sau đó copy 3 file từ thư mục lab3_develop_branch của source code vào thư mục gốc của demo-git:

    • index.html – trang web mẫu (file mới)
    • README.md – ghi đè file README hiện tại (file sửa đổi)
    • .gitignore – danh sách file Git bỏ qua (file mới)
    code .
git status
On branch develop
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
        modified:   README.md

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        .gitignore
        index.html

no changes added to commit (use "git add" and/or "git commit -a")

    README.md ở trạng thái modified, còn index.html, .gitignore là untracked (Git chưa theo dõi).

  4. Bước 4: Xem thay đổi & add vào staging area

    git diff hiển thị nội dung thay đổi (dòng + là thêm, - là xoá). Nhấn q để thoát:

    git diff README.md
git add index.html README.md .gitignore
git status

    Sau khi add, 3 file chuyển sang mục Changes to be committed. Có thể dùng git add . để add toàn bộ thay đổi trong thư mục hiện tại, nhưng hãy luôn git status trước để chắc chắn không add nhầm file.

  5. Bước 5: Commit 
    git commit -m "feat: add index.html, .gitignore and update README"
git log --oneline
3f2a1b9 (HEAD -> develop) feat: add index.html, .gitignore and update README
a1c0d42 (origin/main, origin/HEAD, main) Initial commit

    Commit hiện mới chỉ nằm ở local: develop đi trước main 1 commit và chưa có trên GitHub.

    💡 Commit message nên ngắn gọn, mô tả “làm gì”. Quy ước Conventional Commits hay dùng: feat: (tính năng), fix: (sửa lỗi), docs: (tài liệu), chore: (việc lặt vặt), refactor:, test:.

  6. Bước 6: Push nhánh develop lên GitHub

    Lần push đầu tiên của một branch mới cần -u (--set-upstream) để liên kết branch local với branch trên remote:

    git push -u origin develop
git branch -vv

    Trên GitHub, mục branch giờ có thêm develop. Chọn branch develop để thấy file index.html; branch main vẫn chưa có thay đổi.

  7. Bước 7: Sửa thêm 1 lần, commit & push

    Mở index.html, thêm 1 dòng vào danh sách <ul>:

        <li>Lab 4: Protect branch và Pull Request</li>

    Từ lần thứ 2, chỉ cần git push (đã có upstream):

    git add index.html
git commit -m "docs: add section list to index page"
git push
git log --oneline --graph --all

Kiểm tra kết quả

✅ Lab thành công khi

  • GitHub có 2 branch: main và develop.
  • Branch develop trên GitHub có index.html, .gitignore, README.md mới và 2 commit mới (xem ở mục Commits).
  • git status ở local báo Your branch is up to date with 'origin/develop' và nothing to commit, working tree clean.

Troubleshoot

fatal: The current branch develop has no upstream branch.
Nguyên nhân: Push branch mới mà không chỉ rõ remote/branch.
Giải pháp: Dùng git push -u origin develop cho lần đầu.
Author identity unknown *** Please tell me who you are.
Nguyên nhân: Chưa cấu hình user.name, user.email.
Giải pháp: Chạy lại bước 2 của Lab 1: git config --global user.name "Your Name" và git config --global user.email "your_email@example.com".
! [rejected] develop -> develop (fetch first)
Nguyên nhân: Branch trên remote có commit mới mà local chưa có (ví dụ bạn đã sửa file trực tiếp trên web GitHub).
Giải pháp: git pull origin develop để lấy về và merge, sau đó git push lại.
Lỡ git add nhầm file (ví dụ .env)
Nguyên nhân: Dùng git add . khi chưa kiểm tra git status.
Giải pháp: Chưa commit: git restore --staged .env, sau đó thêm .env vào .gitignore. Nếu đã push secret lên GitHub: coi như secret đã lộ, phải đổi (rotate) secret ngay.
