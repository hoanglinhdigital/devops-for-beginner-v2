Giới thiệu

Git là một hệ thống quản lý phiên bản (Version Control System – VCS) mã nguồn mở, dùng để theo dõi mọi thay đổi trong source code trong quá trình phát triển phần mềm. Git được Linus Torvalds (cha đẻ của Linux) phát triển vào năm 2005 để quản lý mã nguồn Linux kernel, và nhanh chóng trở thành tiêu chuẩn của ngành phần mềm.

Git giúp nhiều developer làm việc cùng nhau trên một dự án mà không ghi đè code của nhau: theo dõi lịch sử thay đổi (ai sửa gì, khi nào, vì sao), tách nhánh (branch) để phát triển song song nhiều tính năng hoặc sửa lỗi, và dễ dàng khôi phục lại phiên bản trước đó khi có sự cố.

Đặc trưng của Git

  • Open-source & miễn phí: chạy trên Windows, Mac, Linux; được tích hợp trong hầu hết IDE và công cụ CI/CD.
  • Kiến trúc phân tán (Distributed): mỗi developer có một bản copy đầy đủ của repository (kể cả lịch sử), có thể commit, xem log, tạo branch khi không có Internet và đồng bộ sau.
  • Nhanh & hiệu quả: hầu hết thao tác thực hiện ở local nên rất nhanh, kể cả với codebase lớn như Linux kernel.
  • Content-addressable file system: mỗi phiên bản file/commit được định danh bằng mã hash (SHA-1/SHA-256), giúp truy xuất nhanh, toàn vẹn dữ liệu và lấy lại phiên bản cũ dễ dàng.
  • Branch “nhẹ”: tạo/chuyển branch gần như tức thì, khuyến khích mỗi tính năng/bug một branch riêng.
  • Lịch sử chỉ thêm, không mất: thay đổi thường là thêm commit mới. Ngay cả khi revert, Git tạo thêm một commit “đảo ngược” chứ không xoá commit cũ.

Với Git, remote repository chỉ là “điểm hẹn” để đồng bộ. Mỗi máy developer đều giữ một bản sao đầy đủ — nếu server mất dữ liệu, có thể khôi phục từ bất kỳ máy nào.

Các nhà cung cấp dịch vụ Git

Git là công cụ; còn GitHub, GitLab, Bitbucket, CodeCommit... là dịch vụ lưu trữ remote repository, bổ sung giao diện web, Pull Request, phân quyền, CI/CD, issue tracking...

Use Cases

Quản lý source code ứng dụng

Team nhiều developer cùng phát triển, mỗi người một branch, review qua Pull Request, merge vào nhánh chính khi đạt chất lượng.

Infrastructure as Code & GitOps

Terraform template, Kubernetes manifest, Ansible playbook được lưu trên Git. Mọi thay đổi hạ tầng đều qua Pull Request và có lịch sử (GitOps với Argo CD ở các section sau).

Kích hoạt CI/CD pipeline

Mỗi lần push/merge vào branch, Jenkins, GitHub Actions, CodePipeline tự động build, test và deploy lên môi trường tương ứng.

Thông tin bổ sung

  • Git là phần mềm chạy ở máy bạn; GitHub là website dịch vụ. Có thể dùng Git mà không cần GitHub (repo local), nhưng làm việc nhóm thì cần một remote repository.
  • Từ năm 2020, GitHub đổi tên branch mặc định từ master sang main. Các repository cũ vẫn có thể dùng master, cách thao tác hoàn toàn giống nhau.
  • GitHub không còn cho phép dùng password tài khoản khi push qua HTTPS – cần dùng SSH key (Lab 2) hoặc Personal Access Token.
  • Tài liệu chính thức: Pro Git book, GitHub Docs.
