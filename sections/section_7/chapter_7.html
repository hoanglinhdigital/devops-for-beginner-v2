7. Thao tác cơ bản với Git / Lab 4: Protect branch, nhánh feature & Pull Request

Mục tiêu

  • Thiết lập bảo vệ branch main và develop bằng GitHub Ruleset: chặn push trực tiếp, chặn xoá, chặn force push.
  • Kiểm chứng việc push thẳng vào develop bị từ chối.
  • Tạo nhánh feature/F001 từ develop, thay đổi code và push lên GitHub.
  • Tạo Pull Request từ feature/F001 vào develop, review và merge.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 3: repository demo-git (Public) đã có branch main và develop.
  • Bạn là owner của repository (có quyền vào tab Settings).
  • Source code: sourcecode/section_7_git_basic_operation/lab4_protect_branch_pull_request/ (commands.sh, about.html).

Các bước thực hành

  1. Bước 1: Tạo Ruleset bảo vệ main & develop

    Trên GitHub, vào repository demo-git → Settings → Rules → Rulesets, tạo branch ruleset mới với các thông số:

    • Ruleset name: protect-main-develop
    • Enforcement status: Active
    • Bypass list: để trống (kể cả admin/owner cũng phải tuân thủ)
    • Target branches: Include default branch (main) và Include by pattern develop
    • Rules:
      • Restrict deletions – không cho xoá branch
      • Require a pull request before merging – Required approvals: 0
      • Block force pushes – không cho git push --force
    Required approvals = 0? GitHub không cho tác giả tự approve Pull Request của chính mình. Nếu học một mình, đặt 0 (vẫn bắt buộc đi qua PR). Nếu có bạn học cùng, mời họ vào repository (Settings → Collaborators) và đặt 1 để thực hành review thật.

    💡 GitHub còn có giao diện cũ Settings → Branches → Branch protection rules với chức năng tương tự. Ruleset là cách mới, linh hoạt hơn (áp dụng nhiều branch theo pattern, có bypass list).

  2. Bước 2: Kiểm chứng – push trực tiếp vào develop bị chặn

    Tạo một commit rỗng trên develop và thử push:

    cd ~/git-labs/demo-git
git checkout develop
git pull origin develop
git commit --allow-empty -m "test: direct push to develop"
git push origin develop
remote: error: GH013: Repository rule violations found for refs/heads/develop.
remote: - Changes must be made through a pull request.
To github.com:<GITHUB_USERNAME>/demo-git.git
 ! [remote rejected] develop -> develop (push declined due to repository rule violations)
error: failed to push some refs to 'github.com:<GITHUB_USERNAME>/demo-git.git'

    Push bị từ chối đúng như mong đợi. Bỏ commit test để develop local trở về giống develop trên GitHub (lệnh reset sẽ được giải thích kỹ ở chương Merge/Rebase/Squash):

    git reset --hard origin/develop
git log --oneline -3
  3. Bước 3: Tạo nhánh feature/F001 từ develop

    Luôn pull code mới nhất trước khi tạo branch mới:

    git checkout develop
git pull origin develop
git checkout -b feature/F001
  4. Bước 4: Thay đổi code
    • Copy file about.html từ source code vào thư mục gốc của demo-git.
    • Mở index.html, thêm link tới trang About vào danh sách <ul>:
        <li><a href="about.html">About</a></li>
    git status
git add about.html index.html
git commit -m "feat(F001): add about page"
  5. Bước 5: Push nhánh feature/F001 lên GitHub 
    git push -u origin feature/F001

    Push thành công vì feature/F001 không nằm trong Ruleset. Output có gợi ý link tạo Pull Request: remote: Create a pull request for 'feature/F001' on GitHub by visiting: ...

  6. Bước 6: Tạo Pull Request

    Trên GitHub (banner Compare & pull request hoặc tab Pull requests → New pull request), tạo PR với thông số:

    • base: develop ← compare: feature/F001 (chú ý: mặc định base là main, cần đổi sang develop)
    • Title: F001 - Add about page
    • Description: mô tả ngắn thay đổi, cách kiểm tra (ví dụ “Mở index.html, click link About”).
  7. Bước 7: Review & Merge Pull Request
    • Tab Files changed: xem diff từng file, thử thêm comment vào một dòng code (dấu + cạnh số dòng).
    • Nếu có reviewer: reviewer chọn Review changes → Approve.
    • Tab Conversation: chọn Merge pull request (kiểu Create a merge commit) → Confirm merge.
    • Xoá branch feature/F001 trên GitHub bằng nút Delete branch sau khi merge.
  8. Bước 8: Cập nhật develop ở local

    Merge diễn ra trên GitHub nên develop ở local chưa có thay đổi. Pull về và xoá branch feature đã merge:

    git checkout develop
git pull origin develop
git log --oneline --graph -10
git branch -d feature/F001
git fetch --prune
git branch -a

    git fetch --prune xoá các tham chiếu remotes/origin/feature/F001 đã bị xoá trên GitHub.

Kiểm tra kết quả

✅ Lab thành công khi

  • Push trực tiếp vào develop (hoặc main) bị từ chối với lỗi GH013: Repository rule violations.
  • Tab Pull requests → Closed có PR F001 - Add about page ở trạng thái Merged.
  • Branch develop (GitHub và local) có file about.html; git log --graph hiển thị merge commit Merge pull request #1 ....

Troubleshoot

Push trực tiếp vào develop vẫn thành công, kèm dòng remote: Bypassed rule violations for refs/heads/develop
Nguyên nhân: Tài khoản của bạn nằm trong Bypass list, hoặc dùng Branch protection rule kiểu cũ mà không bật “Do not allow bypassing the above settings”.
Giải pháp: Xoá mọi mục trong Bypass list của Ruleset, kiểm tra Enforcement status là Active (không phải Evaluate/Disabled).
Không thấy tuỳ chọn Rulesets/Branch protection hoặc có thông báo cần nâng cấp lên GitHub Team
Nguyên nhân: Repository đang để Private trên tài khoản GitHub Free.
Giải pháp: Đổi repository sang Public (Settings → General → Danger Zone → Change visibility) hoặc dùng GitHub Pro (miễn phí cho sinh viên qua GitHub Student Developer Pack).
Nút Merge bị khoá: Review required – At least 1 approving review is required
Nguyên nhân: Ruleset đặt Required approvals ≥ 1 nhưng chỉ có một mình bạn (không thể tự approve PR của mình).
Giải pháp: Sửa Ruleset về Required approvals 0, hoặc mời collaborator vào review.
PR tạo nhầm vào main thay vì develop
Nguyên nhân: Base branch mặc định là default branch (main).
Giải pháp: Trong PR, chọn Edit cạnh tiêu đề để đổi base branch sang develop (chưa merge thì đổi được).
