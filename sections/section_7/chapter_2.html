7. Thao tác cơ bản với Git / Kiến trúc & vòng đời (life cycle) của Git

Giới thiệu

Trước khi gõ lệnh, cần hiểu Git lưu code ở đâu và một thay đổi đi qua những “khu vực” nào trước khi tới được GitHub. Nắm vững các khái niệm repository, commit, branch, remote và 4 khu vực Working Directory → Staging Area → Local Repository → Remote Repository sẽ giúp bạn hiểu mọi lệnh Git thay vì học thuộc lòng.

Các khái niệm chính

  • Repository (repo): nơi lưu toàn bộ file code, thư mục và lịch sử thay đổi của project. Repository có thể nằm ở máy local, server công ty hoặc trên Cloud (GitHub...). Ở local, lịch sử nằm trong thư mục ẩn .git.
  • Commit: ảnh chụp (snapshot) của codebase tại một thời điểm, có mã hash duy nhất (ví dụ a1b2c3d), tác giả, thời gian và message mô tả.
  • Branch: một “dòng phát triển” riêng biệt tạo ra từ một commit. Về bản chất branch chỉ là con trỏ trỏ tới commit mới nhất của nhánh đó.
  • Merge: kết hợp thay đổi của một branch vào branch khác.
  • Remote: bản copy của repository nằm trên máy khác hoặc server (thường tên là origin), dùng để cộng tác và đồng bộ thay đổi giữa các thành viên.
  • Clone / Pull / Push: clone tải bản copy đầy đủ của remote về máy; pull tải thay đổi mới từ remote và merge vào local; push đẩy commit từ local lên remote.

Một thay đổi đi từ trái sang phải: sửa file → add vào staging → commit vào local repo → push lên remote. Chiều ngược lại dùng fetch/pull.

Vì sao cần Staging Area? Bạn sửa 5 file nhưng chỉ muốn commit 2 file liên quan tới một tính năng. Staging Area cho phép chọn chính xác những thay đổi nào đi vào commit, giúp mỗi commit gọn gàng, có ý nghĩa.

  • Create: tạo mới repository ở local (git init) hoặc trên remote rồi clone về (git clone).
  • Modify: thêm/sửa/xoá file bằng IDE (VS Code...). Git tự động phát hiện file thay đổi (git status).
  • Stage: dùng git add để chọn các thay đổi sẽ được commit.
  • Commit: ghi các thay đổi đã stage vào lịch sử của local repository.
  • Push: đẩy commit từ local lên remote repository (GitHub, Git server công ty...) để chia sẻ với team.

Use Cases: một ngày làm việc với Git

Buổi sáng: lấy code mới nhất

git checkout develop → git pull để có code mới nhất mà đồng nghiệp đã merge hôm qua, sau đó git checkout -b feature/T123 để bắt đầu task mới.

Trong ngày: commit thường xuyên

Mỗi khi hoàn thành một phần nhỏ: git status → git add → git commit -m "...". Commit nhỏ giúp dễ review và dễ revert.

Cuối ngày: push & tạo Pull Request

git push -u origin feature/T123 để backup code lên remote, tạo Pull Request vào develop nhờ đồng nghiệp review, CI tự chạy test.

Thông tin bổ sung

  • Thư mục .git chính là toàn bộ repository. Xoá .git = mất toàn bộ lịch sử (chỉ còn file hiện tại). Không chỉnh sửa tay file trong .git.
  • Commit chỉ nằm ở máy bạn cho tới khi push. Hỏng ổ cứng trước khi push = mất code, hãy push thường xuyên.
  • File .gitignore khai báo những file/thư mục Git bỏ qua (ví dụ node_modules/, .env, *.pem, terraform.tfstate).
  • Git chỉ theo dõi file, không theo dõi thư mục rỗng. Muốn giữ thư mục rỗng, tạo file .gitkeep bên trong.
