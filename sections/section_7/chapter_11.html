7. Thao tác cơ bản với Git / Merge vs Rebase vs Squash & các lệnh stash, reset

Giới thiệu

Khi đưa code từ nhánh feature vào nhánh chính (ví dụ develop), có 3 phương án thường dùng: Merge, Rebase và Squash commit. Cả 3 đều cho ra cùng một nội dung code cuối cùng, chỉ khác nhau ở hình dạng lịch sử commit – ảnh hưởng tới việc đọc log, review và revert sau này. Chương này cũng giới thiệu các lệnh hay dùng hằng ngày: git stash (cất tạm công việc dang dở), git reset (di chuyển branch về commit cũ) và git reflog (cứu commit “bị mất”).

Đặc điểm chính

  • Merge: tạo ra một commit mới (“nút thắt”) nối hai nhánh lại với nhau, giữ nguyên toàn bộ lịch sử của cả hai nhánh.
  • Rebase: đem toàn bộ commit của nhánh source “đặt lại” lên đầu nhánh target theo đúng thứ tự, tạo lịch sử thẳng một đường. Commit được tạo lại với hash mới.
  • Squash commit: gom toàn bộ commit của nhánh source thành một commit duy nhất và đặt lên đầu nhánh target.
  • git stash: lưu tạm thay đổi chưa commit vào một “ngăn kéo” để chuyển sang branch khác, sau đó lấy lại.
  • git reset: di chuyển branch hiện tại về một commit chỉ định với 3 chế độ --soft, --mixed, --hard.
  • git reflog: nhật ký mọi vị trí HEAD đã đi qua ở local – giúp tìm lại commit sau khi lỡ reset --hard.

Mô hình: so sánh lịch sử sau khi combine

Tình huống ban đầu: nhánh feature có 2 commit F1, F2 tạo từ C2; trong lúc đó main có thêm commit C3.

1. Merge – lịch sử phân nhánh, có merge commit

gitGraph commit id: "C1" commit id: "C2" branch feature checkout feature commit id: "F1" commit id: "F2" checkout main commit id: "C3" merge feature id: "Merge feature" 
git checkout main
git merge --no-ff feature

2. Rebase – lịch sử thẳng, F1/F2 được tạo lại (F1', F2')

gitGraph commit id: "C1" commit id: "C2" commit id: "C3" commit id: "F1'" commit id: "F2'" 
git checkout feature
git rebase main
git checkout main
git merge feature

3. Squash – 1 commit duy nhất đại diện cho cả feature

gitGraph commit id: "C1" commit id: "C2" commit id: "C3" commit id: "S = F1 + F2" type: HIGHLIGHT 
git checkout main
git merge --squash feature
git commit -m "feat: add feature (F1 + F2)"

Trên GitHub, 3 phương án này tương ứng 3 lựa chọn của nút Merge trong Pull Request: Create a merge commit, Rebase and merge, Squash and merge.

Quy tắc vàng của rebase: không rebase những commit đã push lên branch mà người khác đang dùng (ví dụ develop, main). Rebase tạo commit mới với hash mới, buộc phải push --force và làm lệch lịch sử của cả team.

Các lệnh hữu ích khác

git stash – cất tạm công việc dang dở

Đang code dở tính năng A thì có bug khẩn cấp cần chuyển sang branch khác, nhưng chưa muốn commit code dở dang:

LệnhÝ nghĩa
git stashCất thay đổi của các file đã được track (file mới chưa git add lần nào sẽ không được cất)
git stash push --include-untracked -m "msg"Cất cả file untracked, kèm mô tả
git stash listLiệt kê các stash (stash@{0} là mới nhất)
git stash applyLấy thay đổi đã stash xuống branch hiện tại, vẫn giữ trong danh sách stash
git stash popLấy thay đổi xuống và xoá khỏi danh sách stash
git stash dropXoá một stash

git reset – di chuyển branch về commit chỉ định

flowchart LR R["⏪ git reset COMMIT
branch quay về commit chỉ định"] R --> S["🟢 --soft
thay đổi giữ ở Staged
commit lại ngay được"] R --> M["🟡 --mixed (mặc định)
thay đổi giữ ở Unstaged
review & add lại"] R --> H["🔴 --hard
xoá bỏ mọi thay đổi
sau commit đó"]
LệnhÝ nghĩaVí dụ sử dụng
git reset --soft <commit>Di chuyển branch về commit chỉ định, các file đã thay đổi được giữ ở trạng thái staged. Chạy lại git commit là xong.Gộp 3 commit gần nhất thành 1: git reset --soft HEAD~3 rồi commit lại
git reset --mixed <commit>Di chuyển branch về commit chỉ định, các file đã thay đổi chuyển thành unstaged. Bạn review và add lại file cần thiết.Lỡ commit thừa file, muốn chọn lại
git reset --hard <commit>Di chuyển branch về commit chỉ định và discard toàn bộ thay đổi sau commit đó.Bỏ hết thử nghiệm ở local: git reset --hard origin/develop

💡 HEAD~1 = commit ngay trước HEAD, HEAD~3 = lùi 3 commit. Có thể dùng hash commit thay thế.

Thực hành nhanh trên repository local

Phần thực hành dùng một repository local mới (không cần GitHub) để thoải mái thử nghiệm. Toàn bộ lệnh có trong sourcecode/section_7_git_basic_operation/git_merge_rebase_squash/commands.sh. Sau mỗi phần, chạy git log --oneline --graph --all (hoặc xem bằng SourceTree) để so sánh hình dạng lịch sử.

  1. Bước 1: Tạo repository playground 
    mkdir -p ~/git-labs/git-playground
cd ~/git-labs/git-playground
git init -b main
echo "line 1" > app.txt
git add app.txt
git commit -m "C1: init app"
echo "line 2" >> app.txt
git commit -am "C2: add line 2"

    💡 git commit -am = add tất cả file đã được track + commit (không áp dụng cho file mới).

  2. Bước 2: Merge 
    git checkout -b feature/merge-demo
echo "merge feature" > merge.txt
git add merge.txt
git commit -m "M1: add merge.txt"
echo "merge feature 2" >> merge.txt
git commit -am "M2: update merge.txt"
git checkout main
echo "main change" > main.txt
git add main.txt
git commit -m "C3: add main.txt"
git merge --no-ff feature/merge-demo -m "Merge branch feature/merge-demo"
git log --oneline --graph --all
  3. Bước 3: Rebase 
    git checkout -b feature/rebase-demo
echo "rebase feature" > rebase.txt
git add rebase.txt
git commit -m "R1: add rebase.txt"
echo "rebase feature 2" >> rebase.txt
git commit -am "R2: update rebase.txt"
git checkout main
echo "main change 2" >> main.txt
git commit -am "C4: update main.txt"
git checkout feature/rebase-demo
git log --oneline -3
git rebase main
git log --oneline -3
git checkout main
git merge feature/rebase-demo
git log --oneline --graph -8

    So sánh hash của R1, R2 trước và sau rebase – hash đã thay đổi vì commit được tạo lại. Lệnh merge cuối cùng là fast-forward: không có merge commit, lịch sử thẳng.

  4. Bước 4: Squash 
    git checkout -b feature/squash-demo
echo "squash 1" > squash.txt
git add squash.txt
git commit -m "S1: add squash.txt"
echo "squash 2" >> squash.txt
git commit -am "S2: fix typo"
echo "squash 3" >> squash.txt
git commit -am "S3: fix typo again"
git checkout main
git merge --squash feature/squash-demo
git status
git commit -m "feat: add squash feature (S1+S2+S3)"
git log --oneline --graph -8

    Sau merge --squash, thay đổi nằm ở staging area và chưa có commit – bạn tự commit với message mới. Trên main chỉ có 1 commit thay cho S1, S2, S3.

  5. Bước 5: Stash 
    echo "work in progress" >> app.txt
echo "new file" > draft.txt
git status
git stash
git status
git stash pop

    Quan sát: sau git stash, app.txt trở về như cũ nhưng draft.txt (untracked) vẫn còn. Cất cả file untracked rồi chuyển branch:

    git stash push --include-untracked -m "wip: draft"
git status
git stash list
git checkout -b hotfix/urgent
git checkout main
git stash pop
git status
git add .
git commit -m "C5: finish wip"
  6. Bước 6: Reset soft / mixed / hard 
    echo "reset 1" > reset.txt
git add reset.txt
git commit -m "X1: add reset.txt"
echo "reset 2" >> reset.txt
git commit -am "X2: update reset.txt"
git log --oneline -3

    --soft: commit X2 bị gỡ, thay đổi vẫn ở staged (Changes to be committed):

    git reset --soft HEAD~1
git status
git commit -m "X2: update reset.txt (commit again)"

    --mixed: thay đổi chuyển về unstaged (Changes not staged for commit), phải add lại:

    git reset --mixed HEAD~1
git status
git add reset.txt
git commit -m "X2: update reset.txt (commit again)"

    --hard: thay đổi của X2 bị xoá hoàn toàn khỏi working directory:

    git reset --hard HEAD~1
cat reset.txt
reset 1
  7. Bước 7: Cứu commit bằng reflog

    Commit X2 không còn trên branch nhưng vẫn còn trong reflog (local, giữ mặc định khoảng 90 ngày). Tìm hash của dòng commit: X2: update reset.txt (commit again) và reset về đó:

    git reflog -10
git reset --hard <COMMIT_HASH>
cat reset.txt

    reset.txt có lại dòng reset 2.

Use Cases

Team quy định “Squash and merge” cho PR vào develop

Mỗi PR = 1 commit trên develop kèm mã ticket, lịch sử gọn, dễ tạo release note và revert nguyên một tính năng bằng một lệnh.

Cập nhật feature branch cá nhân

Trước khi tạo PR, developer chạy git pull --rebase origin develop trên branch của riêng mình để đặt commit lên đầu develop mới nhất, PR không có merge commit thừa.

Bug khẩn cấp khi đang code dở

git stash push -u → git checkout -b hotfix/... từ main → sửa bug, tạo PR → quay lại branch cũ và git stash pop tiếp tục công việc.

Thông tin bổ sung

  • Chỉ dùng reset --hard, rebase, commit --amend với commit chưa push hoặc trên branch chỉ mình bạn dùng. Với branch chung, dùng git revert.
  • Nếu bắt buộc phải force push branch cá nhân, dùng git push --force-with-lease thay vì --force – lệnh sẽ từ chối nếu trên remote có commit mới của người khác.
  • Trên GitHub có thể bật/tắt từng kiểu merge tại Settings → General → Pull Requests để cả team dùng thống nhất một kiểu.
  • Dọn dẹp sau khi thực hành: rm -rf ~/git-labs/git-playground.
