5. Infra as Code sử dụng Terraform / Giới thiệu Terraform: thành phần & cơ chế hoạt động

Giới thiệu

Terraform là công cụ IaC mã nguồn mở do HashiCorp phát triển, sử dụng ngôn ngữ HCL (HashiCorp Configuration Language) và hỗ trợ nhiều cloud: AWS, GCP, Azure... Bạn chỉ cần khai báo trạng thái mong muốn của hạ tầng (declarative), Terraform sẽ tự so sánh với hạ tầng thực tế và tính toán cần tạo, sửa hay xoá những gì.

Các thành phần cơ bản của Terraform

  • Template files (.tf): các file cấu hình viết bằng HCL, mô tả hạ tầng mong muốn.
  • Providers: plugin giúp Terraform tương tác với API của cloud, nền tảng hoặc phần mềm (ví dụ hashicorp/aws). Provider được tải về khi chạy terraform init.
  • Resources: các thành phần hạ tầng cần tạo như EC2, VPC, Security Group, S3 bucket... Ngoài ra có data source dùng để đọc thông tin có sẵn (ví dụ tìm AMI mới nhất).
  • Terraform CLI: các lệnh để khởi tạo, lập kế hoạch, áp dụng và huỷ hạ tầng.
  • State files: file terraform.tfstate lưu thông tin về hạ tầng Terraform đã tạo và đang quản lý (ID, IP, ARN...).
  • Variables & Outputs: variable dùng để tuỳ biến cấu hình (instance size, region...), output dùng để lấy giá trị từ hạ tầng đã tạo (IP, DNS...). Modules giúp đóng gói và tái sử dụng một nhóm resource.

Cú pháp HCL cơ bản

Một file .tf gồm nhiều block. Cú pháp chung: <loại block> "<type>" "<tên>" { thuộc_tính = giá_trị }.

# Cấu hình chung: version Terraform, provider cần dùng
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

# Provider: kết nối tới AWS region nào
provider "aws" {
  region = "ap-southeast-1"
}

# Variable: tham số đầu vào
variable "instance_type" {
  type    = string
  default = "t3.micro"
}

# Data source: đọc thông tin có sẵn trên AWS
data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]
  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

# Resource: <type> "aws_instance" + <tên logic> "web"
resource "aws_instance" "web" {
  ami           = data.aws_ami.amazon_linux.id   # tham chiếu data source
  instance_type = var.instance_type              # tham chiếu variable
}

# Output: giá trị trả về sau khi apply
output "web_public_ip" {
  value = aws_instance.web.public_ip             # tham chiếu thuộc tính của resource
}
Tham chiếu giữa các block:
  • var.<tên> — giá trị của variable
  • <resource_type>.<tên>.<thuộc tính> — ví dụ aws_instance.web.id
  • data.<type>.<tên>.<thuộc tính> — ví dụ data.aws_ami.amazon_linux.id
  • module.<tên module>.<output> — ví dụ module.networking.vpc_id
Terraform tự xây dựng dependency graph từ các tham chiếu này để biết resource nào cần tạo trước.

Cấu trúc thư mục một project Terraform điển hình

my-project/
├── main.tf             # provider, resource, module
├── variable.tf         # khai báo variable
├── output.tf           # khai báo output
├── terraform.tfvars    # giá trị của variable (tự động được load)
├── modules/            # các module con tự viết
├── .terraform/         # provider, module đã tải về (tự sinh, không commit)
├── .terraform.lock.hcl # khoá version provider
└── terraform.tfstate   # state (tự sinh, KHÔNG commit lên Git)

Trade-off

✅ Ưu điểm

  • Đa cloud, hệ sinh thái provider và module rất lớn.
  • Cú pháp khai báo, dễ đọc; plan cho thấy trước thay đổi.
  • Không phụ thuộc CloudFormation; template thuộc về bạn.
  • Cộng đồng lớn, tài liệu phong phú.

⚠️ Nhược điểm

  • Phải tự quản lý state (lưu ở đâu, khoá, backup, bảo mật).
  • State có thể chứa thông tin nhạy cảm.
  • Logic phức tạp (vòng lặp, điều kiện) kém linh hoạt hơn ngôn ngữ lập trình.
  • Sửa tay trên Console gây drift, cần kỷ luật trong team.

Use Cases

🏗️ Dựng hạ tầng chuẩn cho dự án

VPC 3 tầng, Security Group, ALB, Auto Scaling, RDS được đóng gói thành module, dự án mới chỉ cần truyền tham số.

🔁 Tích hợp CI/CD

Pipeline chạy terraform plan khi có Pull Request để review, merge vào main thì chạy terraform apply.

🌐 Quản lý cả SaaS

Ngoài AWS, Terraform còn quản lý Github repository, Cloudflare DNS, Datadog monitor... trong cùng một project.

Thông tin bổ sung

  • Tài liệu chính thức: developer.hashicorp.com/terraform.
  • Tra cứu cú pháp resource AWS: Terraform Registry – AWS Provider. Mỗi resource đều có phần Example Usage, Argument Reference (input) và Attribute Reference (giá trị có thể lấy ra).
  • Lệnh tiện ích: terraform fmt (format code), terraform validate (kiểm tra cú pháp), terraform show, terraform state list.
