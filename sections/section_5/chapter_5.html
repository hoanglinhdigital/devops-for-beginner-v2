5. Infra as Code sử dụng Terraform / Lab 2: Template Terraform đầu tiên – EC2 & Security Group

Mục tiêu

  • Chuẩn bị một keypair (1 private key + 1 public key) dùng chung cho các lab.
  • Viết Terraform template đầu tiên gồm 1 EC2 instance và 1 Security Group với cấu hình cơ bản.
  • Thực hành đầy đủ các bước init → plan → apply → destroy và hiểu output của từng bước.
  • Thay đổi thông số resource (instance type) và apply thay đổi.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 1: đã cài AWS CLI v2 (đã aws configure), Terraform >= 1.10, VS Code.
  • Region ap-southeast-1 (Singapore) có Default VPC. Kiểm tra tại VPC → Your VPCs, cột Default VPC = Yes. Nếu đã lỡ xoá, tạo lại bằng Actions → Create default VPC.
  • Thư mục làm việc ~/terraform-labs đã tạo ở Lab 1.

Các bước thực hành

  1. Bước 1: Tạo keypair bằng ssh-keygen

    Keypair này sẽ được dùng lại cho tất cả các lab sau trong section. Chạy trong Git Bash (Windows) hoặc Terminal (Mac):

    cd ~/terraform-labs
ssh-keygen -t rsa -b 4096 -C "udemy-terraform" -f ./keypair/udemy-key -N ""

    Kết quả tạo ra 2 file: keypair/udemy-key (private key – giữ bí mật, dùng để SSH) và keypair/udemy-key.pub (public key – sẽ upload lên AWS).

    Không commit thư mục keypair lên Git. Source code khoá học đã có sẵn .gitignore để loại trừ thư mục này.
  2. Bước 2: Tạo template Terraform

    Tạo thư mục lab2_ec2_basic, mở bằng VS Code, tạo file main.tf và copy nội dung sau:

    mkdir -p ~/terraform-labs/lab2_ec2_basic
cd ~/terraform-labs/lab2_ec2_basic
code .

    📄 lab2_ec2_basic/main.tf

    terraform {
  required_version = ">= 1.10.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

provider "aws" {
  region = "ap-southeast-1"
}

# Data source: tra cứu AMI Amazon Linux 2023 mới nhất (không cần hard-code AMI ID)
data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

# Đăng ký public key lên AWS để SSH vào EC2
resource "aws_key_pair" "udemy_keypair" {
  key_name   = "udemy-keypair"
  public_key = file("../keypair/udemy-key.pub")
}

resource "aws_security_group" "demo_sg" {
  name        = "demo-security-group"
  description = "Allow HTTP, HTTPS, SSH"

  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "demo_instance" {
  ami                    = data.aws_ami.amazon_linux.id
  instance_type          = "t3.micro"
  key_name               = aws_key_pair.udemy_keypair.key_name
  vpc_security_group_ids = [aws_security_group.demo_sg.id]

  tags = {
    Name   = "Udemy Demo"
    Domain = "DevOps"
  }
}
  3. Bước 3: Tìm hiểu các thành phần trong template
    BlockÝ nghĩa
    terraform { required_providers }Khai báo version Terraform tối thiểu và provider hashicorp/aws (bản 6.x).
    provider "aws"Deploy vào region Singapore, credential lấy từ aws configure.
    data "aws_ami"Data source: tra cứu AMI Amazon Linux 2023 mới nhất, tránh hard-code AMI ID (AMI ID khác nhau theo region và thay đổi theo thời gian).
    resource "aws_key_pair"Upload public key lên AWS. Hàm file() đọc nội dung file.
    resource "aws_security_group"Mở inbound 22 (SSH), 80 (HTTP), 443 (HTTPS); cho phép toàn bộ outbound. Không chỉ định vpc_id nên được tạo trong Default VPC.
    resource "aws_instance"EC2 tham chiếu tới AMI, keypair và Security Group ở trên → Terraform tự biết phải tạo keypair, SG trước rồi mới tạo EC2.
  4. Bước 4: terraform init

    Khởi tạo thư mục làm việc, Terraform sẽ tải AWS provider về thư mục .terraform và tạo file .terraform.lock.hcl để khoá version provider:

    terraform init
Terraform has been successfully initialized!
  5. Bước 5: terraform plan

    Xem trước những gì sẽ được tạo. Ký hiệu + là tạo mới; dòng cuối cùng tóm tắt số resource thêm/sửa/xoá:

    terraform plan
Plan: 3 to add, 0 to change, 0 to destroy.

    Các giá trị hiển thị (known after apply) như id, public_ip chỉ có sau khi AWS tạo resource.

  6. Bước 6: terraform apply

    Terraform hiển thị lại plan và hỏi xác nhận, gõ yes để thực thi:

    terraform apply
Apply complete! Resources: 3 added, 0 changed, 0 destroyed.

    Vào EC2 → Instances trên AWS Console để thấy instance Udemy Demo đang ở trạng thái Running, kèm Security Group demo-security-group và key pair udemy-keypair. Trong thư mục lab xuất hiện file terraform.tfstate — đây là nơi Terraform ghi nhớ những gì nó đã tạo.

  7. Bước 7: SSH vào EC2

    Lấy public IP của instance từ state:

    terraform state show aws_instance.demo_instance | grep public_ip

    Trên Mac/Linux cần giới hạn quyền file private key trước khi SSH:

    chmod 400 ../keypair/udemy-key

    SSH vào instance (thay <PUBLIC_IP> bằng IP vừa lấy được, user mặc định của Amazon Linux là ec2-user):

    ssh -i ../keypair/udemy-key ec2-user@<PUBLIC_IP>

    Gõ exit để thoát khỏi EC2.

  8. Bước 8: Thay đổi thông số resource và apply

    Trong main.tf, sửa resource aws_instance.demo_instance:

    • instance_type: "t3.micro" → "t3.small"
    • Thêm một tag mới trong tags: Owner = "Udemy"
    terraform plan
Plan: 0 to add, 1 to change, 0 to destroy.

    Ký hiệu ~ nghĩa là update in-place: Terraform sẽ stop instance, đổi instance type rồi start lại, không tạo instance mới. Chạy terraform apply và kiểm tra trên Console instance type đã đổi thành t3.small.

    Thử thêm: đổi name của Security Group rồi chạy terraform plan. Bạn sẽ thấy ký hiệu -/+ (must be replaced) — một số thuộc tính không sửa tại chỗ được, Terraform phải xoá và tạo lại resource. Đây là lý do luôn phải đọc kỹ plan trước khi apply.
  9. Bước 9: Destroy resources

    Xoá toàn bộ resource đã tạo trong lab, gõ yes để xác nhận:

    terraform destroy
Destroy complete! Resources: 3 destroyed.

Kiểm tra kết quả

✅ Lab thành công khi

  • terraform apply tạo thành công 3 resource; EC2 Udemy Demo ở trạng thái Running.
  • SSH được vào EC2 bằng private key udemy-key.

Troubleshoot

Invalid value for "path" parameter: no file exists at "../keypair/udemy-key.pub"
Nguyên nhân: Chưa tạo keypair, hoặc cấu trúc thư mục không đúng (thư mục keypair phải nằm cùng cấp với lab2_ec2_basic).
Giải pháp: Thực hiện lại Bước 1 và kiểm tra bằng ls ../keypair.
VPCIdNotSpecified: No default VPC for this user
Nguyên nhân: Region không có Default VPC.
Giải pháp: Vào VPC → Your VPCs → Actions → Create default VPC.
InvalidKeyPair.Duplicate: The keypair already exists / InvalidGroup.Duplicate
Nguyên nhân: Đã có key pair/Security Group cùng tên (tạo tay hoặc từ lần chạy trước chưa destroy).
Giải pháp: Xoá resource trùng tên trên Console (EC2 → Key Pairs / Security Groups) rồi apply lại.
WARNING: UNPROTECTED PRIVATE KEY FILE! hoặc Permission denied (publickey)
Nguyên nhân: File private key có quyền quá rộng, hoặc dùng sai user/sai key.
Giải pháp: Chạy chmod 400 ../keypair/udemy-key; dùng user ec2-user cho Amazon Linux.
No valid credential sources found
Nguyên nhân: Terraform không tìm thấy credential AWS.
Giải pháp: Chạy lại aws configure và aws sts get-caller-identity (xem Lab 1).

Dọn dẹp resource

Luôn xoá resource sau khi thực hành để tránh phát sinh chi phí. Giữ lại thư mục keypair để dùng cho các lab sau.
terraform destroy -auto-approve
