5. Infra as Code sử dụng Terraform / Lab 3: Variable, Map & Variable file

Mục tiêu

  • Hiểu về Input Variable (parameter) và các kiểu dữ liệu: string, number, bool, list, map.
  • Dùng map để chọn instance type theo môi trường (dev/test/prod).
  • Biết các cách truyền giá trị cho variable: default, file terraform.tfvars, tham số -var và -var-file trên command line.
  • Thêm validation để chặn giá trị không hợp lệ ngay ở bước plan.

Kiến thức cần nắm

Khai báo variable

variable "instance_type" {
  type        = string            # kiểu dữ liệu
  description = "EC2 size"        # mô tả
  default     = "t3.micro"        # giá trị mặc định (không có default = bắt buộc truyền)
  nullable    = false             # không cho phép null
}

Thứ tự ưu tiên khi truyền giá trị (thấp → cao)

Ưu tiênNguồn giá trịVí dụ
1 (thấp nhất)default trong khối variabledefault = "dev"
2Biến môi trường TF_VAR_<tên>export TF_VAR_environment=test
3File terraform.tfvars, *.auto.tfvars (tự động load)environment = "dev"
4 (cao nhất)-var và -var-file trên command lineterraform plan -var="environment=prod"

Các bước thực hành

  1. Bước 1: Tạo thư mục lab 
    mkdir -p ~/terraform-labs/lab3_variables
cd ~/terraform-labs/lab3_variables
code .
  2. Bước 2: Tạo file variable.tf

    Khai báo toàn bộ biến. Chú ý biến instance_types kiểu map(string) và khối validation của biến environment:

    📄 lab3_variables/variable.tf

    variable "region" {
  type        = string
  description = "AWS region để deploy resource"
  default     = "ap-southeast-1"
}

variable "environment" {
  type        = string
  description = "Tên môi trường: dev, test hoặc prod"
  default     = "dev"

  validation {
    condition     = contains(["dev", "test", "prod"], var.environment)
    error_message = "environment chỉ nhận một trong các giá trị: dev, test, prod."
  }
}

# Map: mỗi môi trường dùng một instance type khác nhau
variable "instance_types" {
  type        = map(string)
  description = "Instance type tương ứng với từng môi trường"
  default = {
    dev  = "t3.micro"
    test = "t3.small"
    prod = "t3.medium"
  }
}

variable "keypair_path" {
  type        = string
  description = "Đường dẫn tới public key"
  default     = "../keypair/udemy-key.pub"
}

variable "allowed_ssh_cidr" {
  type        = string
  description = "Dải IP được phép SSH vào EC2"
  default     = "0.0.0.0/0"
}

variable "tags" {
  type        = map(string)
  description = "Tag dùng chung cho resource"
  default     = {}
}
  3. Bước 3: Tạo file main.tf

    So với Lab 2, các giá trị cố định đã được thay bằng var.xxx. Instance type được lấy từ map theo môi trường: var.instance_types[var.environment]. Chuỗi "udemy-demo-${var.environment}" là cú pháp string interpolation.

    📄 lab3_variables/main.tf

    terraform {
  required_version = ">= 1.10.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

provider "aws" {
  region = var.region
}

data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

resource "aws_key_pair" "udemy_keypair" {
  key_name   = "udemy-keypair-${var.environment}"
  public_key = file(var.keypair_path)
}

resource "aws_security_group" "demo_sg" {
  name        = "demo-sg-${var.environment}"
  description = "Allow HTTP, SSH"

  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = [var.allowed_ssh_cidr]
  }

  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "demo_instance" {
  ami                    = data.aws_ami.amazon_linux.id
  instance_type          = var.instance_types[var.environment]
  key_name               = aws_key_pair.udemy_keypair.key_name
  vpc_security_group_ids = [aws_security_group.demo_sg.id]

  # merge(): gộp tag chung (từ biến) với tag riêng của resource
  tags = merge(var.tags, {
    Name        = "udemy-demo-${var.environment}"
    Environment = var.environment
  })
}
  4. Bước 4: Tạo file terraform.tfvars

    File này chứa giá trị cho các biến và được Terraform tự động load:

    📄 lab3_variables/terraform.tfvars

    region           = "ap-southeast-1"
environment      = "dev"
allowed_ssh_cidr = "0.0.0.0/0"
tags = {
  Owner   = "Udemy"
  Project = "terraform-lab3"
}
  5. Bước 5: Deploy với giá trị trong terraform.tfvars 
    terraform init
terraform plan
terraform apply -auto-approve

    Kiểm tra trên EC2 → Instances: instance udemy-demo-dev, type t3.micro, có các tag Owner, Project, Environment.

  6. Bước 6: Ghi đè biến bằng tham số -var

    Xem Terraform sẽ thay đổi gì nếu chuyển sang môi trường test (không cần apply):

    terraform plan -var="environment=test"

    Plan cho thấy instance type đổi thành t3.small và tên/tag đổi theo. Thử truyền giá trị không hợp lệ để thấy validation hoạt động:

    terraform plan -var="environment=staging"
Error: Invalid value for variable ... environment chỉ nhận một trong các giá trị: dev, test, prod.
  7. Bước 7: Dùng variable file riêng với -var-file

    Trong thực tế mỗi môi trường thường có một file biến riêng. Tạo file prod.tfvars với nội dung:

    environment = "prod"
tags = {
  Owner   = "Udemy"
  Project = "terraform-lab3-prod"
}
    terraform plan -var-file="prod.tfvars"

    Plan hiển thị instance type t3.medium. Giá trị trong prod.tfvars ghi đè giá trị trong terraform.tfvars.

  8. Bước 8: Biến bắt buộc nhập (không có default)

    Tạm xoá dòng environment = "dev" trong terraform.tfvars và xoá dòng default = "dev" trong variable.tf, chạy terraform plan: Terraform sẽ hỏi bạn nhập giá trị cho var.environment trên terminal. Nhập dev để tiếp tục, sau đó khôi phục lại 2 dòng đã xoá.

Kiểm tra kết quả

✅ Lab thành công khi

  • EC2 udemy-demo-dev được tạo với type t3.micro và đầy đủ tag gộp từ biến tags.
  • -var="environment=test" cho plan đổi sang t3.small; -var-file="prod.tfvars" cho plan đổi sang t3.medium.
  • Giá trị staging bị validation chặn ngay ở bước plan.

Troubleshoot

Reference to undeclared input variable
Nguyên nhân: Dùng var.xxx trong main.tf nhưng chưa khai báo trong variable.tf (hoặc gõ sai tên).
Giải pháp: Kiểm tra tên biến giữa 2 file, VS Code extension sẽ gạch chân biến chưa khai báo.
Value for undeclared variable (warning)
Nguyên nhân: File tfvars có biến không được khai báo trong variable.tf.
Giải pháp: Xoá biến thừa trong tfvars hoặc bổ sung khai báo.
Invalid index khi truy cập var.instance_types[var.environment]
Nguyên nhân: Map không có key tương ứng với giá trị environment.
Giải pháp: Bổ sung key vào map, hoặc dùng lookup(var.instance_types, var.environment, "t3.micro") để có giá trị dự phòng.

Luôn xoá resource sau khi thực hành để tránh phát sinh chi phí.
