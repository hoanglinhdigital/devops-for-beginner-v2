5. Infra as Code sử dụng Terraform / Lab 5: Chia module & liên kết module bằng Output

Mục tiêu

  • Hiểu khái niệm module trong Terraform, cách phân chia module và tổ chức thư mục.
  • Tách resource của bài lab trước thành 2 module: security và compute.
  • Dùng output của module này làm input của module khác để liên kết các module.
  • Deploy AWS resource sử dụng module (vẫn dùng Default VPC).

Kiến thức cần nắm

Module là một thư mục chứa các file .tf. Thư mục bạn chạy lệnh terraform gọi là root module; các module được root gọi tới là child module. Mỗi module giống như một "hàm": nhận input qua variable, trả về output qua output. Module bên ngoài chỉ nhìn thấy những gì được khai báo trong output. 

module "security" {
  source = "./modules/security"   # đường dẫn tới thư mục module (local, Git, Registry...)
  vpc_id = "vpc-xxxx"             # truyền giá trị cho variable "vpc_id" của module
}

# Đọc output của module: module.<tên module>.<tên output>
module.security.public_security_group_id
Best practice: chỉ khai báo khối provider ở root module. Child module tự động kế thừa provider từ root, giúp cùng một module có thể deploy ở nhiều region khác nhau (sẽ áp dụng ở Lab 10).

  2. Bước 2: Tạo module security

    Module gồm 2 Security Group. private-security-group chỉ nhận traffic từ public-security-group (kỹ thuật SG chaining đã học ở Section 4). Biến vpc_id mặc định là null → dùng Default VPC; ở Lab 6 ta sẽ truyền VPC tự tạo vào.

    📄 lab5_modules/modules/security/main.tf

    # Security Group cho tầng public (web server)
resource "aws_security_group" "public_security_group" {
  name        = "public-security-group"
  description = "Allow HTTP, HTTPS, SSH from Internet"
  vpc_id      = var.vpc_id

  ingress {
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

# Security Group cho tầng private: chỉ nhận traffic từ public SG (SG chaining)
resource "aws_security_group" "private_security_group" {
  name        = "private-security-group"
  description = "Allow traffic from public security group only"
  vpc_id      = var.vpc_id

  ingress {
    from_port       = 80
    to_port         = 80
    protocol        = "tcp"
    security_groups = [aws_security_group.public_security_group.id]
  }

  ingress {
    from_port       = 3306
    to_port         = 3306
    protocol        = "tcp"
    security_groups = [aws_security_group.public_security_group.id]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

    📄 lab5_modules/modules/security/variable.tf

    variable "vpc_id" {
  type        = string
  description = "VPC ID. Để null sẽ dùng Default VPC"
  default     = null
}

    📄 lab5_modules/modules/security/output.tf

    output "public_security_group_id" {
  value = aws_security_group.public_security_group.id
}

output "private_security_group_id" {
  value = aws_security_group.private_security_group.id
}
  3. Bước 3: Tạo module compute

    Module không tự tạo Security Group hay key pair mà nhận chúng qua input — giúp module độc lập và dễ tái sử dụng.

    📄 lab5_modules/modules/compute/main.tf

    resource "aws_instance" "demo_instance" {
  ami                    = var.image_id
  instance_type          = var.instance_type
  key_name               = var.key_name
  subnet_id              = var.subnet_id
  vpc_security_group_ids = var.ec2_security_group_ids

  tags = {
    Name = "Udemy Demo"
  }
}

  instance = aws_instance.demo_instance.id
  domain   = "vpc"
}

  4. Bước 4: Tạo root module

    Root module khai báo provider, gọi 2 module và nối chúng với nhau. Output ở root "chuyển tiếp" output của các module con để hiển thị ra ngoài.

    📄 lab5_modules/main.tf

    terraform {
  required_version = ">= 1.10.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

# Provider chỉ khai báo ở root module, các sub-module sẽ kế thừa
provider "aws" {
  region = var.region
}

data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

resource "aws_key_pair" "udemy_keypair" {
  key_name   = "udemy-keypair"
  public_key = file(var.keypair_path)
}

module "security" {
  source = "./modules/security"
}

module "compute" {
  source        = "./modules/compute"
  image_id      = data.aws_ami.amazon_linux.id
  instance_type = var.instance_type
  key_name      = aws_key_pair.udemy_keypair.key_name
  # Output của module security trở thành input của module compute
  ec2_security_group_ids = [module.security.public_security_group_id]
}

    📄 lab5_modules/variable.tf

    variable "region" {

variable "instance_type" {
  type        = string

}

variable "keypair_path" {

  5. Bước 5: Init và deploy

    terraform init sẽ hiển thị thêm dòng Initializing modules.... Mỗi khi thêm module mới hoặc đổi source của module, bạn cần chạy lại init.

    terraform init
terraform plan
terraform apply -auto-approve

    Trong output của plan, địa chỉ resource có tiền tố module, ví dụ module.compute.aws_instance.demo_instance. Xem danh sách resource Terraform đang quản lý:

    terraform state list
  6. Bước 6: Kiểm tra trên AWS Console
    • EC2 → Security Groups: có public-security-group và private-security-group; inbound của private SG có source là ID của public SG.
    • EC2 → Instances: instance Udemy Demo gắn public-security-group, public IP bằng output instance_public_ip.

Kiểm tra kết quả

✅ Lab thành công khi

  • terraform state list hiển thị resource thuộc module.security và module.compute.

Troubleshoot

Module not installed / Module source has changed
Nguyên nhân: Thêm module hoặc đổi source nhưng chưa chạy lại init.
Giải pháp: Chạy terraform init.
Unsupported argument: An argument named "xxx" is not expected here
Nguyên nhân: Truyền vào module một tham số mà module không khai báo variable tương ứng.
Giải pháp: Thêm variable "xxx" trong variable.tf của module, hoặc bỏ tham số.
Unsupported attribute: This object does not have an attribute named "..."
Nguyên nhân: Đọc module.xxx.yyy nhưng module không có output yyy.
Giải pháp: Khai báo output trong output.tf của module con.

Dọn dẹp resource

Luôn xoá resource sau khi thực hành để tránh phát sinh chi phí (Elastic IP tính phí theo giờ).
terraform destroy -auto-approve
