5. Infra as Code sử dụng Terraform / Lab 7: Sử dụng module có sẵn từ Terraform Registry

Mục tiêu

  • Hiểu về Terraform Registry và các module có sẵn do cộng đồng/nhà cung cấp phát triển.
  • Biết cách đọc tài liệu module (Inputs, Outputs) và cố định version module.
  • Thay toàn bộ module networking tự viết ở Lab 6 bằng module terraform-aws-modules/vpc/aws.
  • Deploy VPC hoàn chỉnh lên AWS chỉ với vài chục dòng code.

Kiến thức cần nắm

Terraform Registry là kho chứa provider và module công khai. Bộ module terraform-aws-modules (VPC, EKS, RDS, ALB, Security Group...) được dùng rất phổ biến trong các dự án thực tế, đã xử lý sẵn nhiều trường hợp mà tự viết sẽ tốn công: nhiều AZ, NAT Gateway theo từng AZ, subnet cho database, VPC Flow Logs, IPv6... 

module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"   # <namespace>/<tên>/<provider>
  version = "~> 6.0"                          # chỉ module từ Registry mới dùng được "version"
  # ... các input của module
}
Ký hiệu versionÝ nghĩa
= 6.0.1Đúng version 6.0.1
~> 6.0Từ 6.0 tới dưới 7.0 (nhận bản vá và tính năng mới, không nhận thay đổi phá vỡ của major version)
>= 6.0Từ 6.0 trở lên, kể cả major version mới — dễ bị lỗi khi module thay đổi lớn

Module networking của chúng ta trở thành một lớp "wrapper" mỏng, gọi module VPC từ Registry. Root module không cần biết bên trong dùng module tự viết hay module có sẵn.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 6 và đã destroy resource (tránh trùng CIDR và vượt quota VPC/Elastic IP).
  • Máy có kết nối Internet để terraform init tải module từ Registry.

Các bước thực hành

  1. Bước 1: Tìm hiểu module VPC trên Registry

    Mở trang terraform-aws-modules/vpc/aws và xem các tab:

    • Readme: ví dụ sử dụng (Usage) — điểm khởi đầu tốt nhất.
    • Inputs: danh sách tham số, ví dụ name, cidr, azs, public_subnets, private_subnets, enable_nat_gateway, single_nat_gateway.
    • Outputs: giá trị trả về, ví dụ vpc_id, public_subnets, private_subnets, nat_public_ips.
    • Versions: lịch sử version để chọn version phù hợp.

  3. Bước 3: Tạo module networking (wrapper)

    Đặt single_nat_gateway = true để chỉ tạo 1 NAT Gateway dùng chung — nếu không, module sẽ tạo NAT Gateway cho từng private subnet, tốn gấp đôi chi phí.

    📄 lab7_registry_module/modules/networking/main.tf

    # Sử dụng module VPC có sẵn trên Terraform Registry
# https://registry.terraform.io/modules/terraform-aws-modules/vpc/aws/latest
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 6.0"

  name = var.vpc_name
  cidr = var.cidr_block

  azs             = var.availability_zones
  public_subnets  = var.public_subnet_ips
  private_subnets = var.private_subnet_ips

  # Chỉ tạo 1 NAT Gateway dùng chung cho các private subnet để tiết kiệm chi phí
  enable_nat_gateway = true
  single_nat_gateway = true
  enable_vpn_gateway = false

  enable_dns_hostnames = true
  enable_dns_support   = true

  tags = {
    Project = var.vpc_name
  }
}

  5. Bước 5: Init, plan và apply

    Khi init, Terraform tải module từ Registry về thư mục .terraform/modules/:

    terraform init
Downloading registry.terraform.io/terraform-aws-modules/vpc/aws 6.x.x for network.vpc...
    terraform plan
terraform apply -auto-approve

    Trong plan, địa chỉ resource có dạng lồng nhau module.network.module.vpc.aws_vpc.this[0] (module trong module).

Trade-off: tự viết module hay dùng module có sẵn?

🌐 Module từ Registry

  • Nhanh, ít code, đã được cộng đồng kiểm chứng.
  • Hỗ trợ nhiều tính năng nâng cao bằng một tham số.
  • Nhưng: nhiều tham số, khó hiểu hết bên trong; nâng major version có thể phá vỡ code.

✍️ Module tự viết

  • Hiểu rõ và kiểm soát 100% resource được tạo.
  • Phù hợp chuẩn riêng của công ty.
  • Nhưng: tốn công viết, test và bảo trì.

Khi mới học, hãy tự viết (như Lab 6) để hiểu bản chất; khi làm dự án, ưu tiên module phổ biến từ Registry và luôn cố định version.

Troubleshoot

Failed to query available provider packages / không tải được module
Nguyên nhân: Không có Internet, hoặc mạng công ty chặn registry.terraform.io, github.com.
Giải pháp: Kiểm tra kết nối mạng/proxy rồi chạy lại terraform init.
Unsupported argument khi truyền tham số vào module VPC
Nguyên nhân: Tên input sai hoặc không tồn tại ở version đang dùng.
Giải pháp: Đối chiếu tab Inputs trên Registry đúng với version đã khai báo.
Unsupported provider version / xung đột version provider
Nguyên nhân: Module yêu cầu AWS provider version khác với khai báo ở root.
Giải pháp: Chọn version module tương thích (module VPC 6.x yêu cầu AWS provider 6.x), chạy terraform init -upgrade.
