5. Infra as Code sử dụng Terraform / Lab 9: Sử dụng S3 để quản lý Terraform State

Mục tiêu

  • Chuẩn bị một S3 bucket (bật versioning, encryption, chặn public access) để lưu state.
  • Cấu hình S3 backend với state locking bằng use_lockfile.
  • Deploy lại hạ tầng của Lab 6 với state được lưu trên S3.
  • Kiểm tra file state, lock file và các version của state trên S3.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 6 — lab này dùng lại toàn bộ code của Lab 6 (module networking, security, compute).
  • Đã đọc chương Terraform State & các phương án quản lý State.
  • Terraform >= 1.10 (bắt buộc để dùng use_lockfile). Kiểm tra bằng terraform -version.
Chi phí: Lab tạo lại VPC với NAT Gateway và Elastic IP (tính phí theo giờ). Chi phí lưu state trên S3 gần như bằng 0.

Các bước thực hành

  1. Bước 1: Tạo S3 bucket để lưu state

    Trên AWS Console, vào S3 và tạo bucket với các thông số:

    • Region: ap-southeast-1
    • Bucket name: udemy-terraform-state-<tên-của-bạn>-<số ngẫu nhiên>, ví dụ udemy-terraform-state-linh-2026 (tên bucket là duy nhất trên toàn cầu, chỉ gồm chữ thường, số và dấu -)
    • Block all public access: Bật (mặc định)
    • Bucket Versioning: Enable — để có thể khôi phục state cũ
    • Default encryption: SSE-S3 (mặc định)

    Bucket này sẽ được dùng tiếp cho Lab 10, hãy ghi lại tên bucket.

  2. Bước 2: Copy code từ Lab 6

  3. Bước 3: Tạo main.tf có cấu hình S3 backend

    So với Lab 6, chỉ thêm khối backend "s3" bên trong khối terraform. Đổi giá trị bucket thành tên bucket bạn đã tạo ở Bước 1:

    📄 lab9_s3_backend/main.tf

    terraform {
  required_version = ">= 1.10.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
  # Lưu state trên S3 bucket. Đổi tên bucket thành bucket bạn đã tạo ở Bước 1
  backend "s3" {
    bucket       = "udemy-terraform-state-change-me"
    key          = "lab9/terraform.tfstate"
    region       = "ap-southeast-1"
    encrypt      = true
    use_lockfile = true # S3 native state locking (Terraform >= 1.10), không cần DynamoDB
  }
}

provider "aws" {
  region = var.region
}

# PART 1: Create a complete VPC using module networking
module "networking" {

data "aws_ami" "amazon_linux" {

  4. Bước 4: Init với backend S3 
    terraform init
Successfully configured the backend "s3"! Terraform will automatically use this backend unless the backend configuration changes.
  5. Bước 5: Deploy và quan sát lock file 
    terraform apply -auto-approve

    Trong lúc apply đang chạy (NAT Gateway mất 1–2 phút), mở bucket trên S3 Console, vào thư mục lab9/ và bấm Refresh: bạn sẽ thấy file terraform.tfstate.tflock. File này tự biến mất khi apply kết thúc.

  6. Bước 6: Thử chạy đồng thời để thấy state locking

    Thay instance_type trong terraform.tfvars thành "t3.small" và chạy terraform apply (chưa gõ yes, để lệnh đang chờ). Mở một terminal thứ hai ở cùng thư mục và chạy:

    terraform plan
Error: Error acquiring the state lock

    Terraform từ chối vì state đang bị khoá bởi lệnh ở terminal thứ nhất — đây là cơ chế bảo vệ state khi làm việc nhóm. Quay lại terminal thứ nhất gõ yes để hoàn tất.

  7. Bước 7: Kiểm tra state trên S3
    • Trong thư mục lab không còn file terraform.tfstate ở local (chỉ còn file cấu hình backend trong .terraform/).
    • Trên S3 Console, file lab9/terraform.tfstate tồn tại. Bật Show versions để thấy mỗi lần apply tạo ra một version mới của state.
    • Terraform vẫn đọc state bình thường từ S3:
    terraform state list

✅ Lab thành công khi

  • terraform init báo cấu hình thành công backend s3.
  • File lab9/terraform.tfstate có trên S3 với nhiều version; không có file state ở local.

Troubleshoot

Error: Failed to get existing workspaces: S3 bucket "..." does not exist hoặc AccessDenied
Nguyên nhân: Chưa đổi tên bucket trong main.tf, gõ sai tên, hoặc bucket thuộc tài khoản khác.
Giải pháp: Sửa bucket đúng tên bucket ở Bước 1 rồi chạy terraform init -reconfigure.
An argument named "use_lockfile" is not expected here
Nguyên nhân: Terraform cũ hơn 1.10.
Giải pháp: Nâng cấp Terraform (xem Lab 1).
Backend configuration changed
Nguyên nhân: Sửa khối backend (bucket, key...) sau khi đã init.
Giải pháp: Chạy terraform init -reconfigure (bắt đầu với backend mới) hoặc terraform init -migrate-state (chuyển state cũ sang backend mới).
State bị khoá mãi không mở (lệnh trước bị ngắt bằng Ctrl+C, mất mạng)
Nguyên nhân: Lock file không được xoá do lệnh kết thúc bất thường.
Giải pháp: Khi chắc chắn không ai đang chạy Terraform, dùng terraform force-unlock <LOCK_ID> với Lock ID hiển thị trong thông báo lỗi.

Dọn dẹp resource

NAT Gateway và Elastic IP tính phí theo giờ. Destroy hạ tầng ngay sau khi hoàn thành lab. Giữ lại S3 bucket để dùng cho Lab 10 (bucket sẽ được xoá ở cuối Lab 10).
terraform destroy -auto-approve
