18. Final Assignment / Final assignment: Hướng dẫn phần triển khai lên AWS

Mục tiêu

  • Build Docker image cho ứng dụng React (frontend) và Spring Boot (backend) rồi push lên ECR.
  • Triển khai hạ tầng 3 tầng (VPC, ALB, ECS Fargate, MongoDB trên EC2) bằng Terraform.
  • Truy cập ứng dụng thành công qua DNS của ALB.
  • Dựng pipeline CI/CD (Jenkins hoặc CodePipeline) để tự động build & deploy khi push code.

Người dùng truy cập qua ALB; request thường được route tới frontend, các request /api/* được route tới backend; backend gọi MongoDB ở private subnet. Image được ECS pull từ ECR.

Yêu cầu trước khi bắt đầu

  • AWS CLI v2 đã cấu hình profile (aws configure), region ap-southeast-1.
  • Terraform >= 1.6 và Docker đã cài đặt.
  • Đã có một EC2 key pair (tạo ở EC2 → Key Pairs) để SSH vào MongoDB khi cần.
  • Đã đọc kỹ file README của repository đề bài.
  • Bộ source code tham khảo tại sourcecode/section_18_final_assignment/ (Dockerfile, Terraform, CI/CD).

Các bước thực hành

  1. Bước 1: Chuẩn bị source code

    Clone repository của đề bài và xem cấu trúc project:

    git clone https://github.com/hoanglinhdigital/react-spring-mongo-full-stack-demo
cd react-spring-mongo-full-stack-demo
ls -la

    Đọc kỹ README.md để hiểu cách chạy ứng dụng ở local (frontend, backend, MongoDB) và các biến cấu hình cần thiết.

  2. Bước 2: Build Docker image cho frontend & backend

    Sử dụng 2 file Dockerfile trong thư mục docker/ của bộ source code tham khảo (điều chỉnh cho khớp với cấu trúc repo của bạn):

    docker build -f docker/Dockerfile.frontend -t final-assignment-frontend .
docker build -f docker/Dockerfile.backend  -t final-assignment-backend  .

    Kiểm tra image đã được tạo:

    docker images | grep final-assignment
  3. Bước 3: Tạo ECR repository & push image

    Tạo 2 repository trên ECR:

    aws ecr create-repository --repository-name final-assignment-frontend --region ap-southeast-1
aws ecr create-repository --repository-name final-assignment-backend  --region ap-southeast-1

    Đăng nhập ECR, tag và push image (thay <ACCOUNT_ID> bằng Account ID của bạn):

    aws ecr get-login-password --region ap-southeast-1 | docker login --username AWS --password-stdin <ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com
docker tag final-assignment-frontend:latest <ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com/final-assignment-frontend:latest
docker tag final-assignment-backend:latest  <ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com/final-assignment-backend:latest
docker push <ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com/final-assignment-frontend:latest
docker push <ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com/final-assignment-backend:latest

    Nếu build image trên máy Windows/Mac, hãy build đúng nền tảng linux/amd64 để chạy được trên Fargate:

    docker build --platform linux/amd64 -f docker/Dockerfile.frontend -t final-assignment-frontend .
  4. Bước 4: Triển khai hạ tầng bằng Terraform

    Sao chép bộ Terraform tham khảo (hoặc tự viết theo thiết kế của bạn), tạo file biến và điền thông tin:

    cd sourcecode/section_18_final_assignment/terraform
cp terraform.tfvars.example terraform.tfvars
# Sửa key_name, my_ip_cidr... trong terraform.tfvars cho khớp tài khoản của bạn

    Khởi tạo và triển khai:

    terraform init
terraform plan --var-file terraform.tfvars
terraform apply --var-file terraform.tfvars

    Terraform sẽ tạo: VPC (public + private subnet, NAT Gateway), Security Groups, ECR repos, EC2 chạy MongoDB, ALB và ECS cluster với 2 service.

  5. Bước 5: Kiểm tra ứng dụng qua ALB

    Lấy DNS của ALB và truy cập trên trình duyệt:

    terraform output alb_dns_name

    Mở http://<alb_dns_name> để xem giao diện frontend, và thử gọi API backend:

    curl http://<alb_dns_name>/api/health
  6. Bước 6: Triển khai CI/CD (chọn Jenkins hoặc CodePipeline)

    Phương án Jenkins: dựng Jenkins server trên EC2 (tham khảo Section 10), tạo pipeline từ file cicd/jenkins/Jenkinsfile, cấu hình webhook từ GitHub.

    Phương án CodePipeline: tạo pipeline Source (GitHub) → Build (CodeBuild chạy cicd/codepipeline/buildspec.yml) → Deploy (ECS), tham khảo Section 9.

  7. Bước 7: Trigger pipeline & quan sát

    Push một thay đổi nhỏ lên repository (hoặc chạy thủ công) và theo dõi pipeline build image → push ECR → deploy ECS tự động. Kiểm tra tab Deployments của ECS service để thấy task mới được thay thế.

Kiểm tra kết quả

✅ Bài nộp được đánh giá là đạt khi

  • Các task frontend & backend trong ECS đều ở trạng thái RUNNING và Target Group có target healthy.
  • Truy cập DNS ALB hiển thị giao diện React; gọi /api/* nhận được dữ liệu từ backend.
  • MongoDB nhận kết nối từ backend (kiểm tra log của backend).
  • Pipeline CI/CD chạy thành công end-to-end khi push code mới.
  • Đã chụp đủ evidence các sơ đồ thiết kế và kết quả trên AWS Console.

Troubleshoot

Task ECS không pull được image từ ECR (CannotPullContainerError)
Nguyên nhân: task ở private subnet không có route ra ECR (thiếu NAT Gateway / VPC endpoint), hoặc execution role thiếu quyền ECR.
Giải pháp: kiểm tra NAT Gateway trong route table của private subnet; gắn policy AmazonECSTaskExecutionRolePolicy cho execution role.
Backend không kết nối được MongoDB
Nguyên nhân: Security Group của MongoDB chưa cho phép port 27017 từ SG backend, hoặc biến MONGO_HOST sai.
Giải pháp: sửa inbound rule của MongoDB SG (source = SG backend), kiểm tra biến môi trường MONGO_HOST trỏ đúng private IP của MongoDB.
Target Group backend unhealthy
Nguyên nhân: health check path sai (Spring Boot không có endpoint /api/health), hoặc container port không phải 8080.
Giải pháp: đặt health check path đúng endpoint tồn tại (vd / hoặc actuator /actuator/health), xác nhận server.port=8080.
Truy cập /api/* bị trả về trang frontend (hoặc 404)
Nguyên nhân: listener rule /api/* chưa được tạo hoặc ưu tiên (priority) thấp hơn rule khác.
Giải pháp: kiểm tra aws_lb_listener_rule với path_pattern = ["/api/*"] và đảm bảo priority hợp lý.

Dọn dẹp resource

ALB, NAT Gateway, ECS Fargate task, EBS và Elastic IP tính phí theo giờ kể cả khi không có traffic. Hãy chụp đầy đủ evidence rồi xoá toàn bộ ngay sau khi hoàn thành để tránh phát sinh chi phí. 
terraform destroy --var-file terraform.tfvars

Kiểm tra thêm ở EC2 → Elastic IPs, ECR và CloudWatch → Log groups để chắc chắn không còn resource sót lại.
