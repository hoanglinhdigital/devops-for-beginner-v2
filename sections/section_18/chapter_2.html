18. Final Assignment / Final assignment: Đáp án mẫu phần thiết kế

Giới thiệu

Chương này trình bày đáp án mẫu phần thiết kế cho Final Assignment. Đây là một trong nhiều cách thiết kế hợp lý — mục tiêu là giúp bạn thấy được tư duy thiết kế của một hệ thống 3 tầng (React + Spring Boot + MongoDB) chạy trên container, và lý do đằng sau mỗi lựa chọn.

Tổng quan kiến trúc: VPC 3 tầng multi-AZ → ECS Fargate chạy container frontend (public subnet) và backend (private subnet) đứng sau ALB → MongoDB trên EC2 ở private subnet. Image được lưu trên ECR, CI/CD dùng Jenkins hoặc CodePipeline.

1. Thiết kế hệ thống – Networking

Sơ đồ thiết kế Networking (đáp án mẫu)
  • Multi-AZ: trải tài nguyên qua 2 Availability Zone (ap-southeast-1a, ap-southeast-1b) để tăng khả năng chịu lỗi.
  • Public subnet: chứa ALB (Internet-facing) và frontend service — nơi duy nhất tiếp xúc với Internet.
  • Private subnet: chứa backend service và MongoDB — không có route ra Internet trực tiếp, chỉ truy cập ra ngoài qua NAT Gateway.
  • NAT Gateway: cho phép các resource ở private subnet (ECS task backend, MongoDB) tải package/image khi cần.
  • Internet Gateway: gắn vào VPC để cho phép traffic Internet vào public subnet.

2. Thiết kế hệ thống – Security

Sơ đồ thiết kế Security (đáp án mẫu)
  • Security Group chaining: mỗi tầng chỉ cho phép traffic đến từ tầng ngay phía trên nó — SG của ALB là source của SG frontend, SG frontend là source của SG backend, SG backend là source của SG MongoDB.
  • Chỉ mở đúng port: ALB mở 80/443 ra Internet; frontend mở 80 từ ALB; backend mở 8080 từ frontend; MongoDB mở 27017 từ backend.
  • Least privilege IAM: ECS task execution role chỉ có quyền pull image từ ECR và ghi log CloudWatch.
  • Bastion host (tuỳ chọn): là lối vào SSH duy nhất để quản trị MongoDB, chỉ mở SSH từ IP của bạn.

4. Thiết kế CI/CD – Jenkins

Sơ đồ CI/CD sử dụng Jenkins (đáp án mẫu)
  • Source: Jenkins pull source từ GitHub (kích hoạt bằng webhook khi push).
  • Build: Jenkins build Docker image cho frontend & backend từ Dockerfile.
  • Push: đẩy image lên ECR với tag (ví dụ latest hoặc theo build number).
  • Deploy: Jenkins gọi AWS CLI để cập nhật ECS service (update-service --force-new-deployment).
  • Jenkins chạy trên EC2 (Ubuntu) có IAM Role đủ quyền ECR + ECS.

5. Thiết kế CI/CD – CodePipeline

Sơ đồ CI/CD sử dụng CodePipeline (đáp án mẫu)
  • Source stage: CodePipeline nhận source từ GitHub (qua CodeConnections).
  • Build stage: CodeBuild chạy buildspec.yml để build Docker image & push lên ECR, tạo artifact imagedefinitions.json.
  • Deploy stage: CodeDeploy (hoặc action ECS) cập nhật task definition & service trên ECS.
  • Có thể thêm stage Manual approval trước khi deploy để kiểm soát release.

6. Terraform structure

Cấu trúc thư mục Terraform (đáp án mẫu)

Đáp án mẫu chia Terraform thành các module theo đúng từng lớp kiến trúc, giúp dễ đọc, dễ tái sử dụng và dễ mở rộng. Bộ source code tham khảo nằm tại sourcecode/section_18_final_assignment/terraform/:

  • network: VPC, public/private subnet, IGW, NAT Gateway.
  • security: các Security Group (ALB, frontend, backend, MongoDB, bastion).
  • storage: ECR repositories cho frontend & backend.
  • database: EC2 chạy MongoDB (private subnet) + EBS volume.
  • application: ALB + ECS cluster + 2 service (frontend/backend).
