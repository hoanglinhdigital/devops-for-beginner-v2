18. Final Assignment / Final assignment: Đề bài

Giới thiệu

Đây là bài tập lớn cuối khoá (Final Assignment #1): Container Architecture. Sau khi đã học xong toàn bộ các phần từ AWS cơ bản, Terraform, Linux, Git, Docker, CI/CD (Jenkins, CodePipeline, GitHub Actions) cho đến ECS/EKS, bạn sẽ tự mình thiết kế và triển khai một hệ thống hoàn chỉnh trên AWS theo kiến trúc Container, áp dụng đúng các Best Practice.

Đây không phải là bài kiểm tra trí nhớ — mà là cơ hội để bạn tổng hợp mọi kiến thức đã học vào một bài toán thực tế, giống như công việc của một DevOps/Cloud Engineer thực thụ: nhận một ứng dụng có sẵn, đọc hiểu nó, thiết kế hạ tầng, triển khai lên Cloud và dựng pipeline CI/CD.

Mục đích của Assignment

  • Vận dụng kiến thức đã học để thiết kế một hệ thống trên AWS theo kiến trúc Container.
  • Sử dụng các services đã học để triển khai ứng dụng lên AWS, đảm bảo các yếu tố Best Practice của AWS.
  • Implement được một pipeline CI/CD trên hệ thống đã triển khai.
  • Troubleshoot được các lỗi (nếu có) trong quá trình deploy.
  • Tự tin áp dụng vào các dự án Cloud thực tế trong tương lai.

Đề bài

Ứng dụng mẫu: repository được cung cấp sẵn ở link sau
https://github.com/hoanglinhdigital/react-spring-mongo-full-stack-demo

Ứng dụng là một hệ thống full-stack gồm 3 thành phần:

  • Frontend: React (chạy bằng Node.js/nginx).
  • Backend: Spring Boot (Java), expose REST API.
  • Database: MongoDB.

Các việc bạn cần thực hiện:

  1. Bước 1: Đọc hiểu project

    Đọc kỹ file README của repository để hiểu rõ cấu trúc project, cách chạy ứng dụng ở local và các thành phần cần thiết.

  2. Bước 2: Thiết kế hệ thống

    Tạo các sơ đồ Network, Security, Resources. Sử dụng PowerPoint hoặc Draw.io.

  3. Bước 3: Triển khai lên AWS

    Triển khai hệ thống lên AWS theo các bước trong file README. Có thể sử dụng Terraform hoặc thực hiện step-by-step trên AWS Console.

  4. Bước 4: Triển khai CI/CD

    Triển khai pipeline CI/CD cho hệ thống, sử dụng Jenkins hoặc AWS CodePipeline.

  5. Bước 5: Chụp lại kết quả

    Capture (chụp màn hình) các thành phần được tạo ra trên AWS và kết quả chạy thành công của ứng dụng.

Lưu ý quan trọng: các thiết kế (sơ đồ) & Evidence (ảnh chụp màn hình kết quả) cần được dán trực tiếp vào file bài nộp của bạn.

Cấu trúc bài nộp (template)

Bài nộp nên được tổ chức theo cấu trúc sau (mỗi phần là một mục riêng trong file PowerPoint/Word/Draw.io của bạn):

#PhầnNội dung cần có
1Thiết kế hệ thống – NetworkingSơ đồ mạng: VPC, subnet (public/private), AZ, IGW, NAT Gateway, route table.
2Thiết kế hệ thống – SecuritySơ đồ Security Groups, luồng traffic được phép giữa các tầng, IAM role cần thiết.
3Thiết kế – Services and ResourcesLiệt kê các dịch vụ AWS sẽ dùng (ECR, ECS, ALB, EC2, VPC...) và vai trò từng dịch vụ.
4Thiết kế – CI/CDSơ đồ pipeline CI/CD (Jenkins hoặc CodePipeline): Source → Build → Deploy.
5Kết quả triển khai trên AWSẢnh chụp các resource đã tạo và ứng dụng chạy thành công.

Tiêu chí đánh giá

Để tự đánh giá (và cũng là tiêu chí chấm điểm), hãy kiểm tra xem bài của bạn đã đáp ứng các điểm sau chưa:

  • Tính hoàn chỉnh của thiết kế: đủ các sơ đồ Networking, Security, Resources, CI/CD; mô tả đúng luồng dữ liệu.
  • Best Practice về mạng: public subnet cho ALB, private subnet cho backend/database; dùng NAT Gateway cho private subnet truy cập Internet; multi-AZ.
  • Best Practice về bảo mật: Security Group chaining (SG này làm source của SG khác), least privilege cho IAM, không mở port thừa ra Internet.
  • Tính khả thi khi triển khai: hệ thống thực sự chạy được, ứng dụng truy cập thành công.
  • CI/CD hoạt động: push code → pipeline tự build & deploy thành công.
  • Evidence đầy đủ: ảnh chụp các resource và kết quả chạy rõ ràng.

Yêu cầu trước khi bắt đầu

  • Đã hoàn thành các section về AWS cơ bản, Terraform, Docker, ECS (và Jenkins/CodePipeline tuỳ công cụ CI/CD bạn chọn).
  • Tài khoản AWS có quyền tạo VPC, EC2, ECR, ECS, ALB... (khuyến nghị dùng IAM User PowerUserAccess, không dùng root).
  • Công cụ: Git, VS Code, AWS CLI, Terraform, Docker, và (tuỳ chọn) Draw.io.
  • Một cặp EC2 key pair để SSH vào máy chạy MongoDB khi cần troubleshoot.

Thông tin bổ sung

Chi phí: hạ tầng trong bài này (ALB, NAT Gateway, ECS Fargate, EBS, Elastic IP) tính phí theo giờ kể cả khi không dùng. Hãy lên kế hoạch làm bài gọn trong 1–2 buổi và terraform destroy / xoá resource ngay sau khi chụp xong evidence.
Đây là bài tập mở: không có một "đáp án duy nhất". Điều quan trọng là bạn hiểu lý do đằng sau mỗi quyết định thiết kế. Các chương tiếp theo cung cấp đáp án mẫu phần thiết kế và hướng dẫn triển khai để bạn tham khảo — đừng copy nguyên xi mà hãy tự điều chỉnh cho hợp lý.
