11. Chiến lược deployment / Lab 3: Job Switch traffic & rollback

Mục tiêu

  • Tạo job bluegreen-job3-switch-traffic: hoán đổi Target Group giữa listener :80 (production) và :81 (test) trên ALB.
  • Thêm các guardrail: kiểm tra môi trường mới có target healthy trước khi switch, bước input để người release xác nhận.
  • Quan sát switch traffic không downtime (Stage 3 của Blue/Green) bằng vòng lặp curl.
  • Thực hành rollback trong vài giây bằng cách chạy lại chính job này.

Các bước thực hành

  1. Bước 1: Tạo job bluegreen-job3-switch-traffic

    Tạo New Item → Pipeline tên bluegreen-job3-switch-traffic, không có parameter. Pipeline → Definition Pipeline script, dán nội dung lab3_switch_traffic/Jenkinsfile-switch:

    // Section 11 – Job 3: Switch traffic giữa 2 môi trường Blue/Green trên ALB
// Job: bluegreen-job3-switch-traffic | Pipeline definition: Pipeline script (dán nội dung file này)
// Không có parameter: job tự đọc trạng thái hiện tại của ALB rồi hoán đổi Target Group của 2 listener
//   - Listener :80 (production) -> Target Group đang ở listener :81 (môi trường đã kiểm thử)
//   - Listener :81 (test)       -> Target Group production cũ (giữ lại để rollback)
// Chạy lại job một lần nữa = ROLLBACK.
pipeline {
    agent any

    options {
        timeout(time: 30, unit: 'MINUTES')
        disableConcurrentBuilds()
    }

    environment {
        AWS_REGION = 'ap-southeast-1'
        ALB_NAME   = 'bluegreen-lab-alb'
    }

    stages {
        stage('Check current state') {
            steps {
                sh '''
                    ALB_ARN=$(aws elbv2 describe-load-balancers --region ${AWS_REGION} --names ${ALB_NAME} --query 'LoadBalancers[0].LoadBalancerArn' --output text)
                    aws elbv2 describe-listeners --region ${AWS_REGION} --load-balancer-arn ${ALB_ARN} > listeners.json

                    PROD_LISTENER_ARN=$(jq -r '.Listeners[] | select(.Port == 80) | .ListenerArn' listeners.json)
                    TEST_LISTENER_ARN=$(jq -r '.Listeners[] | select(.Port == 81) | .ListenerArn' listeners.json)
                    # Môi trường production = Target Group có weight lớn nhất trên listener :80 (kể cả khi đang chạy canary)
                    CURRENT_PROD_TG=$(jq -r '.Listeners[] | select(.Port == 80) | .DefaultActions[0].ForwardConfig.TargetGroups | max_by(.Weight) | .TargetGroupArn' listeners.json)
                    CURRENT_TEST_TG=$(jq -r '.Listeners[] | select(.Port == 81) | .DefaultActions[0].ForwardConfig.TargetGroups[0].TargetGroupArn' listeners.json)

                    if [ "${CURRENT_PROD_TG}" = "${CURRENT_TEST_TG}" ]; then
                        echo "ERROR: Listener :80 và :81 đang trỏ cùng một Target Group, không có gì để switch."
                        exit 1
                    fi

                    # Không switch sang môi trường chưa có task healthy -> tránh downtime
                    HEALTHY=$(aws elbv2 describe-target-health --region ${AWS_REGION} --target-group-arn ${CURRENT_TEST_TG} | jq '[.TargetHealthDescriptions[] | select(.TargetHealth.State == "healthy")] | length')
                    if [ "${HEALTHY}" -eq 0 ]; then
                        echo "ERROR: Môi trường test không có target healthy. Hãy deploy (bluegreen-job2-deploy) trước khi switch!"
                        exit 1
                    fi

                    PROD_NAME=$(aws elbv2 describe-target-groups --region ${AWS_REGION} --target-group-arns ${CURRENT_PROD_TG} --query 'TargetGroups[0].TargetGroupName' --output text)
                    TEST_NAME=$(aws elbv2 describe-target-groups --region ${AWS_REGION} --target-group-arns ${CURRENT_TEST_TG} --query 'TargetGroups[0].TargetGroupName' --output text)
                    echo "Hiện tại: :80 (production) -> ${PROD_NAME} | :81 (test) -> ${TEST_NAME} (${HEALTHY} target healthy)"
                    echo "Sau khi switch: :80 (production) -> ${TEST_NAME} | :81 (test) -> ${PROD_NAME}"

                    # Lưu lại cho stage Switch traffic
                    echo "${PROD_LISTENER_ARN}" > prod_listener.txt
                    echo "${TEST_LISTENER_ARN}" > test_listener.txt
                    echo "${CURRENT_PROD_TG}" > current_prod_tg.txt
                    echo "${CURRENT_TEST_TG}" > current_test_tg.txt
                '''
            }
        }

        stage('Confirm') {
            steps {
                // Người release xác nhận lần cuối (đọc kết quả stage trước trong Console Output)
                input message: 'Chuyển 100% traffic production sang môi trường đang ở listener :81?', ok: 'Switch'
            }
        }

        stage('Switch traffic') {
            steps {
                sh '''
                    PROD_LISTENER_ARN=$(cat prod_listener.txt)
                    TEST_LISTENER_ARN=$(cat test_listener.txt)
                    CURRENT_PROD_TG=$(cat current_prod_tg.txt)
                    CURRENT_TEST_TG=$(cat current_test_tg.txt)

                    aws elbv2 modify-listener --region ${AWS_REGION} --listener-arn ${PROD_LISTENER_ARN} --default-actions Type=forward,TargetGroupArn=${CURRENT_TEST_TG} > /dev/null
                    aws elbv2 modify-listener --region ${AWS_REGION} --listener-arn ${TEST_LISTENER_ARN} --default-actions Type=forward,TargetGroupArn=${CURRENT_PROD_TG} > /dev/null

                    NEW_PROD_NAME=$(aws elbv2 describe-target-groups --region ${AWS_REGION} --target-group-arns ${CURRENT_TEST_TG} --query 'TargetGroups[0].TargetGroupName' --output text)
                    echo "Switch thành công! Production (:80) đang trỏ tới ${NEW_PROD_NAME}"
                '''
            }
        }
    }
}
    Điểm chínhGiải thích
    Không cần tham sốJob tự đọc trạng thái hiện tại: Target Group của :80 là production, của :81 là môi trường mới → hoán đổi. Không thể chọn nhầm môi trường.
    select(.Port == 80)Tìm listener theo port thay vì .Listeners[0] như phiên bản cũ – thứ tự listener trả về không được đảm bảo.
    max_by(.Weight)Nếu listener :80 đang chia traffic theo trọng số (Lab 5), Target Group có trọng số lớn nhất được coi là production.
    describe-target-healthĐếm target healthy của môi trường mới; bằng 0 → dừng job, tránh switch người dùng sang môi trường không có task (503).
    input message: ..., ok: 'Switch'Job tạm dừng chờ người có quyền bấm Switch hoặc Abort – một dạng manual approval.
    Lưu giá trị ra file *.txtBiến shell không sống qua các stage; ghi ra file trong workspace để stage sau đọc lại.
  2. Bước 2: Theo dõi production liên tục

    Mở một cửa sổ Terminal (Git Bash) trên máy local, chạy vòng lặp in ra thời gian, HTTP status code và version của production mỗi giây (thay <alb-dns-name>, để nguyên cửa sổ này chạy):

    while true; do echo "$(date +%T) $(curl -s -o /dev/null -w '%{http_code}' http://<alb-dns-name>/) $(curl -s http://<alb-dns-name>/ | grep -o '<h1[^>]*>[^<]*' | grep -o 'v[0-9.]*')"; sleep 1; done
  3. Bước 3: Switch traffic sang Green

    Chạy job bluegreen-job3-switch-traffic (Build Now). Mở Console Output và đọc kết quả stage Check current state:

    Hiện tại: :80 (production) -> bluegreen-lab-tg-blue | :81 (test) -> bluegreen-lab-tg-green (2 target healthy)
Sau khi switch: :80 (production) -> bluegreen-lab-tg-green | :81 (test) -> bluegreen-lab-tg-blue
[Pipeline] input
Chuyển 100% traffic production sang môi trường đang ở listener :81?
Switch or Abort

    Job dừng ở stage Confirm. Bấm Switch (ngay trong Console Output, hoặc di chuột vào ô stage Confirm trên trang job). Quan sát cửa sổ Terminal ở Bước 2:

    14:05:01 200 v2.0.0
14:05:02 200 v2.0.0
14:05:03 200 v2.1.0
14:05:04 200 v2.1.0
14:05:05 200 v2.1.0

    Version đổi từ v2.0.0 sang v2.1.0 chỉ trong 1 giây, không có request nào lỗi (luôn 200) – toàn bộ người dùng chuyển sang version mới cùng lúc.

  4. Bước 4: Kiểm tra trạng thái sau khi switch 
    curl -s http://<alb-dns-name>/ | grep -o "<h1[^>]*>[^<]*"
<h1 id="welcome" ...>Welcome to My Website – v2.1.0
curl -s http://<alb-dns-name>:81/ | grep -o "<h1[^>]*>[^<]*"
<h1 id="welcome" ...>Welcome to My Website – v2.0.0

    Trên EC2 Console → Load Balancers → bluegreen-lab-alb → Listeners and rules: HTTP:80 giờ forward tới bluegreen-lab-tg-green, HTTP:81 forward tới bluegreen-lab-tg-blue. Môi trường Blue (v2.0.0) vẫn chạy đủ 2 task – sẵn sàng cho rollback.

  5. Bước 5: Rollback

    Giả sử sau khi release, người dùng báo lỗi nghiêm trọng ở v2.1.0. Chạy lại job bluegreen-job3-switch-traffic và bấm Switch: production quay về v2.0.0 trong vài giây (quan sát Terminal) – không build lại, không deploy lại, không chờ task khởi động.

    💡 So sánh với Section 10 – Lab 10: rollback bằng OnlyDeploy một tag cũ mất vài phút (rolling update tạo task mới). Blue/Green đổi chi phí tài nguyên lấy tốc độ rollback.

  6. Bước 6: Release lại v2.1.0 (roll forward)

    Giả sử lỗi đã được xác nhận là do yếu tố bên ngoài, v2.1.0 vẫn ổn. Chạy job switch thêm một lần nữa để production trở lại v2.1.0 (Green). Trạng thái sau bước này dùng cho Lab 4: :80 → Green v2.1.0, :81 → Blue v2.0.0. Dừng vòng lặp ở Terminal bằng Ctrl + C.

Kiểm tra kết quả

✅ Lab thành công khi

  • Job dừng ở stage Confirm và chỉ switch sau khi bấm Switch.
  • Vòng lặp curl luôn trả về 200 trong lúc switch, version đổi ngay lập tức.
  • Chạy lại job đảo ngược trạng thái (rollback) và ngược lại (roll forward).
  • Trạng thái cuối: :80 → bluegreen-lab-tg-green (v2.1.0), :81 → bluegreen-lab-tg-blue (v2.0.0).

Troubleshoot

User: arn:aws:sts::...:assumed-role/jenkins-server-role/... is not authorized to perform: elasticloadbalancing:ModifyListener
Nguyên nhân: Role của Jenkins chưa có quyền sửa listener.
Giải pháp: Gắn ElasticLoadBalancingFullAccess cho jenkins-server-role (Lab 1 – Bước 2), chạy lại job.
ERROR: Môi trường test không có target healthy...
Nguyên nhân: Môi trường ở :81 chưa deploy hoặc đã bị scale về 0 (Lab 4).
Giải pháp: Chạy bluegreen-job2-deploy cho môi trường đó trước. Đây là guardrail giúp tránh downtime.
Không thấy nút Switch, job treo ở trạng thái chờ
Nguyên nhân: Bước input đang chờ người xác nhận.
Giải pháp: Mở Console Output của build đang chạy, bấm link Switch (hoặc Abort để huỷ). Job có timeout 30 phút – quá thời gian sẽ tự huỷ.
Trình duyệt vẫn hiển thị version cũ sau khi switch
Nguyên nhân: Trình duyệt giữ kết nối keep-alive hoặc cache trang.
Giải pháp: Hard refresh (Ctrl + F5) hoặc mở tab ẩn danh; dùng curl để kiểm tra chính xác.
