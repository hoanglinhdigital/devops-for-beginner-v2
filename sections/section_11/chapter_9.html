11. Chiến lược deployment / Lab 4: Job Clear resource & quy trình release Blue/Green hoàn chỉnh

Mục tiêu

  • Tạo job bluegreen-job4-clear-resource: nhận tham số môi trường, scale ECS Service về 0 task để không tốn chi phí cho môi trường cũ sau khi release ổn định.
  • Job có Safety check: không bao giờ được scale về 0 môi trường đang nhận traffic production.
  • Hiểu trade-off giữa tiết kiệm chi phí và tốc độ rollback; tổng kết quy trình release Blue/Green với 4 job.

Các bước thực hành

  1. Bước 1: Tạo job bluegreen-job4-clear-resource

    Tạo New Item → Pipeline tên bluegreen-job4-clear-resource:

    • General → tick This project is parameterized → Choice Parameter: Name TARGET_ENV, Choices (mỗi giá trị 1 dòng): blue, green
    • Pipeline → Definition Pipeline script, dán nội dung lab4_clear_resource/Jenkinsfile-clear
    // Section 11 – Job 4: Clear resource – scale ECS Service của môi trường cũ (idle) về 0 task để tiết kiệm chi phí
// Job: bluegreen-job4-clear-resource | Pipeline definition: Pipeline script (dán nội dung file này)
// This project is parameterized:
//   - Choice parameter TARGET_ENV (blue, green – mỗi giá trị 1 dòng) – môi trường cần dọn dẹp
pipeline {
    agent any

    options {
        timeout(time: 15, unit: 'MINUTES')
        disableConcurrentBuilds()
    }

    environment {
        AWS_REGION   = 'ap-southeast-1'
        ALB_NAME     = 'bluegreen-lab-alb'
        ECS_CLUSTER  = "bluegreen-lab-cluster-${params.TARGET_ENV}"
        ECS_SERVICE  = 'nodejs-service'
        TARGET_GROUP = "bluegreen-lab-tg-${params.TARGET_ENV}"
    }

    stages {
        stage('Safety check') {
            steps {
                // Tuyệt đối không scale về 0 môi trường đang nhận traffic production
                sh '''
                    ALB_ARN=$(aws elbv2 describe-load-balancers --region ${AWS_REGION} --names ${ALB_NAME} --query 'LoadBalancers[0].LoadBalancerArn' --output text)
                    TARGET_TG_ARN=$(aws elbv2 describe-target-groups --region ${AWS_REGION} --names ${TARGET_GROUP} --query 'TargetGroups[0].TargetGroupArn' --output text)
                    LIVE_TG_ARNS=$(aws elbv2 describe-listeners --region ${AWS_REGION} --load-balancer-arn ${ALB_ARN} | jq -r '.Listeners[] | select(.Port == 80) | .DefaultActions[0].ForwardConfig.TargetGroups[] | select(.Weight > 0) | .TargetGroupArn')

                    if echo "${LIVE_TG_ARNS}" | grep -q "${TARGET_TG_ARN}"; then
                        echo "ERROR: Môi trường ${TARGET_ENV} đang nhận traffic production (listener :80). Không được dọn dẹp!"
                        exit 1
                    fi
                    echo "OK: ${TARGET_ENV} không nhận traffic production."
                '''
            }
        }

        stage('Scale service to 0') {
            steps {
                // ECS tự stop toàn bộ task khi desired count = 0; Cluster, Service, Target Group vẫn giữ nguyên
                sh '''
                    aws ecs update-service --region ${AWS_REGION} --cluster ${ECS_CLUSTER} --service ${ECS_SERVICE} --desired-count 0 --query 'service.{service:serviceName,desired:desiredCount,running:runningCount}'
                    aws ecs wait services-stable --region ${AWS_REGION} --cluster ${ECS_CLUSTER} --services ${ECS_SERVICE}
                    aws ecs describe-services --region ${AWS_REGION} --cluster ${ECS_CLUSTER} --services ${ECS_SERVICE} --query 'services[0].{desired:desiredCount,running:runningCount}'
                '''
            }
        }
    }

    post {
        success {
            echo "Đã scale ${params.TARGET_ENV} về 0 task. Lần release sau, bluegreen-job2-deploy sẽ tự scale lại."
        }
    }
}

    💡 Phiên bản cũ dùng aws ecs list-tasks | xargs aws ecs stop-task để dừng từng task. Với ECS Service, cách đó không đủ: service sẽ tự khởi động lại task để đạt desired count. Cách đúng là đặt --desired-count 0 – ECS tự dừng toàn bộ task.

Trade-off của bước Clear resource: sau khi môi trường cũ về 0 task, rollback không còn “tức thì” – phải chạy Job 2 deploy lại version cũ vào môi trường đó (2–4 phút) rồi mới switch. Một số team giữ môi trường cũ ở 1 task (warm standby) để cân bằng giữa chi phí và tốc độ rollback.

Troubleshoot

Task của Blue vẫn chạy lại sau khi bị stop thủ công trên Console
Nguyên nhân: ECS Service luôn duy trì đủ desired count.
Giải pháp: Dùng job này (đặt desired count = 0) thay vì stop từng task.
terraform apply lại có làm Blue chạy lại 2 task không?
Không. ECS Service trong Terraform có ignore_changes = [task_definition, desired_count] – Terraform không ghi đè số task và revision do Jenkins thay đổi.
