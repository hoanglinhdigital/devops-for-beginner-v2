11. Chiến lược deployment / Lab 2: Job Deploy lên môi trường idle & kiểm thử qua test listener

Mục tiêu

  • Tạo job bluegreen-job2-deploy: nhận tham số VERSION và TARGET_ENV (blue/green), triển khai image lên ECS Cluster tương ứng.
  • Hiểu và áp dụng nguyên tắc số 1 của Blue/Green: chỉ deploy lên môi trường idle – job có bước Safety check từ chối deploy lên môi trường đang nhận traffic production.
  • Release v2.1.0 lên môi trường Green, kiểm thử qua test listener :81 trong khi người dùng vẫn dùng v2.0.0 ở :80 (Stage 1 & Stage 2 của Blue/Green).

Các bước thực hành

  1. Bước 1: Tạo job bluegreen-job2-deploy

    Tạo New Item → Pipeline tên bluegreen-job2-deploy:

    • General → tick This project is parameterized:
      • String Parameter – Name VERSION, Default Value v2.1.0
      • Choice Parameter – Name TARGET_ENV, Choices (mỗi giá trị 1 dòng): green, blue
    • Pipeline → Definition Pipeline script, dán nội dung lab2_deploy_idle_env/Jenkinsfile-deploy (không cần sửa)
    // Section 11 – Job 2: Deploy một version lên môi trường Blue hoặc Green (môi trường KHÔNG nhận traffic production)
// Job: bluegreen-job2-deploy | Pipeline definition: Pipeline script (dán nội dung file này)
// This project is parameterized:
//   - String parameter VERSION (Default: v2.1.0) – image tag đã có trên ECR (build bằng bluegreen-job1-build)
//   - Choice parameter TARGET_ENV (green, blue – mỗi giá trị 1 dòng) – môi trường cần deploy
pipeline {
    agent any

    options {
        timeout(time: 15, unit: 'MINUTES')
        disableConcurrentBuilds()
    }

    environment {
        AWS_REGION     = 'ap-southeast-1'
        ECR_REPO       = 'nodejs-random-color'
        // Các giá trị dưới đây lấy từ terraform output của terraform_bluegreen_stack
        ALB_NAME       = 'bluegreen-lab-alb'
        ECS_CLUSTER    = "bluegreen-lab-cluster-${params.TARGET_ENV}"
        ECS_SERVICE    = 'nodejs-service'
        TARGET_GROUP   = "bluegreen-lab-tg-${params.TARGET_ENV}"
        TASK_FAMILY    = 'bluegreen-lab-nodejs-task'
        CONTAINER_NAME = 'nodejs-container'
        DESIRED_COUNT  = '2'
    }

    stages {
        stage('Safety check') {
            steps {
                // Nguyên tắc Blue/Green: chỉ deploy lên môi trường đang KHÔNG phục vụ người dùng (idle)
                sh '''
                    ALB_ARN=$(aws elbv2 describe-load-balancers --region ${AWS_REGION} --names ${ALB_NAME} --query 'LoadBalancers[0].LoadBalancerArn' --output text)
                    TARGET_TG_ARN=$(aws elbv2 describe-target-groups --region ${AWS_REGION} --names ${TARGET_GROUP} --query 'TargetGroups[0].TargetGroupArn' --output text)

                    # Danh sách Target Group đang nhận traffic (weight > 0) trên listener production :80
                    LIVE_TG_ARNS=$(aws elbv2 describe-listeners --region ${AWS_REGION} --load-balancer-arn ${ALB_ARN} | jq -r '.Listeners[] | select(.Port == 80) | .DefaultActions[0].ForwardConfig.TargetGroups[] | select(.Weight > 0) | .TargetGroupArn')

                    if echo "${LIVE_TG_ARNS}" | grep -q "${TARGET_TG_ARN}"; then
                        echo "ERROR: Môi trường ${TARGET_ENV} đang nhận traffic production (listener :80). Hãy deploy lên môi trường còn lại!"
                        exit 1
                    fi
                    echo "OK: ${TARGET_ENV} là môi trường idle, có thể deploy."
                '''
            }
        }

        stage('Register new task definition') {
            steps {
                sh '''
                    ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
                    FULL_IMAGE=${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/${ECR_REPO}:${VERSION}
                    echo "Deploying image: ${FULL_IMAGE} -> ${ECS_CLUSTER}"

                    # Kiểm tra image tag có tồn tại trên ECR, nếu không job dừng ngay tại đây
                    aws ecr describe-images --region ${AWS_REGION} --repository-name ${ECR_REPO} --image-ids imageTag=${VERSION} > /dev/null

                    # Lấy task definition mới nhất -> đổi image của container -> bỏ các field chỉ đọc
                    aws ecs describe-task-definition --region ${AWS_REGION} --task-definition ${TASK_FAMILY} |
                    jq --arg IMAGE "${FULL_IMAGE}" --arg NAME "${CONTAINER_NAME}" '.taskDefinition | (.containerDefinitions[] | select(.name == $NAME) | .image) = $IMAGE | del(.taskDefinitionArn, .revision, .status, .requiresAttributes, .compatibilities, .registeredAt, .registeredBy)' > new-task-definition.json

                    aws ecs register-task-definition --region ${AWS_REGION} --cli-input-json file://new-task-definition.json --query 'taskDefinition.revision' --output text > revision.txt
                    echo "New revision: ${TASK_FAMILY}:$(cat revision.txt)"
                '''
            }
        }

        stage('Update ECS service') {
            steps {
                // --desired-count: môi trường idle có thể đã bị scale về 0 bởi job Clear resource
                sh '''
                    NEW_REVISION=$(cat revision.txt)
                    aws ecs update-service --region ${AWS_REGION} --cluster ${ECS_CLUSTER} --service ${ECS_SERVICE} --task-definition ${TASK_FAMILY}:${NEW_REVISION} --desired-count ${DESIRED_COUNT} --force-new-deployment --query 'service.deployments[0].{status:status,taskDefinition:taskDefinition,desired:desiredCount}'
                '''
            }
        }

        stage('Wait for service stable') {
            steps {
                sh 'aws ecs wait services-stable --region ${AWS_REGION} --cluster ${ECS_CLUSTER} --services ${ECS_SERVICE}'
            }
        }
    }

    post {
        success {
            echo "Deploy ${params.VERSION} lên môi trường ${params.TARGET_ENV} thành công! Kiểm thử qua test listener: http://<alb-dns-name>:81"
        }
    }
}
    Điểm chínhGiải thích
    ECS_CLUSTER = "bluegreen-lab-cluster-${params.TARGET_ENV}"Tên cluster và Target Group được ghép từ tham số – cùng một job deploy được cho cả 2 môi trường.
    Stage Safety checkLấy danh sách Target Group có Weight > 0 trên listener port 80 (tìm theo port, không phụ thuộc thứ tự). Nếu Target Group của môi trường đích nằm trong đó → exit 1.
    describe-load-balancers --names, describe-target-groups --namesLấy ARN theo tên – không hard-code ARN/Account ID trong Jenkinsfile như phiên bản cũ.
    --desired-count ${DESIRED_COUNT}Môi trường idle có thể đã bị scale về 0 bởi job Clear resource (Lab 4); deploy sẽ scale lại 2 task.
    Task definition dùng chung familyMỗi lần deploy đăng ký revision mới; chỉ service của môi trường đích chuyển sang revision đó, môi trường còn lại giữ nguyên revision cũ.
  2. Bước 2: Release tag v2.1.0

    Sửa text thẻ <h1 id="welcome" ...> trong public/index.html thành Welcome to My Website – v2.1.0, commit và tạo tag:

    cd ~/jenkins-labs/nodejs-random-color
git add public/index.html
git commit -m "feat: release v2.1.0"
git push origin master
git tag -a v2.1.0 -m "Release v2.1.0"
git push origin v2.1.0

    Chạy job bluegreen-job1-build với VERSION = v2.1.0, chờ job thành công (ECR có tag v2.1.0).

  3. Bước 3: Thử deploy nhầm lên môi trường production

    Chạy bluegreen-job2-deploy với VERSION = v2.1.0, TARGET_ENV = blue. Job fail ở stage Safety check – đây là kết quả mong đợi:

    + echo ERROR: Môi trường blue đang nhận traffic production (listener :80). Hãy deploy lên môi trường còn lại!

    💡 Deploy thẳng lên Blue lúc này chính là rolling update trên production – mất hết ý nghĩa của Blue/Green. Guardrail trong pipeline giúp quy trình được “tuân thủ chặt chẽ” mà không phụ thuộc trí nhớ của người release.

  5. Bước 5: Kiểm thử qua test listener (Stage 2 – Kiểm thử)

    Người dùng (port 80) vẫn thấy v2.0.0, QA truy cập port 81 thấy v2.1.0:

    curl -s http://<alb-dns-name>/ | grep -o "<h1[^>]*>[^<]*"
<h1 id="welcome" ...>Welcome to My Website – v2.0.0
curl -s http://<alb-dns-name>:81/ | grep -o "<h1[^>]*>[^<]*"
<h1 id="welcome" ...>Welcome to My Website – v2.1.0

    So sánh revision task definition đang chạy trên 2 cluster:

    aws ecs describe-services --cluster bluegreen-lab-cluster-blue --services nodejs-service --region ap-southeast-1 --query 'services[0].{taskDef:taskDefinition,desired:desiredCount,running:runningCount}'
aws ecs describe-services --cluster bluegreen-lab-cluster-green --services nodejs-service --region ap-southeast-1 --query 'services[0].{taskDef:taskDefinition,desired:desiredCount,running:runningCount}'

    Thực tế, ở bước này QA chạy test case thủ công/tự động (smoke test, E2E test) trên :81. Nếu phát hiện lỗi: sửa code, release v2.1.1 và deploy lại lên Green – người dùng không hề bị ảnh hưởng.

Kiểm tra kết quả

✅ Lab thành công khi

  • Job deploy với TARGET_ENV = blue bị chặn ở stage Safety check.
  • Job deploy với TARGET_ENV = green thành công; cluster Green chạy revision mới với image v2.1.0.

Troubleshoot

An error occurred (ImageNotFoundException) when calling the DescribeImages operation
Nguyên nhân: Chưa build image v2.1.0 hoặc gõ sai VERSION.
Giải pháp: Chạy bluegreen-job1-build với đúng tag trước.
An error occurred (LoadBalancerNotFound) ... One or more load balancers not found
Nguyên nhân: Stack đã bị destroy hoặc đang ở region khác.
Giải pháp: Kiểm tra terraform output, AWS_REGION trong Jenkinsfile.
Stage Wait for service stable chạy rất lâu rồi Waiter ServicesStable failed: Max attempts exceeded
Nguyên nhân: Task mới không healthy (ứng dụng lỗi, sai port) – circuit breaker sẽ rollback cluster Green về revision cũ.
Giải pháp: Xem tab Deployments và Logs của service trong cluster Green; production (Blue) không bị ảnh hưởng.
jq: command not found
Giải pháp: SSH vào Jenkins server chạy sudo apt install -y jq.

Dọn dẹp resource

Giữ nguyên stack để làm tiếp Lab 3. Nếu dừng học, chạy terraform destroy trong thư mục terraform_bluegreen_stack và stop Jenkins server.
