11. Chiến lược deployment / Lab 5: Canary deployment với ALB weighted target group

Mục tiêu

  • Tận dụng hạ tầng Blue/Green sẵn có để làm Canary deployment: listener :80 forward tới 2 Target Group theo trọng số.
  • Tạo job bluegreen-job5-canary với tham số CANARY_ENV và CANARY_WEIGHT (10 / 25 / 50 / 100 / 0).
  • Release v2.2.0 theo các nấc 10% → 50% → 100%, đo tỷ lệ traffic thực tế, theo dõi metric theo Target Group, thực hành rollback về 0%.
  • So sánh Canary “tự làm” bằng Jenkins với Canary tự động của CodeDeploy (Section 9 – Lab 8).

  3. Bước 3: Tạo job bluegreen-job5-canary

    Tạo New Item → Pipeline tên bluegreen-job5-canary:

    • General → tick This project is parameterized:
      • Choice Parameter – Name CANARY_ENV, Choices: blue, green (môi trường chứa version mới)
      • Choice Parameter – Name CANARY_WEIGHT, Choices: 10, 25, 50, 100, 0
    • Pipeline → Definition Pipeline script, dán nội dung lab5_canary_weighted/Jenkinsfile-canary
    // Section 11 – Job 5: Canary deployment bằng ALB weighted target group
// Job: bluegreen-job5-canary | Pipeline definition: Pipeline script (dán nội dung file này)
// This project is parameterized:
//   - Choice parameter CANARY_ENV (blue, green – mỗi giá trị 1 dòng) – môi trường chứa version MỚI (đã deploy bằng job 2)
//   - Choice parameter CANARY_WEIGHT (10, 25, 50, 100, 0 – mỗi giá trị 1 dòng) – % traffic production chuyển sang version mới
//       10 / 25 / 50 : chia traffic theo trọng số giữa version cũ (stable) và version mới (canary)
//       100          : promote – 100% traffic sang version mới, listener :81 trỏ về version cũ (giống sau khi switch Blue/Green)
//       0            : rollback – 100% traffic về version cũ
pipeline {
    agent any

    options {
        timeout(time: 15, unit: 'MINUTES')
        disableConcurrentBuilds()
    }

    environment {
        AWS_REGION = 'ap-southeast-1'
        ALB_NAME   = 'bluegreen-lab-alb'
        CANARY_TG  = "bluegreen-lab-tg-${params.CANARY_ENV}"
    }

    stages {
        stage('Check target health') {
            steps {
                sh '''
                    # Môi trường stable (version cũ) là môi trường còn lại
                    if [ "${CANARY_ENV}" = "blue" ]; then STABLE_TG=bluegreen-lab-tg-green; else STABLE_TG=bluegreen-lab-tg-blue; fi

                    CANARY_TG_ARN=$(aws elbv2 describe-target-groups --region ${AWS_REGION} --names ${CANARY_TG} --query 'TargetGroups[0].TargetGroupArn' --output text)
                    STABLE_TG_ARN=$(aws elbv2 describe-target-groups --region ${AWS_REGION} --names ${STABLE_TG} --query 'TargetGroups[0].TargetGroupArn' --output text)

                    CANARY_HEALTHY=$(aws elbv2 describe-target-health --region ${AWS_REGION} --target-group-arn ${CANARY_TG_ARN} | jq '[.TargetHealthDescriptions[] | select(.TargetHealth.State == "healthy")] | length')
                    STABLE_HEALTHY=$(aws elbv2 describe-target-health --region ${AWS_REGION} --target-group-arn ${STABLE_TG_ARN} | jq '[.TargetHealthDescriptions[] | select(.TargetHealth.State == "healthy")] | length')
                    echo "Canary ${CANARY_TG}: ${CANARY_HEALTHY} target healthy | Stable ${STABLE_TG}: ${STABLE_HEALTHY} target healthy"

                    if [ "${CANARY_WEIGHT}" -gt 0 ] && [ "${CANARY_HEALTHY}" -eq 0 ]; then
                        echo "ERROR: Môi trường canary chưa có target healthy. Hãy deploy version mới (bluegreen-job2-deploy) trước!"
                        exit 1
                    fi
                    if [ "${CANARY_WEIGHT}" -lt 100 ] && [ "${STABLE_HEALTHY}" -eq 0 ]; then
                        echo "ERROR: Môi trường stable không có target healthy, không thể giữ traffic ở version cũ!"
                        exit 1
                    fi

                    echo "${CANARY_TG_ARN}" > canary_tg.txt
                    echo "${STABLE_TG_ARN}" > stable_tg.txt
                    echo "${STABLE_TG}" > stable_tg_name.txt
                '''
            }
        }

        stage('Shift traffic') {
            steps {
                sh '''
                    CANARY_TG_ARN=$(cat canary_tg.txt)
                    STABLE_TG_ARN=$(cat stable_tg.txt)
                    STABLE_TG=$(cat stable_tg_name.txt)
                    ALB_ARN=$(aws elbv2 describe-load-balancers --region ${AWS_REGION} --names ${ALB_NAME} --query 'LoadBalancers[0].LoadBalancerArn' --output text)
                    aws elbv2 describe-listeners --region ${AWS_REGION} --load-balancer-arn ${ALB_ARN} > listeners.json
                    PROD_LISTENER_ARN=$(jq -r '.Listeners[] | select(.Port == 80) | .ListenerArn' listeners.json)
                    TEST_LISTENER_ARN=$(jq -r '.Listeners[] | select(.Port == 81) | .ListenerArn' listeners.json)

                    STABLE_WEIGHT=$((100 - CANARY_WEIGHT))

                    # Default action dạng weighted forward: 1 listener forward tới 2 Target Group theo trọng số
                    jq -n --arg stable "${STABLE_TG_ARN}" --arg canary "${CANARY_TG_ARN}" --argjson sw ${STABLE_WEIGHT} --argjson cw ${CANARY_WEIGHT} '[{Type: "forward", ForwardConfig: {TargetGroups: [{TargetGroupArn: $stable, Weight: $sw}, {TargetGroupArn: $canary, Weight: $cw}]}}]' > actions.json
                    cat actions.json

                    aws elbv2 modify-listener --region ${AWS_REGION} --listener-arn ${PROD_LISTENER_ARN} --default-actions file://actions.json > /dev/null

                    # Promote 100%: listener test :81 trỏ về version cũ để có thể rollback bằng job Switch traffic
                    if [ "${CANARY_WEIGHT}" -eq 100 ]; then
                        aws elbv2 modify-listener --region ${AWS_REGION} --listener-arn ${TEST_LISTENER_ARN} --default-actions Type=forward,TargetGroupArn=${STABLE_TG_ARN} > /dev/null
                    fi

                    echo "Production (:80): ${STABLE_TG} = ${STABLE_WEIGHT}% | ${CANARY_TG} = ${CANARY_WEIGHT}%"
                '''
            }
        }
    }
}
    Điểm chínhGiải thích
    ForwardConfig.TargetGroups với WeightMột forward action chia traffic tới nhiều Target Group (tối đa 5), trọng số 0 – 999. Lab dùng tổng = 100 để dễ đọc như phần trăm.
    jq -n ... > actions.json + file://actions.jsonSinh JSON default action bằng jq thay vì ghép chuỗi có nhiều dấu nháy – dễ đọc và tránh lỗi cú pháp.
    CANARY_WEIGHT = 100Promote: 100% sang version mới, đồng thời đưa listener :81 về version cũ – trạng thái giống hệt sau khi switch Blue/Green, job 3 và job 4 dùng tiếp được.
    CANARY_WEIGHT = 0Rollback: toàn bộ traffic về version cũ.
  4. Bước 4: Canary 10%

    Chạy job với CANARY_ENV = blue, CANARY_WEIGHT = 10. Console Output:

    Canary bluegreen-lab-tg-blue: 2 target healthy | Stable bluegreen-lab-tg-green: 2 target healthy
...
Production (:80): bluegreen-lab-tg-green = 90% | bluegreen-lab-tg-blue = 10%

    Gửi 100 request tới production và đếm theo version (thay <alb-dns-name>):

    for i in $(seq 1 100); do curl -s http://<alb-dns-name>/ | grep -o '<h1[^>]*>[^<]*' | grep -o 'v[0-9.]*'; done | sort | uniq -c
     91 v2.1.0
      9 v2.2.0

    Tỷ lệ xấp xỉ 90/10 (mỗi lần chạy sẽ hơi khác vì ALB chia ngẫu nhiên theo trọng số). Trên EC2 Console → bluegreen-lab-alb → Listeners and rules: rule mặc định của HTTP:80 hiển thị 2 Target Group với weight 90 và 10.

  5. Bước 5: Theo dõi metric của canary

    Mở EC2 Console → Target Groups → bluegreen-lab-tg-blue → tab Monitoring và so sánh với bluegreen-lab-tg-green. Các metric cần chú ý:

    • RequestCount: canary nhận khoảng 10% số request.
    • HTTPCode_Target_5XX_Count: số lỗi 5xx do ứng dụng trả về – tăng ở canary là dấu hiệu phải rollback.
    • TargetResponseTime: độ trễ của version mới so với version cũ.

    💡 Trong thực tế, CloudWatch Alarm trên HTTPCode_Target_5XX_Count của Target Group canary sẽ kích hoạt rollback tự động (CodeDeploy, ECS) – ở lab này ta quyết định bằng tay.

  6. Bước 6: Giả lập phát hiện lỗi – rollback về 0%

    Chạy job với CANARY_ENV = blue, CANARY_WEIGHT = 0. Đo lại: 100% request trả về v2.1.0. Chỉ khoảng 10% người dùng từng thấy version mới trong thời gian canary – blast radius nhỏ hơn nhiều so với Blue/Green.

    for i in $(seq 1 100); do curl -s http://<alb-dns-name>/ | grep -o '<h1[^>]*>[^<]*' | grep -o 'v[0-9.]*'; done | sort | uniq -c
    100 v2.1.0
  7. Bước 7: Release lại 10% → 50% → 100%

    Giả sử lỗi đã được xử lý. Chạy job lần lượt với CANARY_WEIGHT = 10, rồi 50, sau mỗi nấc đo lại tỷ lệ bằng vòng lặp curl và kiểm tra metric. Cuối cùng chạy với CANARY_WEIGHT = 100 (promote):

    for i in $(seq 1 100); do curl -s http://<alb-dns-name>/ | grep -o '<h1[^>]*>[^<]*' | grep -o 'v[0-9.]*'; done | sort | uniq -c
    100 v2.2.0
curl -s http://<alb-dns-name>:81/ | grep -o "<h1[^>]*>[^<]*"
<h1 id="welcome" ...>Welcome to My Website – v2.1.0

    Production chạy v2.2.0 (Blue), test listener trỏ về v2.1.0 (Green) – sẵn sàng rollback bằng job 3 nếu cần.

  8. Bước 8: Dọn môi trường cũ

    Sau thời gian theo dõi, chạy bluegreen-job4-clear-resource với TARGET_ENV = green. Safety check cho phép vì Green có weight 0 trên listener :80.

Kiểm tra kết quả

✅ Lab thành công khi

  • Ở nấc 10% và 50%, vòng lặp 100 request cho tỷ lệ version xấp xỉ trọng số đã đặt.
  • Rollback 0% đưa toàn bộ traffic về v2.1.0 ngay lập tức.

Troubleshoot

ERROR: Môi trường canary chưa có target healthy...
Nguyên nhân: Chưa deploy version mới vào môi trường canary, hoặc chọn nhầm CANARY_ENV (chọn môi trường đã scale về 0).
Giải pháp: Chạy bluegreen-job2-deploy cho môi trường đó, kiểm tra lại CANARY_ENV.
Job 2 báo môi trường đang nhận traffic production dù đang ở nấc 10%
Nguyên nhân: Trong lúc canary, cả 2 Target Group đều có weight > 0 – cả 2 môi trường đều LIVE.
Giải pháp: Hoàn tất canary (promote 100% hoặc rollback 0%) trước khi deploy version tiếp theo.
Tỷ lệ đo được lệch nhiều so với trọng số
Nguyên nhân: Số mẫu nhỏ, hoặc bật stickiness, hoặc trình duyệt giữ kết nối keep-alive.
Giải pháp: Đo bằng curl (mỗi lệnh 1 kết nối mới) với 100–200 request.
ValidationError ... ForwardConfig khi chạy modify-listener
Nguyên nhân: JSON default action sai cấu trúc (thường do sửa Jenkinsfile bằng tay).
Giải pháp: Xem nội dung actions.json được in trong Console Output, so sánh với Jenkinsfile gốc.
