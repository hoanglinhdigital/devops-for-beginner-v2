11. Chiến lược deployment / Lab 1: Job Build theo Git tag & Terraform stack Blue/Green

Mục tiêu

Chuỗi Lab 1 → Lab 4 xây dựng quy trình Blue/Green deployment cho ECS gồm 4 job Jenkins và 1 Terraform stack. Trong lab đầu tiên:

  • Bổ sung quyền thao tác Elastic Load Balancing cho IAM Role của Jenkins server (Section 10).
  • Tạo job bluegreen-job1-build: nhận tham số VERSION (Git tag), build source code và push Docker image lên ECR với tag <VERSION>.
  • Release tag v2.0.0 và build image tương ứng.
  • Dùng Terraform tạo hạ tầng Blue/Green: VPC, Security Group, 1 ALB với 2 listener (:80 production, :81 test), 2 Target Group, 2 ECS Cluster Blue/Green.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Section 10: Jenkins server jenkins-server (EC2 Ubuntu, Docker, jq, AWS CLI v2) với IAM Role jenkins-server-role; credential github-ssh-key và repository nodejs-random-color đã fork (Lab 8); kiến thức job release theo tag (Lab 10).
  • Máy local: Terraform >= 1.10, AWS CLI v2 đã cấu hình profile (Section 5), Git.
  • Source code: sourcecode/section_11_deployment_strategy/ (lab1_build_and_stack/, terraform_bluegreen_stack/).
Chi phí: stack chạy 1 ALB + 4 task Fargate (0.25 vCPU / 0.5 GB) + Public IPv4, cộng với EC2 Jenkins t3.medium. Nên làm liên tục Lab 1 → Lab 5 rồi terraform destroy.

Các bước thực hành

  1. Bước 1: Khởi động Jenkins server & kiểm tra ECR repository

    Start instance jenkins-server nếu đang stop (Public IP có thể đã đổi – truy cập http://<public-ip>:8080 và cập nhật rule Security Group nếu IP máy bạn thay đổi). Kiểm tra ECR repository:

    aws ecr describe-repositories --repository-names nodejs-random-color --region ap-southeast-1 --query 'repositories[0].repositoryUri' --output text

    Nếu đã xoá repository ở cuối Section 10, tạo lại trên ECR Console với thông số:

    • Visibility: Private
    • Repository name: nodejs-random-color
    • Các tuỳ chọn khác: mặc định
  2. Bước 2: Bổ sung quyền Elastic Load Balancing cho Jenkins

    Các job của section này cần đọc và sửa listener của ALB. Trên IAM Console, mở Role jenkins-server-role và gắn thêm permissions policy:

    • Policy: ElasticLoadBalancingFullAccess (AWS managed)
    • Các policy đã có giữ nguyên: AmazonS3FullAccess, AmazonEC2ContainerRegistryPowerUser, AmazonECS_FullAccess

    SSH vào Jenkins server, kiểm tra user jenkins gọi được API của ELB (kết quả là danh sách tên Load Balancer, có thể rỗng []):

    sudo -u jenkins aws elbv2 describe-load-balancers --region ap-southeast-1 --query 'LoadBalancers[].LoadBalancerName'

    💡 Môi trường thật nên viết inline policy chỉ cho phép elasticloadbalancing:Describe* và elasticloadbalancing:ModifyListener trên đúng ALB của dự án (least privilege).

  3. Bước 3: Tạo job bluegreen-job1-build

    Trên Jenkins, tạo New Item → Pipeline tên bluegreen-job1-build:

    • General → tick This project is parameterized → String Parameter: Name VERSION, Default Value v2.0.0, Description Git tag cần build
    • Pipeline → Definition Pipeline script, dán nội dung file lab1_build_and_stack/Jenkinsfile-build, sửa <your-github-username> trong GIT_REPO
    // Section 11 – Job 1: Build Docker image theo Git tag & push lên Amazon ECR (image tag = Git tag)
// Job: bluegreen-job1-build | Pipeline definition: Pipeline script (dán nội dung file này)
// This project is parameterized:
//   - String parameter VERSION (Default: v2.0.0) – Git tag cần build, cũng là image tag trên ECR
pipeline {
    agent any

    options {
        timeout(time: 15, unit: 'MINUTES')
        disableConcurrentBuilds()
    }

    environment {
        // Thay <your-github-username>; credential github-ssh-key đã tạo ở Section 10 – Lab 8
        GIT_REPO       = 'git@github.com:<your-github-username>/nodejs-random-color.git'
        GIT_CREDENTIAL = 'github-ssh-key'
        AWS_REGION     = 'ap-southeast-1'
        ECR_REPO       = 'nodejs-random-color'
    }

    stages {
        stage('Checkout using tag') {
            steps {
                checkout scmGit(
                    branches: [[name: "refs/tags/${params.VERSION}"]],
                    userRemoteConfigs: [[url: "${GIT_REPO}", credentialsId: "${GIT_CREDENTIAL}"]]
                )
                sh 'git log -1 --oneline --decorate'
            }
        }

        stage('Build image') {
            steps {
                sh 'docker build -t ${ECR_REPO}:${VERSION} .'
            }
        }

        stage('Push image to ECR') {
            steps {
                // Lấy Account ID từ IAM Role của Jenkins server -> không hard-code Account ID
                sh '''
                    ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
                    ECR_REGISTRY=${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com
                    aws ecr get-login-password --region ${AWS_REGION} | docker login --username AWS --password-stdin ${ECR_REGISTRY}
                    docker tag ${ECR_REPO}:${VERSION} ${ECR_REGISTRY}/${ECR_REPO}:${VERSION}
                    docker push ${ECR_REGISTRY}/${ECR_REPO}:${VERSION}
                    echo "Pushed image: ${ECR_REGISTRY}/${ECR_REPO}:${VERSION}"
                '''
            }
        }
    }

    post {
        always {
            // Xoá image không còn dùng để tránh đầy ổ đĩa Jenkins server
            sh 'docker image prune -f'
        }
    }
}

    💡 Job này giống job release ở Section 10 – Lab 10 với ACTION = OnlyBuild: image tag trên ECR trùng với Git tag, nhìn tag là biết code nào đang chạy.

  4. Bước 4: Release tag v2.0.0

    Trên máy local, trong repository nodejs-random-color, mở public/index.html và sửa phần text của thẻ <h1 id="welcome" ...> thành Welcome to My Website – v2.0.0 (giữ nguyên thuộc tính). Commit, tạo tag và push:

    cd ~/jenkins-labs/nodejs-random-color
git checkout master
git pull origin master
git add public/index.html
git commit -m "feat: release v2.0.0"
git push origin master
git tag -a v2.0.0 -m "Release v2.0.0"
git push origin v2.0.0
  5. Bước 5: Build image v2.0.0

    Mở job bluegreen-job1-build → Build with Parameters → VERSION = v2.0.0 → Build. Khi job xanh, kiểm tra image trên ECR:

    aws ecr list-images --repository-name nodejs-random-color --region ap-southeast-1 --query 'imageIds[].imageTag'
[
    "v2.0.0"
]
  6. Bước 6: Triển khai Terraform stack Blue/Green

    Cấu trúc stack (tái sử dụng các module của Section 10, thêm listener test và nhân đôi Target Group, Cluster, Service bằng for_each):

    terraform_bluegreen_stack/
├── main.tf                    # locals environments = ["blue", "green"] + gọi 4 module
├── variables.tf / outputs.tf
├── terraform.tfvars.example
└── modules/
    ├── networking/            # VPC 2 public subnet, không NAT Gateway
    ├── security/              # SG ALB (80, 81) + SG ECS (3000 từ ALB)
    ├── load_balancer/         # ALB, tg-blue, tg-green, listener :80 → blue, :81 → green
    └── ecs/                   # cluster-blue, cluster-green, task definition, 2 service

    Điểm quan trọng trong modules/load_balancer/main.tf – listener bỏ qua thay đổi default_action vì job Jenkins sẽ switch traffic:

    #Listener 80 – PRODUCTION: người dùng cuối truy cập. Ban đầu trỏ tới Blue.
resource "aws_lb_listener" "production" {
  load_balancer_arn = aws_lb.alb.arn
  port              = 80
  protocol          = "HTTP"

  default_action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.env["blue"].arn
  }

  # Job Jenkins switch traffic / canary sẽ đổi Target Group của listener,
  # bỏ qua thay đổi này để terraform apply không "switch" ngược traffic.
  lifecycle {
    ignore_changes = [default_action]
  }
}

# Thay 123456789012 bằng AWS Account ID của bạn; v2.0.0 là image tag đã build bằng job bluegreen-job1-build (Lab 1)

    Chờ 1–2 phút để task healthy, mở production_url và test_url trên trình duyệt – cả hai hiển thị v2.0.0. Refresh nhiều lần sẽ thấy 2 màu nền khác nhau (2 task). Hoặc dùng curl:

    curl -s $(terraform output -raw production_url)/ | grep -o "<h1[^>]*>[^<]*"
<h1 id="welcome" ...>Welcome to My Website – v2.0.0
curl -s $(terraform output -raw test_url)/ | grep -o "<h1[^>]*>[^<]*"
<h1 id="welcome" ...>Welcome to My Website – v2.0.0

    Trên EC2 Console → Load Balancers → bluegreen-lab-alb → tab Listeners and rules: HTTP:80 forward tới bluegreen-lab-tg-blue, HTTP:81 forward tới bluegreen-lab-tg-green. Trên ECS Console thấy 2 cluster, mỗi cluster có service nodejs-service với 2 task running.

Troubleshoot

Couldn't find any revision to build. Verify the repository and branch configuration for this job.
Nguyên nhân: Tag v2.0.0 chưa được push lên GitHub hoặc nhập sai tên tag.
Giải pháp: Chạy git push origin v2.0.0, kiểm tra tab Tags của repository trên GitHub.
Truy cập ALB nhận 503 Service Temporarily Unavailable
Nguyên nhân: Task chưa healthy (mới khởi động) hoặc không pull được image.
Giải pháp: Chờ thêm 1–2 phút. Nếu vẫn lỗi, mở ECS Console → cluster → service → tab Tasks (stopped) xem Stopped reason.
CannotPullContainerError: ... nodejs-random-color:v2.0.0: not found
Nguyên nhân: ecr_image_uri trong terraform.tfvars sai Account ID hoặc tag chưa tồn tại.
Giải pháp: Sửa lại ecr_image_uri, chạy job Build nếu thiếu image. Vì service có ignore_changes = [task_definition], sau khi sửa cần ép service dùng revision mới: terraform apply -replace="module.ecs.aws_ecs_service.nodejs[\"blue\"]" -replace="module.ecs.aws_ecs_service.nodejs[\"green\"]".
AccessDenied ... elasticloadbalancing:DescribeLoadBalancers khi chạy lệnh trên Jenkins server
Nguyên nhân: Chưa gắn policy ở Bước 2 (hoặc gắn nhầm Role).
Giải pháp: Kiểm tra EC2 → instance jenkins-server → IAM Role, gắn ElasticLoadBalancingFullAccess vào đúng Role đó.
Unsupported Terraform Core version
Nguyên nhân: Terraform trên máy cũ hơn 1.10.
Giải pháp: Nâng cấp Terraform (Section 5 – Lab 1).
