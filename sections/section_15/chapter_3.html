15. Elastic Kubernetes Service (EKS) / LoadBalancer trong EKS

Giới thiệu

Ở Section 13 bạn đã biết Service kiểu LoadBalancer và Ingress. Trên EKS, khi bạn tạo Service LoadBalancer hoặc Ingress, một thành phần tên AWS Load Balancer Controller sẽ tự động tạo ra Application Load Balancer (ALB) hoặc Network Load Balancer (NLB) thật trên AWS để đưa traffic từ ngoài vào cluster.

Các loại Load Balancer được hỗ trợ

EKS hỗ trợ 2 loại load balancer chính:

  • Network Load Balancer (NLB) – hoạt động ở tầng 4 (transport, TCP/UDP). Hiệu năng cao, IP cố định, phù hợp traffic TCP/TLS lớn.
  • Application Load Balancer (ALB) – hoạt động ở tầng 7 (application, HTTP/HTTPS). Hỗ trợ định tuyến theo host/path, header, host-based và path-based routing.
Network Load Balancer (NLB) – Layer 4
Application Load Balancer (ALB) – Layer 7

AWS Load Balancer Controller

Để EKS có thể tự tạo ALB/NLB, bạn cần cài AWS Load Balancer Controller (kế thừa từ ALB Ingress Controller cũ). Controller chạy như một Deployment trong cluster, quan sát các resource Ingress/Service và tự tạo, cấu hình load balancer tương ứng trên AWS thông qua IAM Role (IRSA – IAM Roles for Service Accounts).

Tầng hoạt độngApplication (HTTP/HTTPS)Transport (TCP/UDP/TLS)

Trade-off

✅ Ưu điểm của LB Controller

  • Khai báo bằng Ingress YAML (declarative), không cần tạo LB thủ công trên Console.
  • Tự cập nhật target group khi Pod scale/restart.
  • Hỗ trợ cả ALB và NLB, có thể kết hợp WAF, ACM (HTTPS), external DNS.

⚠️ Nhược điểm / lưu ý

  • Cần cấu hình IAM (IRSA) đúng, nếu không controller không tạo được LB.
  • Mỗi Ingress/Service có thể tạo một LB riêng → tốn phí nếu lạm dụng.
  • Không dùng được với kiến trúc Ingress Nginx Controller truyền thống (cùng cluster có thể chạy cả hai nhưng cần phân biệt ingressClassName).

Use Cases

Web/API với path-based routing

Một ALB duy nhất định tuyến /api → backend, / → frontend (sẽ làm ở Lab 2 Part 2).

Dịch vụ TCP hiệu năng cao

Dùng NLB cho game server, gRPC, MQTT... cần IP tĩnh và độ trễ thấp.

HTTPS + WAF cho public service

Gắn ACM certificate và AWS WAF vào ALB để bảo vệ ứng dụng web.

Thông tin bổ sung

  • annotation thường dùng: alb.ingress.kubernetes.io/scheme: internet-facing (hoặc internal), alb.ingress.kubernetes.io/target-type: ip (đăng ký IP của Pod trực tiếp, thay vì instance).
  • Service LoadBalancer: khai báo spec.type: LoadBalancer với annotation để tạo NLB thay vì ALB mặc định.
  • IRSA: controller dùng IAM Role gắn vào Service Account (kube-system) để có quyền gọi API tạo LB.
  • Tài liệu: aws-load-balancer-controller.
