15. Elastic Kubernetes Service (EKS) / Lab 2: LoadBalancer trong EKS – Part 2

Mục tiêu

  • Sử dụng ALB làm LoadBalancer cho một ứng dụng nhiều service.
  • Dùng Ingress định tuyến /api → backend và / → frontend.
  • Truy cập ứng dụng qua DNS của ALB.

ALB nhận traffic rồi chuyển tới Ingress; Ingress định tuyến / → frontend, /api → backend; backend gọi MongoDB qua ClusterIP.

Yêu cầu trước khi bắt đầu

  • Đã cài AWS Load Balancer Controller (Lab 2 Part 1).
  • Có image frontend/backend trên ECR (đã build ở Section 13: devops-lab13-frontend, devops-lab13-backend).
  • Source code: sourcecode/section_14_eks_basic/lab2_loadbalancer/demo-app.yaml.

Các bước thực hành

  1. Bước 1: Chuẩn bị file config demo-app.yaml

    File gồm các hạng mục: Deployment + Service cho Frontend, Backend, Mongo và Ingress ALB. Tham khảo cấu trúc (thay <AWS_ACCOUNT_ID>):

    # Mongo (ClusterIP)
apiVersion: v1
kind: Service
metadata:
  name: mongo
spec:
  type: ClusterIP
  selector:
    app: mongo
  ports:
    - protocol: TCP
      port: 27017
      targetPort: 27017
---
# Backend (Deployment + NodePort 30099) - image ECR
# Frontend (Deployment + NodePort 30088) - image ECR
---
# Ingress
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: demo-ingress
  annotations:
    alb.ingress.kubernetes.io/scheme: internet-facing
    alb.ingress.kubernetes.io/target-type: ip
spec:
  ingressClassName: alb
  rules:
  - host:
    http:
      paths:
      - pathType: Prefix
        path: /api
        backend:
          service:
            name: backend
            port:
              number: 3000
      - pathType: Prefix
        path: /
        backend:
          service:
            name: frontend
            port:
              number: 3000

    💡 File đầy đủ tại lab2_loadbalancer/demo-app.yaml.

  2. Bước 2: Apply file config 
    kubectl apply -f demo-app.yaml
  3. Bước 3: Kiểm tra các resource 
    kubectl get deployment
kubectl get service
kubectl get ingress

    Đợi Ingress có địa chỉ ALB (cột ADDRESS).

  4. Bước 4: Truy cập ứng dụng qua DNS của ALB

    Lấy DNS name của ALB và truy cập:

    • http://<alb-dns>/ → giao diện frontend.
    • http://<alb-dns>/api → dữ liệu từ backend.
  5. Bước 5: Xoá resource 
    kubectl delete -f demo-app.yaml

    Giữ lại cluster nếu muốn thực hành lab tiếp theo, ngược lại xoá cluster:

    eksctl delete cluster --name devops-test-cluster --region ap-southeast-1

Kiểm tra kết quả

✅ Lab thành công khi

  • Các Deployment frontend, backend, mongo có Pod Running.
  • Truy cập / thấy frontend, /api nhận dữ liệu từ backend.

Troubleshoot

/api trả lỗi 404 hoặc frontend không gọi được backend
Nguyên nhân: thứ tự path trong Ingress sai (path / khớp trước /api) hoặc sai tên service.
Giải pháp: kiểm tra định nghĩa paths trong Ingress, đảm bảo service name/port khớp.
Pod backend/frontend không kéo được image từ ECR
Nguyên nhân: node không có quyền pull ECR hoặc image tag sai.
Giải pháp: kiểm tra image URI (Account ID, repo name, tag); đảm bảo node group có IAM role cho phép pull ECR.
Mongo không nhận kết nối từ backend
Nguyên nhân: sai service name/port trong backend config.
Giải pháp: backend phải gọi đúng DNS mongo trên port 27017.

Dọn dẹp resource

Chi phí: ALB + node EC2 tính phí theo giờ. Xoá resource và cluster khi không dùng.
kubectl delete -f demo-app.yaml
eksctl delete cluster --name devops-test-cluster --region ap-southeast-1
