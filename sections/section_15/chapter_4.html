15. Elastic Kubernetes Service (EKS) / Lab 2: LoadBalancer trong EKS – Part 1

Mục tiêu

  • Cài đặt AWS Load Balancer Controller (kèm IAM Role qua IRSA) cho cluster.
  • Triển khai ứng dụng mẫu 2048 game và expose bằng ALB.
  • Truy cập ứng dụng qua DNS của ALB.

Yêu cầu trước khi bắt đầu

  • Đã tạo thành công EKS Cluster ở Lab 1 và kết nối được bằng kubectl.
  • Đã cài eksctl, kubectl, aws cli, helm.
  • Source code: sourcecode/section_14_eks_basic/lab2_loadbalancer/.

Các bước thực hành

  1. Bước 1: Tạo IAM Policy cho Load Balancer Controller

    Tạo policy từ file iam_policy.json (đã có trong source code):

    aws iam create-policy \
  --policy-name AWSLoadBalancerControllerIAMPolicy \
  --policy-document file://iam_policy.json
  2. Bước 2: Tạo IAM Role + Service Account (IRSA)

    Thay <AWS_ACCOUNT_ID> bằng Account ID của bạn:

    eksctl create iamserviceaccount \
  --cluster=devops-test-cluster \
  --namespace=kube-system \
  --name=aws-load-balancer-controller \
  --role-name AmazonEKSLoadBalancerControllerRole \
  --attach-policy-arn=arn:aws:iam::<AWS_ACCOUNT_ID>:policy/AWSLoadBalancerControllerIAMPolicy \
  --approve

    💡 Bước này tạo Service Account aws-load-balancer-controller trong namespace kube-system và gắn IAM Role (OIDC) cho nó.

  3. Bước 3: Cài AWS Load Balancer Controller bằng Helm 
    helm repo add eks https://aws.github.io/eks-charts
helm repo update eks
helm install aws-load-balancer-controller eks/aws-load-balancer-controller \
  -n kube-system \
  --set clusterName=devops-test-cluster \
  --set serviceAccount.create=false \
  --set serviceAccount.name=aws-load-balancer-controller

    Kiểm tra controller đã chạy:

    kubectl get deployment -n kube-system aws-load-balancer-controller
  4. Bước 4: Apply ứng dụng mẫu 2048 game

    Áp dụng file 2048-demo.yaml (gồm Namespace, Deployment 5 Pod, Service NodePort, Ingress ALB):

    kubectl apply -f 2048-demo.yaml

    Kiểm tra resource:

    kubectl get deployment -n game-2048
kubectl get service -n game-2048
kubectl get ingress -n game-2048
  5. Bước 5: Kiểm tra ALB và truy cập ứng dụng

    Vào AWS Console → EC2 → Load Balancers, tìm ALB vừa được Controller tạo ra. Lấy DNS name của ALB và truy cập http://<alb-dns-name> trên trình duyệt (nhớ thêm http://) để chơi game 2048.

Kiểm tra kết quả

✅ Lab thành công khi

  • Deployment aws-load-balancer-controller trong kube-system có Pod Running.
  • Ingress ingress-2048 có địa chỉ ALB (cột ADDRESS của kubectl get ingress).
  • Truy cập DNS của ALB hiển thị giao diện game 2048.

Troubleshoot

Ingress không có ADDRESS / ALB không được tạo
Nguyên nhân: controller chưa chạy hoặc Service Account thiếu quyền IAM.
Giải pháp: kiểm tra kubectl logs -n kube-system deployment/aws-load-balancer-controller; xác nhận đã tạo đúng IAM policy và Service Account.
Truy cập ALB trả 502 Bad Gateway
Nguyên nhân: target group chưa có target healthy (Pod chưa ready) hoặc sai port.
Giải pháp: chờ Pod Running, kiểm tra kubectl get pods -n game-2048; xem target group trên Console.
Pod không kéo được image
Nguyên nhân: node không ra được Internet (subnet private không NAT) hoặc image sai.
Giải pháp: kiểm tra subnet có Internet gateway/NAT, kiểm tra lại tên image trong manifest.

Dọn dẹp resource

Chi phí: ALB tính phí theo giờ. Xoá Ingress để Controller xoá ALB, hoặc xoá cluster khi hoàn thành cả chương.
kubectl delete -f 2048-demo.yaml
