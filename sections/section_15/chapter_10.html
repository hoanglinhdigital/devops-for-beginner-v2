15. Elastic Kubernetes Service (EKS) / Lab 4: Add new IAM User to EKS Cluster

Mục tiêu

  • Tạo một IAM User mới (developer01).
  • Gán quyền cho user vào cluster bằng Access Entry (RBAC).
  • Dùng IAM User đó truy cập cluster và kiểm tra quyền.

Kiến trúc tổng quan

(IAM User)"] Profile["aws cli

developer01 được gán vào cluster qua Access Entry (policy AmazonEKSViewPolicy), sau đó dùng aws cli profile để tạo kubeconfig và xem resource.

Yêu cầu trước khi bắt đầu

  • Đã có EKS Cluster (Lab 1) và kết nối được bằng kubectl (user Admin).
  • Có quyền tạo IAM User trong tài khoản AWS.
  • Source code: sourcecode/section_14_eks_basic/lab4_rbac/commands.sh.

Các bước thực hành

  1. Bước 1: Tạo user developer01

    Vào IAM → Users tạo user developer01 với quyền PowerUserAccess. Tạo sẵn một Access Key cho user.

    Thử đăng nhập AWS Console bằng user developer01, tìm đến cluster → không thấy resource (permission denied) vì chưa được cấp quyền trên EKS.

  2. Bước 2: Gán quyền cho developer01 (quay lại user Admin)

    Vào EKS Cluster → tab Access → IAM access entries → Create access entry với các thông số:

    • IAM principal ARN: arn:aws:iam::<ACCOUNT_ID>:user/developer01
    • Type: Standard
    • Access policy: AmazonEKSViewPolicy, Access scope: Cluster

    Review và nhấn Create.

  3. Bước 3: Cấu hình aws cli cho developer01

    Tạo thêm profile developer01:

    aws configure --profile developer01

    Kiểm tra profile:

    aws sts get-caller-identity --profile developer01
{
    "UserId": "AIDAWIVVHVPNJTU7GKK72",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/developer01"
}
  4. Bước 4: Cập nhật kubeconfig cho developer01

    Xoá (hoặc backup) file kubeconfig hiện tại (C:\Users\<user>\.kube\config hoặc ~/.kube/config), sau đó:

    aws eks update-kubeconfig --region ap-southeast-1 --name devops-test-cluster --profile developer01

    Kiểm tra context và quyền:

    kubectl config get-contexts
kubectl cluster-info
kubectl get pods
kubectl get all -A

    Kết quả: xem được các resource trong cluster (do đã gán AmazonEKSViewPolicy).

  5. Bước 5: Xoá user developer01 (tuỳ chọn)

    Vào IAM xoá user developer01 khi không dùng nữa.

  6. Bước 6: Khôi phục kubeconfig cho user Admin 
    aws sts get-caller-identity
{
    "UserId": "AIDAWIVVHVPNJTU7GKK72",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/linhnguyen.admin"
}

    Cập nhật lại config cho user Admin:

    aws eks update-kubeconfig --region ap-southeast-1 --name devops-test-cluster
kubectl config get-contexts
kubectl get all -A

Kiểm tra kết quả

✅ Lab thành công khi

  • aws sts get-caller-identity --profile developer01 trả về user developer01.
  • kubectl get pods (với profile developer01) xem được resource trong cluster.
  • Sau khi khôi phục kubeconfig Admin, user Admin thao tác bình thường.

Troubleshoot

developer01 xem resource báo lỗi forbidden
Nguyên nhân: chưa gán Access Entry/policy đúng, hoặc kubeconfig đang trỏ user khác.
Giải pháp: kiểm tra lại Access Entry trong EKS, đảm bảo chạy update-kubeconfig --profile developer01.
aws eks update-kubeconfig báo lỗi access denied
Nguyên nhân: profile developer01 chưa có quyền eks:DescribeCluster.
Giải pháp: gán quyền (PowerUserAccess đã có) hoặc thêm policy mô tả cluster; kiểm tra lại credential của profile.

Dọn dẹp resource

Chi phí: xoá IAM user developer01 và EKS Cluster khi hoàn thành.
eksctl delete cluster --name devops-test-cluster --region ap-southeast-1
