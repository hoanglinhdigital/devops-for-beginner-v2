4. Giới thiệu & ôn lại kiến thức AWS / Ôn tập: Serverless, Container, Monitoring & Messaging

Giới thiệu

Ngoài mô hình “server truyền thống” với EC2, hệ thống hiện đại trên AWS thường kết hợp Serverless (Lambda, API Gateway), Container (ECS, ECR, EKS), Monitoring (CloudWatch) và Messaging (SQS, SNS, EventBridge) để tách rời các thành phần. Đây cũng là những “đích đến” mà các CICD pipeline trong khoá học sẽ deploy lên, nên cần nắm vững trước khi đi vào phần DevOps.

1. Kiến trúc Serverless (API Gateway, Cognito, Lambda)

  • Không quản lý server: chỉ viết code (function), AWS lo việc chạy, scale và patch hạ tầng.
  • Event-driven: Lambda được kích hoạt bởi sự kiện — HTTP request (API Gateway), file upload (S3), message (SQS), lịch (EventBridge)...
  • Trả tiền theo request & thời gian chạy: không có request thì gần như không tốn phí.
  • Tự động scale từ 0 tới hàng nghìn request đồng thời.
  • Cognito lo phần đăng ký/đăng nhập, cấp JWT token để API Gateway xác thực request.

2. Container: ECR, ECS, Fargate

  • Amazon ECR: registry private lưu trữ Docker image, tích hợp IAM và image scanning.
  • Amazon ECS: dịch vụ điều phối container của AWS. Các khái niệm chính: Cluster, Task Definition (mô tả container: image, CPU, RAM, port, env), Task, Service (duy trì số lượng task mong muốn, gắn với ALB).
  • Launch type: EC2 (tự quản lý instance) hoặc Fargate (serverless, không cần quản lý server).
  • Amazon EKS: Kubernetes được quản lý — sẽ học chi tiết ở các section về Kubernetes.

3. Monitoring với CloudWatch & CloudTrail

📈 Metrics

Số liệu theo thời gian: CPU, memory, request count, latency... Có metric mặc định và custom metric. Metrics Insights để truy vấn.

📜 Logs

Log Group / Log Stream thu thập log từ EC2, Lambda, ECS... Logs Insights để tìm kiếm, phân tích log.

🚨 Alarm

Cảnh báo khi metric vượt ngưỡng → gửi SNS (email, Slack), trigger Auto Scaling.

⏰ Event / Rule

Phản ứng theo sự kiện (event-based) hoặc theo lịch (time-based) — nay thuộc Amazon EventBridge.

🧪 Synthetics & RUM

Synthetics: script giả lập người dùng kiểm tra endpoint định kỳ. RUM: đo trải nghiệm người dùng thật trên trình duyệt.

🕵️ CloudTrail

Ghi lại mọi API call trên account: ai, làm gì, lúc nào, từ đâu — phục vụ audit và điều tra sự cố.

Các tính năng của Amazon CloudWatch: Alarm, Rule, Event, Logs, Metrics Insights, RUM, Evidently, Synthetics...
Mô hình monitoring: CloudWatch thu thập log/metric từ các target, Alarm gửi SNS tới team vận hành hoặc trigger Lambda tự động xử lý

4. Decoupling & Messaging (SQS, SNS, EventBridge)

  • Decoupling: các thành phần giao tiếp qua message thay vì gọi trực tiếp — một bên chậm hoặc lỗi không kéo sập bên còn lại.
  • Amazon SQS (queue): producer gửi message vào hàng đợi, consumer lấy ra xử lý theo tốc độ của mình. Hỗ trợ Standard và FIFO queue, Dead-Letter Queue (DLQ).
  • Amazon SNS (pub/sub): một message được gửi tới nhiều subscriber cùng lúc (SQS, Lambda, email, SMS, HTTP).
  • Fan-out pattern: SNS → nhiều SQS queue để nhiều hệ thống cùng xử lý một sự kiện.
  • Amazon EventBridge: event bus định tuyến sự kiện theo rule, tích hợp sẵn với hàng trăm dịch vụ AWS và SaaS.

Use Cases

Pipeline deploy container

CodeBuild build image → push ECR → cập nhật Task Definition → ECS Service rolling update — nội dung sẽ thực hành ở section CodePipeline.

Cảnh báo sự cố production

CloudWatch Alarm theo dõi 5xx của ALB, CPU của ECS; vượt ngưỡng thì gửi SNS tới email/Slack của team DevOps.

Xử lý đơn hàng chịu tải cao

Đơn hàng vào SQS, worker xử lý dần; giờ cao điểm hàng đợi dài ra nhưng hệ thống không sập, message lỗi được đưa vào DLQ để xử lý lại.

Thông tin bổ sung

Giới hạn cần nhớ: Lambda timeout tối đa 15 phút, memory tối đa 10 GB; SQS message tối đa 1 MiB (trước 8/2025 là 256 KB) (lớn hơn thì lưu S3 và gửi đường dẫn); CloudWatch Logs mặc định lưu vĩnh viễn — hãy đặt retention để tránh tốn phí.
Chi phí: ECS Fargate tính phí theo vCPU/RAM mỗi giây khi task chạy; ECR tính phí lưu trữ image — hãy đặt lifecycle policy xoá image cũ. Khi làm lab, nhớ scale service về 0 hoặc xoá cluster.
