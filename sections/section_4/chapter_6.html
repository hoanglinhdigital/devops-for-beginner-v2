4. Giới thiệu & ôn lại kiến thức AWS / Ôn tập: S3, RDS & CloudFront (CDN)

Giới thiệu

Sau khi có network và quyền truy cập, hệ thống cần nơi lưu trữ dữ liệu và cách phân phối nội dung đến người dùng. Chương này ôn lại 3 dịch vụ xuất hiện trong hầu hết mọi dự án: Amazon S3 (lưu trữ object/file), Amazon RDS (database quan hệ) và Amazon CloudFront (CDN). Trong khoá học, S3 còn đóng vai trò lưu artifact của CICD pipeline và Terraform state.

1. Amazon S3 – Simple Storage Service

  • Bucket & Object: dữ liệu lưu dưới dạng object (file + metadata) trong bucket. Tên bucket là duy nhất toàn cầu, nhưng bucket thuộc về một Region.
  • Độ bền 99.999999999% (11 số 9): dữ liệu tự động được nhân bản qua nhiều AZ.
  • Storage class: Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier (Instant/Flexible/Deep Archive) — đánh đổi giữa giá lưu trữ và tốc độ truy xuất.
  • Lifecycle rule: tự động chuyển class hoặc xoá object theo thời gian.
  • Versioning & Replication: giữ nhiều phiên bản object, sao chép sang bucket/Region khác.
  • Bảo mật: Block Public Access (bật mặc định), Bucket Policy, mã hoá (SSE-S3, SSE-KMS), Pre-signed URL.
S3 là trung tâm lưu trữ: lưu file, log, backup, static web hosting, nguồn dữ liệu cho Lambda/Glue

2. Amazon RDS – Relational Database Service

  • Managed database: AWS lo việc cài đặt, patch, backup tự động, snapshot — bạn chỉ cần tập trung vào schema và query.
  • Engine: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Db2 và Amazon Aurora.
  • Multi-AZ: có một bản standby đồng bộ ở AZ khác, tự động failover khi primary gặp sự cố — dùng cho High Availability.
  • Read Replica: bản sao bất đồng bộ chỉ đọc — dùng để scale đọc (report, query nặng).
  • Aurora Cluster Endpoint: Writer endpoint cho ghi, Reader endpoint tự cân bằng tải giữa các replica.
  • RDS Proxy: connection pooling giữa ứng dụng và DB — đặc biệt hữu ích với Lambda (tạo nhiều connection ngắn).
Các engine được hỗ trợ khi tạo RDS: Aurora, MySQL, MariaDB, PostgreSQL, Oracle, SQL Server

3. Amazon CloudFront – Content Delivery Network

  • Tài nguyên của server (origin) được cache trên các Edge Location; request của user được chuyển tới Edge gần nhất.
  • Origin có thể là S3 bucket, ALB, EC2, API Gateway hoặc bất kỳ HTTP server nào.
  • Website tĩnh (HTML/CSS/JS) có thể deploy lên S3 kết hợp CloudFront. Hầu hết framework hiện nay (React, Angular, Vue, Next.js static export...) đều build được ra dạng static.
  • Behavior: điều hướng request theo path pattern tới đúng origin mong muốn (ví dụ /api/* → ALB, còn lại → S3).
  • Origin Access Control (OAC): chỉ cho phép CloudFront đọc S3, bucket không cần public.
  • Tích hợp ACM (HTTPS miễn phí) và WAF (chặn tấn công) ngay tại Edge.
Khi có CDN, nội dung từ server được phân phối và cache tại các Edge Location gần người dùng
Website static (HTML/CSS/JS) build từ các framework được deploy lên S3 và phân phối qua CloudFront
CloudFront behaviors điều hướng request theo path tới đúng origin (Backend API, Media bucket, Website bucket)
Thứ tự behavior rất quan trọng: CloudFront đánh giá behavior theo thứ tự ưu tiên, khi đã match một path sẽ không đánh giá path tiếp theo. Nếu đặt /* lên trên cùng, các behavior bên dưới sẽ không bao giờ được áp dụng.

Use Cases

Deploy frontend React lên S3 + CloudFront

Pipeline build npm run build, sync thư mục build lên S3 rồi tạo CloudFront invalidation — một bài lab CICD kinh điển.

Database cho ứng dụng production

RDS MySQL Multi-AZ trong private subnet, chỉ cho phép app-sg truy cập port 3306, password lưu trong Secrets Manager.

Lưu trữ log & backup lâu dài

Đẩy log, backup vào S3 kèm lifecycle rule chuyển sang Glacier sau 90 ngày để tiết kiệm chi phí.

Thông tin bổ sung

Chi phí: RDS tính phí theo giờ kể cả khi không có query — với lab, hãy xoá (hoặc stop, nhưng RDS sẽ tự start lại sau 7 ngày). Snapshot thủ công cũng bị tính phí lưu trữ.
Lưu ý: không bao giờ để S3 bucket chứa dữ liệu nhạy cảm ở chế độ public. Muốn chia sẻ file tạm thời, hãy dùng Pre-signed URL; muốn public website, hãy dùng CloudFront + OAC.
