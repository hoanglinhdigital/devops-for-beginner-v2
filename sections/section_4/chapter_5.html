4. Giới thiệu & ôn lại kiến thức AWS / Ôn tập: IAM, VPC & Networking, Load Balancer

Giới thiệu

IAM (ai được làm gì), VPC (mạng chạy ở đâu) và Load Balancer (traffic đi vào thế nào) là 3 nền móng của mọi hệ thống trên AWS. Hầu hết các lỗi “không kết nối được”, “Access Denied” khi làm lab hay khi chạy CICD pipeline đều xuất phát từ việc cấu hình sai một trong ba phần này. Chương này ôn lại nhanh các khái niệm cốt lõi.

1. IAM – Identity and Access Management

Để thiết kế hệ thống đảm bảo Security và không gặp trouble về quyền, cần nắm vững 4 concept cơ bản của IAM:

👤 User

Đại diện cho một người (hoặc ứng dụng) với credential dài hạn: password đăng nhập Console, Access Key cho CLI/SDK. Nên bật MFA.

👥 Group

Tập hợp nhiều User có chung quyền (Developers, Admins...). Gán policy cho Group thay vì gán cho từng User.

🎭 Role

Danh tính được “assume” tạm thời, cấp credential tạm thời qua AWS STS. Dùng cho EC2, Lambda, CodeBuild, truy cập cross-account.

📜 Policy (Permission)

Văn bản JSON định nghĩa Effect (Allow/Deny), Action, Resource, Condition. Gắn vào User, Group hoặc Role.

Các thành phần của AWS IAM: User, Group, Role, Permission, STS, MFA, credential...
Best practice: không dùng root account cho công việc hằng ngày; áp dụng least privilege; ứng dụng chạy trên AWS (EC2, Lambda, ECS, CodeBuild) luôn dùng Role, tuyệt đối không hard-code Access Key trong source code.

2. VPC & Networking

  • VPC: một mạng ảo được tạo ra ở cấp độ Region, có dải IP (CIDR) riêng, ví dụ 10.0.0.0/16.
  • Subnet: một dải IP con nằm trong VPC. Mỗi subnet phải được chỉ định Availability Zone tại thời điểm tạo.
  • IP Address: IPv4 hoặc IPv6, gồm Public IP và Private IP.
  • Route table: xác định traffic sẽ được điều hướng đi đâu. Subnet có route 0.0.0.0/0 → Internet Gateway là public subnet.
  • Elastic IP: Public IP cố định, không bị thu hồi khi instance stop → start.
  • Các component khác: Internet Gateway, NAT Gateway, Elastic Network Interface (ENI), VPC Endpoint, VPC Peering, Transit Gateway, VPN, Flow Logs.
Các khái niệm cơ bản: Region, Availability Zone, VPC, Public/Private subnet, Router, Elastic IP
Các component khác của VPC: Flow logs, VPN, Internet gateway, NAT gateway, Peering, Transit Gateway, ENI, Endpoints

Thiết kế Security Group chuẩn

  • Security Group dùng để gom nhóm các resource có chung network setting (inbound/outbound, protocol, port).
  • Khi thiết kế cần quan tâm tới tính tái sử dụng và dễ quản lý.
  • Source của một rule có thể là CIDR hoặc ID của một Security Group khác (khuyến nghị cho traffic nội bộ).
  • Rule là stateful và không có deny rule: nếu Inbound cho phép request đi vào thì response tự động được trả về mà không cần allow Outbound — khác với Network ACL (stateless, có deny).
Thiết kế Security Group chuẩn: Public-SG → App-SG → Database-SG, Management-SG cho truy cập quản trị

3. Elastic Load Balancing

  • Load Balancer cho phép cấu hình các Listener trên một port (ví dụ HTTP:80, HTTPS:443).
  • Mỗi Listener có nhiều Rule (theo path, host header, HTTP header...).
  • Request sau khi vào Listener được đánh giá bởi các Rule và forward tới Target Group phù hợp.
  • Target Group thực hiện health check để phát hiện và loại bỏ target unhealthy.
Load Balancer → Listener → Rule → Target Group (kèm health check)
4 loại Load Balancer: Application, Network, Gateway, Classic

Application Load Balancer (ALB)

Layer 7 — HTTP/HTTPS
  • Route theo path, host, header
  • Phổ biến nhất cho web/API
  • Tích hợp ECS, EKS, Lambda, WAF

Network Load Balancer (NLB)

Layer 4 — TCP/UDP/TLS
  • Hiệu năng cực cao, độ trễ thấp
  • Hỗ trợ Static IP / Elastic IP
  • Phù hợp game, IoT, gRPC

Gateway Load Balancer (GWLB)

Layer 3 — IP
  • Đưa traffic qua thiết bị bảo mật bên thứ 3
  • Firewall, IDS/IPS

Classic Load Balancer (CLB)

Layer 4/7 — thế hệ cũ
  • Không khuyến nghị cho hệ thống mới
  • Chỉ còn gặp ở hệ thống legacy

Use Cases

CodeBuild push image lên ECR

Gán IAM Role cho CodeBuild project với quyền ecr:PutImage... thay vì lưu Access Key trong buildspec.

Web app 3 tầng chuẩn production

ALB ở public subnet, ECS/EC2 ở private subnet app, RDS ở private subnet data, Security Group xâu chuỗi alb-sg → app-sg → db-sg.

Microservices dùng chung một ALB

Một ALB, nhiều rule theo path (/user/*, /order/*) trỏ tới các Target Group khác nhau — tiết kiệm chi phí ALB.

Thông tin bổ sung

Chi phí: NAT Gateway và Load Balancer tính phí theo giờ ngay cả khi không có traffic. Khi làm lab, hãy xoá ngay sau khi thực hành xong. Elastic IP không gắn vào instance đang chạy cũng bị tính phí (hiện nay mọi Public IPv4 đều tính phí).
Debug kết nối: khi không kết nối được, kiểm tra theo thứ tự: Route table → Security Group (inbound) → Network ACL → ứng dụng có đang listen đúng port không → Target Group health check.
