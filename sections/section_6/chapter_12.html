6. Thao tác cơ bản với Linux / Lab 9: Thêm SSH key cho thành viên dự án

Mục tiêu

  • Hiểu cơ chế đăng nhập SSH bằng cặp khoá public key / private key.
  • Sinh cặp khoá cho thành viên dự án bằng ssh-keygen.
  • Tạo user dev01 trên server và cấu hình ~/.ssh/authorized_keys với quyền đúng chuẩn.
  • Đăng nhập bằng private key của dev01 và thu hồi quyền truy cập khi thành viên rời dự án.

Thành viên chỉ gửi public key cho admin. Private key không bao giờ rời khỏi máy của thành viên.

Yêu cầu trước khi bắt đầu

  • Instance linux-lab-server đang Running, SSH được bằng ec2-user.
  • Đã hoàn thành Lab 3 (user/group) và Lab 4 (permission).
  • PC Local có lệnh ssh-keygen (Git Bash trên Windows, Terminal trên Mac/Linux).
  • Source code: sourcecode/section_6_linux_basic_operation/lab9_ssh_key/commands.sh.

Các bước thực hành

  1. Bước 1: Sinh cặp khoá trên PC Local

    Đóng vai thành viên dev01, chạy trên PC Local (không phải trên server). Nhấn Enter để bỏ qua passphrase (hoặc đặt passphrase để bảo vệ key tốt hơn):

    mkdir -p ~/.ssh
ssh-keygen -t ed25519 -C "dev01" -f ~/.ssh/dev01
ls -l ~/.ssh/dev01 ~/.ssh/dev01.pub
cat ~/.ssh/dev01.pub

    Thuật toán ed25519 ngắn, nhanh và an toàn hơn RSA. Nếu hệ thống cũ không hỗ trợ, dùng ssh-keygen -t rsa -b 4096 -C "dev01" -f ~/.ssh/dev01. Copy toàn bộ nội dung dòng ssh-ed25519 AAAA... dev01 để dùng ở bước 3.

  2. Bước 2: Tạo user dev01 trên server

    SSH vào server bằng ec2-user. Tạo user không đặt password – user này chỉ đăng nhập được bằng SSH key:

    sudo useradd dev01
id dev01
  3. Bước 3: Cấu hình authorized_keys cho dev01

    Chuyển sang user dev01 để file tạo ra thuộc đúng owner dev01:

    sudo su - dev01
    pwd
/home/dev01
whoami
dev01
mkdir -p ~/.ssh
chmod 700 ~/.ssh
vim ~/.ssh/authorized_keys

    Nhấn i, dán nội dung public key đã copy ở bước 1 (đúng 1 dòng), Esc → :wq. Mỗi dòng trong file là một public key được phép đăng nhập. Đặt quyền cho file:

    chmod 600 ~/.ssh/authorized_keys
ls -la ~/.ssh
exit
    Đường dẫnQuyềnOwner
    /home/dev01700 (không được để group/other có quyền ghi)dev01
    /home/dev01/.ssh700dev01
    /home/dev01/.ssh/authorized_keys600dev01

    💡 Không cần restart sshd — SSH server đọc file authorized_keys ở mỗi lần đăng nhập.

  4. Bước 4: Đăng nhập bằng private key của dev01

    Từ PC Local (thay <PUBLIC_IP> bằng IP của server):

    ssh -i ~/.ssh/dev01 dev01@<PUBLIC_IP>
    whoami
dev01
exit
  5. Bước 5 (tuỳ chọn): Cấu hình ~/.ssh/config để SSH nhanh

    Trên PC Local, mở (hoặc tạo) file ~/.ssh/config bằng VS Code và thêm nội dung sau (thay <PUBLIC_IP>):

    code ~/.ssh/config
    Host linux-lab-dev01
    HostName <PUBLIC_IP>
    User dev01
    IdentityFile ~/.ssh/dev01

    Sau đó chỉ cần gõ:

    ssh linux-lab-dev01
  6. Bước 6: Thu hồi quyền truy cập

    Khi thành viên rời dự án hoặc bị lộ private key: xoá dòng public key tương ứng trong authorized_keys (nếu dùng chung user), hoặc xoá hẳn user. Login bằng ec2-user:

    sudo userdel -r dev01
id dev01
id: 'dev01': no such user

    Thử lại ssh -i ~/.ssh/dev01 dev01@<PUBLIC_IP> từ PC Local sẽ bị từ chối.

Kiểm tra kết quả

✅ Lab thành công khi

  • Đăng nhập được bằng ssh -i ~/.ssh/dev01 dev01@<PUBLIC_IP> mà không cần password.
  • ls -la /home/dev01/.ssh cho thấy thư mục drwx------ và file -rw-------, owner dev01.
  • Sau bước 6, dev01 không còn đăng nhập được.

Troubleshoot

dev01@...: Permission denied (publickey,gssapi-keyex,gssapi-with-mic)
Nguyên nhân: Public key dán sai (bị xuống dòng, thiếu ký tự), dùng sai private key, hoặc quyền/owner của .ssh, authorized_keys không đúng (ví dụ tạo file bằng ec2-user với sudo nên owner là root).
Giải pháp: Kiểm tra sudo ls -la /home/dev01/.ssh; sửa owner bằng sudo chown -R dev01:dev01 /home/dev01/.ssh và quyền 700/600. Xem lý do chi tiết trên server: sudo journalctl -u sshd -n 20.
Authentication refused: bad ownership or modes for directory /home/dev01 (trong log sshd)
Nguyên nhân: Thư mục home hoặc .ssh cho phép group/other ghi.
Giải pháp: sudo chmod 700 /home/dev01 /home/dev01/.ssh.
Debug chi tiết quá trình SSH từ phía client
Nguyên nhân: Cần biết SSH client đang thử key nào, server phản hồi gì.
Giải pháp: Thêm -v (hoặc -vvv): ssh -v -i ~/.ssh/dev01 dev01@<PUBLIC_IP>.
Trong thực tế: quản lý SSH key thủ công trên nhiều server rất khó kiểm soát. Các giải pháp thường dùng trên AWS: AWS Systems Manager Session Manager (không cần mở cổng 22, không cần key, phân quyền bằng IAM), EC2 Instance Connect (đẩy key tạm thời 60 giây), hoặc tự động hoá bằng Ansible/user data.

Dọn dẹp resource

User dev01 đã được xoá ở bước 6. Trên PC Local có thể xoá cặp key thực hành bằng rm ~/.ssh/dev01 ~/.ssh/dev01.pub và xoá block linux-lab-dev01 trong ~/.ssh/config. Dọn dẹp toàn bộ resource AWS của section ở chương tiếp theo.
