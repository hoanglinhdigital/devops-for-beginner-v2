6. Thao tác cơ bản với Linux / Process & Service trong Linux

Giới thiệu

Process là một instance của chương trình đang chạy: mỗi lần bạn gõ ls, mở vim hay khởi động web server, hệ điều hành tạo ra một process với mã định danh riêng PID. Service (còn gọi là daemon) là process được thiết kế để chạy ngầm liên tục và cung cấp dịch vụ cho hệ thống hoặc ứng dụng khác — ví dụ sshd (cho phép SSH), httpd (web server), crond (lập lịch). Trên các distro hiện đại, service được quản lý bởi systemd thông qua lệnh systemctl.

Đặc điểm chính

  • PID & PPID: mỗi process có một PID duy nhất và một PPID (PID của process cha). Process đầu tiên là systemd với PID 1, là “tổ tiên” của mọi process khác.
  • Tài nguyên riêng: OS cấp phát cho mỗi process vùng nhớ (memory), file đang mở, biến môi trường và chạy với quyền của một user nhất định.
  • Trạng thái: Running (R), Sleeping (S), Stopped (T), Zombie (Z) — hiển thị ở cột STAT của ps aux hoặc cột S của top.
  • Foreground & Background: process có thể chạy trước mặt (chiếm terminal) hoặc chạy nền (thêm & sau lệnh).
  • Signal: cơ chế để “nói chuyện” với process, ví dụ kill gửi tín hiệu yêu cầu process dừng.
  • Service (systemd unit): được định nghĩa bằng file .service, có thể tự khởi động cùng OS (enable) và tự khởi động lại khi bị lỗi (Restart=always).

Lệnh quản lý process và service

Process

  • ps: process của user hiện tại trong terminal
  • ps -ef / ps aux: tất cả process, có owner, %CPU, %MEM
  • top: theo dõi real-time
  • pgrep -a <tên>: tìm PID theo tên
  • kill, kill -9, pkill <tên>: dừng process
  • jobs, fg, bg, &: quản lý foreground/background

Service (systemctl)

  • systemctl start | stop | restart <service>
  • systemctl reload <service>: đọc lại cấu hình
  • systemctl status <service>: trạng thái, PID, log gần nhất
  • systemctl enable | disable <service>: bật/tắt tự khởi động cùng OS
  • systemctl enable --now <service>: enable và start cùng lúc
  • journalctl -u <service>: xem log của service

💡 Lệnh cũ service httpd restart (trong slide/tài liệu cũ) vẫn chạy được trên AL2023 nhưng thực chất được chuyển sang systemctl. Hãy dùng systemctl.

Use Cases

Xử lý server bị chậm, treo

Dùng top hoặc ps aux --sort=-%cpu tìm process chiếm CPU/RAM bất thường, xem process đó của ai, sau đó kill hoặc restart service tương ứng.

Triển khai web server / ứng dụng

Cài httpd/nginx và enable để tự chạy khi Auto Scaling tạo instance mới; đóng gói ứng dụng Spring Boot/Node.js thành service để tự restart khi crash.

Cập nhật cấu hình không gián đoạn

Sửa file cấu hình Nginx rồi dùng systemctl reload nginx thay vì restart để các kết nối đang phục vụ không bị ngắt.

Thông tin bổ sung

  • File service do hệ thống/package cài nằm ở /usr/lib/systemd/system/; file do bạn tự tạo hoặc ghi đè đặt ở /etc/systemd/system/. Sau khi sửa file service phải chạy sudo systemctl daemon-reload.
  • start chỉ chạy service ngay lúc đó; enable chỉ cài đặt để chạy ở lần boot sau. Muốn cả hai, dùng enable --now.
  • Không nên lạm dụng kill -9 với database hoặc ứng dụng đang ghi dữ liệu — có thể gây hỏng dữ liệu. Ưu tiên systemctl stop hoặc kill (SIGTERM).
  • Công cụ theo dõi thân thiện hơn top: htop, btop. Trên AWS, có thể đẩy metric CPU/RAM và log của service lên CloudWatch bằng CloudWatch Agent.
