6. Thao tác cơ bản với Linux / Lab 7: EBS Volume – Partition, Mount & mở rộng dung lượng

Mục tiêu

  • Kiểm tra disk, partition, mount point bằng lsblk, df -h.
  • Mở rộng dung lượng ổ root (8 GiB → 10 GiB) trên Console và trên OS.
  • Gắn thêm một EBS volume 10 GiB: tạo partition, format file system, mount vào /data và ghi thử file.
  • Cấu hình /etc/fstab để volume tự mount lại khi OS khởi động lại.
  • Tăng dung lượng EBS volume (10 GiB → 15 GiB) trên Console và mở rộng partition, file system trên OS.

Các bước thực hành

  2. Bước 2: Mở rộng ổ root trên Console

    Vào EC2 → Instances → linux-lab-server → tab Storage, click vào Volume ID của root volume, sau đó Modify volume với thông số:

    • Volume type: gp3 (giữ nguyên)
    • Size: 10 GiB

    Đợi trạng thái volume chuyển sang optimizing hoặc completed (vài chục giây) là có thể làm tiếp. Không cần stop instance.

  3. Bước 3: Mở rộng partition và file system của ổ root trên OS

    Disk đã là 10G nhưng partition và file system vẫn là 8G. Cần mở rộng partition số 1 trước, sau đó mở rộng file system XFS:

    sudo growpart /dev/nvme0n1 1
CHANGED: partition=1 start=24576 old: size=16752607 end=16777183 new: size=20946911 end=20971487
lsblk
sudo xfs_growfs -d /
df -h /

    Lưu ý cú pháp growpart <disk> <số partition> có dấu cách giữa disk và số 1. Kết quả df -h / hiển thị khoảng 10G.

  4. Bước 4: Tạo và attach EBS volume mới

    Vào EC2 → Volumes, tạo volume với thông số:

    • Volume type: gp3, Size: 10 GiB
    • Availability Zone: cùng AZ với instance
    • Tag: Name = linux-lab-data

    Khi volume ở trạng thái Available, chọn Actions → Attach volume: Instance = linux-lab-server, Device name = /dev/sdf. Kiểm tra trên OS:

    lsblk
sudo file -s /dev/nvme1n1
/dev/nvme1n1: data

    Disk mới nvme1n1 10G xuất hiện. Kết quả data nghĩa là disk trống, chưa có file system.

  5. Bước 5: Tạo partition bằng fdisk 
    sudo fdisk /dev/nvme1n1

    fdisk là công cụ tương tác. Gõ lần lượt các phím sau, mỗi phím nhấn Enter:

    GõÝ nghĩa
    nTạo partition mới
    pLoại primary
    1Partition số 1
    (Enter)First sector mặc định
    (Enter)Last sector mặc định → dùng toàn bộ dung lượng
    wGhi thay đổi xuống disk và thoát
     
    lsblk /dev/nvme1n1

    Xuất hiện partition nvme1n1p1 dung lượng 10G.

  6. Bước 6: Format file system và mount 
    sudo mkfs -t xfs /dev/nvme1n1p1
sudo mkdir /data
sudo mount /dev/nvme1n1p1 /data
df -h /data

    Sau khi mount, thư mục /data thuộc root. Đổi owner cho ec2-user rồi ghi thử file:

    sudo chown ec2-user:ec2-user /data
echo "Hello EBS volume" > /data/test.txt
cat /data/test.txt
ls -l /data
  7. Bước 7: Cấu hình tự động mount với /etc/fstab

    Lệnh mount chỉ có tác dụng tới lần reboot tiếp theo. Để mount vĩnh viễn, thêm cấu hình vào /etc/fstab. Dùng UUID thay vì tên device vì tên NVMe có thể thay đổi giữa các lần boot:

    sudo blkid /dev/nvme1n1p1
/dev/nvme1n1p1: UUID="2f8fae87-be68-46d4-a4bf-a9948f9d0a91" BLOCK_SIZE="4096" TYPE="xfs" PARTUUID="b4994ce5-01"
sudo cp /etc/fstab /etc/fstab.bak
sudo vim /etc/fstab

    Thêm một dòng vào cuối file (thay <UUID> bằng UUID của bạn, không có dấu ngoặc kép):

    UUID=<UUID>  /data  xfs  defaults,nofail  0  2

    6 cột lần lượt là: device, mount point, loại file system, tuỳ chọn (nofail = nếu không tìm thấy volume thì vẫn boot bình thường), dump, thứ tự kiểm tra lỗi. Kiểm tra cấu hình bằng cách unmount rồi mount lại toàn bộ theo fstab:

    sudo umount /data
df -h | grep /data
sudo systemctl daemon-reload
sudo mount -a
df -h /data
cat /data/test.txt

    Nếu mount -a không báo lỗi và file test.txt vẫn còn, reboot server để kiểm chứng (SSH lại sau 1–2 phút):

    sudo reboot
    df -h /data
cat /data/test.txt
    Sai cú pháp trong /etc/fstab (không có nofail) có thể khiến server không boot được và không SSH vào được. Luôn chạy sudo mount -a để kiểm tra trước khi reboot.
  8. Bước 8: Tăng dung lượng EBS volume trên Console

    Vào EC2 → Volumes, chọn linux-lab-data → Modify volume, đổi Size thành 15 GiB. Đợi trạng thái optimizing/completed.

  9. Bước 9: Mở rộng partition và file system của /data trên OS 
    lsblk /dev/nvme1n1
sudo growpart /dev/nvme1n1 1
sudo xfs_growfs -d /data
df -h /data
cat /data/test.txt

    df -h /data hiển thị khoảng 15G và dữ liệu cũ vẫn còn nguyên. Với file system ext4, dùng sudo resize2fs /dev/nvme1n1p1 thay cho xfs_growfs.

Kiểm tra kết quả

✅ Lab thành công khi

  • df -h / hiển thị ổ root khoảng 10G.
  • Sau khi reboot, df -h /data vẫn hiển thị volume đã mount (tự động qua fstab).
  • df -h /data hiển thị khoảng 15G sau bước 9 và /data/test.txt vẫn còn nội dung Hello EBS volume.

Troubleshoot

Không chọn được instance khi Attach volume
Nguyên nhân: Volume được tạo ở AZ khác với instance.
Giải pháp: Xoá volume và tạo lại ở đúng AZ của instance (EBS là tài nguyên cấp AZ).
NOCHANGE: partition 1 is size ... it cannot be grown
Nguyên nhân: Volume chưa được modify xong trên Console, hoặc partition đã được mở rộng rồi.
Giải pháp: Kiểm tra lsblk xem disk đã có dung lượng mới chưa; đợi volume chuyển sang optimizing rồi chạy lại.
You've reached the maximum modification rate per volume limit. Wait at least 6 hours...
Nguyên nhân: Mỗi EBS volume chỉ được modify một lần trong 6 giờ.
Giải pháp: Đợi sau 6 giờ, hoặc tạo volume mới với dung lượng mong muốn. Vì vậy cần ước lượng dung lượng hợp lý ngay từ đầu.
mount: /data: wrong fs type, bad option, bad superblock on /dev/nvme1n1
Nguyên nhân: Mount nhầm disk (nvme1n1) thay vì partition (nvme1n1p1), hoặc partition chưa được format.
Giải pháp: Kiểm tra lsblk -f; mount đúng /dev/nvme1n1p1 sau khi đã chạy mkfs.
Server không boot / không SSH được sau khi sửa fstab
Nguyên nhân: Dòng cấu hình fstab sai và không có nofail.
Giải pháp: Dùng EC2 Serial Console để sửa, hoặc stop instance, detach root volume, attach vào một instance khác để sửa file /etc/fstab rồi gắn lại.

Dọn dẹp resource

EBS volume tính phí theo dung lượng đã cấp phát (gp3 ở Singapore khoảng 0.096 USD/GB-tháng), kể cả khi không gắn vào instance nào. Hãy xoá volume linux-lab-data sau khi thực hành.
  1. Bước 1: Unmount và khôi phục fstab 
    sudo umount /data
sudo cp /etc/fstab.bak /etc/fstab
sudo systemctl daemon-reload
lsblk
  2. Bước 2: Detach và xoá volume trên Console

    Vào EC2 → Volumes, chọn linux-lab-data → Detach volume. Khi trạng thái là Available → Delete volume. Root volume (10 GiB) được giữ lại cùng instance và sẽ tự xoá khi terminate instance.
