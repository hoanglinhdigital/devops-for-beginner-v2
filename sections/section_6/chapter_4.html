6. Thao tác cơ bản với Linux / User, Group & phân quyền trong Linux

Giới thiệu

Linux là hệ điều hành đa người dùng: nhiều người và nhiều phần mềm cùng sử dụng một server. User và Group là hai khái niệm dùng để xác định “ai” đang thao tác, còn Permission (quyền) trên từng file/folder quyết định “ai được làm gì”. Hiểu rõ cơ chế này giúp bạn cấp quyền vừa đủ cho từng thành viên dự án và tránh lỗi Permission denied khi triển khai ứng dụng.

Các khái niệm chính

  • User: tài khoản đăng nhập hoặc chạy chương trình. Mỗi user có một định danh duy nhất là UID (User ID). Thông tin user lưu ở /etc/passwd, mật khẩu (đã mã hoá) lưu ở /etc/shadow.
  • Group: tập hợp nhiều user để cấp quyền chung. Mỗi group có định danh GID, lưu ở /etc/group.
  • Primary group & Secondary group: mỗi user thuộc đúng một primary group (mặc định trùng tên user, là group sở hữu file user tạo ra) và có thể thuộc nhiều secondary group khác.
  • root (superuser): user đặc biệt có UID = 0, có toàn quyền trên hệ thống, không bị giới hạn bởi permission. Không thể đổi tên hay xoá root.
  • sudo: cho phép user thường chạy một lệnh với quyền root (hoặc user khác). Danh sách ai được sudo cấu hình ở /etc/sudoers và thư mục /etc/sudoers.d/.
  • System user: user do phần mềm tạo ra để chạy service (ví dụ apache, sshd, chrony), thường có UID < 1000 và không đăng nhập được.

User thuộc một hoặc nhiều group. Mỗi file có 1 owner (user) và 1 group sở hữu; quyền được chia cho 3 đối tượng: owner, group và other.

Biểu diễn quyền dạng số (octal)

Mỗi quyền tương ứng một giá trị: r = 4, w = 2, x = 1. Cộng lại sẽ ra một chữ số cho mỗi đối tượng owner / group / other:

SốKý hiệuReadWriteExecuteGiải thích (bit rwx)
0---NoNoNo000 → 0
4r--YesNoNo100 → 4
5r-xYesNoYes101 → 4 + 1
6rw-YesYesNo110 → 4 + 2
7rwxYesYesYes111 → 4 + 2 + 1

Ví dụ: muốn file run.sh có quyền rwx r-x --- (owner toàn quyền, group đọc + chạy, other không có quyền) → chmod 750 run.sh. Một số giá trị hay gặp: 644 (file thường), 755 (script, thư mục), 600 (file bí mật như private key), 700 (thư mục .ssh).

Linux chỉ áp dụng một bộ quyền theo thứ tự owner → group → other. Ngoài ra, để mở được file, user cần quyền x trên tất cả thư mục cha trong đường dẫn.

Các lệnh quản lý thường dùng

User & Group

  • useradd / userdel -r: tạo / xoá user (kèm home)
  • passwd: đặt, đổi mật khẩu
  • usermod -aG <group> <user>: thêm user vào group
  • groupadd / groupmod / groupdel: tạo / sửa / xoá group
  • id, groups, whoami: xem thông tin user
  • su - <user>, sudo <lệnh>, visudo: chuyển user, chạy lệnh quyền root, sửa sudoers

File & Folder

  • ls -l, ls -ld: xem quyền file / folder
  • chmod 750 file: đổi quyền dạng số
  • chmod u+x,g-w,o= file: đổi quyền dạng ký hiệu
  • chown user[:group] file: đổi owner (và group)
  • chown -R user:group folder: đổi owner cho cả thư mục con
  • chgrp group file: chỉ đổi group sở hữu

Use Cases

Cấp quyền cho thành viên dự án

Tạo user riêng cho từng developer, thêm vào group developer_group; chỉ group ops mới có quyền sudo để restart service hoặc cài phần mềm.

Chạy ứng dụng bằng user riêng

Ứng dụng Node.js/Java chạy bằng user appuser không có quyền sudo. Nếu ứng dụng bị khai thác, kẻ tấn công cũng không chiếm được toàn bộ server.

Bảo vệ file bí mật

File chứa cấu hình kết nối database đặt quyền 640, owner là root, group là group của ứng dụng — chỉ ứng dụng đọc được, user khác không xem được.

Thông tin bổ sung

  • Trên Amazon Linux, ec2-user thuộc group wheel và được sudo không cần mật khẩu (cấu hình bởi cloud-init tại /etc/sudoers.d/90-cloud-init-users).
  • Luôn sửa sudoers bằng visudo (có kiểm tra cú pháp). Sửa trực tiếp file sai cú pháp có thể khiến không ai dùng được sudo nữa.
  • Thay đổi group của user chỉ có hiệu lực ở phiên đăng nhập mới — cần logout/login lại.
  • Khi tạo file mới, quyền mặc định được quyết định bởi umask (thường là 0022 → file 644, folder 755).
  • Quyền nâng cao (tự tìm hiểu thêm): SUID, SGID, Sticky bit (ví dụ thư mục /tmp có quyền drwxrwxrwt), ACL (setfacl/getfacl).
