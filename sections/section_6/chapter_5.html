6. Thao tác cơ bản với Linux / Lab 3: Quản lý User, Group & quyền sudo

Mục tiêu

  • Thay đổi cấu hình SSH server để cho phép đăng nhập bằng username/password (chỉ phục vụ học tập).
  • Tạo user developer1, đặt mật khẩu và đăng nhập bằng user mới.
  • Tạo group developer_group, thêm user vào group và cấp quyền sudo cho cả group.
  • Thực hành các lệnh useradd, passwd, usermod, groupadd, groupmod, visudo.
  • Tắt lại đăng nhập bằng mật khẩu sau khi thực hành để đảm bảo bảo mật.

Các bước thực hành

  1. Bước 1: Cho phép đăng nhập SSH bằng password

    Mặc định EC2 chỉ cho đăng nhập bằng key. Kiểm tra cấu hình hiện tại (có thể nằm ở file chính hoặc các file trong thư mục sshd_config.d):

    sudo grep -ri "PasswordAuthentication" /etc/ssh/sshd_config /etc/ssh/sshd_config.d/

    File /etc/ssh/sshd_config có dòng Include /etc/ssh/sshd_config.d/*.conf ở đầu, và với SSH giá trị được đọc trước sẽ được ưu tiên. Vì vậy ta tạo một file có tên bắt đầu bằng số nhỏ để ghi đè:

    sudo vim /etc/ssh/sshd_config.d/01-password-auth.conf

    Nhấn i, nhập 1 dòng sau, sau đó Esc → :wq:

    PasswordAuthentication yes

    Kiểm tra cú pháp (không in gì = OK), xem giá trị đang có hiệu lực rồi restart SSH service:

    sudo sshd -t
sudo sshd -T | grep -i passwordauthentication
passwordauthentication yes
sudo systemctl restart sshd
  2. Bước 2: Tạo user developer1 và đặt mật khẩu 
    sudo useradd developer1
sudo passwd developer1

    Nhập mật khẩu 2 lần (khi gõ sẽ không hiển thị ký tự nào, đây là hành vi bình thường). Kiểm tra thông tin user vừa tạo:

    id developer1
uid=1001(developer1) gid=1001(developer1) groups=1001(developer1)
grep developer1 /etc/passwd
ls -ld /home/developer1

    useradd tự tạo primary group cùng tên developer1 và thư mục home /home/developer1.

  3. Bước 3: Đăng nhập bằng developer1

    Thoát khỏi server, sau đó từ PC Local SSH bằng user mới (không cần -i key), nhập mật khẩu vừa đặt:

    exit
    ssh developer1@<PUBLIC_IP>
    whoami
developer1
pwd
/home/developer1
sudo whoami
[sudo] password for developer1:
developer1 is not in the sudoers file.

    User mới chưa có quyền sudo. Thoát ra để cấp quyền bằng ec2-user:

    exit
  4. Bước 4: Tạo group và thêm user vào group 
    ssh -i linux-lab-key.pem ec2-user@<PUBLIC_IP>
    sudo groupadd developer_group
sudo usermod -a -G developer_group developer1
id developer1
uid=1001(developer1) gid=1001(developer1) groups=1001(developer1),1002(developer_group)
grep developer_group /etc/group

    -G chỉ định secondary group, -a (append) để thêm vào danh sách group hiện có. Nếu quên -a, user sẽ bị gỡ khỏi tất cả secondary group khác.

  5. Bước 5: Cấp quyền sudo cho group

    Dùng visudo tạo file cấu hình riêng trong /etc/sudoers.d/ (cách làm khuyến nghị, dễ quản lý hơn sửa trực tiếp /etc/sudoers). visudo mở trình soạn thảo Vim:

    sudo visudo -f /etc/sudoers.d/developer_group

    Nhấn i, nhập dòng sau, Esc → :wq:

    %developer_group ALL=(ALL) ALL

    Ý nghĩa: % = group; group developer_group được chạy trên mọi host (ALL), với quyền của mọi user (ALL), mọi lệnh (ALL), cần nhập mật khẩu của chính mình. Kiểm tra cú pháp toàn bộ sudoers:

    sudo visudo -c

    💡 Cách của slide cũ: chạy sudo visudo và thêm dòng trên ngay dưới dòng %wheel ALL=(ALL) ALL — kết quả tương tự.

  6. Bước 6: Đăng nhập lại bằng developer1 và thử sudo 
    exit
    ssh developer1@<PUBLIC_IP>
    sudo whoami
[sudo] password for developer1:
root
sudo su -

    Sau lệnh sudo su -, dấu nhắc chuyển thành [root@ip-172-31-xx-xx ~]# (ký tự #) – bạn đang là root. Thoát dần ra:

    whoami
exit
    exit
  7. Bước 7: Một số lệnh quản lý user/group khác

    Đăng nhập lại bằng ec2-user, thử sửa thông tin user và đổi tên group:

    sudo usermod -c "Developer 1 - Team A" developer1
getent passwd developer1
sudo groupmod -n dev_team developer_group
getent group dev_team
sudo groupmod -n developer_group dev_team
groups developer1
    LệnhÝ nghĩa
    usermod -c "..."Sửa mô tả (comment) của user
    usermod -s /sbin/nologin userKhoá đăng nhập shell của user (thường dùng cho user chạy service)
    usermod -L / -UKhoá / mở khoá mật khẩu của user
    groupmod -n <tên_mới> <tên_cũ>Đổi tên group (GID giữ nguyên nên quyền trên file không đổi)
    gpasswd -d <user> <group>Gỡ user khỏi một group
  8. Bước 8: Tắt lại đăng nhập bằng password

    Server mở cổng SSH ra Internet mà cho phép đăng nhập bằng mật khẩu rất dễ bị brute-force. Sau khi thực hành xong, hãy tắt lại:

    sudo rm /etc/ssh/sshd_config.d/01-password-auth.conf
sudo systemctl restart sshd
sudo sshd -T | grep -i passwordauthentication
passwordauthentication no

    User developer1 và group developer_group được giữ lại cho Lab 4. Ở Lab 9 bạn sẽ học cách cho thành viên dự án đăng nhập bằng SSH key – cách làm đúng trong thực tế.

Troubleshoot

developer1@...: Permission denied (publickey,gssapi-keyex,gssapi-with-mic) khi đăng nhập bằng password
Nguyên nhân: PasswordAuthentication vẫn là no (một file khác trong sshd_config.d được đọc trước) hoặc chưa restart sshd.
Giải pháp: Chạy sudo sshd -T | grep -i passwordauthentication; đảm bảo tên file bắt đầu bằng 01- và đã sudo systemctl restart sshd.
Đã thêm vào group nhưng vẫn báo developer1 is not in the sudoers file
Nguyên nhân: Thay đổi group chỉ có hiệu lực ở phiên đăng nhập mới; hoặc file sudoers gõ sai tên group (thiếu dấu %).
Giải pháp: Logout và login lại; kiểm tra nội dung sudo cat /etc/sudoers.d/developer_group.
>>> /etc/sudoers.d/developer_group: syntax error near line 1 <<<
Nguyên nhân: Gõ sai cú pháp trong file sudoers.
Giải pháp: visudo sẽ hỏi What now? — gõ e để sửa lại. Đây là lý do luôn dùng visudo thay vì sửa file trực tiếp.
useradd: user 'developer1' already exists
Nguyên nhân: User đã được tạo từ lần thực hành trước.
Giải pháp: Bỏ qua bước tạo user, hoặc xoá bằng sudo userdel -r developer1 rồi tạo lại.
