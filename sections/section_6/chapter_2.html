6. Thao tác cơ bản với Linux / Lab 1: Tạo EC2 Linux, kết nối SSH & các lệnh cơ bản

Mục tiêu

  • Tạo một EC2 instance chạy Amazon Linux 2023 dùng chung cho toàn bộ lab trong section.
  • Kết nối tới server bằng SSH với private key.
  • Làm quen với cấu trúc thư mục của Linux và các lệnh cơ bản: hostname, whoami, pwd, cd, ls, cat, mkdir, cp, mv, rm...

Yêu cầu trước khi bắt đầu

  • Tài khoản AWS đã setup ở Section 2, đăng nhập bằng IAM user có quyền quản lý EC2.
  • Region ap-southeast-1 (Singapore) có Default VPC.
  • Windows: đã cài Git Bash (đi kèm Git for Windows). Mac/Linux: dùng Terminal có sẵn. Kiểm tra lệnh ssh đã có:
ssh -V
OpenSSH_9.x ...

Các bước thực hành

  1. Bước 1: Tạo Key pair

    Vào EC2 → Key Pairs, tạo key pair với các thông số:

    • Name: linux-lab-key
    • Key pair type: ED25519 (hoặc RSA)
    • Private key file format: .pem (dùng cho OpenSSH / Git Bash)

    Trình duyệt sẽ tự tải file linux-lab-key.pem về. AWS chỉ cho tải một lần duy nhất, hãy lưu file cẩn thận (ví dụ thư mục ~/Downloads).

    Private key giống như chìa khoá nhà: không gửi qua chat, không commit lên Git.
  2. Bước 2: Tạo Security Group

    Vào EC2 → Security Groups, tạo Security Group trong Default VPC:

    • Name: linux-lab-sg, Description: SSH and HTTP for Linux lab
    • Inbound rule 1: SSH (TCP 22), Source: My IP
    • Inbound rule 2: HTTP (TCP 80), Source: 0.0.0.0/0 (dùng cho Lab 6 – web server)
    • Outbound: giữ mặc định (All traffic)

    💡 Chỉ mở SSH cho IP của bạn để tránh bị dò mật khẩu/brute-force từ Internet. Nếu IP nhà mạng thay đổi, cập nhật lại rule này.

  3. Bước 3: Tạo EC2 instance

    Vào EC2 → Instances, launch instance với các thông số:

    • Name: linux-lab-server
    • AMI: Amazon Linux 2023 AMI (64-bit x86)
    • Instance type: t3.micro (Free Tier eligible)
    • Key pair: linux-lab-key
    • Network: Default VPC, subnet bất kỳ, Auto-assign public IP: Enable
    • Security Group: chọn existing linux-lab-sg
    • Storage: 8 GiB gp3 (mặc định, sẽ mở rộng ở Lab 7)

    Đợi instance chuyển sang Running và Status check: 3/3 checks passed. Copy Public IPv4 address của instance.

  4. Bước 4: SSH vào server

    Mở Git Bash/Terminal trên PC Local, di chuyển tới thư mục chứa private key và giới hạn quyền file key:

    cd ~/Downloads
chmod 400 linux-lab-key.pem

    SSH vào server (thay <PUBLIC_IP> bằng IP vừa copy). Lần đầu kết nối, gõ yes để xác nhận fingerprint của server:

    ssh -i linux-lab-key.pem ec2-user@<PUBLIC_IP>

    Kết nối thành công, dấu nhắc lệnh chuyển thành dạng [ec2-user@ip-172-31-xx-xx ~]$: user ec2-user, hostname ip-172-31-xx-xx, thư mục hiện tại ~ (home), ký tự $ = user thường (# = root).

    💡 Cách khác không cần key: chọn instance → Connect → EC2 Instance Connect để mở terminal ngay trên trình duyệt.

  5. Bước 5: Xem thông tin hệ thống 
    hostname
whoami
id
date
uptime

    LệnhÝ nghĩa
    hostnameTên máy chủ
    whoami / idUser đang đăng nhập / UID, GID và các group của user
    date / uptimeNgày giờ hệ thống (mặc định UTC) / thời gian server đã chạy và tải trung bình

  6. Bước 6: Tìm hiểu cấu trúc thư mục của Linux

    Linux không có ổ C:, D: như Windows. Mọi thứ nằm trong một cây thư mục bắt đầu từ gốc / (root directory):

    ls /
    Thư mụcChứa gì
    /etcFile cấu hình hệ thống và ứng dụng (/etc/ssh/sshd_config, /etc/passwd...)
    /homeThư mục cá nhân của từng user, ví dụ /home/ec2-user (viết tắt là ~)
    /rootThư mục cá nhân của user root
    /varDữ liệu thay đổi liên tục: log (/var/log), web (/var/www)
    /usr/bin, /usr/local/binCác chương trình/lệnh (ls, cp, python3...)
    /optPhần mềm cài thêm từ bên thứ ba
    /tmpFile tạm, có thể bị xoá khi khởi động lại
    /dev, /procThiết bị (ổ đĩa /dev/nvme0n1...) và thông tin process/kernel
  7. Bước 7: Di chuyển giữa các thư mục 
    pwd
cd /etc
pwd
cd ~
cd ..
pwd
cd -
    • pwd (print working directory): in ra thư mục hiện tại.
    • cd /etc: đường dẫn tuyệt đối (bắt đầu bằng /). cd linux-lab: đường dẫn tương đối so với thư mục hiện tại.
    • ~ = home của user, .. = thư mục cha, . = thư mục hiện tại, cd - = quay lại thư mục trước đó.

    💡 Nhấn phím Tab để tự động hoàn thành tên lệnh/đường dẫn, nhấn ↑ / ↓ để gọi lại lệnh đã gõ.

  8. Bước 8: Liệt kê file và xem danh sách user 
    ls
ls -l
ls -la
ls -lh /var/log

    -l: hiển thị chi tiết (quyền, owner, size, ngày sửa); -a: hiện cả file ẩn (tên bắt đầu bằng dấu . như .bashrc, .ssh); -h: size dễ đọc (K, M, G).

    Xem danh sách user trên hệ thống, sắp xếp theo tên. Ký tự | (pipe) chuyển output của lệnh trước làm input cho lệnh sau:

    cat /etc/passwd | sort

    Mỗi dòng có dạng ec2-user:x:1000:1000:EC2 Default User:/home/ec2-user:/bin/bash = tên : x : UID : GID : mô tả : home : shell. Phần lớn user là system user do các phần mềm tạo ra.

  9. Bước 9: Tạo, copy, đổi tên, xoá file/folder 
    cd ~
mkdir linux-lab
cd linux-lab
touch hello.txt
echo "Hello Linux from EC2" > hello.txt
echo "Dòng thứ 2" >> hello.txt
cat hello.txt
cp hello.txt hello-copy.txt
mv hello-copy.txt hello-backup.txt
mkdir -p demo/sub1/sub2
ls -R demo
rm hello-backup.txt
rm -r demo
ls -l
    LệnhÝ nghĩa
    mkdir / mkdir -pTạo thư mục / tạo cả thư mục cha nếu chưa có
    touchTạo file rỗng (hoặc cập nhật thời gian sửa đổi)
    echo "..." > file / >> fileGhi đè nội dung vào file / ghi thêm vào cuối file
    catIn nội dung file ra màn hình
    cp / mvCopy / di chuyển hoặc đổi tên file
    rm / rm -rXoá file / xoá thư mục và toàn bộ nội dung bên trong
    Linux không có thùng rác khi dùng rm. Đặc biệt cẩn thận với rm -rf và sudo: xoá nhầm thư mục hệ thống có thể làm hỏng server.
  10. Bước 10: Tra cứu cách dùng lệnh & thoát 
    ls --help
man ls
history
clear
exit

    man mở trang hướng dẫn (manual) của lệnh, nhấn q để thoát. exit đóng phiên SSH và quay về PC Local.

Troubleshoot

WARNING: UNPROTECTED PRIVATE KEY FILE! / Permissions 0644 ... are too open
Nguyên nhân: File private key cho phép user khác đọc, SSH từ chối sử dụng.
Giải pháp: Chạy chmod 400 linux-lab-key.pem. Trên Windows, nếu file nằm trên ổ NTFS mà vẫn lỗi, copy key vào ~/.ssh/ trong Git Bash rồi chmod lại.
ssh: connect to host ... port 22: Connection timed out
Nguyên nhân: Security Group không cho phép IP hiện tại của bạn ở cổng 22, instance không có Public IP, hoặc mạng công ty chặn cổng 22.
Giải pháp: Sửa inbound rule SSH → Source My IP; kiểm tra instance có Public IPv4; thử mạng khác (4G) hoặc dùng EC2 Instance Connect.
Permission denied (publickey,gssapi-keyex,gssapi-with-mic)
Nguyên nhân: Sai username (ví dụ dùng ubuntu hoặc root với Amazon Linux) hoặc sai file key.
Giải pháp: Dùng đúng ec2-user@<PUBLIC_IP> và đúng file linux-lab-key.pem đã chọn khi tạo instance.
Public IP thay đổi sau khi Stop/Start instance
Nguyên nhân: Public IP tự động cấp sẽ được thu hồi khi Stop instance.
Giải pháp: Lấy lại Public IP mới trên Console mỗi lần Start. Không cần Elastic IP cho bài lab (Elastic IP và Public IPv4 đều tính phí theo giờ).

Dọn dẹp resource

Giữ lại instance linux-lab-server, Security Group và Key pair để dùng cho các lab tiếp theo. Nếu nghỉ giữa chừng, hãy Stop instance để không tính phí compute (vẫn tính phí lưu trữ EBS, khoảng 0.8 USD/tháng cho 8 GiB gp3 ở Singapore). Toàn bộ resource sẽ được xoá ở chương cuối section.
