13. Serverless Application Model (SAM) / Cấu trúc template SAM & các lệnh SAM CLI

Giới thiệu

Mọi ứng dụng SAM xoay quanh một file template.yaml mô tả resource, cùng thư mục chứa source code của các function. Hiểu rõ các phần của template và nắm các lệnh SAM CLI cơ bản là đủ để làm việc với hầu hết dự án serverless. Bài này giải thích cấu trúc template, samconfig.toml và vai trò của từng lệnh trước khi bạn thực hành ở các lab sau.

Đặc điểm chính

  • Transform: dòng Transform: AWS::Serverless-2016-10-31 bắt buộc – báo cho CloudFormation biết đây là template SAM cần được mở rộng.
  • Globals: cấu hình mặc định dùng chung cho mọi function / API (runtime, timeout, memory, biến môi trường...), tránh lặp lại.
  • Resources: phần chính, khai báo function, API, bảng DynamoDB... Mỗi function có CodeUri, Handler, Events, Policies.
  • Events: nguồn kích hoạt function – Api, HttpApi, S3, SQS, SNS, Schedule, DynamoDB... SAM tự tạo permission và kết nối.
  • Parameters / Outputs: tham số đầu vào theo môi trường và giá trị xuất ra (URL của API, tên table...) sau khi deploy.
  • samconfig.toml: lưu các lựa chọn của sam deploy --guided (stack name, region, capabilities...) để lần sau chỉ cần sam deploy.

Mô hình kiến trúc

Cấu trúc thư mục dự án

url-shorten-app/
├── template.yaml            # Định nghĩa resource (IaC)
├── samconfig.toml           # Cấu hình deploy (sinh ra bởi sam deploy --guided)
├── generate_short_url/      # CodeUri của function 1
│   └── app.py               # Handler: app.lambda_handler
├── get_url/                 # CodeUri của function 2
│   └── app.py
├── events/                  # Event JSON mẫu để test local
└── tests/                   # Unit test / integration test

Các phần của template

AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31      # bắt buộc với SAM

Globals:                                    # mặc định cho mọi function
  Function:
    Runtime: python3.13
    Timeout: 10
    Environment:
      Variables:
        TABLE_NAME: !Ref UrlShortenTable

Resources:
  GetUrlFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: get_url/                     # thư mục chứa code
      Handler: app.lambda_handler           # file app.py, hàm lambda_handler
      Policies:                             # policy template (least privilege)
        - DynamoDBReadPolicy:
            TableName: !Ref UrlShortenTable
      Events:
        GetUrl:
          Type: Api                         # tạo route API Gateway
          Properties:
            Path: /link/{short_url}
            Method: get

Outputs:
  TableName:
    Value: !Ref UrlShortenTable

Chuỗi lệnh quen thuộc: sửa code → sam build → sam deploy. Trong lúc phát triển có thể dùng sam sync để cập nhật nhanh hơn.

Các lệnh SAM CLI thường dùng

LệnhCông dụng
sam initTạo project mới từ template mẫu (chọn runtime, loại ứng dụng)
sam validate --lintKiểm tra cú pháp và best practice của template
sam buildCài dependency, đóng gói code từng function vào .aws-sam/build. Thêm --use-container để build trong container Docker
sam local invokeChạy 1 function ở local với event JSON
sam local start-apiGiả lập API Gateway ở http://127.0.0.1:3000
sam deploy --guidedDeploy lần đầu, hỏi từng thông số và lưu vào samconfig.toml
sam deployDeploy các lần sau theo samconfig.toml
sam list endpoints / stack-outputsLiệt kê endpoint API và Outputs của stack đã deploy
sam logs --tailXem log CloudWatch của function ngay trên terminal
sam sync --watchĐồng bộ thay đổi code lên AWS gần như tức thì (chỉ dùng cho dev)
sam deleteXoá stack và các resource đã tạo

Trade-off

✅ Nên dùng khi

  • Dùng policy templates thay cho dynamodb:* trên Resource: "*" để giữ least privilege.
  • Đặt cấu hình chung vào Globals, khác biệt giữa môi trường vào Parameters.
  • Để CloudFormation tự đặt tên resource (không hard-code TableName) nhằm deploy được nhiều stack cùng account.
  • Truyền tên resource cho Lambda qua biến môi trường thay vì viết cứng trong code.

⚠️ Cần lưu ý

  • sam sync bỏ qua change set → không dùng cho production.
  • sam local gọi AWS thật (DynamoDB, S3...) nếu code dùng boto3; cần credential và có thể phát sinh chi phí/ghi dữ liệu thật.
  • Không commit .aws-sam/ và samconfig.toml chứa thông tin môi trường cá nhân.
  • Đổi logical ID của resource trong template sẽ khiến CloudFormation xoá và tạo lại resource đó.

Use Cases

Nhiều môi trường dev / staging / prod

Một template, nhiều section trong samconfig.toml (--config-env prod) hoặc Parameters khác nhau cho mỗi môi trường.

Chạy trong CI/CD pipeline

Pipeline chạy sam validate → sam build → sam deploy --no-confirm-changeset --no-fail-on-empty-changeset với IAM Role của pipeline.

Debug nhanh tại máy dev

sam local invoke với event mẫu và sam logs --tail giúp tìm lỗi mà không phải mở Console.

Thông tin bổ sung

  • Hàm nội tại thường gặp: !Ref (trả về tên/ID resource), !GetAtt (lấy thuộc tính, ví dụ ARN), !Sub (nội suy chuỗi, ví dụ ${AWS::Region}).
  • Resource ngầm định: nếu Function có event Api mà không khai báo RestApiId, SAM tự tạo API tên ServerlessRestApi với stage Prod (và Stage). Khai báo AWS::Serverless::Api riêng giúp kiểm soát tên stage, CORS, auth.
  • Capabilities: template tạo IAM Role cần CAPABILITY_IAM khi deploy; sam deploy --guided hỏi bạn câu này ("Allow SAM CLI IAM role creation").
  • Bucket deploy: resolve_s3 = true trong samconfig.toml để SAM tự tạo / dùng bucket managed aws-sam-cli-managed-default-* chứa package code.
