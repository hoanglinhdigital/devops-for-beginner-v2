13. Serverless Application Model (SAM) / Serverless và AWS SAM là gì?

Mục tiêu section

Trong Section 4 bạn đã làm quen với Lambda, API Gateway và DynamoDB bằng AWS Console. Khi ứng dụng có nhiều function, nhiều API, nhiều môi trường thì thao tác thủ công không còn phù hợp. Section này hướng dẫn bạn định nghĩa và triển khai toàn bộ ứng dụng serverless bằng code với AWS SAM:

  • Hiểu serverless application là gì và AWS SAM giải quyết vấn đề gì so với CloudFormation thuần.
  • Đọc, viết được template.yaml và sử dụng thành thạo các lệnh sam init / build / deploy / local / logs / sync / delete.
  • Triển khai ứng dụng URL Shortener (API Gateway + Lambda + DynamoDB) chỉ bằng vài lệnh.
  • Triển khai an toàn (canary) cho Lambda với CodeDeploy và tự động rollback bằng CloudWatch Alarm.

Giới thiệu

Serverless là mô hình trong đó bạn chỉ viết code và cấu hình; AWS lo toàn bộ việc cấp phát, mở rộng và vá lỗi server. Một ứng dụng serverless điển hình ghép nhiều dịch vụ managed: API Gateway nhận request, Lambda xử lý, DynamoDB lưu dữ liệu, SQS/SNS/EventBridge kết nối sự kiện. AWS Serverless Application Model (SAM) là một framework mã nguồn mở, là phần mở rộng của CloudFormation, cho phép mô tả cả ứng dụng ấy trong một file YAML ngắn gọn, kèm SAM CLI để build, test ở local và deploy.

Đặc điểm chính

  • Cú pháp rút gọn: vài dòng AWS::Serverless::Function được SAM tự mở rộng thành Lambda + IAM Role + API Gateway + permission, tiết kiệm hàng trăm dòng CloudFormation.
  • Là CloudFormation: template SAM là template CloudFormation có thêm Transform; có thể trộn lẫn resource CloudFormation thông thường (DynamoDB, SNS, S3...).
  • SAM CLI mạnh mẽ: build, đóng gói, upload S3, deploy, xem log, đồng bộ code nhanh chỉ với các lệnh ngắn.
  • Test ở local: chạy Lambda và giả lập API Gateway ngay trên máy bằng container Docker giống môi trường Lambda thật.
  • Policy templates: khai báo quyền tối thiểu bằng tên ngắn gọn như DynamoDBReadPolicy, S3ReadPolicy thay vì tự viết JSON policy.
  • Safe deployment: chỉ cần vài dòng cấu hình để deploy Lambda theo Canary/Linear qua CodeDeploy và tự rollback.

Trade-off

✅ Ưu điểm

  • Template ngắn, dễ đọc hơn nhiều so với CloudFormation thuần cho ứng dụng serverless.
  • Một công cụ cho cả vòng đời: init → build → test local → deploy → log → xoá.
  • Tích hợp sẵn safe deployment (canary/linear) và policy templates theo best practice.
  • Dùng chung hệ sinh thái CloudFormation: change set, rollback, drift detection, StackSets.
  • Miễn phí; chỉ trả tiền cho resource tạo ra.

⚠️ Nhược điểm

  • Chỉ dành cho AWS; không đa cloud như Terraform.
  • Tập trung vào serverless; hạ tầng lớn (VPC, EKS...) vẫn nên dùng Terraform / CloudFormation.
  • Vẫn phải hiểu CloudFormation để debug khi stack lỗi.
  • sam local chỉ giả lập; hành vi có thể khác môi trường thật (IAM, timeout, network).

Use Cases

REST API cho web / mobile

API Gateway + Lambda + DynamoDB: URL shortener, to-do, đặt chỗ... Chi phí gần bằng 0 khi không có người dùng, tự scale khi traffic tăng.

Xử lý sự kiện / bất đồng bộ

Upload ảnh lên S3 → Lambda tạo thumbnail; message từ SQS/SNS/EventBridge kích hoạt Lambda xử lý đơn hàng.

Tác vụ định kỳ & tự động hoá

Lambda chạy theo lịch (EventBridge Schedule) để dọn dẹp resource, tạo báo cáo chi phí, sao lưu dữ liệu.

Thông tin bổ sung

  • Chi phí: Lambda tính theo số request và thời gian chạy (có free tier hằng tháng); API Gateway tính theo số request; DynamoDB on-demand tính theo số đọc/ghi. SAM CLI không tốn phí, nhưng sam deploy tạo bucket S3 và stack CloudFormation (chi phí không đáng kể).
  • Runtime: khoá học dùng Python 3.13. Luôn chọn runtime còn được AWS hỗ trợ; runtime đã deprecated sẽ không thể tạo/cập nhật function.
  • Giới hạn Lambda cần nhớ: timeout tối đa 15 phút, bộ nhớ 128 MB – 10 GB, package zip tối đa 50 MB (250 MB sau khi giải nén). Quá giới hạn thì dùng container image.
  • Cold start: lần gọi đầu sau thời gian không dùng cần khởi tạo môi trường; khai báo client (boto3...) bên ngoài handler để tái sử dụng khi warm start.
  • Quan hệ với DevOps: template SAM chính là Infrastructure as Code cho serverless; kết hợp với CI/CD (Section 9, 10) bằng các bước sam build và sam deploy trong pipeline.
