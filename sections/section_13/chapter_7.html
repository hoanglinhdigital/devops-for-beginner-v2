13. Serverless Application Model (SAM) / Lab 4: Canary deployment cho Lambda với SAM & CodeDeploy

Mục tiêu

  • Bật AutoPublishAlias và DeploymentPreference cho GetUrlFunction của ứng dụng URL Shortener.
  • Release v2 theo Canary 10% trong 5 phút và quan sát tỷ lệ traffic giữa v1 / v2.
  • Release v3 cố tình lỗi và xem CloudWatch Alarm kích hoạt CodeDeploy tự động rollback về v2.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 2: stack url-shorten-app đã deploy; có ApiUrl và ít nhất một short_url_code (tạo lại bằng POST nếu cần). Lab 3 không bắt buộc, nhưng hãy đảm bảo sam sync --watch đã tắt.
  • Terminal dạng bash (Git Bash, WSL, macOS / Linux) để chạy vòng lặp curl. Trên Windows PowerShell thay curl bằng curl.exe và viết lại vòng lặp tương ứng.
  • Source code: sourcecode/section_12_serverless_application_model/lab4_canary_deployment/ (template.yaml, get_url_v2.py, get_url_v3_broken.py).
Lưu ý: Mỗi lần sam deploy có DeploymentPreference sẽ chờ CodeDeploy hoàn tất (khoảng 6–8 phút với Canary 5 phút). Chuẩn bị 30–40 phút cho cả lab. Phiên bản lỗi v3 chỉ ảnh hưởng ~10% request trong vài phút.

Các bước thực hành

  1. Bước 1: Chuẩn bị dữ liệu thử nghiệm

    Lấy ApiUrl và tạo một short URL để dùng xuyên suốt lab:

    sam list stack-outputs --stack-name url-shorten-app
curl -X POST "<ApiUrl>/generate-short-url" -H "Content-Type: application/json" -d '{"url": "https://aws.amazon.com/serverless/sam/"}'

    Ghi lại short_url_code trả về.

  2. Bước 2: Thay template bằng template có Canary

    Copy lab4_canary_deployment/template.yaml đè lên lab2_url_shorten_app/template.yaml:

    cd sourcecode/section_12_serverless_application_model
cp lab4_canary_deployment/template.yaml lab2_url_shorten_app/template.yaml
cd lab2_url_shorten_app

    Những điểm khác so với template Lab 2 – chỉ nằm ở GetUrlFunction và một alarm mới:

      GetUrlFunction:
    Type: AWS::Serverless::Function
    Properties:
      # ... như Lab 2 ...
      AutoPublishAlias: live
      DeploymentPreference:
        Type: Canary10Percent5Minutes
        Alarms:
          - !Ref GetUrlCanaryErrorsAlarm

  GetUrlCanaryErrorsAlarm:
    Type: AWS::CloudWatch::Alarm
    Properties:
      Namespace: AWS/Lambda
      MetricName: Errors
      Statistic: Sum
      Period: 60
      EvaluationPeriods: 1
      Threshold: 0
      ComparisonOperator: GreaterThanThreshold
      TreatMissingData: notBreaching
      Dimensions:
        - Name: Resource
          Value: !Sub "${GetUrlFunction}:live"
        - Name: FunctionName
          Value: !Ref GetUrlFunction
        - Name: ExecutedVersion
          Value: !GetAtt GetUrlFunction.Version.Version   # chỉ đo version mới nhất

    Alarm sẽ ở trạng thái ALARM nếu version đang được canary có ít nhất 1 lỗi trong 1 phút.

  3. Bước 3: Deploy baseline (v1)

    Code get_url/app.py hiện tại trả header X-App-Version: v1. Deploy để tạo alias live, CodeDeploy application / deployment group và alarm:

    sam build
sam deploy

    Xem change set: Add cho Alias, Version, CodeDeploy Application, DeploymentGroup, IAM Role, Alarm; Modify cho API Gateway và permission (giờ gọi qua alias). Nhập y. Lần này chưa có canary vì chưa có version cũ.

    Trên Console kiểm tra:

    • Lambda → GetUrlFunction → tab Aliases: alias live trỏ version 1.
    • CodeDeploy → Applications: có application tên dạng ServerlessDeploymentApplication-xxxx với deployment group GetUrlFunctionDeploymentGroup-xxxx.

    Kiểm tra response header (kết quả x-app-version: v1):

    curl -s -o /dev/null -D - "<ApiUrl>/link/<short_url_code>" | grep -i x-app-version
x-app-version: v1
  4. Bước 4: Release v2 theo Canary 10% / 5 phút

    Thay code của GetUrlFunction bằng v2 (chỉ đổi header thành X-App-Version: v2) rồi deploy:

    cp ../lab4_canary_deployment/get_url_v2.py get_url/app.py
sam build
sam deploy

    Nhập y ở change set. Lệnh sẽ đứng chờ ở trạng thái UPDATE_IN_PROGRESS trong khi CodeDeploy chuyển traffic – giữ nguyên terminal này.

  5. Bước 5: Quan sát traffic được chia

    Mở terminal thứ hai, gửi 30 request và đếm số lần mỗi version phản hồi (kỳ vọng khoảng 90% v1 và 10% v2, số liệu thực tế dao động):

    for i in $(seq 1 30); do curl -s -o /dev/null -D - "<ApiUrl>/link/<short_url_code>" | grep -i x-app-version; done | sort | uniq -c
     27 x-app-version: v1
      3 x-app-version: v2

    Đồng thời quan sát trên Console:

    • CodeDeploy → Deployments → deployment mới nhất: trạng thái In progress, thanh tiến trình Traffic shifting (10% rồi 100%).
    • Lambda → GetUrlFunction → Aliases → live: hiển thị 2 version với trọng số (version 1 = 90%, version 2 = 10%).

    Sau 5 phút CodeDeploy chuyển 100% sang v2 và sam deploy kết thúc. Chạy lại vòng lặp: toàn bộ response là v2.

  6. Bước 6: Release v3 bị lỗi và quan sát rollback tự động

    Thay code bằng v3 (mọi request đều ném exception) và deploy:

    cp ../lab4_canary_deployment/get_url_v3_broken.py get_url/app.py
sam build
sam deploy

    Nhập y. Ngay khi deployment bắt đầu (CodeDeploy status In progress), mở terminal thứ hai và tạo traffic liên tục để version mới có dữ liệu lỗi (khoảng 3–4 phút):

    for i in $(seq 1 200); do curl -s -o /dev/null -w "%{http_code}\n" "<ApiUrl>/link/<short_url_code>"; sleep 1; done | sort | uniq -c

    Sẽ thấy phần lớn request vẫn trả 308 (v2) và vài request trả 502 (v3 lỗi). Theo dõi trên Console:

    • CloudWatch → Alarms → GetUrlCanaryErrorsAlarm: chuyển sang In alarm.
    • CodeDeploy → Deployments: deployment Stopped / Rolled back, kèm lý do alarm.
    • CloudFormation → stack: update thất bại và stack quay về UPDATE_ROLLBACK_COMPLETE; terminal sam deploy báo lỗi.
  7. Bước 7: Xác nhận hệ thống vẫn chạy v2

    Chạy lại vòng lặp đếm header:

    for i in $(seq 1 10); do curl -s -o /dev/null -D - "<ApiUrl>/link/<short_url_code>" | grep -i x-app-version; done | sort | uniq -c
     10 x-app-version: v2

    Người dùng chỉ bị ảnh hưởng bởi một phần nhỏ request trong vài phút; hệ thống tự quay về v2 mà không cần ai can thiệp. Khôi phục code v2 trong thư mục project để không deploy nhầm v3 lần sau:

    cp ../lab4_canary_deployment/get_url_v2.py get_url/app.py

Kiểm tra kết quả

✅ Lab thành công khi

  • Alias live của GetUrlFunction có thể trỏ tới nhiều version; sau v2 trỏ vào version 2.
  • Trong lúc canary v2, tỷ lệ response ~90% v1 / ~10% v2; sau 5 phút 100% v2.
  • Với v3 lỗi: alarm vào trạng thái In alarm, CodeDeploy rollback, stack về UPDATE_ROLLBACK_COMPLETE, API tiếp tục trả v2.

Troubleshoot

Deploy v3 xong nhưng không rollback, 100% traffic chuyển sang v3 (API trả toàn 502)
Nguyên nhân: Không có (đủ) traffic trong lúc canary nên alarm không có dữ liệu để kích hoạt (TreatMissingData: notBreaching).
Giải pháp: Luôn chạy vòng lặp curl ngay khi deployment bắt đầu. Để khôi phục, copy lại get_url_v2.py vào get_url/app.py rồi sam build và sam deploy (đây cũng là cách rollback thủ công).
Stack bị kẹt ở UPDATE_FAILED sau khi rollback, sam deploy không chạy lại được
Nguyên nhân: Bật Disable rollback = y trong samconfig.toml nên CloudFormation giữ nguyên trạng thái lỗi.
Giải pháp: Sửa disable_rollback = false trong samconfig.toml (hoặc chạy sam deploy --guided lại và chọn n), sau đó deploy lại. Trên CloudFormation Console có thể chọn Stack actions → Continue update rollback.
Template format error: ... Version.Version hoặc "Invalid value for AutoPublishAlias"
Nguyên nhân: Thiếu AutoPublishAlias trên function, hoặc gõ sai !GetAtt GetUrlFunction.Version.Version.
Giải pháp: Dùng đúng template của lab và chạy sam validate --lint.
Response vẫn là v1 sau khi deploy v2 xong
Nguyên nhân: Quên sam build sau khi copy code (SAM deploy bản build cũ trong .aws-sam/build).
Giải pháp: Chạy sam build rồi sam deploy lại.
