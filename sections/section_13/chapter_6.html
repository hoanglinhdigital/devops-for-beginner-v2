13. Serverless Application Model (SAM) / Lambda version, alias & Safe deployment với CodeDeploy

Giới thiệu

Mặc định mỗi lần deploy, Lambda code mới thay thế code cũ và nhận 100% traffic ngay lập tức – nếu có bug, mọi người dùng đều bị ảnh hưởng. Ở Section 11 bạn đã học Canary / Linear trên ECS. Với Lambda, SAM tích hợp sẵn AWS CodeDeploy để làm điều tương tự (gradual deployment / safe deployment): chuyển traffic dần dần từ version cũ sang version mới thông qua alias, theo dõi bằng CloudWatch Alarm và tự động rollback khi có lỗi.

Đặc điểm chính

  • Version: bản chụp bất biến (immutable) của code + cấu hình function, đánh số 1, 2, 3... $LATEST là bản đang chỉnh sửa, không cố định.
  • Alias: con trỏ có tên (ví dụ live) trỏ tới một version; có thể chia traffic theo trọng số cho hai version cùng lúc (weighted alias).
  • AutoPublishAlias: SAM tự publish version mới mỗi khi code đổi và cập nhật alias; các event (API Gateway...) gọi function qua alias.
  • DeploymentPreference: chọn kiểu chuyển traffic (Canary, Linear, AllAtOnce); SAM tự tạo CodeDeploy Application, Deployment Group và IAM Role.
  • Alarms: danh sách CloudWatch Alarm được CodeDeploy giám sát trong lúc chuyển traffic; alarm ở trạng thái ALARM → rollback.
  • Hooks: PreTraffic / PostTraffic – hai Lambda function chạy kiểm tra (smoke test) trước và sau khi chuyển traffic.

Cấu hình trong template

GetUrlFunction:
  Type: AWS::Serverless::Function
  Properties:
    CodeUri: get_url/
    Handler: app.lambda_handler
    AutoPublishAlias: live                       # bắt buộc để dùng DeploymentPreference
    DeploymentPreference:
      Type: Canary10Percent5Minutes              # 10% trong 5 phút rồi 100%
      Alarms:
        - !Ref GetUrlCanaryErrorsAlarm           # alarm kích hoạt rollback
      # Hooks:
      #   PreTraffic: !Ref PreTrafficFunction    # (tuỳ chọn) smoke test trước khi chuyển traffic

Trade-off

✅ Ưu điểm

  • Giảm blast radius: lỗi chỉ ảnh hưởng một phần nhỏ request.
  • Rollback tự động, không cần can thiệp thủ công.
  • Cấu hình chỉ vài dòng trong template; không phải tự dựng CodeDeploy.
  • Version cũ vẫn tồn tại → rollback gần như tức thì, không cần build lại.

⚠️ Nhược điểm

  • Deploy lâu hơn (phải chờ hết thời gian canary/linear).
  • Cần alarm tốt – alarm sai/thiếu thì rollback không hoạt động; cần có đủ traffic để alarm có dữ liệu.
  • Hai version chạy song song → phải tương thích ngược (DB schema, API contract).
  • Không áp dụng được cho sam sync (sync bỏ qua CodeDeploy).

Use Cases

API thanh toán / đặt hàng

Canary 10% trong 10 phút với alarm trên Errors và độ trễ; bug trong logic mới chỉ ảnh hưởng một lượng nhỏ đơn hàng và được rollback tự động.

Hàm xử lý dữ liệu quan trọng

PreTraffic hook gọi thử function mới với dữ liệu mẫu; chỉ khi pass mới bắt đầu chuyển traffic.

Thông tin bổ sung

  • Chỉ áp dụng khi cập nhật: lần deploy đầu tiên (tạo function) không có version cũ nên không có canary. Từ lần deploy thứ hai trở đi mới chuyển traffic dần.
  • CloudFormation chờ CodeDeploy: lệnh sam deploy chỉ kết thúc khi deployment hoàn tất (hoặc rollback), nên thời gian chạy bằng thời gian canary cộng thêm.
  • Rollback ảnh hưởng stack: khi CodeDeploy rollback, CloudFormation đánh dấu update là thất bại và đưa stack về trạng thái trước đó. Đừng bật Disable rollback trong sam deploy khi dùng tính năng này.
  • Metric của alias: dùng dimension Resource = <function>:<alias> và ExecutedVersion để chỉ theo dõi riêng version mới đang nhận canary.
  • Chi phí: CodeDeploy cho Lambda không tính phí; chỉ trả tiền CloudWatch Alarm (rất nhỏ).
  • Dọn dẹp version: mỗi lần deploy tạo thêm một version; Lambda giữ các version cũ (tính vào dung lượng code 75 GB của account). Nên dọn định kỳ nếu deploy rất nhiều.
