16. Monitoring for Kubernetes/EKS / Lab 3: Monitoring for Kubernetes – Request Tracing

Mục tiêu

  • Làm quen với khái niệm Request Tracing (Distributed Tracing).
  • Cài đặt các công cụ để hiện thực hoá request tracing bằng OpenTelemetry và Jaeger.
  • Theo dõi hành trình của một request đi qua frontend → backend → MongoDB.

Giới thiệu nhanh về 2 công cụ

OpenTelemetry (OTel)

Chuẩn chung để thu thập dữ liệu quan sát (traces, metrics, logs). Đóng vai trò "người trung gian": thay vì sửa mã nguồn mỗi khi đổi công cụ theo dõi, bạn chỉ cần dùng OTel rồi gửi dữ liệu tới bất kỳ backend nào.

Đặc điểm: vendor-agnostic — gửi tới Jaeger, Prometheus hay DataDog mà không cần đổi code.

Jaeger

Công cụ chuyên dụng để lưu trữ, visualize và phân tích distributed traces. Giúp bạn theo dõi hành trình của một request đi qua nhiều service.

Giải quyết vấn đề: khi tính năng bị chậm/lỗi, Jaeger chỉ đích danh: "Lỗi nằm ở Service A, tại bước query Mongo, mất 1500ms".

Kiến trúc tổng quan

Sơ đồ thực tế hệ thống của bài Lab 3

OTel Operator dùng auto-instrumentation tự nhúng thư viện tracing vào pod (không cần sửa code). App gửi trace tới OpenTelemetry Collector, Collector chuyển tiếp sang Jaeger All-in-one để lưu và visualize.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 1: đã có Minikube và ứng dụng TODO (frontend/backend/mongo) đang chạy.
  • Source code bài lab nằm tại sourcecode/section_15_monitoring_for_eks/lab3_request_tracing/.

Các bước thực hành

  1. Bước 1: Cài đặt các Operator cần thiết

    Cấu hình tracing dùng các Custom Resource Definition (CRD) như Jaeger, Instrumentation, OpenTelemetryCollector, nên cần cài Operator tương ứng trước.

    Cài cert-manager (yêu cầu bởi OpenTelemetry Operator):

    kubectl apply -f cert-manager.yaml
kubectl get pods -n cert-manager

    Cài Jaeger Operator:

    kubectl create namespace observability
kubectl apply -f jaeger-operator.yaml -n observability
kubectl get all -n observability
kubectl get pods -n observability

    Đợi cert-manager sẵn sàng (~1 phút) rồi cài OpenTelemetry Operator:

    kubectl apply -f opentelemetry-operator.yaml
kubectl get all -n opentelemetry-operator-system
kubectl get pods -n opentelemetry-operator-system
    Hãy cho các operator pod vài phút để khởi động hoàn tất trước khi sang bước tiếp theo.
  2. Bước 2: Áp dụng cấu hình tracing 
    kubectl apply -f tracing.yaml
kubectl get pods -n monitoring

    File tracing.yaml triển khai Jaeger All-in-one, cấu hình Auto-Instrumentation cho Node.js và OpenTelemetry Collector.

  3. Bước 3: Thêm annotation auto-instrument và rollout

    Thêm annotation (đã có sẵn trong file todo-app-minikube-local-with-mongo-exporter.yaml của Lab 3):

    # Dòng quan trọng: Inject cấu hình tracing cho Node.js
instrumentation.opentelemetry.io/inject-nodejs: "monitoring/nodejs-instrumentation"

    Apply và rollout lại ứng dụng:

    kubectl apply -f todo-app-minikube-local-with-mongo-exporter.yaml

kubectl rollout restart deployment/backend-deployment -n default
kubectl rollout restart deployment/frontend-deployment -n default

kubectl rollout status deployment/backend-deployment -n default
kubectl rollout status deployment/frontend-deployment -n default

kubectl get pods
kubectl describe pod <pod-name> -n default
  4. Bước 4: Truy cập Jaeger UI 
    minikube service jaeger-all-in-one-query -n monitoring
  5. Bước 5: Sinh trace và xem dữ liệu
    • Mở ứng dụng TODO (frontend), tạo/xoá vài todo.
    • Trong Jaeger UI, mục Service (khung trái) chọn frontend hoặc backend → bấm Find Traces.
    • Bấm vào từng trace để xem các span chi tiết (thời gian xử lý ở từng service, query MongoDB...).

Kiểm tra kết quả

✅ Lab thành công khi

  • Các Operator (cert-manager, Jaeger, OpenTelemetry) chạy đúng namespace.
  • Jaeger All-in-one và OpenTelemetry Collector chạy trong namespace monitoring.
  • Pod frontend/backend được inject auto-instrumentation (xem kubectl describe pod thấy init container/annotation).
  • Jaeger UI hiển thị service frontend/backend và tìm được trace khi thao tác trên app.

Troubleshoot

Không thấy service trong Jaeger UI
Nguyên nhân: Annotation auto-instrument chưa được inject, hoặc app chưa được rollout lại.
Giải pháp: Kiểm tra annotation đúng tên monitoring/nodejs-instrumentation; chạy kubectl rollout restart và đợi pod mới; sinh lại request trên app.
OpenTelemetry Operator không lên
Nguyên nhân: cert-manager chưa sẵn sàng khi cài OTel Operator.
Giải pháp: Xoá và cài lại OTel Operator sau khi kubectl get pods -n cert-manager cho thấy cert-manager đã Running.
Trace không tới được Jaeger
Nguyên nhân: Endpoint của Collector sai namespace, hoặc Collector chưa kết nối tới Jaeger.
Giải pháp: Kiểm tra endpoint http://otel-collector-collector.monitoring.svc.cluster.local:4318 trong tracing.yaml; xem log pod collector và jaeger.
