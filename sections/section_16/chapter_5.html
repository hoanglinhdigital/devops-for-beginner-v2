16. Monitoring for Kubernetes/EKS / Lab 1: Monitoring for Kubernetes – Metrics and Alert

Mục tiêu

  • Làm quen với giám sát metrics trên Kubernetes bằng các giải pháp Open Source: Prometheus, Grafana, AlertManager.
  • Cài đặt các công cụ để thu thập metrics của Cluster và Pods, rồi visualize thành dashboard.
  • Cấu hình Alert và Notification bằng AlertManager (kèm tuỳ chọn gửi qua Slack).

Kiến trúc tổng quan

Sơ đồ hệ thống của bài Lab 1

Ứng dụng TODO (frontend/backend/mongo, kèm mongo-exporter) chạy trên Minikube. Prometheus scrape metrics từ các pod, Grafana đọc dữ liệu từ Prometheus để vẽ dashboard, AlertManager đánh giá các rule và gửi cảnh báo về Slack.

Yêu cầu trước khi bắt đầu

  • Máy local đã cài Docker Desktop, Minikube và kubectl.
  • Ứng dụng TODO được clone từ https://github.com/hoanglinhdigital/react-express-mongodb (xem hướng dẫn ở Lab 1 của repository đó).
  • Source code bài lab nằm tại sourcecode/section_15_monitoring_for_eks/lab1_metrics_alert/.

Các bước thực hành

  1. Bước 1: Chuẩn bị Minikube và cài đặt ứng dụng TODO

    Kiểm tra và cập nhật Minikube nếu cần:

    minikube update-check
minikube stop
minikube delete
choco upgrade minikube
minikube start

    Deploy ứng dụng TODO lên Minikube (chú ý dùng file có kèm mongo-exporter):

    kubectl apply -f todo-app-minikube-local-with-mongo-exporter.yaml

    Kiểm tra pod và service đã chạy:

    kubectl get pods
kubectl get services
  2. Bước 2: Deploy Monitoring Stack (Prometheus + Grafana + AlertManager) 
    kubectl apply -f todo-app-monitoring-stack.yaml

    Kiểm tra kết quả deploy trong namespace monitoring:

    kubectl get pods -n monitoring
kubectl get services -n monitoring
kubectl get deployments -n monitoring
  3. Bước 3: Truy cập các service

    Mở Grafana (đăng nhập admin/admin):

    minikube service grafana -n monitoring

    Mở Prometheus UI:

    minikube service prometheus -n monitoring

    Mở AlertManager UI:

    minikube service alertmanager -n monitoring
  4. Bước 4: Truy vấn dữ liệu trên Prometheus

    Tại Prometheus UI, chạy thử một số query (xem thêm prometheus_query.md trong thư mục source):

    up{kubernetes_pod_name=~"backend.*"}
up{kubernetes_pod_name=~"frontend.*"}
rate(container_cpu_usage_seconds_total{pod=~"backend.*"}[5m])
topk(5, container_memory_usage_bytes{namespace="default"})
  5. Bước 5: Tạo Dashboard trên Grafana

    Vào Connections → Data sources xác nhận Prometheus đã được cấu hình (URL http://prometheus:9090, bấm Save & test để kiểm tra).

    Sau đó tạo các panel minh hoạ (xem chi tiết trong grafana-dashboard.md):

    # Panel "Pod Status - Default Namespace"
up{kubernetes_namespace="default"}

# Panel "Backend Pods Running"
count(up{kubernetes_pod_name=~"backend-deployment.*"} == 1)

# Panel "Memory Usage Over Time"
container_memory_usage_bytes{pod=~"backend-deployment.*", container="backend"}

# Panel "CPU Usage (5m rate)"
rate(container_cpu_usage_seconds_total{pod=~"backend-deployment.*", container="backend"}[5m])

    Bạn cũng có thể import dashboard có sẵn của cộng đồng (ví dụ ID 7249, 6417) qua Dashboards → New → Import.

  6. Bước 6: Cấu hình Alert Rules

    Áp dụng ConfigMap chứa 5 alert rules (BackendPodDown, FrontendPodDown, MongoPodDown, HighCPUUsage, HighMemoryUsage):

    kubectl apply -f alert-rules.yaml

    Mở file todo-app-monitoring-stack.yaml, bỏ comment ở dòng 113 và 130 để Prometheus mount file alert_rules.yml, rồi apply lại:

    kubectl apply -f todo-app-monitoring-stack.yaml

    Vào Prometheus UI → tab Alerts, bạn sẽ thấy 5 alert ở trạng thái Inactive (xanh lá).

  7. Bước 7 (Tuỳ chọn): Cấu hình Slack Notification

    Tạo Slack Incoming Webhook (Slack → Settings & administration → Manage apps → Incoming WebHooks), copy Webhook URL.

    Cập nhật Webhook URL và channel trong file alert-manager-configmap-for-slack.yaml, rồi thay block AlertManager ConfigMap trong todo-app-monitoring-stack.yaml bằng nội dung file đó:

    kubectl apply -f todo-app-monitoring-stack.yaml
kubectl rollout restart deployment alertmanager -n monitoring
  8. Bước 8: Kiểm thử Alert

    Scale backend về 0 để kích hoạt alert BackendPodDown:

    kubectl scale deployment backend-deployment --replicas=0 -n default

    Đợi khoảng 1 phút, quan sát alert chuyển sang Firing trong Prometheus → AlertManager → Slack (nếu đã cấu hình). Sau đó scale lại:

    kubectl scale deployment backend-deployment --replicas=2 -n default

Kiểm tra kết quả

✅ Lab thành công khi

  • Prometheus, Grafana, AlertManager chạy trong namespace monitoring.
  • Prometheus scrape được metrics của các pod ứng dụng (query up{...} trả giá trị 1).
  • Grafana hiển thị dashboard (CPU/Memory/pod status) từ data source Prometheus.
  • 5 alert xuất hiện trong tab Alerts và chuyển Firing khi scale backend về 0.
  • (Nếu có) Slack nhận được notification khi alert firing.

Troubleshoot

Grafana không nhận dữ liệu từ Prometheus
Nguyên nhân: Data source URL sai (dùng localhost thay vì tên service).
Giải pháp: Đặt URL là http://prometheus:9090 (tên service trong cùng namespace) và bấm Save & test.
Alert không xuất hiện trong tab Alerts
Nguyên nhân: Chưa bỏ comment 2 dòng mount alert_rules.yml trong todo-app-monitoring-stack.yaml, hoặc chưa apply lại.
Giải pháp: Bỏ comment dòng 113 và 130, kubectl apply -f todo-app-monitoring-stack.yaml rồi đợi pod Prometheus khởi động lại.
Không nhận được notification Slack
Nguyên nhân: Webhook URL sai/thiếu, channel sai, hoặc AlertManager chưa restart.
Giải pháp: Kiểm tra lại URL, channel; chạy kubectl rollout restart deployment alertmanager -n monitoring; xem log pod alertmanager.
