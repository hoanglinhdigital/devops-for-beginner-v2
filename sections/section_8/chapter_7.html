8. Thao tác cơ bản với Docker / Lab 4: Phân biệt CMD và ENTRYPOINT

Mục tiêu

  • Dùng docker image inspect để xem Entrypoint và Cmd mặc định của một image.
  • Build 3 image từ alpine với các tổ hợp ENTRYPOINT / CMD khác nhau.
  • Chạy container có và không có tham số, giải thích kết quả của từng trường hợp.

Các bước thực hành

  1. Bước 1: Inspect image alpine

    Di chuyển vào thư mục lab4_cmd_entrypoint, pull image và xem Entrypoint, Cmd mặc định (dùng --format để lọc gọn kết quả JSON):

    cd lab4_cmd_entrypoint
docker pull alpine:latest
docker image inspect alpine:latest --format 'Entrypoint={{json .Config.Entrypoint}} Cmd={{json .Config.Cmd}}'
Entrypoint=null Cmd=["/bin/sh"]

    Image alpine không có ENTRYPOINT, CMD mặc định là /bin/sh.

  2. Bước 2: Chuẩn bị 3 Dockerfile

    Tạo 3 file với nội dung như sau:

    Dockerfile-1

    FROM alpine:latest
ENTRYPOINT ["ls"]

    Dockerfile-2

    FROM alpine:latest
CMD ["ls"]

    Dockerfile-3

    FROM alpine:latest
ENTRYPOINT ["ls"]
CMD ["-alh"]
  3. Bước 3: Image alpine-1 – chỉ có ENTRYPOINT (kịch bản 1, 2) 
    docker build -t alpine-1 -f Dockerfile-1 .
docker image inspect alpine-1 --format 'Entrypoint={{json .Config.Entrypoint}} Cmd={{json .Config.Cmd}}'
Entrypoint=["ls"] Cmd=null
    docker run --rm alpine-1
bin
dev
...
docker run --rm alpine-1 -alh
total 64K
drwxr-xr-x    1 root     root        4.0K Oct 25 09:35 .
drwxr-xr-x    1 root     root        4.0K Oct 25 09:35 ..
...

    Tham số -alh được nối thêm vào sau ENTRYPOINT → ls -alh.

  4. Bước 4: Image alpine-2 – chỉ có CMD (kịch bản 3, 4) 
    docker build -t alpine-2 -f Dockerfile-2 .
docker image inspect alpine-2 --format 'Entrypoint={{json .Config.Entrypoint}} Cmd={{json .Config.Cmd}}'
docker run --rm alpine-2

    Không truyền tham số → chạy CMD mặc định ls. Giờ truyền tham số -alh:

    docker run --rm alpine-2 -alh
docker: Error response from daemon: ... exec: "-alh": executable file not found in $PATH

    Báo lỗi! Khi có tham số lúc run, nó ghi đè toàn bộ CMD. Docker chạy lệnh -alh thay vì ls -alh → không tìm thấy chương trình nào tên -alh. Muốn chạy đúng phải truyền đầy đủ lệnh:

    docker run --rm alpine-2 ls -alh
  5. Bước 5: Image alpine-3 – ENTRYPOINT + CMD (kịch bản 5, 6) 
    docker build -t alpine-3 -f Dockerfile-3 .
docker image inspect alpine-3 --format 'Entrypoint={{json .Config.Entrypoint}} Cmd={{json .Config.Cmd}}'
Entrypoint=["ls"] Cmd=["-alh"]
    docker run --rm alpine-3
total 64K
drwxr-xr-x    1 root     root        4.0K Oct 25 09:35 .
...
docker run --rm alpine-3 -p --full-time
total 56
drwxr-xr-x    2 root     root          4096 2026-10-21 21:52:47 +0000 bin/
drwxr-xr-x    5 root     root           340 2026-10-25 09:35:54 +0000 dev/
...

    Không truyền tham số → ls -alh (CMD là tham số mặc định). Truyền -p --full-time → thay thế CMD, lệnh thực tế là ls -p --full-time (không còn -alh).

  6. Bước 6: Ghi đè ENTRYPOINT lúc run

    ENTRYPOINT chỉ bị ghi đè khi dùng cờ --entrypoint:

    docker run --rm --entrypoint echo alpine-3 "Hello from new entrypoint"
Hello from new entrypoint

Kiểm tra kết quả

✅ Lab thành công khi

  • Kết quả 6 kịch bản khớp với cột “Lệnh thực tế” trong bảng.
  • Giải thích được: tham số của docker run được nối vào ENTRYPOINT nhưng thay thế CMD.
  • Biết khi nào dùng ENTRYPOINT (image như một câu lệnh cố định) và khi nào dùng CMD (lệnh mặc định có thể thay đổi dễ dàng).

Troubleshoot

PowerShell: lệnh docker image inspect ... --format '{{json .Config.Entrypoint}}' báo lỗi hoặc in sai
Nguyên nhân: PowerShell xử lý dấu ngoặc nhọn/nháy khác Bash.
Giải pháp: Chạy lệnh trong Git Bash, hoặc dùng docker image inspect alpine-1 rồi tìm mục "Entrypoint" và "Cmd" trong kết quả JSON.
Container chạy ENTRYPOINT dạng shell form không nhận tham số
Nguyên nhân: Viết ENTRYPOINT ls (shell form) thay vì ENTRYPOINT ["ls"]. Shell form chạy qua /bin/sh -c và bỏ qua CMD cũng như tham số của docker run.
Giải pháp: Luôn dùng exec form (JSON array) cho ENTRYPOINT và CMD.
