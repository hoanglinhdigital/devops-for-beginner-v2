8. Thao tác cơ bản với Docker / Lab 5: Multi-stage Dockerfile

Mục tiêu

  • Build một ứng dụng Node.js (webpack) thành static web, đóng gói vào httpd bằng Dockerfile 2 stage:
    • Stage #1: dùng image node:20 để build ra static file.
    • Stage #2: dùng image httpd:2.4, chỉ copy output từ stage #1, tạo thành image custom-httpd hoàn chỉnh.
  • So sánh kích thước image single-stage và multi-stage.
  • Chạy container từ image custom-httpd và kiểm tra kết quả.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 3. Đã đọc phần Multi-stage Dockerfile trong chương Dockerfile.
  • Dung lượng trống tối thiểu 3 GB (image node:20 khá lớn). Không cần cài Node.js trên máy vì toàn bộ quá trình build diễn ra trong container.
  • Source code: sourcecode/section_8_docker_basic_operation/lab5_multi_stage/.

Các bước thực hành

  1. Bước 1: Tìm hiểu cấu trúc project

    Copy thư mục lab5_multi_stage từ source code về máy (hoặc EC2):

    lab5_multi_stage/
├── app/                 # source: index.html, scripts, styles, images
├── package.json         # khai báo thư viện webpack, script "build"
├── package-lock.json
├── webpack.config.js    # output ra thư mục ./build
├── webpack.parts.js
├── .dockerignore        # loại node_modules, build khỏi build context
├── Dockerfile-single    # 1 stage – để so sánh
└── Dockerfile           # 2 stage

    Lệnh npm run build dùng webpack gom app/ thành các file tĩnh trong thư mục build/ – chỉ thư mục này là cần thiết để chạy website.

  2. Bước 2: Build image single-stage để so sánh

    Nội dung Dockerfile-single:

    # Single stage: dùng để so sánh kích thước với multi-stage
FROM node:20
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm install
COPY . .
RUN npm run build
    cd lab5_multi_stage
docker build -t tmp-nodejs -f Dockerfile-single .
  3. Bước 3: Viết & build Dockerfile multi-stage

    Nội dung Dockerfile:

    # ===== Stage 1: build source Node.js thành static file =====
FROM node:20 AS buildstep
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm install
COPY . .
RUN npm run build

# ===== Stage 2: image cuối cùng chỉ chứa httpd + static file =====
FROM httpd:2.4

# Chỉ copy kết quả build (/app/build) từ stage 1, bỏ lại node_modules & source code
COPY --from=buildstep /app/build/ /usr/local/apache2/htdocs/

EXPOSE 80

CMD ["httpd-foreground"]
    docker build -t custom-httpd -f Dockerfile .

    💡 Build lần 2 rất nhanh: các bước của stage #1 trùng với Dockerfile-single nên được lấy từ cache (CACHED).

  4. Bước 4: So sánh kích thước image 
    docker images tmp-nodejs
REPOSITORY   TAG       IMAGE ID       CREATED         SIZE
tmp-nodejs   latest    6f0c2a1b3d4e   2 minutes ago   1.7GB
docker images custom-httpd
REPOSITORY     TAG       IMAGE ID       CREATED         SIZE
custom-httpd   latest    9a8b7c6d5e4f   1 minute ago    175MB

    Image multi-stage nhỏ hơn khoảng 10 lần (con số cụ thể tuỳ version image và cách Docker tính dung lượng trên máy bạn). Xem nội dung bên trong 2 image:

    docker run --rm tmp-nodejs ls /app
docker run --rm custom-httpd ls /usr/local/apache2/htdocs

    Image tmp-nodejs chứa cả node_modules, source code và Node.js runtime; image custom-httpd chỉ có index.html, bundle.js và 2 file ảnh.

  5. Bước 5: Chạy container từ image custom-httpd 
    docker run -d -p 8080:80 --name custom-httpd custom-httpd
curl http://localhost:8080

    Truy cập http://localhost:8080 (hoặc http://<EC2_PUBLIC_IP>:8080), bạn sẽ thấy trang Welcome to DevOps!!! với 2 hình minh hoạ.

  6. Bước 6 (tuỳ chọn): Chỉ build tới một stage

    Cờ --target cho phép dừng ở stage chỉ định – hữu ích khi muốn debug quá trình build hoặc chạy test ở stage trung gian:

    docker build -t build-only --target buildstep -f Dockerfile .
docker run --rm build-only ls /app/build

Kiểm tra kết quả

✅ Lab thành công khi

  • Image custom-httpd nhỏ hơn rất nhiều so với tmp-nodejs.
  • Truy cập http://localhost:8080 hiển thị trang Welcome to DevOps!!! kèm hình ảnh.
  • Giải thích được vì sao image cuối không chứa node_modules.

Troubleshoot

npm ERR! network / build rất lâu ở bước RUN npm install
Nguyên nhân: Mạng chậm hoặc proxy công ty chặn registry npm.
Giải pháp: Thử lại; nếu mạng công ty chặn, thực hành trên EC2 (Lab 1 – Cách 2).
COPY --from=buildstep ... "/app/build": not found
Nguyên nhân: Lệnh npm run build ở stage #1 lỗi hoặc output ra thư mục khác, hoặc tên stage trong AS và --from không khớp.
Giải pháp: Xem log của bước npm run build; kiểm tra output.path trong webpack.config.js và tên stage.
no space left on device
Nguyên nhân: Ổ đĩa hết dung lượng (hay gặp trên EC2 dùng EBS 8 GB mặc định).
Giải pháp: docker system prune -a để xoá image không dùng; tăng EBS volume (Section 6 – Lab 7).

Dọn dẹp resource

docker rm -f custom-httpd
docker rmi tmp-nodejs custom-httpd build-only
docker builder prune -f

docker builder prune xoá build cache (có thể chiếm hàng GB sau khi build nhiều lần).
