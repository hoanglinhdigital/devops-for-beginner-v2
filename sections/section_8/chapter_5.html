8. Thao tác cơ bản với Docker / Dockerfile & các chỉ thị cơ bản

Giới thiệu

Dockerfile là một file text chứa danh sách các chỉ thị (instruction) mô tả cách build một Docker image: dùng base image nào, copy những file gì, cài đặt thư viện gì và chạy lệnh gì khi container khởi động. Dockerfile biến quy trình chuẩn bị môi trường vốn làm thủ công trên server thành code – có thể lưu trên Git, review và build lặp lại cho ra kết quả giống nhau.

Các chỉ thị chính

  • FROM – khai báo base image: Dockerfile thường bắt đầu bằng FROM để chỉ định image nền. Ví dụ: FROM ubuntu:24.04, FROM httpd:2.4, FROM node:20-alpine.
  • WORKDIR – thư mục làm việc: đặt thư mục hiện tại cho các chỉ thị phía sau (tự tạo nếu chưa có). Ví dụ: WORKDIR /app.
  • COPY / ADD – sao chép file & thư mục: từ máy build (build context) vào trong image. Ví dụ: COPY app.py /app/, COPY . /usr/local/apache2/htdocs/.
  • RUN – thực thi lệnh lúc build image: cài phần mềm, update package... Ví dụ: RUN apt-get update && apt-get install -y python3.
  • ENV – biến môi trường: có hiệu lực cả lúc build và lúc container chạy. Ví dụ: ENV LOGLEVEL=DEBUG.
  • EXPOSE – khai báo port: port mà ứng dụng trong container lắng nghe. Ví dụ: EXPOSE 80. Đây chỉ là tài liệu, muốn truy cập từ ngoài vẫn cần -p khi docker run.
  • CMD / ENTRYPOINT – lệnh chạy khi container start: ví dụ CMD ["python3", "/app/app.py"].

Ví dụ Dockerfile hoàn chỉnh

# Base image
FROM node:20-alpine

# Thư mục làm việc trong container
WORKDIR /app

# Copy file khai báo thư viện trước để tận dụng cache
COPY package*.json ./
RUN npm install --omit=dev

# Copy source code
COPY . .

ENV NODE_ENV=production
EXPOSE 3000

# Lệnh chạy khi container start
CMD ["node", "index.js"]

Phân biệt CMD và ENTRYPOINT

Ngoài CMD, chỉ thị ENTRYPOINT cũng định nghĩa lệnh chạy khi container start, nhưng có sự khác biệt:

  • ENTRYPOINT định nghĩa process sẽ được thực thi bên trong container (khó ghi đè, cần --entrypoint).
  • CMD định nghĩa tham số mặc định cung cấp cho entrypoint process – bị ghi đè bởi bất kỳ tham số nào truyền sau tên image trong docker run.
  • Thông thường ENTRYPOINT định nghĩa đường dẫn tới chương trình, CMD định nghĩa tham số (nếu có).
  • Nếu không khai báo ENTRYPOINT, toàn bộ CMD được coi là lệnh cần chạy.

Exec form vs Shell form: nên viết CMD ["npm", "start"] (exec form – JSON array) thay vì CMD npm start (shell form, chạy qua /bin/sh -c). Với exec form, ứng dụng là process PID 1 và nhận được tín hiệu SIGTERM khi docker stop, giúp tắt ứng dụng an toàn. Bạn sẽ thực hành chi tiết ở Lab 4.

Multi-stage Dockerfile

Một Dockerfile có thể chứa nhiều FROM, mỗi FROM bắt đầu một stage. Stage sau có thể copy kết quả từ stage trước bằng COPY --from=<stage>; image cuối cùng chỉ chứa stage cuối.

  • Giảm kích thước image: quá trình build cần nhiều công cụ (compiler, npm, Maven...) – nếu giữ lại sẽ làm image cuối rất lớn.
  • Tăng hiệu suất & bảo mật: dùng base image có sẵn cho từng giai đoạn thay vì tự cài tools; image cuối ít phần mềm hơn → ít lỗ hổng hơn.
  • Tách biệt các giai đoạn build, test, runtime trong cùng một file.
# Stage #1: dùng image Node.js để build project thành static file
FROM node:20 AS buildstep
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm install
COPY . .
RUN npm run build

# Stage #2: dùng image nginx, chỉ copy static file từ stage #1
FROM nginx:1.27-alpine
COPY --from=buildstep /app/build /usr/share/nginx/html

Best practice khi viết Dockerfile

  • Dùng base image chính thức, version cụ thể (node:20-alpine thay vì node hay node:latest) để build lặp lại được.
  • Sắp xếp chỉ thị theo tần suất thay đổi: copy package.json + cài thư viện trước, copy source code sau – sửa code không làm cài lại thư viện (tận dụng layer cache).
  • Gộp lệnh RUN liên quan và dọn cache trong cùng lệnh: RUN apt-get update && apt-get install -y curl && rm -rf /var/lib/apt/lists/*.
  • Dùng .dockerignore để loại node_modules, .git, .env khỏi build context: build nhanh hơn và không lộ secret.
  • Không đưa secret vào image (password, access key) qua ENV hay COPY – ai pull được image đều đọc được.
  • Chạy bằng user không phải root khi có thể (USER node), và dùng multi-stage để image cuối nhỏ gọn.

Use Cases

Đóng gói web tĩnh

FROM httpd hoặc nginx, COPY file HTML/CSS/JS vào web root – image vài chục MB, chạy ở đâu cũng giống nhau.

Ứng dụng backend

Node.js/Java/Python: cài thư viện bằng RUN, khai báo EXPOSE và CMD khởi động server.

Công cụ CLI đóng gói

Dùng ENTRYPOINT để image hoạt động như một câu lệnh, người dùng chỉ cần truyền tham số: docker run my-tool --help.
