8. Thao tác cơ bản với Docker / Giới thiệu Amazon ECR & Amazon ECS

Giới thiệu

Sau khi đóng gói ứng dụng thành Docker image, bạn cần nơi lưu trữ image và nơi chạy container trên Cloud. Trên AWS, hai dịch vụ cơ bản đảm nhận vai trò này là Amazon Elastic Container Registry (ECR) – registry lưu trữ Docker image, và Amazon Elastic Container Service (ECS) – dịch vụ chạy và quản lý container. Đây là nền tảng cho các section CI/CD (CodePipeline, Jenkins, GitHub Actions) phía sau.

Amazon Elastic Container Registry (ECR)

ECR là dịch vụ của AWS cung cấp khả năng quản lý và lưu trữ Docker image (và các artifact chuẩn OCI), được thiết kế để làm việc với các dịch vụ chạy container của AWS – tương tự Docker Hub nhưng nằm trong AWS account của bạn và được bảo vệ bằng IAM.

  • Registry: mỗi AWS account có 1 private registry cho mỗi region, địa chỉ dạng <account-id>.dkr.ecr.<region>.amazonaws.com.
  • Repository: đơn vị quản lý trong registry. Thông thường một repository chỉ lưu image của một ứng dụng (ví dụ my-httpd, order-service).
  • Image & tag: tương tự Docker image; image trên repository cần đánh tag (1.0, 2.0, commit SHA) để quản lý version. Có thể bật tag immutability để chặn ghi đè tag đã tồn tại.
  • Bảo mật: phân quyền push/pull bằng IAM, mã hoá image khi lưu trữ (AES-256 hoặc KMS), quét lỗ hổng bảo mật (image scanning).
  • Lifecycle policy: tự động xoá image cũ (ví dụ chỉ giữ 10 image gần nhất) để tiết kiệm chi phí lưu trữ.

Amazon Elastic Container Service (ECS)

ECS là dịch vụ quản lý container (container orchestration) do AWS cung cấp, cho phép bạn chạy và quản lý các ứng dụng container trên AWS một cách dễ dàng và linh hoạt – không cần tự cài đặt, vận hành control plane như Kubernetes.

Các tính năng của ECS

  • Quản lý đơn giản: AWS quản lý control plane; bạn chỉ khai báo chạy image nào, bao nhiêu CPU/RAM, bao nhiêu bản sao.
  • Tích hợp với công cụ container: chạy trực tiếp Docker image (từ ECR, Docker Hub...) mà không cần thay đổi mã nguồn hoặc cấu hình.
  • Mở rộng linh hoạt: kết hợp Auto Scaling để scale in/out số lượng task theo CPU, memory, số request.
  • Tích hợp dịch vụ AWS khác: Elastic Load Balancer, ECR, IAM, CloudWatch Logs, Secrets Manager, Service Connect / Cloud Map.
  • Linh hoạt về hạ tầng chạy container: EC2 launch type (bạn quản lý các EC2 trong cluster) hoặc Fargate (serverless, không quản lý server), lựa chọn tuỳ nhu cầu và khả năng customize của dự án.

  • Cluster: đơn vị lớn nhất của ECS, nhóm logic cung cấp tài nguyên cần thiết (EC2, Fargate) để chạy ứng dụng.
  • Task Definition: bản thiết kế (dạng JSON, có revision) chỉ dẫn ECS cách tạo một task: image, CPU/RAM, port mapping, biến môi trường, IAM role, cấu hình log – tương tự file docker-compose.yaml.
  • Task: một instance đang chạy của task definition, được cấp phát tài nguyên (CPU, RAM). Một task có thể chứa 1 hoặc nhiều container.
  • Service: duy trì số lượng task mong muốn (desired count), tự thay thế task lỗi, kết nối với Load Balancer và expose ứng dụng ra bên ngoài hoặc nội bộ cluster.
  • Container: tương tự Docker container – một image đang chạy.
  • ECS Service Connect: cung cấp cơ chế giao tiếp service-to-service bằng tên ngắn gọn, kèm metrics và retry.

Use Cases

Web application / API

ECS Service + ALB chạy nhiều task ở nhiều AZ, Auto Scaling theo số request, deploy version mới bằng rolling update.

Batch job / scheduled task

Chạy task Fargate theo lịch (EventBridge Scheduler) để xử lý dữ liệu, xuất báo cáo; chỉ trả tiền trong thời gian task chạy.

Pipeline CI/CD container

Pipeline build image → push lên ECR → cập nhật task definition → ECS Service deploy version mới (các section CI/CD tiếp theo).

Thông tin bổ sung

  • Chi phí ECR: tính theo dung lượng lưu trữ (khoảng 0,10 USD/GB/tháng) và data transfer ra Internet/khác region. Dùng lifecycle policy để xoá image cũ.
  • Chi phí ECS: bản thân ECS không tính phí; bạn trả tiền cho Fargate (vCPU, RAM theo giây) hoặc EC2, cùng các tài nguyên đi kèm (ALB, NAT Gateway, Public IPv4, CloudWatch Logs).
  • Kiến trúc CPU: Fargate hỗ trợ X86_64 và ARM64 (Graviton – rẻ hơn ~20%). Image phải build đúng kiến trúc khai báo trong task definition.
  • Pull image từ private subnet cần NAT Gateway hoặc VPC Endpoint cho ECR/S3 (đều có phí). Lab trong khoá học dùng public subnet + Public IP để tiết kiệm chi phí.
