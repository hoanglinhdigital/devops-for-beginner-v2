8. Thao tác cơ bản với Docker / Docker là gì? Kiến trúc & các thành phần cơ bản

Giới thiệu

Docker là nền tảng phần mềm cho phép bạn dựng, kiểm thử và triển khai ứng dụng một cách nhanh chóng. Docker đóng gói phần mềm vào các đơn vị tiêu chuẩn hoá gọi là container, chứa mọi thứ phần mềm cần để chạy: thư viện, công cụ hệ thống, code, runtime. Nhờ Docker, bạn có thể nhanh chóng triển khai và thay đổi quy mô ứng dụng trên bất kỳ môi trường nào và biết chắc rằng code sẽ chạy được – “Build once, run anywhere”.

Lưu ý: Docker không phải là nền tảng duy nhất để chạy container. Một số lựa chọn khác: Podman, containerd + nerdctl, CRI-O (dùng trong Kubernetes). Tuy nhiên Docker vẫn là công cụ phổ biến nhất cho developer.

Các khái niệm chính

  • Image: “khuôn mẫu” chỉ đọc (read-only) chứa ứng dụng và môi trường chạy, được tạo thành từ nhiều layer xếp chồng. Định danh bằng <repository>:<tag>, ví dụ nginx:1.27.
  • Container: một instance đang chạy của image (giống quan hệ class – object trong lập trình). Từ 1 image có thể chạy nhiều container.
  • Dockerfile: file text mô tả các bước để build ra image (base image, copy code, cài thư viện, lệnh khởi động...).
  • Registry: nơi lưu trữ và phân phối image. Mặc định là Docker Hub; trên AWS dùng Amazon ECR.
  • Volume: vùng lưu trữ dữ liệu bền vững nằm ngoài vòng đời container (container bị xoá, dữ liệu vẫn còn).
  • Network: mạng ảo cho phép các container giao tiếp với nhau và với bên ngoài (bridge, host, none...).

Docker Client gửi lệnh tới Docker daemon qua REST API. Daemon quản lý image, container, volume, network và pull/push image từ Registry.

  • Docker daemon (dockerd): nơi quản lý các thành phần của Docker như image, container, volume, network. Daemon nhận API từ Client để thực thi các nhiệm vụ.
  • Docker Client (docker CLI): cung cấp phương thức để tương tác với Docker daemon. Mỗi lệnh docker ... bạn gõ sẽ được gửi tới daemon.
  • Docker Registry: nơi lưu trữ Docker image. Mặc định Docker kết nối tới Docker Hub (docker.io).
Khi cài Docker Desktop (Windows/MacOS), Daemon và Client cùng nằm trên máy tính của bạn – daemon thực chất chạy trong một máy ảo Linux nhỏ do Docker Desktop quản lý (WSL 2 trên Windows). Client cũng có thể điều khiển daemon trên một máy khác (remote host).

Image layer

Mỗi chỉ thị trong Dockerfile (FROM, RUN, COPY...) tạo ra một layer. Các layer được cache và dùng chung giữa các image: nếu 10 image cùng dùng base node:20, layer của node:20 chỉ lưu và tải về 1 lần. Khi chạy container, Docker thêm một layer có thể ghi (writable) lên trên cùng; mọi thay đổi trong container chỉ nằm ở layer này và mất đi khi container bị xoá – đó là lý do cần Volume cho dữ liệu cần giữ lại.

  1. Chuẩn bị Dockerfile:

    mô tả các bước cần thiết để tạo ra môi trường container chứa ứng dụng của bạn.

  2. Build Docker Image:

    dùng lệnh docker build để xây dựng image từ Dockerfile.

  3. Kiểm tra Docker Image:

    dùng lệnh docker images để đảm bảo image đã được build thành công và xuất hiện trong danh sách.

  4. Chạy Docker Container:

    dùng lệnh docker run để chạy container từ image.

  5. Kiểm tra ứng dụng:

    truy cập ứng dụng qua địa chỉ IP hoặc tên miền cùng với port đã chỉ định.

Use Cases

Thử nhanh phần mềm

Cần MySQL, Redis, Nginx để test? Chỉ cần docker run, không phải cài trực tiếp lên máy, xoá đi cũng không để lại “rác”.

Chuẩn hoá build

Build ứng dụng Java/Node.js bên trong container với version JDK/Node cố định, không phụ thuộc vào môi trường của build server.

Đóng gói để deploy lên AWS

Image build từ Dockerfile được push lên ECR và chạy trên ECS, EKS, App Runner hoặc Lambda (container image).

Thông tin bổ sung

  • Tag latest chỉ là tên tag mặc định khi không chỉ định tag, không đảm bảo là bản mới nhất. Trong dự án thực tế nên dùng tag cụ thể (1.0.3, commit SHA...).
  • Official image trên Docker Hub (ví dụ nginx, node, mysql) được Docker kiểm duyệt – ưu tiên dùng làm base image.
  • CPU architecture: image có thể build cho linux/amd64 (Intel/AMD) hoặc linux/arm64 (Apple Silicon, AWS Graviton). Chú ý khi build trên Mac M-series rồi chạy trên server x86.
