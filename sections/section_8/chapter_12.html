8. Thao tác cơ bản với Docker / Lab 8: Docker Compose – Load Balancer với NGINX

Mục tiêu

  • Sử dụng lại resource của Lab 7, chạy 3 replica của service Node.js.
  • Thêm service NGINX làm load balancer (reverse proxy) đứng trước các replica, phân phối request theo round-robin.
  • Quan sát request được xử lý bởi các container khác nhau, nhưng dùng chung dữ liệu trên Redis và MySQL.
  • Scale số lượng replica và giả lập một container bị lỗi.

Client chỉ biết tới NGINX ở port 8080. Mỗi replica của web được Docker gán 1 port ngẫu nhiên trên host (ví dụ 54499, 54500, 54501).

Đây chính là mô hình thu nhỏ của Application Load Balancer + nhiều EC2/ECS task trên AWS: ứng dụng stateless, trạng thái chung (session, cache, dữ liệu) được lưu ở Redis/MySQL nên request đi vào replica nào cũng cho kết quả như nhau.

  2. Bước 2: Cấu hình NGINX làm load balancer

    Tạo file nginx/nginx.conf:

    # Nhóm backend: "web" là tên service trong docker-compose.yaml.
# Docker DNS trả về IP của tất cả container (replica) của service web,
# NGINX phân phối request theo thuật toán round-robin (mặc định).
upstream web_backend {
    server web:3000;
}

server {
    listen 80;

    location / {
        proxy_pass http://web_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # Container backend bị dừng => sau 2 giây chuyển request sang container khác (mặc định chờ 60 giây)
        proxy_connect_timeout 2s;

        # Trả về địa chỉ container backend đã xử lý request (để quan sát load balancing)
        add_header X-Upstream $upstream_addr always;
    }
}
  3. Bước 3: Viết file docker-compose.yaml

    So với Lab 7: thêm service nginx; service web chạy 3 replica và chỉ khai báo port container ("3000") vì 3 replica không thể cùng dùng port 8080 trên host; db không cần publish port 3306.

    services:
  nginx:
    image: nginx:1.27-alpine
    ports:
      - "8080:80"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - web
    restart: unless-stopped

  web:
    build:
      context: ./web
      dockerfile: Dockerfile
    image: compose-lb-web:1.0
    # Chạy 3 replica của service web
    deploy:
      replicas: 3
    # Chỉ khai báo port container => Docker tự chọn port ngẫu nhiên trên host cho từng replica
    ports:
      - "3000"
    environment:
      - NODE_ENV=development
      - DB_HOST=db
      - DB_USER=appuser
      - DB_PASSWORD=${MYSQL_PASSWORD}
      - DB_NAME=testdb
      - REDIS_HOST=cache
    depends_on:
      db:
        condition: service_healthy
      cache:
        condition: service_started
    restart: unless-stopped

  cache:
    image: redis:7-alpine
    restart: unless-stopped

  db:
    image: mysql:8.4
    environment:
      - MYSQL_ROOT_PASSWORD=${MYSQL_ROOT_PASSWORD}
      - MYSQL_DATABASE=testdb
      - MYSQL_USER=appuser
      - MYSQL_PASSWORD=${MYSQL_PASSWORD}
    volumes:
      - db-data:/var/lib/mysql
      - ./db/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h 127.0.0.1 -uroot -p$${MYSQL_ROOT_PASSWORD} --silent"]
      interval: 10s
      timeout: 5s
      retries: 10
      start_period: 30s
    restart: unless-stopped

  5. Bước 5: Quan sát load balancing

    Đợi khoảng 10–15 giây sau khi start (để các replica sẵn sàng), sau đó gửi nhiều request qua NGINX:

    for i in $(seq 1 6); do curl -s http://localhost:8080/api/info; echo; done
{"hostname":"cd15aedb89da","visits":7}
{"hostname":"22d3fc825fa2","visits":8}
{"hostname":"bc0fb9efc15b","visits":9}
{"hostname":"cd15aedb89da","visits":10}
{"hostname":"22d3fc825fa2","visits":11}
{"hostname":"bc0fb9efc15b","visits":12}

    Nếu dùng PowerShell:

    1..6 | ForEach-Object { curl.exe -s http://localhost:8080/api/info; "" }

    hostname lần lượt thay đổi giữa 3 container (round-robin), trong khi visits vẫn tăng liên tục vì cả 3 replica dùng chung Redis. Mở http://localhost:8080 trên browser và refresh nhiều lần để thấy kết quả tương tự.

    Xem container backend đã xử lý request qua header X-Upstream và đối chiếu với IP của các container:

    curl -s -I http://localhost:8080/api/info
docker compose ps -q web | xargs docker inspect --format '{{.Name}} {{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}'
  6. Bước 6: Scale lên 5 replica 
    docker compose up -d --scale web=5
docker compose restart nginx
for i in $(seq 1 10); do curl -s http://localhost:8080/api/info; echo; done

    💡 NGINX (bản open source) chỉ phân giải tên web thành danh sách IP lúc khởi động, nên cần restart NGINX sau khi scale. Load balancer trên Cloud (ALB + Target Group) tự động cập nhật danh sách backend khi scale.

  7. Bước 7: Giả lập một container bị lỗi

    Dừng 1 replica của web, sau đó tiếp tục gửi request:

    docker stop $(docker compose ps -q web | head -n 1)
for i in $(seq 1 6); do curl -s http://localhost:8080/api/info; echo; done

    Tất cả request vẫn thành công: NGINX phát hiện không kết nối được tới container đã dừng (sau proxy_connect_timeout 2 giây) và chuyển request sang replica khác, đồng thời tạm loại container lỗi khỏi danh sách. Một request có thể chậm khoảng 2 giây.

Kiểm tra kết quả

✅ Lab thành công khi

  • docker compose ps hiển thị 3 container web, mỗi container một host port ngẫu nhiên.
  • Gửi request liên tiếp tới http://localhost:8080/api/info, hostname luân phiên giữa các container và visits tăng liên tục.

Troubleshoot

Bind for 0.0.0.0:8080 failed: port is already allocated khi scale web
Nguyên nhân: Service web khai báo port cố định "8080:3000" (như Lab 7) – nhiều replica không thể cùng chiếm 1 port trên host.
Giải pháp: Chỉ khai báo port container "3000" (hoặc bỏ hẳn ports vì NGINX truy cập web qua network nội bộ).
Request luôn vào cùng 1 container
Nguyên nhân: Vừa start xong, các replica khác chưa sẵn sàng nên NGINX tạm đánh dấu lỗi (khoảng 10 giây); hoặc NGINX start trước khi scale.
Giải pháp: Đợi 10–15 giây rồi thử lại; docker compose restart nginx sau khi scale.
NGINX trả về 502 Bad Gateway
Nguyên nhân: Không có replica web nào đang chạy hoặc web bị lỗi kết nối DB.
Giải pháp: docker compose ps, docker compose logs web; kiểm tra file .env và trạng thái healthy của db.
NGINX báo host not found in upstream "web:3000" và dừng
Nguyên nhân: NGINX start khi chưa có container web nào (ví dụ web lỗi build).
Giải pháp: Sửa lỗi của service web, sau đó docker compose up -d lại.
