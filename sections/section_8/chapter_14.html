8. Thao tác cơ bản với Docker / Lab 9: Push image lên ECR & chạy container trên ECS Fargate

Mục tiêu

  • Tạo ECR repository, build image từ Dockerfile của Lab 3, đánh tag và push lên ECR.
  • Tạo ECS cluster (Fargate), task definition sử dụng image trên ECR.
  • Chạy một task Fargate có Public IP và truy cập website qua browser.
  • Ôn lại các khái niệm Docker, ECR, ECS – chuẩn bị cho các section CI/CD (deploy lên ECS bằng pipeline).

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 3 (thư mục lab3_dockerfile với Dockerfile và web/index.html).
  • AWS CLI v2 đã cấu hình profile (Section 4/5), IAM user có quyền ECR (ví dụ policy AmazonEC2ContainerRegistryPowerUser) và ECS. Nếu làm trên EC2 docker-lab-server: AL2023 có sẵn AWS CLI, hãy gắn IAM Role có policy AmazonEC2ContainerRegistryPowerUser cho instance thay vì lưu access key.
  • Biết AWS Account ID (12 chữ số) – xem ở góc phải trên của AWS Console hoặc lệnh aws sts get-caller-identity.
  • Region thực hành: ap-southeast-1 (Singapore). Trên Windows, chạy các lệnh trong Git Bash.
  • Source code: sourcecode/section_8_docker_basic_operation/lab9_ecr_ecs/commands.sh.

Các bước thực hành

  1. Bước 1: Tạo ECR repository

    Vào Amazon ECR → Private registry → Repositories, tạo repository với các thông số:

    • Repository name: my-httpd
    • Image tag mutability: Mutable
    • Encryption: AES-256 (mặc định)

    Copy URI của repository, có dạng <AWS_ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com/my-httpd.

  2. Bước 2: Khai báo biến & kiểm tra AWS CLI

    Thay 123456789012 bằng Account ID của bạn:

    export AWS_REGION=ap-southeast-1
export AWS_ACCOUNT_ID=123456789012
export ECR_REGISTRY=${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com
aws sts get-caller-identity
  3. Bước 3: Build image

    Di chuyển vào thư mục Lab 3 và build. --platform linux/amd64 đảm bảo image chạy được trên Fargate X86_64, kể cả khi bạn build trên Mac chip Apple Silicon (ARM):

    cd lab3_dockerfile
docker build --platform linux/amd64 -t my-httpd-image:1.0 .
  4. Bước 4: Đăng nhập Docker vào ECR

    AWS CLI lấy token tạm thời (hiệu lực 12 giờ) và truyền cho docker login:

    aws ecr get-login-password --region ${AWS_REGION} | docker login --username AWS --password-stdin ${ECR_REGISTRY}
Login Succeeded

    💡 Nút View push commands trong trang repository của ECR Console hiển thị sẵn các lệnh login/build/tag/push cho đúng repository của bạn.

  5. Bước 5: Đánh tag & push image lên ECR

    Tên image phải chứa địa chỉ registry để Docker biết push tới đâu:

    docker tag my-httpd-image:1.0 ${ECR_REGISTRY}/my-httpd:1.0
docker images
docker push ${ECR_REGISTRY}/my-httpd:1.0
    aws ecr list-images --repository-name my-httpd --region ${AWS_REGION}

    Mở repository my-httpd trên ECR Console, bạn sẽ thấy image tag 1.0 cùng dung lượng và digest (sha256:...). Copy Image URI để dùng ở Bước 8.

  6. Bước 6: Tạo Security Group cho task

    Tạo Security Group ecs-task-sg trong Default VPC với inbound rule:

    • HTTP (TCP 80) – Source: My IP
  7. Bước 7: Tạo ECS cluster

    Vào Amazon ECS → Clusters, tạo cluster với các thông số:

    • Cluster name: docker-lab-cluster
    • Infrastructure: chỉ chọn AWS Fargate (serverless)
    • Monitoring: để mặc định
  8. Bước 8: Tạo Task Definition

    Vào Amazon ECS → Task definitions, tạo task definition mới với các thông số:

    • Task definition family: my-httpd-task
    • Launch type: AWS Fargate
    • Operating system/Architecture: Linux/X86_64
    • Task size: CPU .25 vCPU, Memory .5 GB
    • Task execution role: Create new role (ECS tạo role ecsTaskExecutionRole có quyền pull image từ ECR và ghi log CloudWatch)
    • Container: Name httpd, Image URI <AWS_ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com/my-httpd:1.0, Essential: Yes
    • Port mappings: Container port 80, Protocol TCP, App protocol HTTP
    • Log collection: Use log collection → Amazon CloudWatch (mặc định)
  9. Bước 9: Chạy task

    Vào cluster docker-lab-cluster → tab Tasks → Run new task với các thông số:

    • Compute options: Launch type = FARGATE, Platform version: LATEST
    • Application type: Task
    • Task definition: Family my-httpd-task, Revision: mới nhất; Desired tasks: 1
    • Networking: Default VPC, chọn các public subnet; Security group: ecs-task-sg (bỏ Security Group default)
    • Public IP: Turned on (để task pull image từ ECR qua Internet và để bạn truy cập từ browser)

    Đợi trạng thái task chuyển từ PROVISIONING → PENDING → RUNNING (khoảng 1 phút).

  10. Bước 10: Truy cập website & xem log

    Mở task vừa chạy, tab Configuration → copy Public IP. Truy cập http://<task-public-ip> trên browser: trang Welcome to DevOps on AWS – Docker Lab – cùng image với Lab 3 nhưng giờ chạy trên AWS.

    Tab Logs của task hiển thị log của httpd (được đẩy lên CloudWatch Logs, log group /ecs/my-httpd-task).

  11. Bước 11 (tuỳ chọn): Deploy version 2.0

    Sửa web/index.html (đổi v1.0 → v2.0), build và push tag mới:

    docker build --platform linux/amd64 -t my-httpd-image:2.0 .
docker tag my-httpd-image:2.0 ${ECR_REGISTRY}/my-httpd:2.0
docker push ${ECR_REGISTRY}/my-httpd:2.0

    Tạo revision mới của task definition my-httpd-task với Image URI tag 2.0, chạy task mới từ revision này rồi Stop task cũ. Quy trình thủ công này sẽ được tự động hoá bằng ECS Service + pipeline CI/CD ở các section sau.

Kiểm tra kết quả

✅ Lab thành công khi

  • Repository my-httpd trên ECR có image tag 1.0 (và 2.0 nếu làm Bước 11).
  • Task trong cluster docker-lab-cluster ở trạng thái RUNNING.
  • Truy cập http://<task-public-ip> hiển thị trang web của Lab 3.
  • Thấy access log của httpd trong tab Logs / CloudWatch Logs.

Troubleshoot

no basic auth credentials / denied: Your authorization token has expired khi push
Nguyên nhân: Chưa docker login vào ECR, đăng nhập sai region/registry, hoặc token đã quá 12 giờ.
Giải pháp: Chạy lại lệnh ở Bước 4, kiểm tra biến ECR_REGISTRY đúng Account ID và region.
name unknown: The repository with name 'my-httpd' does not exist in the registry
Nguyên nhân: Repository chưa được tạo, hoặc tạo ở region khác ap-southeast-1.
Giải pháp: Kiểm tra region trên Console, tạo repository như Bước 1.
Task dừng với lỗi CannotPullContainerError / ResourceInitializationError: unable to pull secrets or registry auth
Nguyên nhân: Task không có Public IP (hoặc chạy ở private subnet không có NAT Gateway) nên không kết nối được ECR; hoặc Image URI sai tag.
Giải pháp: Chạy lại task với Public IP: Turned on ở public subnet; kiểm tra Image URI trong task definition khớp với tag trên ECR.
Task dừng ngay, log có exec format error
Nguyên nhân: Image build cho arm64 (Mac Apple Silicon) nhưng task definition khai báo X86_64.
Giải pháp: Build lại với --platform linux/amd64 và push lại; hoặc đổi task definition sang Linux/ARM64.
Task RUNNING nhưng browser không truy cập được
Nguyên nhân: Security Group ecs-task-sg chưa mở port 80 cho IP của bạn, hoặc truy cập bằng https://.
Giải pháp: Kiểm tra inbound rule; truy cập bằng http://.

Dọn dẹp resource

Task Fargate và Public IPv4 tính phí theo thời gian chạy, ECR tính phí theo dung lượng lưu trữ. Dọn dẹp ngay sau khi học xong.

  1. Cluster docker-lab-cluster → tab Tasks → chọn tất cả task đang chạy → Stop.

  2. Xoá cluster docker-lab-cluster.

  3. Task definitions → my-httpd-task → Deregister tất cả revision, sau đó Delete.

  4. Xoá ECR repository my-httpd (xoá kèm toàn bộ image bên trong).

  5. Xoá Security Group ecs-task-sg và CloudWatch log group /ecs/my-httpd-task.

  6. Xoá image local:

    docker rmi my-httpd-image:1.0 my-httpd-image:2.0 ${ECR_REGISTRY}/my-httpd:1.0 ${ECR_REGISTRY}/my-httpd:2.0
docker logout ${ECR_REGISTRY}

IAM role ecsTaskExecutionRole không tính phí và sẽ được dùng lại ở các section ECS/CI-CD sau, có thể giữ lại.
