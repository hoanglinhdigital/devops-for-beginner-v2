8. Thao tác cơ bản với Docker / Docker Compose – giới thiệu & cú pháp

Giới thiệu

Docker Compose là công cụ dùng để định nghĩa và chạy các ứng dụng multi-container. Thay vì gõ nhiều lệnh docker run dài với hàng loạt tham số, bạn khai báo các service, network, volume và cấu hình trong một file YAML duy nhất (docker-compose.yaml hoặc compose.yaml), sau đó chỉ cần docker compose up để tạo và chạy toàn bộ hệ thống.

Trong thực tế, Docker Compose được developer dùng để dựng môi trường local nhanh chóng (web + cache + database) và áp dụng thay đổi tức thì. Trên Cloud thường không dùng Docker Compose để deploy production, mà dùng các dịch vụ orchestration như Amazon ECS, Kubernetes (EKS).

Đặc điểm chính

  • Khai báo (declarative): mô tả trạng thái mong muốn của hệ thống trong YAML, lưu trên Git cùng source code.
  • Một lệnh cho cả hệ thống: docker compose up / down tạo hoặc xoá toàn bộ container, network, volume.
  • Network tự động: Compose tạo một network riêng cho project; các service gọi nhau bằng tên service (ví dụ db:3306) nhờ DNS nội bộ.
  • Thứ tự khởi động: depends_on kết hợp healthcheck đảm bảo database sẵn sàng trước khi ứng dụng start.
  • Biến môi trường: đọc từ file .env, tách cấu hình nhạy cảm (password) ra khỏi file compose.
  • Scale đơn giản: docker compose up --scale web=3 chạy nhiều replica của một service.

Các service trong cùng project giao tiếp với nhau qua tên service; chỉ những port được khai báo trong ports mới truy cập được từ máy host.

Cú pháp file docker-compose.yaml cơ bản

services:                    # danh sách service – đơn vị quản lý của Compose
  web:
    build:                     # build image từ Dockerfile
      context: ./web
      dockerfile: Dockerfile
    image: my-web:1.0          # tên image sau khi build
    ports:
      - "8080:3000"            # host-port:container-port
    environment:               # khai báo / ghi đè biến môi trường
      - NODE_ENV=development
      - DB_PASSWORD=${MYSQL_PASSWORD}   # lấy giá trị từ file .env
    volumes:
      - ./web:/app             # bind mount: thư mục host -> container
    depends_on:
      db:
        condition: service_healthy
    restart: unless-stopped

  db:
    image: mysql:8.4           # dùng image có sẵn, không cần build
    environment:
      - MYSQL_ROOT_PASSWORD=${MYSQL_ROOT_PASSWORD}
    volumes:
      - db-data:/var/lib/mysql # named volume: dữ liệu bền vững
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h 127.0.0.1 --silent"]
      interval: 10s
      retries: 10

volumes:                       # định nghĩa các named volume
  db-data:
Thuộc tínhÝ nghĩa
servicesĐơn vị quản lý của Docker Compose. Mỗi service có thể chạy 1 hoặc nhiều container (replica).
buildChỉ thị build: dùng Dockerfile nào, build context ở đâu để tạo ra image.
imageImage dùng để chạy (hoặc tên đặt cho image khi kết hợp với build).
portsMapping host-port:container-port. Chỉ ghi "3000" → Docker tự chọn port ngẫu nhiên trên host.
volumes (trong service)Mapping giữa thư mục máy host / named volume và thư mục trong container.
environmentKhai báo hoặc ghi đè biến môi trường cho container.
depends_onThứ tự khởi động; condition: service_healthy đợi service phụ thuộc pass healthcheck.
volumes (cấp cao nhất)Định nghĩa các persistent volume dùng chung cho các service.
Compose V2: lệnh mới là docker compose (có dấu cách, là plugin của Docker CLI), thay cho docker-compose (V1, đã ngừng hỗ trợ). Thuộc tính version: '3' ở đầu file cũng không còn cần thiết – Compose V2 sẽ cảnh báo “version is obsolete” nếu bạn vẫn khai báo.

Bind mount vs Named volume

Tiêu chíBind mount ./web:/appNamed volume db-data:/var/lib/mysql
Dữ liệu nằm ở đâuThư mục cụ thể trên máy hostVùng lưu trữ do Docker quản lý
Mục đích chínhChia sẻ source code để sửa code thấy ngay (dev)Lưu dữ liệu bền vững (database, upload)
Khi docker compose downKhông ảnh hưởngVẫn giữ lại (chỉ xoá khi thêm -v)
Phụ thuộc OS hostCó (đường dẫn, quyền file, hiệu năng trên Windows/Mac)Không

Các lệnh thường dùng

LệnhÝ nghĩa
docker compose configKiểm tra cú pháp, hiển thị cấu hình sau khi thay biến từ .env
docker compose up -d --buildBuild image (nếu cần) và tạo, chạy toàn bộ service ở chế độ nền
docker compose psLiệt kê container của project
docker compose logs -f <service>Xem log của service
docker compose exec <service> shMở shell trong container của service
docker compose stop / start / restartDừng / chạy lại container (không xoá)
docker compose downXoá container & network (thêm -v để xoá volume, --rmi local để xoá image đã build)

Trade-off

✅ Ưu điểm

  • Rất dễ học, cấu hình ngắn gọn, đọc là hiểu.
  • Dựng môi trường dev giống nhau cho cả team chỉ với 1 lệnh.
  • Phù hợp chạy integration test trong pipeline CI.

⚠️ Hạn chế

  • Chỉ chạy trên 1 máy host – không có high availability.
  • Không có auto scaling, rolling update, self-healing mạnh như ECS/Kubernetes.
  • Không phù hợp để vận hành production quy mô lớn.

Use Cases

Môi trường dev local

Web + Redis + MySQL chạy bằng 1 lệnh, source code mount vào container để sửa code thấy ngay.

Integration test trong CI

Pipeline dựng database & các dependency bằng Compose, chạy test, sau đó down -v để dọn sạch.

Demo / PoC nhanh

Chia sẻ một file docker-compose.yaml để người khác chạy thử toàn bộ hệ thống trên máy của họ.

Thông tin bổ sung

  • Tên project mặc định là tên thư mục chứa file compose; container được đặt tên dạng <project>-<service>-<số thứ tự>. Có thể đổi bằng -p <tên>.
  • File .env cùng thư mục được Compose tự động đọc. Hãy thêm .env vào .gitignore và cung cấp .env.example cho người khác.
  • Tài liệu tham khảo: docs.docker.com/reference/compose-file.
