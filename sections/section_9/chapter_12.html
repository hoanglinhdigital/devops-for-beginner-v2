9. CI/CD với AWS CodePipeline / Lab 8: Canary deployment lên ECS với CodeDeploy

Mục tiêu

  • Tạo custom deployment configuration kiểu Canary: chuyển 25% traffic sang version mới, chờ 5 phút, sau đó chuyển 100%.
  • Cập nhật deployment group của Lab 7 để dùng chiến lược Canary, reroute traffic tự động.
  • Push code, đo tỷ lệ request trả về version mới qua ALB trong giai đoạn canary.

Canary ở mức service: CodeDeploy điều chỉnh trọng số (weight) giữa 2 Target Group trên listener 80, không thay đổi số task của mỗi task set.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 7: ECS service ở controller CODE_DEPLOY, CodeDeploy application nodejs-ecs-app, deployment group nodejs-ecs-dg, pipeline nodejs-ecs-bluegreen-pipeline.
  • Deployment của Lab 7 đã kết thúc (task set cũ đã terminate).
  • Source code: sourcecode/section_9_code_pipeline/lab8_ecs_canary/commands.sh.

Các bước thực hành

  1. Bước 1: Tạo custom deployment configuration

    Vào CodeDeploy → Deployment configurations, tạo deployment configuration với thông số:

    • Deployment configuration name: ECSCanary25Percent5Minutes
    • Compute platform: Amazon ECS
    • Type: Canary; Step: 25 (%); Interval: 5 (phút)

    💡 AWS có sẵn các cấu hình như CodeDeployDefault.ECSCanary10Percent5Minutes, CodeDeployDefault.ECSLinear10PercentEvery1Minutes. Lab dùng 25% để dễ quan sát với số request nhỏ.

  2. Bước 2: Cập nhật deployment group

    Edit deployment group nodejs-ecs-dg:

    • Traffic rerouting: Reroute traffic immediately (canary bắt đầu ngay khi task set mới sẵn sàng)
    • Deployment configuration: ECSCanary25Percent5Minutes
    • Original revision termination: chờ 5 phút
  3. Bước 3: Sửa code & push

    Sửa text thẻ <h1> trong public/index.html thành Welcome to My Website – v4 Canary:

    cd ~/codepipeline-labs/nodejs-random-color
git add public/index.html
git commit -m "feat: update welcome message v4 canary"
git push origin master
  4. Bước 4: Quan sát giai đoạn canary 25%

    Mở deployment trên CodeDeploy: phần Traffic shifting progress hiển thị Original 75% / Replacement 25%. Mở ALB → listener HTTP:80: rule forward tới 2 Target Group với trọng số tương ứng.

    Gửi 20 request và đếm theo version (thay <alb-dns-name>):

    for i in $(seq 1 20); do curl -s http://<alb-dns-name>/ | grep -o "<h1[^>]*>[^<]*" | sed 's/<h1[^>]*>//'; done | sort | uniq -c
     15 Welcome to My Website – v3 Blue/Green
      5 Welcome to My Website – v4 Canary

    Kết quả xấp xỉ 25% request trả về v4 (có sai số do số request nhỏ). Lặp lại lệnh vài lần để thấy tỷ lệ ổn định.

  5. Bước 5: Chờ hết 5 phút – 100% traffic sang version mới

    Sau 5 phút, CodeDeploy tự chuyển 100% traffic sang task set mới. Chạy lại lệnh đếm ở Bước 4 – toàn bộ 20 request trả về v4. Sau thêm 5 phút (Original revision termination), task set cũ bị terminate và pipeline Succeeded.

  6. Bước 6 (tuỳ chọn): Thử Linear & rollback
    • Đổi deployment configuration sang CodeDeployDefault.ECSLinear10PercentEvery1Minutes, push code và quan sát traffic tăng 10% mỗi phút.
    • Trong giai đoạn canary, bấm Stop and roll back deployment: traffic quay về 100% version cũ ngay lập tức.
Có cần tăng số task lên 4? Không bắt buộc. Với CodeDeploy, task set mới được tạo với đủ số task như task set cũ, còn tỷ lệ 25% được điều khiển bằng trọng số của ALB – không phụ thuộc số task. Tăng desired_count chỉ giúp mô phỏng hệ thống lớn hơn (và tốn chi phí hơn).

Kiểm tra kết quả

✅ Lab thành công khi

  • Trong 5 phút đầu, khoảng 25% request trả về v4, listener 80 có trọng số 75/25.
  • Sau 5 phút, 100% request trả về v4; deployment và pipeline Succeeded.

Troubleshoot

Deployment vẫn dừng ở bước chờ reroute, không tự chuyển 25%
Nguyên nhân: Deployment group vẫn để Specify when to reroute traffic từ Lab 7.
Giải pháp: Bấm Reroute traffic để tiếp tục lần này, sau đó sửa deployment group thành Reroute traffic immediately.
Traffic chuyển 100% ngay, không có giai đoạn 25%
Nguyên nhân: Deployment group vẫn dùng CodeDeployDefault.ECSAllAtOnce, hoặc pipeline chạy trước khi bạn lưu thay đổi.
Giải pháp: Kiểm tra lại Bước 2, xem cột Deployment configuration của deployment vừa chạy.
Tỷ lệ đếm được lệch nhiều so với 25%
Nguyên nhân: Số mẫu nhỏ, hoặc curl tái sử dụng kết nối.
Giải pháp: Tăng số request (ví dụ seq 1 100); tỷ lệ sẽ tiến gần 25%.
