9. CI/CD với AWS CodePipeline / Lab 5: CodePipeline – GitHub → CodeBuild → Elastic Beanstalk

Mục tiêu

  • Tạo Elastic Beanstalk application + environment chạy Java (Corretto 17) bằng file .jar của Lab 2, kiểm tra ứng dụng chạy thành công.
  • Tạo pipeline đầu tiên trong CodePipeline: Source (GitHub) → Build (CodeBuild Lab 2) → Deploy (Elastic Beanstalk).
  • Sửa code, push lên GitHub và quan sát pipeline được trigger tự động, Elastic Beanstalk được cập nhật version mới.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 2: CodeBuild project java-project-build build thành công, file demo-v0.0.2.jar trên S3 (đã tải về máy ở Lab 2 – Bước 5). Webhook của project ở Lab 2 đã tắt.
  • Không bắt buộc kinh nghiệm với Elastic Beanstalk – lab hướng dẫn đầy đủ các thông số cần thiết.
  • Source code: sourcecode/section_9_code_pipeline/lab5_pipeline_beanstalk/commands.sh.

Các bước thực hành

  1. Bước 1: Chuẩn bị IAM role cho Elastic Beanstalk

    Elastic Beanstalk cần 2 role. Nếu tài khoản chưa có, tạo trong IAM:

    • EC2 instance profile aws-elasticbeanstalk-ec2-role: trusted entity EC2, gắn policy AWSElasticBeanstalkWebTier, AWSElasticBeanstalkWorkerTier, AWSElasticBeanstalkMulticontainerDocker.
    • Service role aws-elasticbeanstalk-service-role: có thể để Console tạo tự động ở Bước 2.
  2. Bước 2: Tạo Elastic Beanstalk application & environment

    Vào Elastic Beanstalk → Create application với các thông số:

    • Environment tier: Web server environment
    • Application name: java-beanstalk-app; Environment name: java-beanstalk-dev
    • Platform: Java, Platform branch: Corretto 17 running on 64bit Amazon Linux 2023, Platform version: bản Recommended
    • Application code: Upload your code, Version label v1, chọn file demo-v0.0.2.jar
    • Presets: Single instance (free tier eligible)
    • Service role: aws-elasticbeanstalk-service-role (tạo mới nếu chưa có); EC2 instance profile: aws-elasticbeanstalk-ec2-role
    • Networking: Default VPC, Public IP address: Activated; Instance type: t3.micro
    • Các thiết lập khác: để mặc định

    Quá trình tạo environment mất khoảng 3–5 phút. Ứng dụng Spring Boot lắng nghe port 5000 – trùng với port mặc định mà nginx của Elastic Beanstalk proxy tới.

  3. Bước 3: Kiểm tra ứng dụng version 1

    Khi Health chuyển Ok, mở Domain của environment (dạng java-beanstalk-dev.eba-xxxx.ap-southeast-1.elasticbeanstalk.com). Trang hiển thị dòng chữ xanh lá Congratulations, your app has been deployed!

  4. Bước 4: Tạo pipeline – thông tin chung & Source stage

    Vào CodePipeline → Create pipeline, chọn Build custom pipeline, nhập các thông số:

    • Pipeline name: java-beanstalk-pipeline; Execution mode: Superseded
    • Service role: New service role (tên mặc định AWSCodePipelineServiceRole-ap-southeast-1-java-beanstalk-pipeline)
    • Artifact store: Default location
    • Source provider: GitHub (via GitHub App); Connection: github-connection; Repository: <your-github-username>/java-elasticbeanstalk-sample; Default branch: main
    • Output artifact format: CodePipeline default
    • Trigger: Start the pipeline on push vào branch main
  5. Bước 5: Build stage & Deploy stage
    • Build provider: AWS CodeBuild; Region: Asia Pacific (Singapore); Project name: java-project-build; Build type: Single build
    • Test stage: Skip
    • Deploy provider: AWS Elastic Beanstalk; Application name: java-beanstalk-app; Environment name: java-beanstalk-dev

    Review và tạo pipeline. Pipeline chạy ngay lần đầu với commit mới nhất trên main.

    💡 Khi chạy trong pipeline, CodeBuild bỏ qua cấu hình Artifacts (S3) của project và trả output về artifact bucket của CodePipeline (BuildArtifact).

  6. Bước 6: Quan sát pipeline chạy

    Theo dõi 3 stage chuyển lần lượt sang Succeeded. Có thể bấm View details ở stage Build để mở log CodeBuild, và xem tab Events của Elastic Beanstalk environment để thấy quá trình deploy version mới.

  7. Bước 7: Sửa code & push để trigger pipeline

    Mở file src/main/java/com/deploy/aws/demo/controller/HelloController.java, đổi nội dung trả về, ví dụ:

    return new ResponseEntity<Object>("<h1 style='color:blue;'>Version 2 – deployed by CodePipeline!<h1>", HttpStatus.OK);
    cd ~/codepipeline-labs/java-elasticbeanstalk-sample
git add .
git commit -m "feat: update greeting message v2"
git push origin main

    Pipeline tự động chạy (xem cột Source hiển thị commit message mới). Khi stage Deploy thành công, tải lại trang web – nội dung mới màu xanh dương xuất hiện.

  8. Bước 8 (tuỳ chọn): Release change thủ công

    Trong pipeline, bấm Release change để chạy lại pipeline với commit mới nhất – hữu ích khi deploy lỗi do môi trường mà không có thay đổi code.

Kiểm tra kết quả

✅ Lab thành công khi

  • Pipeline java-beanstalk-pipeline có ít nhất 2 execution Succeeded, execution sau được trigger bởi lệnh git push.
  • Tab Application versions của Elastic Beanstalk có version mới do CodePipeline tạo.
  • Domain của environment hiển thị nội dung version 2.

Troubleshoot

Stage Build lỗi AccessDenied khi tải source / ghi artifact
Nguyên nhân: Service role của CodeBuild không có quyền với artifact bucket của CodePipeline (thường gặp khi chọn Custom location).
Giải pháp: Thêm quyền s3:GetObject, s3:PutObject trên bucket artifact của pipeline vào role codebuild-java-project-build-service-role.
Environment Health Severe, trang web trả về 502 Bad Gateway
Nguyên nhân: Ứng dụng không lắng nghe port 5000, hoặc artifact không chứa file .jar ở thư mục gốc.
Giải pháp: Kiểm tra server.port=5000 trong application.properties, discard-paths: yes trong buildspec; xem log bằng Logs → Request logs của environment.
Push code nhưng pipeline không tự chạy
Nguyên nhân: Push sai branch, hoặc trigger của pipeline không bật cho branch main.
Giải pháp: Edit pipeline → Source stage → kiểm tra Trigger (Push, branch main).
Deploy lỗi Insufficient permissions / không tạo được application version
Nguyên nhân: Service role của pipeline thiếu quyền Elastic Beanstalk, S3, Auto Scaling, CloudFormation.
Giải pháp: Dùng role do Console tạo mới; với role tự tạo, môi trường học có thể gắn tạm AdministratorAccess-AWSElasticBeanstalk.

Dọn dẹp resource

EC2 instance của Elastic Beanstalk tính phí theo giờ (cùng Public IPv4). Xoá environment ngay sau khi hoàn thành lab.

  1. Elastic Beanstalk → environment java-beanstalk-dev → Terminate environment, sau đó xoá application java-beanstalk-app.

  2. Xoá pipeline java-beanstalk-pipeline (hoặc giữ lại để tham khảo nhưng disable transition sang stage Deploy để push code không gây lỗi).

  3. Xoá bớt file lớn trong artifact bucket của CodePipeline và bucket codebuild-artifact-<your-suffix>.

  4. Giữ lại CodeBuild project java-project-build để tham khảo.
