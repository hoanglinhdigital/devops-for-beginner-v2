9. CI/CD với AWS CodePipeline / Lab 6: CodePipeline deploy lên ECS (Rolling update)

Mục tiêu

  • Triển khai stack VPC + ALB + ECS Fargate bằng Terraform có sẵn, chạy image của Lab 4.
  • Cập nhật buildspec của Lab 4 để sinh file imagedefinitions.json.
  • Tạo pipeline GitHub → CodeBuild → Amazon ECS, deploy theo phương án rolling update.
  • Sửa code, push và quan sát ECS thay thế dần task cũ bằng task mới qua ALB.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 4: ECR repository nodejs-random-color có image tag latest, CodeBuild project nodejs-docker-build.
  • Terraform >= 1.10, AWS CLI v2 đã cấu hình profile (Section 5).
  • Source code: sourcecode/section_9_code_pipeline/terraform_ecs_stack/ và sourcecode/section_9_code_pipeline/lab6_pipeline_ecs_rolling/.

Các bước thực hành

  1. Bước 1: Tìm hiểu Terraform stack

    Stack terraform_ecs_stack được dùng chung cho Lab 6 → Lab 9, gồm 4 module:

    ModuleResource
    networkingVPC 10.20.0.0/16, 2 public subnet ở 2 AZ (module terraform-aws-modules/vpc/aws), không NAT Gateway
    securitySG cho ALB (mở 80, 81), SG cho ECS task (chỉ nhận port 3000 từ SG của ALB)
    load_balancerALB, Target Group nodejs-tg-blue & nodejs-tg-green, listener 80 → Blue, listener 81 → Green
    ecsCluster codepipeline-lab-cluster, task definition nodejs-task-definition, service nodejs-service (2 task Fargate), log group, task execution role

    💡 Biến deployment_controller_type = ECS cho lab này. Service có lifecycle { ignore_changes = [task_definition, load_balancer] } để terraform apply sau này không ghi đè version do pipeline deploy.

  2. Bước 2: Cấu hình biến & apply Terraform 
    cd sourcecode/section_9_code_pipeline/terraform_ecs_stack
cp terraform.tfvars.example terraform.tfvars

    Mở file terraform.tfvars, sửa ecr_image_uri thành Image URI tag latest của bạn (Lab 4 – Bước 5) và giữ deployment_controller_type = "ECS":

    ecr_image_uri = "123456789012.dkr.ecr.ap-southeast-1.amazonaws.com/nodejs-random-color:latest"

desired_count = 2

# Lab 6: ECS (rolling update) | Lab 7, Lab 8: CODE_DEPLOY (Blue/Green, Canary)
deployment_controller_type = "ECS"
    terraform init
terraform plan
terraform apply
terraform output alb_dns_name
  3. Bước 3: Truy cập website qua ALB

    Chờ khoảng 1–2 phút để task RUNNING và Target Group nodejs-tg-blue báo healthy, sau đó truy cập http://<alb-dns-name>. Trang Welcome to My Website hiển thị – mỗi task tô tiêu đề một màu ngẫu nhiên, tải lại trang vài lần sẽ thấy màu thay đổi giữa 2 task.

  4. Bước 4: Cập nhật buildspec.yml để sinh imagedefinitions.json

    Copy nội dung lab6_pipeline_ecs_rolling/buildspec.yml đè lên buildspec.yml trong repository nodejs-random-color. Phần thay đổi so với Lab 4:

    env:
  variables:
    IMAGE_REPO_NAME: nodejs-random-color
    CONTAINER_NAME: nodejs-container
...
  post_build:
    commands:
      - echo Pushing the Docker image...
      - docker push $REPOSITORY_URI:latest
      - docker push $REPOSITORY_URI:$COMMIT_HASH
      - echo Writing imagedefinitions.json...
      - printf '[{"name":"%s","imageUri":"%s"}]' $CONTAINER_NAME $REPOSITORY_URI:$COMMIT_HASH > imagedefinitions.json
      - cat imagedefinitions.json
      - echo Build completed on `date`

artifacts:
  files:
    - imagedefinitions.json

    💡 Action deploy Amazon ECS đọc imagedefinitions.json để biết container nào (nodejs-container – phải trùng tên container trong task definition) cần đổi sang image nào, sau đó tạo task definition revision mới và cập nhật service.

    cd ~/codepipeline-labs/nodejs-random-color
git add buildspec.yml
git commit -m "ci: generate imagedefinitions.json for ECS deploy"
git push origin master
  5. Bước 5: Tạo pipeline

    Vào CodePipeline → Create pipeline → Build custom pipeline với các thông số:

    • Pipeline name: nodejs-ecs-rolling-pipeline; Execution mode: Superseded; Service role: New service role
    • Source: GitHub (via GitHub App), connection github-connection, repository <your-github-username>/nodejs-random-color, branch master, trigger khi push
    • Build: AWS CodeBuild, project nodejs-docker-build, Single build
    • Test: Skip
    • Deploy provider: Amazon ECS; Cluster name: codepipeline-lab-cluster; Service name: nodejs-service; Image definitions file: imagedefinitions.json

    Tạo pipeline – lần chạy đầu tiên deploy commit vừa push ở Bước 4.

  6. Bước 6: Sửa code & push để trigger pipeline

    Mở public/index.html, sửa phần text của thẻ <h1 id="welcome" ...>, ví dụ Welcome to My Website – v2 Rolling update. Giữ nguyên thuộc tính id và style – index.js dựa vào chúng để đổi màu ngẫu nhiên khi container khởi động.

    git add public/index.html
git commit -m "feat: update welcome message v2"
git push origin master
  7. Bước 7: Quan sát rolling update

    Trong lúc stage Deploy đang chạy, mở ECS → nodejs-service → tab Deployments: có 2 deployment (Primary – revision mới, Active – revision cũ), task mới được khởi động trước, task cũ bị dừng sau khi task mới healthy. Gọi ALB liên tục để thấy giai đoạn 2 version cùng phục vụ (thay <alb-dns-name>, nhấn Ctrl + C để dừng):

    while true; do curl -s http://<alb-dns-name>/ | grep -o "<h1[^>]*>[^<]*"; sleep 1; done

    Vào ECS → Task definitions → nodejs-task-definition: có revision mới với image tag là commit SHA vừa push.

Kiểm tra kết quả

✅ Lab thành công khi

  • Pipeline nodejs-ecs-rolling-pipeline chạy Succeeded cả 3 stage sau khi push code.
  • ECR có image tag commit SHA mới; task definition có revision mới dùng đúng image đó.
  • Truy cập http://<alb-dns-name> hiển thị nội dung version 2, không bị gián đoạn trong lúc deploy.

Troubleshoot

Deploy lỗi Exception while trying to read the image artifact file. Please check the image artifact file and retry.
Nguyên nhân: BuildArtifact không có file imagedefinitions.json (buildspec chưa cập nhật, hoặc thiếu mục artifacts).
Giải pháp: Kiểm tra buildspec trên GitHub đã là bản của Lab 6, log build có dòng cat imagedefinitions.json.
Deploy lỗi Invalid action configuration: The AWS ECS container nodejs-container does not exist
Nguyên nhân: Tên container trong imagedefinitions.json khác tên container trong task definition.
Giải pháp: Giữ CONTAINER_NAME: nodejs-container trong buildspec trùng với Terraform.
Task mới liên tục bị dừng, deployment bị rollback bởi circuit breaker
Nguyên nhân: Container lỗi khi khởi động hoặc health check của Target Group thất bại.
Giải pháp: Xem tab Logs của task (log group /ecs/nodejs-random-color) và lý do dừng trong tab Tasks → Stopped; chạy thử image trên máy local như Lab 4 – Bước 6.
CannotPullContainerError khi task khởi động
Nguyên nhân: Sai ecr_image_uri trong terraform.tfvars (sai Account ID, region, tag).
Giải pháp: Copy lại Image URI từ ECR Console, chạy terraform apply.
Truy cập ALB trả về 503 Service Temporarily Unavailable
Nguyên nhân: Target Group chưa có target healthy (task đang khởi động hoặc bị lỗi).
Giải pháp: Chờ 1–2 phút, kiểm tra tab Targets của nodejs-tg-blue.

Dọn dẹp resource

ALB, task Fargate và Public IPv4 tính phí theo giờ. Nếu học tiếp Lab 7 ngay, giữ lại Terraform stack; nếu không, chạy terraform destroy.

  2. Nếu dừng lại ở lab này, xoá toàn bộ stack:
