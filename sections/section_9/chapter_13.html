9. CI/CD với AWS CodePipeline / Lab 9: Manual approval & notification trong CodePipeline

Mục tiêu

  • Tạo notification rule gửi email khi pipeline bắt đầu, thành công, thất bại và khi cần phê duyệt.
  • Tạo notification rule cho các event của CodeDeploy (deployment started / succeeded / failed).
  • Thêm stage Approval (Manual approval) trước stage Deploy – mô phỏng quy trình Team Lead duyệt trước khi release production.
  • Push code, chờ đến bước phê duyệt, Approve / Reject và quan sát kết quả.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 7 (hoặc Lab 8): pipeline nodejs-ecs-bluegreen-pipeline chạy thành công, Terraform stack đang chạy.
  • Một địa chỉ email có thể nhận thư để xác nhận subscription của SNS.
  • Lab thao tác hoàn toàn trên AWS Console, không có source code riêng.

Các bước thực hành

  1. Bước 1: Tạo notification rule cho pipeline & SNS topic

    Mở pipeline nodejs-ecs-bluegreen-pipeline → Notify → Create notification rule với các thông số:

    • Notification name: nodejs-pipeline-notify; Detail type: Full
    • Events: Pipeline execution – Started, Succeeded, Failed; Manual approval – Needed
    • Targets: Create target → Target type SNS topic, Topic name pipeline-topic (Console tạo topic codestar-notifications-pipeline-topic với access policy cho phép dịch vụ notification publish)
  2. Bước 2: Đăng ký email vào SNS topic

    Vào Amazon SNS → Topics → codestar-notifications-pipeline-topic, tạo subscription:

    • Protocol: Email; Endpoint: email của bạn

    Mở hộp thư, bấm Confirm subscription trong email từ AWS Notifications. Subscription chuyển sang trạng thái Confirmed.

  3. Bước 3: Tạo notification rule cho CodeDeploy

    Mở CodeDeploy application nodejs-ecs-app → Notify → Create notification rule:

    • Notification name: nodejs-codedeploy-notify; Detail type: Basic
    • Events: Deployment – Started, Succeeded, Failed
    • Targets: SNS topic codestar-notifications-pipeline-topic (dùng lại topic ở Bước 1)
  4. Bước 4: Thêm stage Approval vào pipeline

    Edit pipeline, thêm stage mới giữa Build và Deploy:

    • Stage name: Approval
    • Action name: ManualApproval; Action provider: Manual approval
    • SNS topic ARN: codestar-notifications-pipeline-topic (tuỳ chọn – đã có notification rule ở Bước 1)
    • URL for review: link commit trên GitHub, ví dụ https://github.com/<your-github-username>/nodejs-random-color/commits/master
    • Comments: Review thay đổi trước khi deploy lên production

    Lưu pipeline (Save).

  5. Bước 5: Push code & chờ phê duyệt

    Sửa text thẻ <h1> trong public/index.html thành Welcome to My Website – v5 Approved:

    cd ~/codepipeline-labs/nodejs-random-color
git add public/index.html
git commit -m "feat: update welcome message v5 approved"
git push origin master

    Pipeline chạy Source → Build rồi dừng ở stage Approval với trạng thái Waiting for approval. Bạn nhận được các email: pipeline execution started và manual approval needed.

  6. Bước 6: Approve

    Trên stage Approval bấm Review, mở URL review để xem commit, nhập comment (ví dụ LGTM – approved by Team Lead) và chọn Approve. Stage Deploy chạy tiếp, bạn nhận thêm email deployment started / succeeded từ CodeDeploy và pipeline execution succeeded.

  7. Bước 7 (tuỳ chọn): Reject

    Sửa code thêm một lần nữa và push. Ở bước phê duyệt chọn Reject kèm lý do: stage Approval chuyển Failed, pipeline dừng, version mới không được deploy – website giữ nguyên v5. Bạn nhận email pipeline execution failed.

Kiểm tra kết quả

✅ Lab thành công khi

  • Pipeline có 4 stage: Source → Build → Approval → Deploy.
  • Nhận được email khi pipeline bắt đầu, khi cần phê duyệt, khi CodeDeploy deploy và khi pipeline kết thúc.
  • Sau khi Approve, website hiển thị v5; khi Reject, version mới không được deploy.
  • Lịch sử execution lưu lại người phê duyệt và comment.

Troubleshoot

Không nhận được email nào
Nguyên nhân: Chưa confirm subscription, email rơi vào Spam, hoặc topic không cho phép codestar-notifications.amazonaws.com publish.
Giải pháp: Kiểm tra trạng thái subscription; tạo topic bằng nút Create target trong notification rule như Bước 1 (nếu tự tạo topic, phải thêm access policy cho service principal codestar-notifications.amazonaws.com).
Stage Approval lỗi The provided role does not have sufficient permissions ... sns:Publish
Nguyên nhân: Service role của pipeline không có quyền publish lên SNS topic đã chọn trong action.
Giải pháp: Thêm quyền sns:Publish trên ARN của topic vào role của pipeline, hoặc bỏ trống SNS topic ARN trong action (đã có notification rule gửi email).
Email nhận được là chuỗi JSON khó đọc
Nguyên nhân: Notification gửi nội dung event dạng JSON tới SNS Email.
Giải pháp: Chọn Detail type Basic để gọn hơn; trong thực tế nên dùng target Amazon Q Developer in chat applications (tên cũ: AWS Chatbot) để gửi thông báo dạng dễ đọc vào Slack / Microsoft Teams.
