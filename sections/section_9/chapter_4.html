9. CI/CD với AWS CodePipeline / Lab 2: CodeBuild – Build Java project, lưu artifact lên S3

Mục tiêu

  • Viết file buildspec.yml cho project Java (Maven, Corretto 17) và commit vào repository.
  • Tạo CodeBuild project đọc source từ GitHub qua connection đã tạo ở Lab 1.
  • Chạy build, đọc log từng phase và kiểm tra file .jar được upload lên S3.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 1: repository java-elasticbeanstalk-sample đã fork & clone, connection github-connection ở trạng thái Available, S3 bucket codebuild-artifact-<your-suffix>.
  • Source code: sourcecode/section_9_code_pipeline/lab2_codebuild_java/buildspec.yml.

Các bước thực hành

  1. Bước 1: Thêm buildspec.yml vào repository

    Tạo file buildspec.yml tại thư mục gốc của repository java-elasticbeanstalk-sample, copy nội dung từ file lab2_codebuild_java/buildspec.yml:

    version: 0.2

phases:
  install:
    runtime-versions:
      java: corretto17
  pre_build:
    commands:
      - echo Java version
      - java -version
      - mvn -version
  build:
    commands:
      - echo Build started on `date`
      - mvn clean package -DskipTests
  post_build:
    commands:
      - echo Build completed on `date`
      - ls -lh target/*.jar

artifacts:
  files:
    - target/*.jar
  discard-paths: yes

cache:
  paths:
    - '/root/.m2/**/*'

    💡 discard-paths: yes bỏ đường dẫn target/, file jar nằm ngay ở gốc artifact – cần thiết cho việc deploy lên Elastic Beanstalk ở Lab 5.

    Commit & push:

    cd ~/codepipeline-labs/java-elasticbeanstalk-sample
git add buildspec.yml
git commit -m "ci: add buildspec for CodeBuild"
git push origin main
  2. Bước 2: Tạo CodeBuild project – phần Source

    Vào CodeBuild → Build projects, tạo build project với các thông số:

    • Project name: java-project-build
    • Source provider: GitHub
    • Credential: dùng GitHub App với connection github-connection (thiết lập làm default source credential nếu Console yêu cầu)
    • Repository: <your-github-username>/java-elasticbeanstalk-sample
    • Source version: main
    • Webhook (Primary source webhook events): không bật – lab này chạy build thủ công
  3. Bước 3: Cấu hình Environment, Buildspec, Artifacts, Logs
    • Provisioning model: On-demand; Environment image: Managed image; Compute: EC2
    • Operating system: Amazon Linux; Runtime: Standard; Image: aws/codebuild/amazonlinux-x86_64-standard:5.0; Image version: luôn dùng bản mới nhất
    • Service role: New service role, tên codebuild-java-project-build-service-role
    • Additional configuration: Compute 3 GB memory, 2 vCPUs; Timeout 15 phút
    • Buildspec: Use a buildspec file (để trống tên – mặc định đọc buildspec.yml)
    • Artifacts: Type Amazon S3; Bucket codebuild-artifact-<your-suffix>; Name java-artifact; Path: để trống; Namespace type: None; Artifacts packaging: None
    • Logs: bật CloudWatch logs, Group name /codebuild/java-project-build

    Tạo project. CodeBuild tự tạo service role với quyền ghi log và ghi vào bucket artifact đã chọn.

  4. Bước 4: Chạy build & theo dõi log

    Chọn project java-project-build → Start build. Theo dõi:

    • Tab Phase details: các phase SUBMITTED → PROVISIONING → DOWNLOAD_SOURCE → INSTALL → PRE_BUILD → BUILD → POST_BUILD → UPLOAD_ARTIFACTS → FINALIZING → COMPLETED.
    • Tab Build logs: output của java -version, quá trình Maven tải dependency và dòng BUILD SUCCESS.

    Lần build đầu mất khoảng 2–3 phút do Maven phải tải dependency.

  5. Bước 5: Kiểm tra artifact trên S3 
    aws s3 ls s3://codebuild-artifact-<your-suffix>/java-artifact/
2026-10-25 10:15:32   19876543 demo-v0.0.2.jar

    (Tuỳ chọn) Tải file về và chạy thử nếu máy bạn đã cài Java 17, sau đó truy cập http://localhost:5000:

    aws s3 cp s3://codebuild-artifact-<your-suffix>/java-artifact/demo-v0.0.2.jar .
java -jar demo-v0.0.2.jar
  6. Bước 6 (tuỳ chọn): Build tự động khi push code

    Edit project → Source → bật Rebuild every time a code change is pushed to this repository, Event type: PUSH. Sửa nội dung trong HelloController.java, commit & push – một build mới tự động chạy. Sau khi thử xong, tắt webhook để tránh trùng build khi dùng CodePipeline ở Lab 5.

Kiểm tra kết quả

✅ Lab thành công khi

  • Build của project java-project-build ở trạng thái Succeeded.
  • Log có dòng BUILD SUCCESS và output ls -lh target/*.jar.
  • S3 có file java-artifact/demo-v0.0.2.jar.

Troubleshoot

YAML_FILE_ERROR: stat /codebuild/output/.../buildspec.yml: no such file or directory
Nguyên nhân: File buildspec.yml chưa được push, đặt sai thư mục, hoặc build branch khác.
Giải pháp: Kiểm tra file nằm ở thư mục gốc repository trên GitHub, đúng tên (không phải buildspec.yaml) và Source version là main.
CLIENT_ERROR: authorization failed for primary source / repository not found
Nguyên nhân: Connection chưa Available hoặc GitHub App chưa được cấp quyền repository.
Giải pháp: Xem lại Lab 1 – Bước 3 và mục Troubleshoot của Lab 1.
Unknown runtime version named 'corretto17' of java
Nguyên nhân: Build image không hỗ trợ runtime khai báo trong runtime-versions.
Giải pháp: Dùng image aws/codebuild/amazonlinux-x86_64-standard:5.0, hoặc tra bảng Available runtimes trong tài liệu CodeBuild để chọn phiên bản phù hợp.
AccessDenied ở phase UPLOAD_ARTIFACTS hoặc không tạo được log stream
Nguyên nhân: Service role không có quyền với bucket/log group (thường do đổi bucket sau khi tạo project).
Giải pháp: Vào IAM, thêm quyền s3:PutObject cho bucket artifact và quyền CloudWatch Logs vào role codebuild-java-project-build-service-role. Môi trường học có thể gắn tạm AmazonS3FullAccess, CloudWatchLogsFullAccess.

Dọn dẹp resource

Giữ lại CodeBuild project java-project-build và artifact trên S3 – sẽ dùng lại trong Lab 5. CodeBuild không tính phí khi không có build đang chạy.
