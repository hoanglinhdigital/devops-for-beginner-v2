9. CI/CD với AWS CodePipeline / Lab 7: Blue/Green deployment lên ECS với CodeDeploy

Mục tiêu

  • Chuyển deployment controller của ECS service sang CODE_DEPLOY bằng Terraform (đã có sẵn Target Group Green và listener test port 81).
  • Tạo CodeDeploy application & deployment group cho ECS với chiến lược Blue/Green.
  • Chuẩn bị appspec.yaml, taskdef.json, imageDetail.json và tạo pipeline với action Amazon ECS (Blue/Green).
  • Kiểm thử version mới qua port 81, chủ động Reroute traffic và Terminate original task set.

Các bước thực hành

  1. Bước 1: Chuyển deployment controller sang CODE_DEPLOY

    Sửa terraform.tfvars:

    deployment_controller_type = "CODE_DEPLOY"
    cd sourcecode/section_9_code_pipeline/terraform_ecs_stack
terraform plan
terraform apply

    Đọc kỹ output của terraform plan: service nodejs-service được cập nhật deployment controller (hoặc tạo lại). Sau khi apply, truy cập http://<alb-dns-name> kiểm tra website vẫn hoạt động.

    💡 Listener 81 và Target Group Green đã được tạo sẵn từ Lab 6 nhưng chưa có target. Với controller CODE_DEPLOY, mọi thay đổi version của service phải đi qua CodeDeploy.

  2. Bước 2: Tạo IAM role cho CodeDeploy

    Vào IAM → Roles, tạo role với thông số:

    • Trusted entity: AWS service → CodeDeploy, use case CodeDeploy - ECS
    • Permission policy: AWSCodeDeployRoleForECS (được chọn tự động)
    • Role name: codedeploy-ecs-service-role
  3. Bước 3: Tạo CodeDeploy application

    Vào CodeDeploy → Applications, tạo application:

    • Application name: nodejs-ecs-app
    • Compute platform: Amazon ECS
  4. Bước 4: Tạo deployment group

    Trong application nodejs-ecs-app, tạo deployment group với các thông số:

    • Deployment group name: nodejs-ecs-dg; Service role: codedeploy-ecs-service-role
    • ECS cluster name: codepipeline-lab-cluster; ECS service name: nodejs-service
    • Load balancer: codepipeline-lab-alb; Production listener port: HTTP:80; Test listener port: HTTP:81
    • Target group 1 name: nodejs-tg-blue; Target group 2 name: nodejs-tg-green
    • Traffic rerouting: Specify when to reroute traffic – chờ 10 phút (cho phép bạn test qua port 81 rồi bấm Reroute traffic thủ công)
    • Deployment configuration: CodeDeployDefault.ECSAllAtOnce
    • Original revision termination: chờ 10 phút sau khi reroute rồi mới terminate task set cũ
  5. Bước 5: Đưa appspec.yaml, taskdef.json, buildspec.yml vào repository

    Copy 3 file trong thư mục lab7_ecs_blue_green đè lên file cùng tên ở thư mục gốc repository nodejs-random-color (repository mẫu đã có sẵn appspec.yaml, taskdef.json với Account ID của tác giả – cần thay bằng bản mới).

    appspec.yaml – <TASK_DEFINITION> được CodePipeline tự điền ARN task definition revision mới:

    version: 0.0
Resources:
  - TargetService:
      Type: AWS::ECS::Service
      Properties:
        TaskDefinition: <TASK_DEFINITION>
        LoadBalancerInfo:
          ContainerName: "nodejs-container"
          ContainerPort: 3000

    taskdef.json – <IMAGE_NAME> được thay bằng image URI trong imageDetail.json, <AWS_ACCOUNT_ID> được buildspec thay bằng lệnh sed:

    {
    "family": "nodejs-task-definition",
    "executionRoleArn": "arn:aws:iam::<AWS_ACCOUNT_ID>:role/nodejs-task-execution-role",
    "networkMode": "awsvpc",
    "requiresCompatibilities": ["FARGATE"],
    "cpu": "256",
    "memory": "512",
    "containerDefinitions": [
        {
            "name": "nodejs-container",
            "image": "<IMAGE_NAME>",
            "essential": true,
            "portMappings": [{ "containerPort": 3000, "protocol": "tcp", "appProtocol": "http" }],
            "logConfiguration": { "logDriver": "awslogs", "options": { "...": "..." } }
        }
    ]
}

    Phần thay đổi của buildspec.yml so với Lab 6:

          - echo Writing imageDetail.json...
      - printf '{"ImageURI":"%s"}' $REPOSITORY_URI:$COMMIT_HASH > imageDetail.json
      - cat imageDetail.json
      - echo Replacing AWS_ACCOUNT_ID placeholder in taskdef.json...
      - sed -i "s/<AWS_ACCOUNT_ID>/$AWS_ACCOUNT_ID/g" taskdef.json

artifacts:
  files:
    - imagedefinitions.json
    - imageDetail.json
    - appspec.yaml
    - taskdef.json

    Đồng thời sửa text thẻ <h1> trong public/index.html thành Welcome to My Website – v3 Blue/Green, rồi commit & push:

    cd ~/codepipeline-labs/nodejs-random-color
git add appspec.yaml taskdef.json buildspec.yml public/index.html
git commit -m "ci: add appspec and taskdef for ECS blue/green"
git push origin master
  6. Bước 6: Tạo pipeline Blue/Green

    Tạo pipeline (Build custom pipeline) với các thông số:

    • Pipeline name: nodejs-ecs-bluegreen-pipeline; Execution mode: Superseded; Service role: New service role
    • Source: GitHub (via GitHub App), repository nodejs-random-color, branch master, trigger khi push
    • Build: AWS CodeBuild, project nodejs-docker-build
    • Test: Skip
    • Deploy provider: Amazon ECS (Blue/Green); CodeDeploy application: nodejs-ecs-app; Deployment group: nodejs-ecs-dg
    • Amazon ECS task definition: BuildArtifact – taskdef.json
    • AWS CodeDeploy AppSpec file: BuildArtifact – appspec.yaml
    • Dynamically update task definition image: input artifact BuildArtifact, placeholder text IMAGE_NAME

    Tạo pipeline – execution đầu tiên chạy với commit vừa push ở Bước 5.

  7. Bước 7: Theo dõi deployment & test qua port 81

    Khi stage Deploy đang chạy, bấm Details để mở deployment trên CodeDeploy. Các bước lần lượt: Deploying replacement task set → Test traffic route setup → Rerouting production traffic (đang chờ) → Wait original task set termination → Terminate original task set.

    Khi đến bước chờ reroute, so sánh 2 listener (thay <alb-dns-name>):

    curl -s http://<alb-dns-name>/ | grep -o "<h1[^>]*>[^<]*"
<h1 id="welcome" style="color: #3A7BC2;">Welcome to My Website – v2 Rolling update
curl -s http://<alb-dns-name>:81/ | grep -o "<h1[^>]*>[^<]*"
<h1 id="welcome" style="color: #E04F1A;">Welcome to My Website – v3 Blue/Green

    Port 80 (production) vẫn là version cũ, port 81 (test) đã là version mới – người dùng thật chưa bị ảnh hưởng.

  8. Bước 8: Reroute traffic & terminate task set cũ

    Version mới hoạt động đúng → trên trang deployment bấm Reroute traffic. Truy cập lại port 80: đã là v3. Mở ECS service → tab Deployments / Task sets để thấy 2 task set đang cùng tồn tại.

    Bấm Terminate original task set để xoá task set cũ ngay (không cần chờ 10 phút). Pipeline chuyển sang Succeeded.

    💡 Muốn quay lại version cũ trước khi terminate? Bấm Stop and roll back deployment – CodeDeploy đổi listener 80 về Target Group cũ gần như tức thì.

Kiểm tra kết quả

✅ Lab thành công khi

  • Deployment trên CodeDeploy ở trạng thái Succeeded, pipeline nodejs-ecs-bluegreen-pipeline Succeeded.
  • Trước khi reroute: port 80 trả về v2, port 81 trả về v3. Sau khi reroute: port 80 trả về v3.

Troubleshoot

terraform apply lỗi InvalidParameterException khi đổi deployment controller
Nguyên nhân: ECS không cho cập nhật trực tiếp deployment controller trong một số trường hợp (ví dụ service đang có deployment chạy).
Giải pháp: Chờ deployment hiện tại hoàn tất rồi apply lại, hoặc buộc tạo lại service: terraform apply -replace="module.ecs.aws_ecs_service.nodejs".
Exception while trying to read the task definition artifact file from: BuildArtifact
Nguyên nhân: taskdef.json hoặc appspec.yaml không có trong BuildArtifact.
Giải pháp: Kiểm tra mục artifacts.files trong buildspec và 2 file nằm ở thư mục gốc repository, đúng tên (phân biệt .yaml/.yml).
Task của replacement task set bị dừng, lỗi CannotPullContainerError ... <IMAGE_NAME>
Nguyên nhân: Placeholder không được thay: thiếu imageDetail.json, hoặc placeholder text trong action khác IMAGE_NAME.
Giải pháp: Edit stage Deploy, kiểm tra Dynamically update task definition image; kiểm tra log build có nội dung imageDetail.json.
ECS was unable to assume the role 'arn:aws:iam::<AWS_ACCOUNT_ID>:role/...' hoặc lỗi iam:PassRole
Nguyên nhân: executionRoleArn trong taskdef.json sai Account ID / tên role, hoặc pipeline role không được PassRole.
Giải pháp: Kiểm tra lệnh sed trong buildspec đã chạy; so sánh với output task_execution_role_arn của Terraform.
Deployment lỗi The ELB could not be found / Primary taskset target group must be behind listener
Nguyên nhân: Cấu hình listener/Target Group trong deployment group không khớp với ALB thực tế.
Giải pháp: Kiểm tra listener 80 đang forward tới Target Group mà service đang dùng; chọn lại đúng TG1/TG2 trong deployment group.
