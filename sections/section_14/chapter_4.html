13. Kubernetes (k8s) cơ bản / Lab 1: Cài đặt Minikube & chạy Pod đầu tiên

Mục tiêu

  • Cài đặt kubectl và Minikube để có một Kubernetes cluster chạy ngay trên máy cá nhân, xác nhận kết nối bằng kubectl get nodes.
  • Biết cách kiểm tra và chuyển context khi máy kết nối nhiều cluster.
  • Chạy một Pod nginx bằng lệnh kubectl run (imperative), xem chi tiết bằng kubectl get / kubectl describe.
  • Hiểu cấu trúc file YAML định nghĩa Pod và triển khai bằng kubectl apply -f (declarative).
  • Xoá Pod theo cả hai cách và hiểu vòng đời "tạo – chạy – xoá" của Pod.

Minikube tạo một cluster Kubernetes một node ngay trên máy bạn (dùng Docker/VirtualBox làm driver). kubectl là công cụ ra lệnh cho cluster: tạo Pod bằng lệnh trực tiếp (kubectl run) hoặc khai báo qua file YAML (kubectl apply -f).

Yêu cầu trước khi bắt đầu

  • Đã cài Docker Desktop (bỏ qua nếu có sẵn – Section 8).
  • Kết nối internet để pull image nginx từ Docker Hub.
  • Source code: sourcecode/section_13_kubernetes_k8s_basic/lab1_minikube_first_pod/ (commands.sh + nginx-pod.yaml).

Các bước thực hành

Phần 1: Cài đặt Minikube & kubectl

  1. Bước 1: Cài đặt kubectl

    Tham khảo hướng dẫn chính thức theo hệ điều hành của bạn:

    # macOS: https://kubernetes.io/docs/tasks/tools/install-kubectl-macos/
# Windows / Linux: https://kubernetes.io/docs/tasks/tools/install-kubectl/

    Sau khi cài, kiểm tra phiên bản:

    kubectl version --client
  2. Bước 2: Cài đặt Minikube

    Tham khảo hướng dẫn chính thức:

    # https://minikube.sigs.k8s.io/docs/start/

    Bạn có thể cài Minikube trên máy cá nhân, máy ảo hoặc EC2. Kiểm tra phiên bản:

    minikube version
  3. Bước 3: Khởi động cluster Minikube 
    minikube start

    Lệnh này tạo một cluster Kubernetes một node. Kiểm tra các node của cluster:

    kubectl get nodes
NAME       STATUS   ROLES           AGE   VERSION
minikube   Ready    control-plane   84m   v1.27.4

    💡 Thấy node minikube với STATUS Ready là thành công.

Phần 2: Chạy Pod đầu tiên bằng kubectl

  1. Bước 4: Tạo một Pod bằng lệnh 
    kubectl run nginx-pod --image=nginx

    Cluster sẽ tạo Pod tên nginx-pod chạy image nginx (phiên bản latest từ Docker Hub).

  2. Bước 5: Liệt kê Pod 
    kubectl get pods
kubectl get pods -o wide

    -o wide hiển thị thêm cột IP, NODE – cho biết Pod đang nằm ở đâu.

  3. Bước 6: Xem chi tiết Pod 
    kubectl describe pod nginx-pod

    Đọc các thông tin: Events (lịch sử pull image, khởi động container), IP, image, namespace...

  4. Bước 7: Xoá Pod 
    kubectl delete pod nginx-pod

    Kiểm tra lại để chắc chắn Pod đã bị xoá:

    kubectl get pods

Phần 3: Triển khai Pod bằng file YAML

  1. Bước 8: Tạo file YAML định nghĩa Pod

    Trong thực tế, ta khai báo resource qua file YAML rồi apply lên cluster, thay vì gõ từng lệnh cho mỗi resource. Tạo file nginx-pod.yaml với nội dung sau:

    apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
spec:
  containers:
    - name: nginx-container
      image: nginx
      ports:
        - containerPort: 80
    • apiVersion + kind: loại resource (v1 / Pod).
    • metadata.name: tên Pod.
    • spec.containers: danh sách container, mỗi container có name, image, ports.
  2. Bước 9: Apply file cấu hình 
    kubectl apply -f nginx-pod.yaml
  3. Bước 10: Kiểm tra Pod được tạo 
    kubectl get pods
kubectl get pods -o wide
  4. Bước 11: Xoá Pod bằng file YAML 
    kubectl delete -f nginx-pod.yaml

    Kiểm tra lại:

    kubectl get pods

Kiểm tra kết quả

✅ Lab thành công khi

  • kubectl version --client và minikube version trả về phiên bản hợp lệ.
  • kubectl get nodes hiển thị node minikube ở trạng thái Ready.
  • Sau kubectl run và sau kubectl apply -f nginx-pod.yaml, kubectl get pods đều hiển thị nginx-pod với STATUS Running.
  • kubectl describe pod nginx-pod cho thấy image nginx và các Events.
  • Sau kubectl delete pod nginx-pod / kubectl delete -f nginx-pod.yaml, kubectl get pods không còn Pod nào.

Troubleshoot

kubectl get nodes trả về node không phải minikube
Nguyên nhân: máy bạn đang kết nối tới một cluster khác (ví dụ Docker Desktop).
Giải pháp: xem danh sách context và chuyển về minikube: 
kubectl config get-contexts
CURRENT   NAME                   CLUSTER                AUTHINFO               NAMESPACE
          docker-desktop         docker-desktop         docker-desktop
*         minikube               minikube               minikube               default
kubectl config use-context minikube
(Dấu * là context đang được trỏ đến; dùng kubectl config use-context <tên> để chuyển.)
minikube ip trả về lỗi hoặc minikube không khởi động được
Nguyên nhân: Docker context/daemon bị lệch.
Giải pháp: kiểm tra và chuyển Docker về context mặc định: 
docker info
docker context ls
docker context use default
Sau đó restart Docker: trên Windows restart Docker Desktop; trên Linux systemctl restart docker; trên macOS restart Docker Desktop.
Unable to connect to the server
Nguyên nhân: Minikube chưa chạy hoặc sai context.
Giải pháp: chạy minikube start rồi kubectl config use-context minikube.
ContainerCreating kéo dài hoặc ImagePullBackOff
Nguyên nhân: chưa pull được image (mạng chậm, sai tên image).
Giải pháp: chờ vài phút rồi kubectl describe pod nginx-pod xem Events; kiểm tra kết nối internet và tên image đúng chính tả.
error: error parsing nginx-pod.yaml: ...
Nguyên nhân: sai cú pháp YAML (sai thụt lề, thiếu dấu gạch ngang).
Giải pháp: kiểm tra lại số dấu cách (dùng 2 hoặc 4 dấu cách, không dùng tab); đối chiếu với file mẫu.
Error from server (AlreadyExists): pods "nginx-pod" already exists
Nguyên nhân: Pod tạo ở Phần 2 chưa được xoá trước khi apply file YAML ở Phần 3.
Giải pháp: chạy kubectl delete pod nginx-pod rồi apply lại.
