13. Kubernetes (k8s) cơ bản / Persistent Volume & Storage Class

Giới thiệu

Pod là tạm thời, và dữ liệu trong container cũng mất khi Pod bị xoá. Với các ứng dụng cần lưu trữ lâu dài (database, service đọc/ghi file), ta cần Persistent Volume (PV) – một phần lưu trữ độc lập với vòng đời của Pod. PV có thể nằm trên ổ cứng của node, trên NFS hoặc trên cloud (EBS, EFS). Lưu ý quan trọng: Kubernetes không chịu trách nhiệm quản lý các disk – việc cấp phát và bảo trì disk do bạn (hoặc cloud provider) đảm nhiệm.

Đặc điểm chính

  • Độc lập với Pod: dữ liệu tồn tại cả khi Pod chết và được tạo lại.
  • Nằm ngoài namespace: PV là resource toàn cluster, Pod ở namespace nào cũng có thể claim.
  • Dùng qua PVC: Pod cần tạo Persistent Volume Claim (PVC) để định nghĩa mapping giữa Pod và volume thực tế.
  • Kubernetes không quản lý disk: bạn phải tự cấp ổ đĩa (EBS, NFS...) và khai báo cho Kubernetes.

Storage Class

Storage Class cung cấp cơ chế tạo và quản lý volume tự động: thay vì tự tạo PV thủ công, bạn định nghĩa một Storage Class (ví dụ tự tạo EBS khi cần), rồi PVC chỉ cần trỏ tới Storage Class đó để được cấp volume phù hợp.

Pod request volume qua PVC; PVC request volume qua Storage Class; Storage Class tự tạo các volume đáp ứng yêu cầu (dynamic provisioning).

Thực hành: Tạo Persistent Volume gắn vào Pod

Các bước thực hành

  1. Bước 1: Tạo file cấu hình PV + PVC + Service + Deployment

    Tạo file persistent-volume.yaml:

    apiVersion: v1
kind: PersistentVolume
metadata:
  name: my-pv
spec:
  capacity:
    storage: 1Gi
  accessModes:
    - ReadWriteOnce
  hostPath:
    path: /data/mysql
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
---
apiVersion: v1
kind: Service
metadata:
  name: mysql-service
spec:
  type: NodePort
  ports:
    - port: 3306
      targetPort: 3306
      nodePort: 30088
  selector:
    app: mysql
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mysql-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
        - name: mysql
          image: mysql
          env:
            - name: MYSQL_ROOT_PASSWORD
              value: password123
          ports:
            - containerPort: 3306
          volumeMounts:
            - name: mysql-persistent-storage
              mountPath: /var/lib/mysql
      volumes:
        - name: mysql-persistent-storage
          persistentVolumeClaim:
            claimName: my-pvc
  2. Bước 2: Deploy và kiểm tra 
    kubectl create -f persistent-volume.yaml
kubectl get all
kubectl get pv
kubectl get pvc
kubectl get pvc --all-namespaces
  3. Bước 3: Kết nối MySQL và insert dữ liệu

    Tạo tunnel tới Service:

    minikube service mysql-service --url
http://127.0.0.1:<port>

    Mở MySQL Workbench, kết nối với host = localhost, port từ lệnh trên, username = root, password = password123. Chạy script script.sql:

    CREATE DATABASE mydb;
USE mydb;
CREATE TABLE employee (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(50),
  age INT,
  salary DECIMAL(10,2)
);
INSERT INTO employee (name, age, salary) VALUES
  ('John Doe', 30, 5000),
  ('Jane Smith', 25, 4000),
  ('Mike Johnson', 35, 6000);
SELECT * FROM employee;
  4. Bước 4: Xoá Pod và quan sát tự phục hồi 
    kubectl get pods -o wide
kubectl delete pod mysql-deployment-<xxxxxx>

    Thay <xxxxxx> bằng đuôi ngẫu nhiên của Pod. Chờ Pod mới được tạo (Deployment tự phục hồi).

  5. Bước 5: Kiểm tra dữ liệu vẫn còn

    Truy cập lại MySQL Workbench và chạy:

    SELECT * FROM mydb.employee;

    Bạn sẽ thấy 3 bản ghi vẫn còn nguyên – dữ liệu được lưu trong PV, không mất khi Pod chết.

  6. Bước 6: Xoá resource 
    kubectl delete -f persistent-volume.yaml

Troubleshoot

PVC báo Pending không Bound được
Nguyên nhân: không có PV nào khớp (capacity/accessMode khác với yêu cầu).
Giải pháp: kiểm tra kubectl get pv; đảm bảo PV có đủ capacity: 1Gi và accessModes: ReadWriteOnce.
Pod báo CrashLoopBackOff
Nguyên nhân: thư mục /data/mysql trong minikube chưa tồn tại hoặc không ghi được.
Giải pháp: vào trong node tạo thư mục: minikube ssh -- sudo mkdir -p /data/mysql rồi apply lại.

Thông tin bổ sung

  • Access mode: ReadWriteOnce (một node ghi), ReadOnlyMany, ReadWriteMany – tuỳ loại storage hỗ trợ.
  • On Minikube: thường dùng hostPath (Local volume) để demo; trên cluster thật dùng StorageClass + EBS/EFS.
  • Mối quan hệ: PV là "ổ đĩa", PVC là "đơn xin dùng ổ đĩa", Storage Class là "nhà máy tự sản xuất ổ đĩa theo đơn".
  • Liên hệ Section 6: EBS volume đã học ở phần Linux cũng chính là storage backend phổ biến cho Kubernetes trên AWS.
