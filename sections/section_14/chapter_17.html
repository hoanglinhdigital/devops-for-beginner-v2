13. Kubernetes (k8s) cơ bản / Lab 5: Triển khai ứng dụng mẫu lên Kubernetes

Mục tiêu

  • Triển khai một ứng dụng mẫu (React + Express + MongoDB) lên cluster Kubernetes thật (tạo ở Lab 4).
  • Thực hành trọn vẹn quy trình: chạy thử local → build image → push ECR → viết manifest → deploy → expose bằng ALB.
  • Hiểu cách Ingress định tuyến /api → backend và / → frontend.

ALB đứng trước cluster chuyển traffic tới Ingress Nginx Controller (NodePort). Ingress định tuyến / → frontend, /api → backend; backend gọi tới MongoDB qua ClusterIP.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 4: đã có cluster kops và kết nối được bằng kubectl.
  • Có Docker và đã tạo ECR repositories cho backend & frontend.
  • Source code: sourcecode/section_13_kubernetes_k8s_basic/lab5_deploy_resources/.
Chi phí: lab chạy trên cluster thật (EC2) + ALB, tính phí theo giờ. Xoá hết khi hoàn thành.

Các bước thực hành

  1. Bước 1: Kiểm tra cluster & lấy ứng dụng mẫu 
    kubectl cluster-info
kubectl get nodes
git clone https://github.com/hoanglinhdigital/react-express-mongodb
  2. Bước 2: Chạy thử local bằng Docker Compose

    Trong thư mục frontend, mở package.json_local, copy dòng proxy vào package.json:

    "proxy": "http://backend:3000"

    Chạy thử (đảm bảo đúng định dạng JSON):

    docker-compose up -d

    Mở localhost:3000 để test. Sau khi xác nhận chạy tốt, xoá dòng proxy khỏi package.json (tránh lỗi khi deploy lên K8s) rồi dừng compose:

    docker-compose down --volumes
  3. Bước 3: Build image & push lên ECR

    Build và push image backend & frontend lên ECR (thay <AWS_ACCOUNT_ID>):

    aws ecr get-login-password --region ap-southeast-1 | docker login --username AWS --password-stdin <AWS_ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com
docker build -t <AWS_ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com/devops-lab13-backend:latest ./backend
docker push <AWS_ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com/devops-lab13-backend:latest
docker build -t <AWS_ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com/devops-lab13-frontend:latest ./frontend
docker push <AWS_ACCOUNT_ID>.dkr.ecr.ap-southeast-1.amazonaws.com/devops-lab13-frontend:latest

    💡 Đối với frontend, hãy chắc chắn đã xoá dòng proxy trong package.json trước khi build.

  4. Bước 4: Tạo file manifest cho các resource

    Tạo lab5.yaml (mongo, backend, frontend, Ingress). Tham khảo cấu trúc:

    # Mongo (ClusterIP)
apiVersion: v1
kind: Service
metadata:
  name: mongo
spec:
  type: ClusterIP
  selector:
    app: mongo
  ports:
    - protocol: TCP
      port: 27017
      targetPort: 27017
---
# Backend (Deployment + NodePort 30099) - image ECR
# Frontend (Deployment + NodePort 30088) - image ECR
---
# Ingress
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: ingress-nginx
spec:
  ingressClassName: nginx
  rules:
  - http:
      paths:
      - pathType: Prefix
        path: /api
        backend:
          service:
            name: backend
            port:
              number: 3000
      - pathType: Prefix
        path: /
        backend:
          service:
            name: frontend
            port:
              number: 3000

    💡 File đầy đủ tại lab5_deploy_resources/lab5.yaml; nhớ thay <AWS_ACCOUNT_ID> bằng Account ID của bạn.

  5. Bước 5: Cài Ingress Nginx Controller 
    kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.10.0/deploy/static/provider/baremetal/deploy.yaml
kubectl get services -n ingress-nginx

    Kết quả mong đợi: Service ingress-nginx-controller kiểu NodePort (vd 80:31646/TCP – ghi nhớ nodePort này).

  6. Bước 6: Deploy các resource 
    kubectl apply -f lab5.yaml
kubectl get pods
kubectl get services
kubectl get deployments
kubectl get ingress
kubectl describe ingress/ingress-nginx
  7. Bước 7: Tạo LoadBalancer + Target Group
    • Tạo Security Group cho ALB, cho phép HTTP:80 từ mọi nơi.
    • Tạo Application Load Balancer (internet-facing), listener port 80.
    • Tạo Target Group type Instance, port HTTP = nodePort của Ingress Nginx Controller (lấy ở Bước 5).
    • Cấu hình Security Group của các EC2 instance cho phép truy cập từ Security Group của ALB (all traffic).

    Truy cập DNS của Load Balancer trên trình duyệt để test ứng dụng.

Kiểm tra kết quả

✅ Lab thành công khi

  • kubectl get pods hiển thị các Pod backend, frontend, mongo ở trạng thái Running.
  • Truy cập DNS của ALB thấy giao diện ứng dụng; gọi /api nhận dữ liệu từ backend.

Troubleshoot

Frontend không gọi được backend (lỗi proxy)
Nguyên nhân: còn dòng proxy trong package.json của frontend.
Giải pháp: xoá dòng proxy, build lại image và deploy lại.
ALB trả 502 hoặc không nhận traffic
Nguyên nhân: target group chưa có instance healthy, sai port, hoặc SG chưa mở.
Giải pháp: kiểm tra target group type Instance, port đúng nodePort, và SG của instance cho phép traffic từ SG của ALB.

Dọn dẹp resource

Bắt buộc: xoá LoadBalancer, Target Group, các resource trên Kubernetes, sau đó xoá cluster kops và EC2 để tránh tốn phí.
kubectl delete -f lab5.yaml
# Trên kops admin server:
kops delete cluster --name hoanglinhdigital.com --state=s3://udemy-devops-kops --yes

Kiểm tra và xoá thêm: ALB, Target Group, EBS volume, NAT Gateway, Elastic IP, ECR (nếu không dùng nữa).
