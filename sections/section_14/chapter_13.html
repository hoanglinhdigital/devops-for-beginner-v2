13. Kubernetes (k8s) cơ bản / ConfigMap

Giới thiệu

ConfigMap là một đối tượng API dùng để lưu trữ các cấu hình không nhạy cảm dưới dạng key-value. Nó giúp tách cấu hình ra khỏi code và container, khiến ứng dụng dễ cấu hình và dễ di chuyển giữa các môi trường mà không phải sửa image.

Đặc điểm chính

  • Key-value: lưu cấu hình dạng chuỗi (vd name: "Linh", age: "20").
  • Không nhạy cảm: chỉ dành cho cấu hình thường; dữ liệu nhạy cảm (mật khẩu, token) nên dùng Secret.
  • Tách khỏi code: thay đổi cấu hình mà không cần build lại image.
  • 3 cách sử dụng: biến môi trường, command-line argument, hoặc mount thành file trong volume.

ConfigMap lưu cấu hình và được truyền vào Pod theo 3 cách: như biến môi trường, như đối số dòng lệnh, hoặc mount thành file trong volume (mỗi cặp key:value thành một file).

Ví dụ ConfigMap

apiVersion: v1
kind: ConfigMap
metadata:
  name: my-configmap
data:
  MYSQL_ROOT_PASSWORD: "123456789"
  name: "Linh"
  age: "20"

Đưa ConfigMap vào Pod dưới dạng biến môi trường:

spec:
  containers:
    - name: mysql
      image: mysql
      envFrom:
        - configMapRef:
            name: my-configmap

Thực hành: Tạo ConfigMap

Tạo ConfigMap lưu các key:value đơn giản, truyền vào Pod MySQL (NodePort) dưới dạng biến môi trường (envFrom), sau đó kết nối MySQL bằng thông tin trong ConfigMap.

Các bước thực hành

  1. Bước 1: Tạo file cấu hình ConfigMap + MySQL

    Tạo file configmap-simple.yaml:

    apiVersion: v1
kind: ConfigMap
metadata:
  name: my-configmap
data:
  MYSQL_ROOT_PASSWORD: "123456789"
  name: "Linh"
  age: "20"
---
# ... (PersistentVolume + PVC + Service NodePort giống phần thực hành Persistent Volume)
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mysql-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
        - name: mysql
          image: mysql
          envFrom:
            - configMapRef:
                name: my-configmap
          ports:
            - containerPort: 3306
          volumeMounts:
            - name: mysql-persistent-storage
              mountPath: /var/lib/mysql
      volumes:
        - name: mysql-persistent-storage
          persistentVolumeClaim:
            claimName: my-pvc

    💡 envFrom.configMapRef nạp toàn bộ key của ConfigMap thành biến môi trường, trong đó MYSQL_ROOT_PASSWORD sẽ được image MySQL tự động dùng làm mật khẩu root.

  2. Bước 2: Apply và kiểm tra ConfigMap 
    kubectl apply -f configmap-simple.yaml
kubectl get configmap my-configmap -o yaml
kubectl get pods
  3. Bước 3: Kiểm tra biến môi trường trong Pod

    Xem nội dung Pod để xác nhận env đã được nạp:

    kubectl get pods mysql-deployment-<xxxx> -o yaml

    (thay <xxxx> bằng đuôi Pod thực tế)

  4. Bước 4: Kết nối MySQL bằng thông tin trong ConfigMap 
    minikube service mysql-service --url
http://127.0.0.1:<port>

    Mở MySQL Workbench, kết nối với password 123456789 (giá trị trong ConfigMap) để xác nhận thành công.

  5. Bước 5: Xoá resource 
    kubectl delete -f configmap-simple.yaml

Kiểm tra kết quả

✅ Thực hành thành công khi

  • kubectl get configmap my-configmap -o yaml hiển thị 3 key:value.
  • MySQL khởi động và kết nối được với mật khẩu 123456789 từ ConfigMap.

Troubleshoot

MySQL không khởi động, báo lỗi password
Nguyên nhân: ConfigMap không có key MYSQL_ROOT_PASSWORD hoặc Pod chưa nạp env.
Giải pháp: kiểm tra lại data trong ConfigMap và envFrom trong Deployment.

Thông tin bổ sung

  • Xem ConfigMap: kubectl get configmap my-configmap -o yaml.
  • Mỗi key thành một file: khi mount ConfigMap vào volume, mỗi cặp key:value trở thành một file (tên file = key, nội dung = value).
  • Best practice: dùng ConfigMap cho mọi cấu hình không nhạy cảm; kết hợp với biến môi trường đã học ở phần Docker/ECS.
  • Giới hạn: ConfigMap không mã hoá; không đặt mật khẩu, key, token vào đây.
