10. CI/CD sử dụng Jenkins / Lab 1: Cài đặt Jenkins server trên EC2 (Ubuntu)

Mục tiêu

  • Tạo EC2 instance Ubuntu Server 24.04 LTS làm Jenkins server, gắn IAM Role để thao tác với S3, ECR, ECS ở các lab sau.
  • Cài Java 21 và Jenkins LTS theo hướng dẫn chính thức, chạy Jenkins như một service systemd.
  • Truy cập Jenkins Dashboard qua port 8080: unlock, cài plugin theo gợi ý, tạo tài khoản admin.
  • Cài sẵn các tool CI/CD dùng chung: Git, jq, AWS CLI v2.

Yêu cầu trước khi bắt đầu

  • AWS account, region ap-southeast-1 (Singapore); biết tạo EC2, Security Group, key pair (Section 4, Section 6 – Lab 1).
  • Terminal có lệnh ssh (Git Bash trên Windows, Terminal trên macOS/Linux).
  • GitHub account (dùng từ Lab 4).
  • Source code: sourcecode/section_10_cicd_with_jenkins/lab1_install_jenkins/commands.sh.

Các bước thực hành

  1. Bước 1: Tạo IAM Role cho Jenkins server

    Vào IAM → Roles, tạo role với các thông số:

    • Trusted entity: AWS service → EC2
    • Permissions policies: AmazonS3FullAccess, AmazonEC2ContainerRegistryPowerUser, AmazonECS_FullAccess
    • Role name: jenkins-server-role

    💡 Nhờ IAM Role, mọi lệnh aws ... chạy trong job Jenkins tự nhận credential tạm thời từ EC2 metadata – không cần tạo access key và lưu vào Jenkins. Các managed policy trên rộng hơn mức cần thiết để bài lab đơn giản; môi trường thật nên viết policy giới hạn đúng bucket, repository, cluster (least privilege).

  2. Bước 2: Tạo Security Group

    Vào EC2 → Security Groups, tạo SG trong Default VPC:

    • Name: jenkins-sg
    • Inbound: SSH (22) – Source My IP; Custom TCP 8080 – Source My IP
    • Outbound: giữ mặc định (All traffic)
  3. Bước 3: Tạo EC2 instance

    Vào EC2 → Launch instance với các thông số:

    • Name: jenkins-server
    • AMI: Ubuntu Server 24.04 LTS (HVM), SSD Volume Type – Architecture 64-bit (x86)
    • Instance type: t3.medium (2 vCPU, 4 GiB RAM)
    • Key pair: tạo mới jenkins-key (RSA, .pem) và lưu file về máy
    • Network: Default VPC, public subnet bất kỳ, Auto-assign public IP: Enable, Security Group jenkins-sg
    • Storage: 30 GiB gp3
    • Advanced details → IAM instance profile: jenkins-server-role

    💡 Public IP thay đổi mỗi lần Stop/Start instance. Nếu muốn giữ cố định (cần cho webhook ở Lab 9), bạn có thể gắn một Elastic IP – nhớ release khi dọn dẹp.

  4. Bước 4: SSH vào Jenkins server

    Mở Git Bash / Terminal tại thư mục chứa file jenkins-key.pem, thay <jenkins-public-ip> bằng Public IPv4 của instance:

    chmod 400 jenkins-key.pem
ssh -i jenkins-key.pem ubuntu@<jenkins-public-ip>
  5. Bước 5: Cài Java 21

    Jenkins là ứng dụng Java nên cần cài Java trước. Cài bản JDK (thay vì chỉ JRE) để dùng chung cho việc build Java ở Lab 4:

    sudo apt update
sudo apt install -y fontconfig openjdk-21-jdk
java -version
    openjdk version "21.0.x" ...
OpenJDK Runtime Environment (build 21.0.x+...-Ubuntu-...)
OpenJDK 64-Bit Server VM (build 21.0.x+..., mixed mode, sharing)
  6. Bước 6: Thêm Jenkins repository & cài Jenkins LTS

    Các lệnh dưới đây lấy từ hướng dẫn cài đặt chính thức (bản LTS – debian-stable):

    sudo wget -O /etc/apt/keyrings/jenkins-keyring.asc https://pkg.jenkins.io/debian-stable/jenkins.io-2023.key
echo "deb [signed-by=/etc/apt/keyrings/jenkins-keyring.asc] https://pkg.jenkins.io/debian-stable binary/" | sudo tee /etc/apt/sources.list.d/jenkins.list > /dev/null
sudo apt update
sudo apt install -y jenkins
    Jenkins định kỳ thay đổi signing key của repository. Nếu apt update báo lỗi NO_PUBKEY, mở link hướng dẫn chính thức ở trên và copy lại URL key mới nhất.
  7. Bước 7: Khởi động Jenkins 
    sudo systemctl enable --now jenkins
sudo systemctl status jenkins --no-pager
● jenkins.service - Jenkins Continuous Integration Server
     Loaded: loaded (/usr/lib/systemd/system/jenkins.service; enabled; preset: enabled)
     Active: active (running) since ...
...
sudo ss -tlnp | grep 8080

    💡 Package jenkins tạo sẵn user hệ thống jenkins – mọi job đều chạy bằng user này, thư mục dữ liệu là /var/lib/jenkins (xem lại Section 6 về system user & service).

  8. Bước 8: Unlock Jenkins & cài plugin theo gợi ý

    Lấy mật khẩu admin ban đầu:

    sudo cat /var/lib/jenkins/secrets/initialAdminPassword

    Mở trình duyệt http://<jenkins-public-ip>:8080 và hoàn tất màn hình setup:

    • Unlock Jenkins: dán mật khẩu vừa lấy.
    • Customize Jenkins: chọn Install suggested plugins (Git, Pipeline, Credentials Binding, GitHub, JUnit...) – chờ vài phút.
    • Create First Admin User: tạo user admin của bạn (username, password mạnh, email).
    • Instance Configuration: Jenkins URL giữ http://<jenkins-public-ip>:8080/.

    💡 Từ đây trở đi luôn đăng nhập bằng user admin vừa tạo. Nếu muốn đổi mật khẩu: click tên user ở góc phải → Security → Password.

  9. Bước 9: Cài các tool CI/CD dùng chung

    Quay lại cửa sổ SSH, cài Git, unzip, jq và AWS CLI v2 (Ubuntu 24.04 không còn package awscli trong apt):

    sudo apt install -y git unzip jq
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
unzip -q awscliv2.zip
sudo ./aws/install
rm -rf aws awscliv2.zip
git --version
jq --version
aws --version
  10. Bước 10: Kiểm tra IAM Role

    Chạy với cả user ubuntu và user jenkins – kết quả phải có assumed-role/jenkins-server-role/...:

    sudo -u jenkins aws sts get-caller-identity
{
    "UserId": "AROAXXXXXXXXXXXXXXXXX:i-0abc123def4567890",
    "Account": "123456789012",
    "Arn": "arn:aws:sts::123456789012:assumed-role/jenkins-server-role/i-0abc123def4567890"
}

Troubleshoot

Trình duyệt không mở được http://<jenkins-public-ip>:8080 (timeout)
Nguyên nhân: Security Group chưa mở 8080, IP của bạn đã đổi (My IP), hoặc Jenkins chưa chạy.
Giải pháp: Kiểm tra inbound rule của jenkins-sg (cập nhật lại My IP), chạy sudo ss -tlnp | grep 8080 trên server; dùng http:// chứ không phải https://.
apt update báo NO_PUBKEY / The following signatures couldn't be verified với pkg.jenkins.io
Nguyên nhân: Jenkins đã đổi signing key của repository.
Giải pháp: Lấy URL key mới trong hướng dẫn chính thức, chạy lại lệnh wget ở Bước 6 rồi sudo apt update.
Jenkins không khởi động được (failed) sau khi cài thêm một bản Java khác
Nguyên nhân: Java mặc định của hệ thống bị đổi sang version Jenkins không hỗ trợ.
Giải pháp: Xem log và chọn lại Java 21 bằng update-alternatives (gõ số tương ứng với java-21-openjdk rồi Enter): 
sudo journalctl -u jenkins -n 100 --no-pager
sudo update-alternatives --config java
sudo systemctl restart jenkins
aws sts get-caller-identity báo Unable to locate credentials
Nguyên nhân: Instance chưa gắn IAM Role.
Giải pháp: EC2 → chọn instance → Actions → Security → Modify IAM role → chọn jenkins-server-role, chờ vài giây rồi chạy lại.
Jenkins rất chậm hoặc treo khi cài plugin / build
Nguyên nhân: Instance quá nhỏ (t2.micro, t3.micro chỉ 1 GiB RAM).
Giải pháp: Stop instance → Actions → Instance settings → Change instance type → t3.medium → Start.

Dọn dẹp resource

Giữ lại Jenkins server cho các lab tiếp theo, nhưng hãy Stop instance mỗi khi nghỉ học – EC2 t3.medium và Public IPv4 tính phí theo giờ. Dữ liệu Jenkins nằm trên EBS volume nên không bị mất khi Stop. Việc terminate instance sẽ làm ở chương tổng kết.
