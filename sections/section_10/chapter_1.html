10. CI/CD sử dụng Jenkins / Giới thiệu Jenkins & CI/CD với Jenkins

Mục tiêu của section

  • Hiểu Jenkins là gì, kiến trúc và các thành phần cơ bản: controller, agent, job, plugin, workspace, credential.
  • Tự cài đặt một Jenkins server trên EC2, thiết lập các setting & plugin cơ bản.
  • Làm quen với Jenkins qua các bài lab từ dễ đến khó: job Freestyle, biến & credential, Declarative / Scripted Pipeline.
  • Tạo các job Build/Deploy cho từng loại project: Java (Maven), Node.js (Webpack), Docker image → S3, ECR, ECS.
  • Kết hợp Jenkins với GitHub (Pipeline from SCM, webhook, Git tag) và Slack để có một luồng CI/CD hoàn chỉnh.

Giới thiệu

Jenkins là công cụ mã nguồn mở (viết bằng Java) dùng để tự động hoá quy trình phát triển phần mềm: build source code, chạy automation test, đóng gói artifact, deploy ứng dụng và thông báo kết quả. Bạn định nghĩa công việc dưới dạng các job; Jenkins chạy job khi có người bấm nút, theo lịch hoặc khi có commit mới trên Git. Ở Section 9 bạn đã dùng dịch vụ managed của AWS (CodePipeline, CodeBuild); trong section này bạn sẽ tự host một CI/CD server – cách làm vẫn rất phổ biến ở doanh nghiệp, đặc biệt với hệ thống on-premise hoặc multi-cloud.

Tại sao Jenkins được sử dụng nhiều?

  • Miễn phí & mã nguồn mở: không tốn phí license, chỉ trả chi phí server chạy Jenkins.
  • Dễ bắt đầu: giao diện web thân thiện, tạo và quản lý job ngay trên trình duyệt; nâng cao dần lên Pipeline as Code (Jenkinsfile).
  • Đa nền tảng: chạy trên Linux, Windows, macOS, Docker, Kubernetes; build được mọi ngôn ngữ (Java, Node.js, Python, Go, .NET...).
  • Hệ sinh thái plugin khổng lồ: hơn 2.000 plugin tích hợp với Git, GitHub, Docker, AWS, Slack, SonarQube, Nexus...
  • Mở rộng linh hoạt: mô hình controller – agent cho phép phân tán build ra nhiều máy, chạy song song nhiều job.
  • Cộng đồng lớn: tài liệu, hướng dẫn, diễn đàn phong phú – gặp lỗi gì gần như đều đã có người gặp trước.

Các thành phần cơ bản

Thành phầnÝ nghĩa
Controller (tên cũ: master)Server Jenkins chính: giao diện web, lưu cấu hình job, lịch sử build, điều phối build. Thư mục dữ liệu JENKINS_HOME (/var/lib/jenkins).
Agent (node)Máy thực thi build. Bài lab dùng luôn controller làm agent (built-in node); production nên tách agent riêng (EC2, Docker, Kubernetes pod).
ExecutorMột "slot" chạy build trên agent – số executor = số build chạy song song tối đa trên agent đó.
Job / ProjectĐịnh nghĩa một công việc: lấy code ở đâu, chạy lệnh gì, trigger khi nào. Các loại chính: Freestyle, Pipeline, Multibranch Pipeline.
BuildMột lần chạy của job, đánh số tăng dần (#1, #2...), có log (Console Output) và trạng thái SUCCESS / FAILURE / UNSTABLE / ABORTED.
WorkspaceThư mục làm việc của job trên agent (/var/lib/jenkins/workspace/<job-name>) – nơi checkout code và build.
PluginMở rộng tính năng: Git, Pipeline, Credentials, GitHub, Slack Notification...
CredentialNơi lưu secret (password, SSH key, token) đã mã hoá; job tham chiếu qua credential ID, không ghi secret vào code.

Trade-off: Jenkins vs AWS CodePipeline vs GitHub Actions

Tiêu chíJenkins (tự host)AWS CodePipeline + CodeBuildGitHub Actions
Vận hànhTự cài đặt, nâng cấp, vá lỗi, backup, scaleFully managedFully managed (GitHub-hosted runner)
Chi phíMiễn phí license, trả tiền server chạy 24/7 + công vận hànhTheo phút build / phút actionTheo phút runner, có free quota
Tuỳ biến & pluginRất cao, hơn 2.000 pluginHạn chế hơnMarketplace lớn
Multi-cloud / on-premiseRất linh hoạt, chạy được trong mạng nội bộChủ yếu cho AWSLinh hoạt (self-hosted runner)
Bảo mậtTự chịu trách nhiệm: plugin cũ, lộ port, credentialIAM role, AWS quản lý hạ tầngOIDC + IAM role, GitHub quản lý hạ tầng
  • Nên dùng Jenkins khi cần chạy CI/CD trong mạng nội bộ / on-premise, multi-cloud, cần plugin đặc thù hoặc doanh nghiệp đã có sẵn hệ thống Jenkins.
  • Cân nhắc khi team nhỏ, không có người vận hành server CI/CD – managed service (CodePipeline, GitHub Actions) thường rẻ và an toàn hơn về tổng thể.
  • Dù dùng công cụ nào, khái niệm CI/CD là như nhau (Section 3): checkout → build → test → push artifact → deploy. Học Jenkins giúp bạn hiểu rõ từng bước "bên dưới" mà dịch vụ managed đã che đi.

Use Cases

Doanh nghiệp có hệ thống on-premise

Ngân hàng, công ty tài chính không cho source code ra Internet: Jenkins đặt trong mạng nội bộ, build và deploy lên server on-premise lẫn AWS qua VPN/Direct Connect.

Dự án nhiều loại ứng dụng

Một Jenkins phục vụ nhiều team: backend Java build ra .jar, frontend Vue build ra file tĩnh lên S3, microservice build Docker image lên ECR rồi deploy ECS.

Quy trình release theo nhánh & tag

Merge vào develop → tự động deploy môi trường Dev; tạo tag v1.2.0 trên master → Team Lead bấm job release lên Production, kết quả báo về Slack.

Thông tin bổ sung

  • Phiên bản: luôn dùng bản LTS (Long-Term Support, phát hành mỗi ~12 tuần) cho môi trường thật; bản Weekly có tính năng mới nhưng kém ổn định hơn. Jenkins LTS hiện tại yêu cầu Java 17 hoặc 21 – bài lab dùng Java 21.
  • Cấu hình server tối thiểu: 2 vCPU, 4 GiB RAM, 30 GiB ổ đĩa cho lab có build Docker (t3.medium). Server quá nhỏ (t3.micro) dễ bị treo khi chạy npm install, mvn hoặc docker build.
  • Chi phí: Jenkins miễn phí nhưng EC2 + Public IPv4 tính phí theo giờ. Hãy Stop instance khi không học, chỉ start lại khi làm lab (EBS volume vẫn giữ nguyên dữ liệu Jenkins).
  • Bảo mật: không mở port 8080 cho 0.0.0.0/0 lâu dài, luôn cập nhật plugin, dùng IAM Role thay vì access key, lưu secret trong Jenkins Credentials.
  • Lưu ý chứng chỉ: đề thi AWS (DVA, DOP) không hỏi sâu về Jenkins, nhưng có thể xuất hiện các tình huống "tích hợp Jenkins với CodePipeline/CodeBuild" hoặc "chuyển từ Jenkins sang dịch vụ managed".
