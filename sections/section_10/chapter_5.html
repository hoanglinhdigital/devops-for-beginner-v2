10. CI/CD sử dụng Jenkins / Jenkins Pipeline: Jenkinsfile, Declarative vs Scripted

Giới thiệu

Job Freestyle cấu hình hoàn toàn bằng giao diện – dễ bắt đầu nhưng khó review, khó tái sử dụng và không có lịch sử thay đổi. Jenkins Pipeline giải quyết vấn đề này bằng cách mô tả toàn bộ luồng CI/CD dưới dạng code (Pipeline as Code), viết bằng cú pháp dựa trên Groovy và thường lưu trong file Jenkinsfile cùng repository với source code. Pipeline có 2 kiểu cú pháp: Declarative (khuyến khích dùng) và Scripted (kiểu cũ, linh hoạt hơn).

Đặc điểm chính

  • Pipeline as Code: Jenkinsfile được commit, review qua Pull Request và có lịch sử trên Git như mọi file code khác.
  • Chia stage rõ ràng: Checkout → Build → Test → Push → Deploy hiển thị trực quan trên giao diện (Stage View / Pipeline Graph), biết ngay stage nào lỗi.
  • Bền vững (durable): pipeline có thể tiếp tục sau khi Jenkins restart; hỗ trợ chờ input (approval), chạy song song (parallel).
  • Xử lý kết quả: khối post (always / success / failure) để dọn dẹp, gửi notification.
  • Điều kiện & tham số: when để bật/tắt stage, parameters để nhận input khi build.
  • Tái sử dụng: cùng một Jenkinsfile chạy được cho nhiều nhánh (Multibranch Pipeline), có thể tách hàm dùng chung thành Shared Library.

Cấu trúc một Declarative Pipeline

flowchart TB P["pipeline { }"] --> A["agent – chạy ở đâu"] P --> O["options · tools · parameters · environment
cấu hình chung"] P --> S["stages { }"] S --> S1["stage('Build') { steps { sh ... } }"] S --> S2["stage('Deploy') { when { ... } steps { ... } }"] P --> PO["post { always · success · failure }"] 
pipeline {
    agent any                          // chạy trên agent bất kỳ (lab: built-in node)

    options {
        timeout(time: 15, unit: 'MINUTES')
    }

    tools {
        maven 'M3'                     // tool khai báo ở Manage Jenkins -> Tools
    }

    parameters {
        choice(name: 'ACTION', choices: ['BuildAndDeploy', 'OnlyBuild'])
    }

    environment {
        AWS_REGION = 'ap-southeast-1'  // biến môi trường cho mọi stage
        IMAGE_TAG  = "ver-${BUILD_NUMBER}"
    }

    stages {
        stage('Build') {
            steps {
                sh 'mvn -B clean package'
            }
        }
        stage('Deploy') {
            when {
                expression { params.ACTION == 'BuildAndDeploy' }
            }
            steps {
                echo "Deploying ${IMAGE_TAG} to ${AWS_REGION}"
            }
        }
    }

    post {
        always  { echo 'Luôn chạy – dọn dẹp workspace, docker image...' }
        success { echo 'Gửi notification thành công' }
        failure { echo 'Gửi notification lỗi' }
    }
}

Scripted Pipeline

Scripted Pipeline là dạng cũ của Jenkins Pipeline, viết bằng Groovy gần như "tự do": bắt đầu bằng khối node và thực thi tuần tự từ đầu đến cuối trong khối đó. Bạn sẽ thực hành ở Lab 11.

node {
    try {
        stage('Checkout') {
            git branch: 'master', url: 'https://github.com/<your-github-username>/nodejs-random-color.git'
        }
        stage('Build') {
            def tags = ["ver-${env.BUILD_NUMBER}", 'latest']   // biến & logic Groovy tuỳ ý
            for (t in tags) {
                sh "docker build -t nodejs-random-color:${t} ."
            }
        }
    } catch (err) {
        currentBuild.result = 'FAILURE'
        throw err
    } finally {
        echo "Kết quả: ${currentBuild.currentResult}"           // tương đương post { always }
    }
}

Use Cases

Chuẩn hoá CI cho cả công ty

Mỗi repository có một Jenkinsfile Declarative theo mẫu chung (Checkout → Build → Test → Scan → Push). Thay đổi pipeline được review qua Pull Request như code.

Release có điều kiện

Pipeline nhận parameter ACTION, dùng when để chỉ build, chỉ deploy (rollback về version cũ) hoặc cả hai – một job phục vụ nhiều tình huống vận hành.

Logic phức tạp

Deploy lần lượt lên danh sách 10 region, retry khi lỗi, đọc file cấu hình để quyết định bước tiếp theo – dùng khối script { } trong Declarative hoặc Scripted Pipeline.

Thông tin bổ sung

  • Pipeline Syntax / Snippet Generator: trong trang cấu hình Pipeline job có link Pipeline Syntax – chọn step (ví dụ git, withCredentials, checkout) và điền form để Jenkins sinh code giúp bạn.
  • Replay: với Pipeline job, có thể sửa tạm script và chạy lại một build cũ mà không cần sửa job – tiện để debug.
  • Mỗi sh là một process riêng: biến shell khai báo trong sh trước không tồn tại ở sh sau – gộp các lệnh liên quan vào một khối sh '''...''', hoặc ghi ra file / dùng environment.
  • Đừng chạy logic nặng bằng Groovy: code Groovy chạy trên controller; công việc build/test nên nằm trong sh để chạy trên agent.
  • Multibranch Pipeline: tự tạo job con cho mỗi nhánh/PR có Jenkinsfile – bước tiếp theo nên tìm hiểu sau khi hoàn thành section.
