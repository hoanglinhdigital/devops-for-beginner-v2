10. CI/CD sử dụng Jenkins / Lab 10: Job release theo Git tag & tham số ACTION

Mục tiêu

Thiết kế một job Jenkins cho production với các yêu cầu:

  • Job release được trigger thủ công (không tự động từ GitHub như Lab 9).
  • Code được checkout theo một Git tag chỉ định trên nhánh master (ví dụ v1.0.0) thay vì commit mới nhất; image trên ECR có tag trùng với Git tag.
  • Chọn được hành động: BuildAndDeploy, OnlyBuild, OnlyDeploy (dùng when trong Declarative Pipeline).
  • Stage deploy tạm thời dùng rolling update (force-new-deployment) cho ECS; thử rollback bằng OnlyDeploy một tag cũ.

Các bước thực hành

  1. Bước 1: Tạo job release có tham số

    Tạo New Item → Pipeline tên lab10-release-manual:

    • General → tick This project is parameterized:
      • String Parameter – Name VERSION, Default Value v1.0.0, Description Git tag cần release
      • Choice Parameter – Name ACTION, Choices (mỗi giá trị 1 dòng): BuildAndDeploy, OnlyBuild, OnlyDeploy
    • Triggers: không tick trigger nào (release thủ công)
    • Pipeline → Definition Pipeline script, dán nội dung lab10_release_by_tag/Jenkinsfile-release và sửa GIT_REPO
    // Lab 10 – Job release production: trigger thủ công, checkout theo Git tag trên nhánh master
// Job: lab10-release-manual | Pipeline definition: Pipeline script (dán nội dung file này)
// This project is parameterized:
//   - String parameter VERSION (Default: v1.0.0) – Git tag cần release, cũng là image tag trên ECR
//   - Choice parameter ACTION (BuildAndDeploy, OnlyBuild, OnlyDeploy – mỗi giá trị 1 dòng)
pipeline {
    agent any

    options {
        timeout(time: 20, unit: 'MINUTES')
        disableConcurrentBuilds()
    }

    environment {
        // Thay <your-github-username>; credential github-ssh-key đã tạo ở Lab 8
        GIT_REPO       = 'git@github.com:<your-github-username>/nodejs-random-color.git'
        GIT_CREDENTIAL = 'github-ssh-key'
        AWS_REGION     = 'ap-southeast-1'
        ECR_REPO       = 'nodejs-random-color'
        ECS_CLUSTER    = 'jenkins-lab-cluster'
        ECS_SERVICE    = 'nodejs-service'
        TASK_FAMILY    = 'jenkins-lab-nodejs-task'
        CONTAINER_NAME = 'nodejs-container'
    }

    stages {
        stage('Checkout using tag') {
            when {
                expression { params.ACTION in ['BuildAndDeploy', 'OnlyBuild'] }
            }
            steps {
                checkout scmGit(
                    branches: [[name: "refs/tags/${params.VERSION}"]],
                    userRemoteConfigs: [[url: "${GIT_REPO}", credentialsId: "${GIT_CREDENTIAL}"]]
                )
                sh 'git log -1 --oneline --decorate'
            }
        }

        stage('Build image') {
            when {
                expression { params.ACTION in ['BuildAndDeploy', 'OnlyBuild'] }
            }
            steps {
                sh 'docker build -t ${ECR_REPO}:${VERSION} .'
            }
        }

        stage('Push image to ECR') {
            when {
                expression { params.ACTION in ['BuildAndDeploy', 'OnlyBuild'] }
            }
            steps {
                sh '''
                    ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
                    ECR_REGISTRY=${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com
                    aws ecr get-login-password --region ${AWS_REGION} | docker login --username AWS --password-stdin ${ECR_REGISTRY}
                    docker tag ${ECR_REPO}:${VERSION} ${ECR_REGISTRY}/${ECR_REPO}:${VERSION}
                    docker push ${ECR_REGISTRY}/${ECR_REPO}:${VERSION}
                '''
            }
        }

        stage('Deploy to ECS') {
            when {
                expression { params.ACTION in ['BuildAndDeploy', 'OnlyDeploy'] }
            }
            steps {
                // Tạm thời dùng rolling update (force-new-deployment) giống Lab 7
                sh '''
                    ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
                    FULL_IMAGE=${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/${ECR_REPO}:${VERSION}
                    echo "Deploying image: ${FULL_IMAGE}"

                    # OnlyDeploy: image tag phải tồn tại sẵn trên ECR
                    aws ecr describe-images --region ${AWS_REGION} --repository-name ${ECR_REPO} --image-ids imageTag=${VERSION} > /dev/null

                    aws ecs describe-task-definition --region ${AWS_REGION} --task-definition ${TASK_FAMILY} |
                    jq --arg IMAGE "${FULL_IMAGE}" --arg NAME "${CONTAINER_NAME}" '.taskDefinition | (.containerDefinitions[] | select(.name == $NAME) | .image) = $IMAGE | del(.taskDefinitionArn, .revision, .status, .requiresAttributes, .compatibilities, .registeredAt, .registeredBy)' > new-task-definition.json

                    NEW_REVISION=$(aws ecs register-task-definition --region ${AWS_REGION} --cli-input-json file://new-task-definition.json --query 'taskDefinition.revision' --output text)
                    echo "New revision: ${TASK_FAMILY}:${NEW_REVISION}"

                    aws ecs update-service --region ${AWS_REGION} --cluster ${ECS_CLUSTER} --service ${ECS_SERVICE} --task-definition ${TASK_FAMILY}:${NEW_REVISION} --force-new-deployment > /dev/null
                    aws ecs wait services-stable --region ${AWS_REGION} --cluster ${ECS_CLUSTER} --services ${ECS_SERVICE}
                '''
            }
        }
    }

    post {
        always {
            sh 'docker image prune -f'
        }
        success {
            echo "Release ${params.VERSION} (${params.ACTION}) thành công!"
        }
    }
}
    Điểm mớiGiải thích
    checkout scmGit(branches: [[name: "refs/tags/${params.VERSION}"]], ...)Checkout đúng commit mà tag trỏ tới, thay vì commit mới nhất của một nhánh. Dùng nháy kép để Groovy thay giá trị VERSION.
    when { expression { params.ACTION in [...] } }Stage chỉ chạy khi điều kiện đúng; stage bị bỏ qua hiển thị màu xám (skipped) trên giao diện.
    Image tag = VERSIONImage trên ECR mang đúng tên release (v1.0.0) – nhìn tag biết ngay code nào đang chạy production.
    disableConcurrentBuilds()Không cho 2 lần release chạy cùng lúc.
  2. Bước 2: Đưa code từ develop lên master

    Có thể tạo Pull Request develop → master trên GitHub và merge, hoặc merge trực tiếp trên máy local:

    cd ~/jenkins-labs/nodejs-random-color
git checkout master
git pull origin master
git merge develop
git push origin master
  3. Bước 3: Tạo tag v1.0.0 trên master 
    git tag -a v1.0.0 -m "Release v1.0.0"
git push origin v1.0.0
git tag -l
  4. Bước 4: Release v1.0.0 (BuildAndDeploy)

    Mở job lab10-release-manual → Build with Parameters → VERSION = v1.0.0, ACTION = BuildAndDeploy → Build. Log stage checkout:

     > git checkout -f a1b2c3d4...
+ git log -1 --oneline --decorate
a1b2c3d (HEAD, tag: v1.0.0, origin/master) feat: update welcome message v3 from develop

    Sau khi job xong, website qua ALB hiển thị nội dung của v1.0.0; ECR có image tag v1.0.0.

  5. Bước 5: Chuẩn bị v1.0.1 (OnlyBuild)

    Sửa text thẻ <h1 id="welcome" ...> trong public/index.html thành Welcome to My Website – v1.0.1, commit lên master và tạo tag mới:

    git add public/index.html
git commit -m "feat: release v1.0.1"
git push origin master
git tag -a v1.0.1 -m "Release v1.0.1"
git push origin v1.0.1

    Chạy job với VERSION = v1.0.1, ACTION = OnlyBuild: stage Deploy to ECS bị skip – image v1.0.1 đã sẵn sàng trên ECR nhưng production vẫn chạy v1.0.0. Thực tế, bước này thường làm trước giờ release (build sẵn, chờ lịch deploy).

  6. Bước 6: Deploy v1.0.1 (OnlyDeploy)

    Chạy job với VERSION = v1.0.1, ACTION = OnlyDeploy: chỉ stage deploy chạy (không checkout, không build) → website hiển thị v1.0.1.

  7. Bước 7: Rollback về v1.0.0

    Giả sử v1.0.1 có lỗi: chạy job với VERSION = v1.0.0, ACTION = OnlyDeploy. Production quay về v1.0.0 chỉ trong vài phút, không cần build lại.

    aws ecr list-images --repository-name nodejs-random-color --region ap-southeast-1 --query 'imageIds[].imageTag'
curl -s http://<alb-dns-name>/ | grep -o "<h1[^>]*>[^<]*"

Kiểm tra kết quả

✅ Lab thành công khi

  • ECR có image tag v1.0.0 và v1.0.1.
  • Giao diện job hiển thị đúng stage bị skip theo từng giá trị ACTION.
  • Website qua ALB đổi đúng version sau mỗi lần OnlyDeploy (v1.0.1 → rollback v1.0.0).
  • Trang Parameters của từng build cho biết ai đã release version nào, lúc nào.

Troubleshoot

Couldn't find any revision to build. Verify the repository and branch configuration for this job.
Nguyên nhân: Tag chưa được push lên GitHub (git push thường không đẩy tag) hoặc nhập sai tên tag.
Giải pháp: Chạy git push origin v1.0.0, kiểm tra tab Tags trên GitHub.
OnlyDeploy lỗi ImageNotFoundException
Nguyên nhân: Version đó chưa từng được build (chưa có image trên ECR).
Giải pháp: Chạy OnlyBuild hoặc BuildAndDeploy cho version đó trước.
Không thấy nút Build with Parameters
Nguyên nhân: Chưa tick This project is parameterized.
Giải pháp: Làm lại Bước 1. Lưu ý tên parameter phân biệt hoa/thường (VERSION, ACTION).
Push một tag lên GitHub làm job lab09-cicd-nodejs-auto cũng chạy
Nguyên nhân & giải pháp: Webhook gửi push event cho cả tag; job Lab 9 sẽ kiểm tra nhánh develop và thường không có thay đổi mới nên không build. Nếu muốn tách hẳn, xoá webhook của Lab 9 sau khi học xong.
