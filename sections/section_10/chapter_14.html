10. CI/CD sử dụng Jenkins / Lab 12: Gửi notification kết quả job sang Slack

Mục tiêu

  • Tạo Slack channel và một Slack App (bot) cho Jenkins bằng app manifest.
  • Cài & cấu hình plugin Slack Notification, lưu Bot token vào Jenkins credential loại Secret text.
  • Tạo job có khối post { always { slackSend ... } } – notify kết quả sang Slack với màu theo trạng thái.
  • Chạy job trong trường hợp success và fail (giả lập unit test lỗi bằng parameter).

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 6 (Docker, ECR) và Lab 8 (credential github-ssh-key). Lab này không cần Terraform stack.
  • Slack workspace mà bạn có quyền cài app (tạo miễn phí tại slack.com nếu chưa có).
  • Source code: sourcecode/section_10_cicd_with_jenkins/lab12_slack_notification/ (slack-app-manifest.yaml, Jenkinsfile-slack).

Các bước thực hành

  1. Bước 1: Tạo Slack channel

    Trong Slack workspace, tạo channel #jenkins-notification (Public).

  2. Bước 2: Tạo Slack App cho Jenkins

    Truy cập api.slack.com/apps → Create New App → From a manifest, chọn workspace, dán nội dung slack-app-manifest.yaml (định dạng YAML):

    display_information:
  name: Jenkins
features:
  bot_user:
    display_name: Jenkins
    always_online: true
oauth_config:
  scopes:
    bot:
      - channels:read
      - chat:write
      - chat:write.customize
      - files:write
      - reactions:write
      - users:read
      - users:read.email
      - groups:read
settings:
  org_deploy_enabled: false
  socket_mode_enabled: false
  token_rotation_enabled: false

    Create → Install to Workspace → Allow. Vào OAuth & Permissions, copy Bot User OAuth Token (bắt đầu bằng xoxb-).

    💡 App "Jenkins CI" cũ trong Slack App Directory (dùng trong phiên bản trước của khoá học) đã ngừng hỗ trợ. Plugin Slack Notification hiện khuyến nghị tạo Slack App riêng với bot token như trên.

  3. Bước 3: Mời bot vào channel

    Trong channel #jenkins-notification, gõ lệnh sau và gửi:

    /invite @Jenkins
  4. Bước 4: Cài plugin Slack Notification

    Vào Manage Jenkins → Plugins → Available plugins, tìm Slack Notification → Install. Chờ cài xong (tick Restart Jenkins when installation is complete nếu được yêu cầu).

  5. Bước 5: Tạo credential cho Bot token

    Vào Manage Jenkins → Credentials → System → Global credentials → Add Credentials:

    • Kind: Secret text; Secret: dán Bot User OAuth Token xoxb-...
    • ID: slack-bot-token; Description: Slack bot token for Jenkins
  6. Bước 6: Cấu hình Slack trong Jenkins

    Vào Manage Jenkins → System, tìm mục Slack:

    • Workspace: Team Subdomain của workspace (phần trước .slack.com, ví dụ myworkspace)
    • Credential: slack-bot-token
    • Default channel / member id: #jenkins-notification
    • Tick Custom slack app bot user

    Bấm Test Connection → Jenkins báo Success và channel nhận được một tin nhắn test. Save.

  7. Bước 7: Tạo job có notification

    Tạo New Item → Pipeline tên lab12-slack-notification:

    • General → tick This project is parameterized → Boolean Parameter: Name SIMULATE_FAILURE, Set by Default: không tick
    • Pipeline → Definition Pipeline script, dán nội dung Jenkinsfile-slack và sửa GIT_REPO
    // Lab 12 – Gửi notification kết quả job sang Slack channel
// Job: lab12-slack-notification | Pipeline definition: Pipeline script (dán nội dung file này)
// This project is parameterized: Boolean parameter SIMULATE_FAILURE (Default: không tick)
// Yêu cầu: plugin "Slack Notification" đã cấu hình ở Manage Jenkins -> System -> Slack
def COLOR_MAP = [
    'SUCCESS' : 'good',
    'FAILURE' : 'danger',
    'UNSTABLE': 'warning',
    'ABORTED' : '#808080',
]

pipeline {
    agent any

    environment {
        // Thay <your-github-username>; credential github-ssh-key đã tạo ở Lab 8
        GIT_REPO      = 'git@github.com:<your-github-username>/nodejs-random-color.git'
        AWS_REGION    = 'ap-southeast-1'
        ECR_REPO      = 'nodejs-random-color'
        IMAGE_TAG     = "slack-${BUILD_NUMBER}"
        SLACK_CHANNEL = '#jenkins-notification'
    }

    stages {
        stage('Checkout') {
            steps {
                git branch: 'master', url: "${GIT_REPO}", credentialsId: 'github-ssh-key'
            }
        }

        stage('Unit test') {
            steps {
                // Giả lập test thất bại khi tick SIMULATE_FAILURE để kiểm tra notification lỗi
                sh '''
                    if [ "${SIMULATE_FAILURE}" = "true" ]; then
                        echo "Unit test failed: expected 200 but got 500"
                        exit 1
                    fi
                    echo "All tests passed"
                '''
            }
        }

        stage('Build image') {
            steps {
                sh 'docker build -t ${ECR_REPO}:${IMAGE_TAG} .'
            }
        }

        stage('Push image to ECR') {
            steps {
                sh '''
                    ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
                    ECR_REGISTRY=${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com
                    aws ecr get-login-password --region ${AWS_REGION} | docker login --username AWS --password-stdin ${ECR_REGISTRY}
                    docker tag ${ECR_REPO}:${IMAGE_TAG} ${ECR_REGISTRY}/${ECR_REPO}:${IMAGE_TAG}
                    docker push ${ECR_REGISTRY}/${ECR_REPO}:${IMAGE_TAG}
                '''
            }
        }
    }

    post {
        always {
            sh 'docker image prune -f'
            echo 'Build has been finished! Notify to Slack'
            slackSend channel: "${SLACK_CHANNEL}",
                color: COLOR_MAP[currentBuild.currentResult],
                message: "*${currentBuild.currentResult}:* Job `${env.JOB_NAME}` build #${env.BUILD_NUMBER} (image tag `${IMAGE_TAG}`)\nThời gian: ${currentBuild.durationString}\nChi tiết: ${env.BUILD_URL}"
        }
    }
}

    💡 post { always { } } chạy dù pipeline thành công hay lỗi. currentBuild.currentResult trả về SUCCESS / FAILURE / UNSTABLE / ABORTED, được map sang màu của Slack (good = xanh lá, danger = đỏ).

  8. Bước 8: Chạy job – trường hợp success

    Build with Parameters, giữ SIMULATE_FAILURE không tick → Build. Channel #jenkins-notification nhận tin nhắn có viền xanh:

    SUCCESS: Job lab12-slack-notification build #1 (image tag slack-1)
Thời gian: 35 sec and counting
Chi tiết: http://<jenkins-public-ip>:8080/job/lab12-slack-notification/1/
  9. Bước 9: Chạy job – trường hợp fail

    Build lại, tick SIMULATE_FAILURE. Stage Unit test lỗi, các stage sau bị skip, Slack nhận tin nhắn viền đỏ FAILURE: .... Click link Chi tiết để mở thẳng trang build và xem log lỗi.

Kiểm tra kết quả

✅ Lab thành công khi

  • Test Connection trong Manage Jenkins → System báo Success.
  • Channel #jenkins-notification nhận 2 tin nhắn: 1 SUCCESS (xanh) và 1 FAILURE (đỏ), có link tới đúng build.

Troubleshoot

Test Connection báo Failure / log có not_in_channel
Nguyên nhân: Bot chưa được mời vào channel.
Giải pháp: Gõ /invite @Jenkins trong channel (Bước 3).
Log có invalid_auth hoặc not_authed
Nguyên nhân: Sai token, dùng nhầm token khác (không phải xoxb-), hoặc chưa tick Custom slack app bot user.
Giải pháp: Copy lại Bot User OAuth Token, cập nhật credential slack-bot-token, kiểm tra lại Bước 6.
No such DSL method 'slackSend' found among steps
Nguyên nhân: Chưa cài plugin Slack Notification hoặc chưa restart Jenkins sau khi cài.
Giải pháp: Kiểm tra Installed plugins, restart bằng sudo systemctl restart jenkins.
channel_not_found
Nguyên nhân: Sai tên channel trong SLACK_CHANNEL, hoặc channel Private mà bot chưa được mời.
Giải pháp: Kiểm tra tên channel (có dấu #), mời bot vào channel.

Dọn dẹp resource

Lab này không tạo resource tính phí trên AWS (chỉ thêm vài image slack-* trên ECR). Sau khi học xong có thể xoá Slack App tại api.slack.com/apps → Basic Information → Delete App và xoá credential slack-bot-token.
