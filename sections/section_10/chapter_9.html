10. CI/CD sử dụng Jenkins / Lab 7: Job deploy lên Amazon ECS (Terraform stack)

Mục tiêu

  • Dùng Terraform template có sẵn tạo VPC + ALB + ECS Fargate, chạy service Node.js bằng image ver-1 của Lab 6; test truy cập qua ALB.
  • Tạo job Jenkins lab07-deploy-ecs nhận tham số IMAGE_TAG (ví dụ ver-1, ver-2) và deploy image đó lên ECS: đăng ký task definition revision mới → update-service --force-new-deployment → chờ service ổn định.
  • Ghép job CI (Lab 6) + job CD (Lab 7): sửa code → build image mới → deploy → kiểm tra trên ALB; rollback bằng cách deploy lại tag cũ.

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 6: ECR có image nodejs-random-color:ver-1; Jenkins server có jq và IAM Role có AmazonECS_FullAccess (Lab 1).
  • Máy local: Terraform >= 1.10, AWS CLI v2 đã cấu hình profile (Section 5).
  • Source code: sourcecode/section_10_cicd_with_jenkins/terraform_ecs_stack/ và sourcecode/section_10_cicd_with_jenkins/lab7_deploy_ecs/.

Các bước thực hành

  1. Bước 1: Tìm hiểu Terraform stack

    Stack terraform_ecs_stack được dùng chung cho Lab 7 → Lab 10, gồm 4 module:

    ModuleResource
    networkingVPC 10.30.0.0/16, 2 public subnet ở 2 AZ (module terraform-aws-modules/vpc/aws), không NAT Gateway
    securitySG cho ALB (mở 80), SG cho ECS task (chỉ nhận port 3000 từ SG của ALB)
    load_balancerALB jenkins-lab-alb, Target Group jenkins-lab-nodejs-tg (target type ip), listener 80
    ecsCluster jenkins-lab-cluster, task definition jenkins-lab-nodejs-task (container nodejs-container, 0.25 vCPU / 0.5 GB), service nodejs-service (2 task Fargate), log group /ecs/jenkins-lab-nodejs, task execution role

    💡 Service có lifecycle { ignore_changes = [task_definition] }: Jenkins sẽ tạo revision mới mỗi lần deploy, Terraform bỏ qua thay đổi này để terraform apply sau này không rollback version do Jenkins deploy. Circuit breaker được bật để tự rollback nếu version mới không khởi động được.

  2. Bước 2: Cấu hình biến & apply Terraform

    Mở terraform.tfvars, sửa ecr_image_uri thành Image URI tag ver-1 của bạn (Lab 6 – Bước 7):

  3. Bước 3: Truy cập website qua ALB

    Chờ 1–2 phút để task RUNNING và Target Group báo healthy, truy cập http://<alb-dns-name>. Trang Welcome to My Website hiển thị – mỗi task tô tiêu đề một màu ngẫu nhiên, tải lại trang vài lần sẽ thấy màu đổi giữa 2 task.

  4. Bước 4: Tạo job deploy có tham số

    Tạo New Item → Pipeline tên lab07-deploy-ecs:

    • General → tick This project is parameterized → String Parameter: Name IMAGE_TAG, Default Value ver-1, Description Image tag trên ECR cần deploy
    • Pipeline → Definition Pipeline script, dán nội dung lab7_deploy_ecs/Jenkinsfile (không cần sửa nếu giữ nguyên tên resource của Terraform)
    pipeline {
    agent any

    options {
        timeout(time: 15, unit: 'MINUTES')
    }

    environment {
        AWS_REGION     = 'ap-southeast-1'
        ECR_REPO       = 'nodejs-random-color'
        // Các giá trị dưới đây lấy từ terraform output của terraform_ecs_stack
        ECS_CLUSTER    = 'jenkins-lab-cluster'
        ECS_SERVICE    = 'nodejs-service'
        TASK_FAMILY    = 'jenkins-lab-nodejs-task'
        CONTAINER_NAME = 'nodejs-container'
    }

    stages {
        stage('Register new task definition') {
            steps {
                sh '''
                    ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
                    FULL_IMAGE=${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/${ECR_REPO}:${IMAGE_TAG}
                    echo "Deploying image: ${FULL_IMAGE}"

                    # Kiểm tra image tag có tồn tại trên ECR, nếu không job dừng ngay tại đây
                    aws ecr describe-images --region ${AWS_REGION} --repository-name ${ECR_REPO} --image-ids imageTag=${IMAGE_TAG} > /dev/null

                    # Lấy task definition hiện tại -> đổi image của container -> bỏ các field chỉ đọc
                    aws ecs describe-task-definition --region ${AWS_REGION} --task-definition ${TASK_FAMILY} |
                    jq --arg IMAGE "${FULL_IMAGE}" --arg NAME "${CONTAINER_NAME}" '.taskDefinition | (.containerDefinitions[] | select(.name == $NAME) | .image) = $IMAGE | del(.taskDefinitionArn, .revision, .status, .requiresAttributes, .compatibilities, .registeredAt, .registeredBy)' > new-task-definition.json

                    # Đăng ký revision mới, lưu số revision ra file để stage sau sử dụng
                    aws ecs register-task-definition --region ${AWS_REGION} --cli-input-json file://new-task-definition.json --query 'taskDefinition.revision' --output text > revision.txt
                    echo "New revision: ${TASK_FAMILY}:$(cat revision.txt)"
                '''
            }
        }

        stage('Update ECS service') {
            steps {
                sh '''
                    NEW_REVISION=$(cat revision.txt)
                    aws ecs update-service --region ${AWS_REGION} --cluster ${ECS_CLUSTER} --service ${ECS_SERVICE} --task-definition ${TASK_FAMILY}:${NEW_REVISION} --force-new-deployment --query 'service.deployments[0].{status:status,taskDefinition:taskDefinition}'
                '''
            }
        }

        stage('Wait for service stable') {
            steps {
                // Chờ rolling update hoàn tất: task mới healthy, task cũ đã dừng
                sh 'aws ecs wait services-stable --region ${AWS_REGION} --cluster ${ECS_CLUSTER} --services ${ECS_SERVICE}'
                echo "Deploy ${params.IMAGE_TAG} thành công!"
            }
        }
    }
}
    BướcLệnhGiải thích
    1describe-task-definitionLấy JSON của revision mới nhất (CPU, memory, port, log, role...)
    2jqChỉ đổi image của container nodejs-container, xoá các field chỉ đọc mà API register-task-definition không chấp nhận
    3register-task-definitionTạo revision mới (ví dụ jenkins-lab-nodejs-task:2) trỏ tới image mới
    4update-service --force-new-deploymentService chuyển sang revision mới theo kiểu rolling update (Section 9 – Chiến lược deployment)
    5wait services-stableJob chỉ báo SUCCESS khi deployment hoàn tất – nếu lỗi/timeout job báo FAILURE
  5. Bước 5: Sửa code & chạy job build (Lab 6)

    Trên máy local, mở public/index.html, sửa phần text của thẻ <h1 id="welcome" ...> thành Welcome to My Website – v2 from Jenkins (giữ nguyên thuộc tính id và style):

    cd ~/jenkins-labs/nodejs-random-color
git add public/index.html
git commit -m "feat: update welcome message v2"
git push origin master

    Chạy job lab06-docker-ecr → ghi lại tag mới được push (ví dụ ver-3).

  6. Bước 6: Chạy job deploy

    Mở job lab07-deploy-ecs → Build with Parameters → IMAGE_TAG = ver-3 → Build. Stage Wait for service stable mất khoảng 2–4 phút.

  7. Bước 7: Quan sát rolling update

    Trong lúc job đang chạy, mở ECS → jenkins-lab-cluster → nodejs-service → tab Deployments: deployment mới (revision mới) khởi động task mới trước, task cũ dừng sau khi task mới healthy. Gọi ALB liên tục để thấy giai đoạn 2 version cùng phục vụ (Ctrl + C để dừng):

    while true; do curl -s http://<alb-dns-name>/ | grep -o "<h1[^>]*>[^<]*"; sleep 1; done
  8. Bước 8: Rollback bằng tag cũ

    Chạy lại job lab07-deploy-ecs với IMAGE_TAG = ver-1 – website quay về nội dung ban đầu. Đây là lợi ích của việc tách job build và job deploy, đồng thời gắn tag duy nhất cho mỗi image: rollback chỉ là deploy lại một tag đã có, không cần build lại.

    aws ecs list-task-definitions --family-prefix jenkins-lab-nodejs-task --region ap-southeast-1

Kiểm tra kết quả

✅ Lab thành công khi

  • Truy cập http://<alb-dns-name> hiển thị nội dung v2 sau khi deploy ver-3, và quay về nội dung ban đầu sau khi deploy ver-1.
  • Task definition jenkins-lab-nodejs-task có nhiều revision, mỗi revision trỏ tới đúng image tag đã deploy.
  • Job lab07-deploy-ecs báo SUCCESS chỉ sau khi service ổn định.

Troubleshoot

jq: not found
Nguyên nhân: Chưa cài jq trên Jenkins server.
Giải pháp: sudo apt install -y jq (Lab 1 – Bước 9).
An error occurred (ImageNotFoundException) when calling the DescribeImages operation
Nguyên nhân: Nhập sai IMAGE_TAG hoặc tag chưa được push.
Giải pháp: Kiểm tra danh sách tag: aws ecr list-images --repository-name nodejs-random-color --region ap-southeast-1.
AccessDeniedException ... is not authorized to perform: iam:PassRole khi register-task-definition
Nguyên nhân: Jenkins cần quyền iam:PassRole cho task execution role.
Giải pháp: Gắn AmazonECS_FullAccess (đã bao gồm PassRole cho ecs-tasks.amazonaws.com) vào jenkins-server-role.
Stage Wait for service stable bị timeout / task mới liên tục bị dừng
Nguyên nhân: Container lỗi khi khởi động, health check thất bại, hoặc circuit breaker đã rollback.
Giải pháp: Xem lý do dừng ở Tasks → Stopped và log group /ecs/jenkins-lab-nodejs; chạy thử image ở local: docker run -p 3000:3000 <image-uri>.
Truy cập ALB trả về 503 Service Temporarily Unavailable
Nguyên nhân: Target Group chưa có target healthy.
Giải pháp: Chờ 1–2 phút, kiểm tra tab Targets của jenkins-lab-nodejs-tg.
