Mục tiêu

  • Viết lại job build Docker image & push ECR (Lab 6) bằng Scripted Pipeline – bắt đầu bằng khối node { }.
  • Thực hành các tính năng chỉ Scripted (hoặc khối script { }) làm tự nhiên: biến Groovy, if, vòng lặp for, readFile, withEnv.
  • Tự xử lý lỗi bằng try / catch / finally và currentBuild.result – tương đương khối post của Declarative.

Các bước thực hành

  1. Bước 1: Tạo Pipeline job với Scripted Pipeline

    Tạo New Item → Pipeline tên lab11-scripted-pipeline, Definition Pipeline script, dán nội dung Jenkinsfile-scripted và sửa gitRepo:

    // Lab 11 – Viết lại job Lab 6 (Build Docker image & push ECR) bằng Scripted Pipeline
// Job: lab11-scripted-pipeline | Pipeline definition: Pipeline script (dán nội dung file này)
// Scripted Pipeline: bắt đầu bằng node { }, viết bằng Groovy, tự xử lý lỗi bằng try / catch / finally.

// Thay <your-github-username>; credential github-ssh-key đã tạo ở Lab 8 (repository đang ở chế độ Private)
def gitRepo       = 'git@github.com:<your-github-username>/nodejs-random-color.git'
def gitCredential = 'github-ssh-key'
def awsRegion     = 'ap-southeast-1'
def ecrRepo       = 'nodejs-random-color'

node {
    // Logic Groovy tuỳ ý: build từ nhánh master thì gắn thêm tag "stable"
    def gitBranch = 'master'
    def imageTags = ["scripted-${env.BUILD_NUMBER}"]
    if (gitBranch == 'master') {
        imageTags << 'stable'
    }
    echo "Image tags sẽ được push: ${imageTags}"

    try {
        stage('Checkout') {
            git branch: gitBranch, url: gitRepo, credentialsId: gitCredential
        }

        stage('Build image') {
            sh "docker build -t ${ecrRepo}:${imageTags[0]} ."
        }

        stage('Push image to ECR') {
            // withEnv: đưa biến Groovy thành biến môi trường cho shell
            withEnv(["AWS_REGION=${awsRegion}", "ECR_REPO=${ecrRepo}", "BUILD_TAG_MAIN=${imageTags[0]}"]) {
                sh '''
                    ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
                    echo "${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com" > ecr_registry.txt
                    aws ecr get-login-password --region ${AWS_REGION} | docker login --username AWS --password-stdin $(cat ecr_registry.txt)
                '''
                def ecrRegistry = readFile('ecr_registry.txt').trim()
                // Vòng lặp Groovy: tag & push từng tag trong danh sách
                for (tag in imageTags) {
                    sh "docker tag ${ecrRepo}:${imageTags[0]} ${ecrRegistry}/${ecrRepo}:${tag}"
                    sh "docker push ${ecrRegistry}/${ecrRepo}:${tag}"
                }
            }
        }

        currentBuild.result = 'SUCCESS'
    } catch (err) {
        currentBuild.result = 'FAILURE'
        echo "Build lỗi: ${err}"
        throw err
    } finally {
        // Luôn chạy, tương đương post { always { } } của Declarative
        sh 'docker image prune -f'
        echo "Kết quả: ${currentBuild.currentResult}"
    }
}

  5. Bước 5: Kết hợp – khối script trong Declarative

    Trong thực tế, bạn hiếm khi viết cả pipeline bằng Scripted. Cách phổ biến là giữ Declarative và chỉ dùng khối script { } ở chỗ cần logic Groovy:

    stage('Push image to ECR') {
    steps {
        script {
            def imageTags = ["ver-${env.BUILD_NUMBER}", 'stable']
            for (tag in imageTags) {
                echo "Pushing tag ${tag}"
            }
        }
    }
}

Troubleshoot

Scripts not permitted to use method ... / RejectedAccessException
Nguyên nhân: Groovy sandbox chặn một số method không an toàn.
Giải pháp: Dùng các step có sẵn của Pipeline (readFile, sh, writeFile...) thay vì gọi trực tiếp API Java. Chỉ approve tại Manage Jenkins → In-process Script Approval khi hiểu rõ method đó làm gì.
groovy.lang.MissingPropertyException: No such property: ACCOUNT_ID
Nguyên nhân: Dùng biến shell (ACCOUNT_ID) bên trong chuỗi nháy kép – Groovy cố thay giá trị trước khi chạy shell.
Giải pháp: Dùng nháy đơn '''...''' cho đoạn script có biến shell, hoặc escape thành \$ACCOUNT_ID.
Permission denied (publickey) ở stage Checkout
Nguyên nhân: Repository đã ở chế độ Private nhưng dùng URL HTTPS hoặc thiếu credentialsId.
Giải pháp: Dùng URL SSH git@github.com:... và credential github-ssh-key (Lab 8).
