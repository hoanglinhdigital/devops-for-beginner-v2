10. CI/CD sử dụng Jenkins / Lab 3: Biến (Variable), Parameter & Credential trong Jenkins

Mục tiêu

  • Phân biệt 4 nguồn biến trong Jenkins: built-in variable, global environment variable, job parameter, credential variable.
  • Tạo job có tham số (This project is parameterized): String, Choice, Boolean.
  • Lưu username/password vào Jenkins Credentials và dùng trong job qua credential binding – quan sát Jenkins che (mask) secret trong log.

Các bước thực hành

  1. Bước 1: Xem danh sách built-in variable

    Jenkins cung cấp sẵn nhiều biến môi trường cho mọi build. Xem danh sách đầy đủ tại http://<jenkins-public-ip>:8080/env-vars.html. Các biến hay dùng:

    BiếnÝ nghĩaVí dụ
    JOB_NAMETên joblab03-variables
    BUILD_NUMBER / BUILD_IDSố thứ tự build – thường dùng làm version/tag5
    BUILD_URLLink tới trang build – dùng trong notificationhttp://.../job/lab03-variables/5/
    WORKSPACEĐường dẫn workspace/var/lib/jenkins/workspace/lab03-variables
    JENKINS_HOMEThư mục dữ liệu Jenkins/var/lib/jenkins
    GIT_COMMIT, GIT_BRANCHCommit / branch vừa checkout (khi job có Git)origin/master
  2. Bước 2: Tạo global environment variable

    Vào Manage Jenkins → System → Global properties, tick Environment variables, thêm:

    • Name: COMPANY_NAME – Value: DevOps for Beginner

    Save. Biến này dùng được trong mọi job – phù hợp cho giá trị dùng chung như region mặc định, tên công ty, URL registry.

  3. Bước 3: Tạo credential dạng Username with password

    Vào Manage Jenkins → Credentials → System → Global credentials (unrestricted) → Add Credentials:

    • Kind: Username with password
    • Username: dbadmin – Password: MySecretP@ssw0rd (giá trị giả lập); Treat username as secret: không tick
    • ID: dblogin – Description: Demo database login

    💡 Job chỉ tham chiếu ID dblogin, không bao giờ chứa password. Các loại credential khác sẽ dùng trong section: SSH Username with private key (Lab 8), Secret text (Lab 12).

  4. Bước 4: Tạo job có parameter & credential binding

    Tạo New Item → Freestyle project tên lab03-variables với cấu hình:

    • General → tick This project is parameterized, thêm 3 parameter:
      • String Parameter – Name APP_ENV, Default Value dev
      • Choice Parameter – Name REGION, Choices (mỗi giá trị 1 dòng): ap-southeast-1, ap-northeast-1
      • Boolean Parameter – Name DRY_RUN, Set by Default: tick
    • Environment → tick Use secret text(s) or file(s) → Add Username and password (separated): Username Variable USERNAME, Password Variable PASSWORD, Credentials dbadmin/****** (Demo database login)
    • Build Steps → Execute shell: copy nội dung file variables.sh
    echo "===== 1. Built-in variables ====="
echo "JOB_NAME     : ${JOB_NAME}"
echo "BUILD_NUMBER : ${BUILD_NUMBER}"
echo "BUILD_ID     : ${BUILD_ID}"
echo "BUILD_URL    : ${BUILD_URL}"
echo "WORKSPACE    : ${WORKSPACE}"
echo "JENKINS_HOME : ${JENKINS_HOME}"
echo "NODE_NAME    : ${NODE_NAME}"

echo "===== 2. Global environment variable ====="
echo "COMPANY_NAME : ${COMPANY_NAME}"

echo "===== 3. Job parameters ====="
echo "APP_ENV : ${APP_ENV}"
echo "REGION  : ${REGION}"
echo "DRY_RUN : ${DRY_RUN}"
if [ "${DRY_RUN}" = "true" ]; then
  echo "DRY_RUN = true -> chỉ in thông tin, không deploy."
else
  echo "Deploying to ${APP_ENV} in ${REGION}..."
fi

echo "===== 4. Credential variables ====="
echo "Username: ${USERNAME}"
echo "Password: ${PASSWORD}"
echo "Password length: ${#PASSWORD}"
  5. Bước 5: Build with Parameters

    Nút Build Now đổi thành Build with Parameters. Nhập APP_ENV = staging, chọn REGION = ap-northeast-1, bỏ tick DRY_RUN → Build. Console Output:

    ===== 3. Job parameters =====
APP_ENV : staging
REGION  : ap-northeast-1
DRY_RUN : false
Deploying to staging in ap-northeast-1...
===== 4. Credential variables =====
Username: dbadmin
Password: ****
Password length: 16

    💡 Jenkins tự thay giá trị secret bằng **** trong log (username chỉ bị che nếu tick Treat username as secret khi tạo credential). Tuy nhiên script vẫn đọc được giá trị thật (độ dài 16) – masking chỉ là lớp bảo vệ log, không ngăn được script cố tình gửi secret ra ngoài. Đừng bao giờ echo secret trong job thật.

  6. Bước 6: Xem lại parameter của từng build

    Mở build vừa chạy → Parameters: Jenkins lưu lại giá trị parameter của mỗi lần build – giúp truy vết "ai deploy version nào lên môi trường nào". Chạy thêm 1 build với giá trị mặc định để so sánh.

  7. Bước 7: (Tham khảo) Cùng nội dung bằng Pipeline

    Trong Pipeline, credential được dùng qua withCredentials. Đoạn này sẽ dễ hiểu hơn sau chương Jenkins Pipeline – file đầy đủ: lab3_variables_credentials/Jenkinsfile.

    withCredentials([usernamePassword(credentialsId: 'dblogin', usernameVariable: 'USERNAME', passwordVariable: 'PASSWORD')]) {
    // Dùng nháy đơn để shell (không phải Groovy) đọc biến bí mật -> tránh lộ secret
    sh '''
        echo "Username: $USERNAME"
        echo "Password: $PASSWORD"
    '''
}

Troubleshoot

Biến in ra rỗng (ví dụ COMPANY_NAME :)
Nguyên nhân: Sai chính tả tên biến (phân biệt hoa/thường) hoặc chưa Save cấu hình global properties.
Giải pháp: Kiểm tra lại tên biến; với parameter, đảm bảo build bằng Build with Parameters.
Không thấy mục Use secret text(s) or file(s)
Nguyên nhân: Chưa cài plugin Credentials Binding (có trong suggested plugins).
Giải pháp: Manage Jenkins → Plugins → Available plugins → tìm Credentials Binding → Install.
Credential dblogin không xuất hiện trong danh sách chọn
Nguyên nhân: Tạo credential sai loại (ví dụ Secret text) hoặc tạo trong folder/domain khác.
Giải pháp: Tạo lại credential loại Username with password trong Global credentials.
