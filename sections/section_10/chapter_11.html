10. CI/CD sử dụng Jenkins / Lab 9: Tự động trigger job từ GitHub webhook

Mục tiêu

  • Viết Jenkinsfile-auto gộp build + push ECR + deploy ECS (Lab 6 + Lab 7) thành một pipeline CI/CD hoàn chỉnh; image được tag ver-<BUILD_NUMBER> và latest.
  • Tạo job lab09-cicd-nodejs-auto (Pipeline from SCM, nhánh develop) với trigger GitHub hook trigger for GITScm polling.
  • Cấu hình webhook trên GitHub để mỗi lần push/merge vào develop, Jenkins tự động build và deploy – không cần bấm tay.

Các bước thực hành

  1. Bước 1: Tạo nhánh develop & thêm Jenkinsfile-auto

    Copy file lab9_github_webhook/Jenkinsfile-auto vào thư mục gốc repository trên máy local. Pipeline này gộp Lab 6 + Lab 7: push thêm tag latest và deploy ngay sau khi push (không có stage Checkout vì dùng Pipeline from SCM):

    pipeline {
    agent any

    options {
        timeout(time: 20, unit: 'MINUTES')
        // Không chạy 2 build cùng lúc trên cùng một service ECS
        disableConcurrentBuilds()
    }

    environment {
        AWS_REGION     = 'ap-southeast-1'
        ECR_REPO       = 'nodejs-random-color'
        IMAGE_TAG      = "ver-${BUILD_NUMBER}"
        ECS_CLUSTER    = 'jenkins-lab-cluster'
        ECS_SERVICE    = 'nodejs-service'
        TASK_FAMILY    = 'jenkins-lab-nodejs-task'
        CONTAINER_NAME = 'nodejs-container'
    }

    stages {
        stage('Show commit') {
            steps {
                sh 'git log -1 --oneline'
            }
        }

        stage('Build image') {
            steps {
                sh 'docker build -t ${ECR_REPO}:${IMAGE_TAG} .'
            }
        }

        stage('Push image to ECR') {
            steps {
                // Push 2 tag: ver-<BUILD_NUMBER> (truy vết, rollback) và latest (bản mới nhất của develop)
                sh '''
                    ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
                    ECR_REGISTRY=${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com
                    aws ecr get-login-password --region ${AWS_REGION} | docker login --username AWS --password-stdin ${ECR_REGISTRY}
                    docker tag ${ECR_REPO}:${IMAGE_TAG} ${ECR_REGISTRY}/${ECR_REPO}:${IMAGE_TAG}
                    docker tag ${ECR_REPO}:${IMAGE_TAG} ${ECR_REGISTRY}/${ECR_REPO}:latest
                    docker push ${ECR_REGISTRY}/${ECR_REPO}:${IMAGE_TAG}
                    docker push ${ECR_REGISTRY}/${ECR_REPO}:latest
                '''
            }
        }

        stage('Deploy to ECS') {
            steps {
                // Deploy theo tag ver-<BUILD_NUMBER> thay vì latest: mỗi revision task definition trỏ tới đúng 1 image
                sh '''
                    ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
                    FULL_IMAGE=${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/${ECR_REPO}:${IMAGE_TAG}
                    echo "Deploying image: ${FULL_IMAGE}"

                    aws ecs describe-task-definition --region ${AWS_REGION} --task-definition ${TASK_FAMILY} |
                    jq --arg IMAGE "${FULL_IMAGE}" --arg NAME "${CONTAINER_NAME}" '.taskDefinition | (.containerDefinitions[] | select(.name == $NAME) | .image) = $IMAGE | del(.taskDefinitionArn, .revision, .status, .requiresAttributes, .compatibilities, .registeredAt, .registeredBy)' > new-task-definition.json

                    NEW_REVISION=$(aws ecs register-task-definition --region ${AWS_REGION} --cli-input-json file://new-task-definition.json --query 'taskDefinition.revision' --output text)
                    echo "New revision: ${TASK_FAMILY}:${NEW_REVISION}"

                    aws ecs update-service --region ${AWS_REGION} --cluster ${ECS_CLUSTER} --service ${ECS_SERVICE} --task-definition ${TASK_FAMILY}:${NEW_REVISION} --force-new-deployment > /dev/null
                    aws ecs wait services-stable --region ${AWS_REGION} --cluster ${ECS_CLUSTER} --services ${ECS_SERVICE}
                '''
            }
        }
    }

    post {
        always {
            sh 'docker image prune -f'
        }
        success {
            echo "Deploy ${IMAGE_TAG} lên ${ECS_SERVICE} thành công!"
        }
    }
}

  2. Bước 2: Mở port 8080 cho GitHub webhook

    GitHub cần gọi được vào Jenkins. Vào EC2 → Security Groups → jenkins-sg → Edit inbound rules, thêm rule Custom TCP 8080 cho các dải IP webhook của GitHub (giữ rule My IP cũ):

    • 192.30.252.0/22, 185.199.108.0/22, 140.82.112.0/20, 143.55.64.0/20 – Description GitHub webhook

    Danh sách IP chính thức có thể thay đổi, kiểm tra lại bằng:

    curl -s https://api.github.com/meta | jq '.hooks'
    Không mở 8080 cho 0.0.0.0/0: Jenkins public ra Internet là mục tiêu tấn công phổ biến. Production thường đặt Jenkins sau ALB + HTTPS, hoặc trong private subnet và nhận webhook qua một endpoint trung gian / dùng polling.
  3. Bước 3: Kiểm tra plugin GitHub

    Vào Manage Jenkins → Plugins → Installed plugins, tìm GitHub plugin (đã có trong suggested plugins). Nếu chưa có: Available plugins → GitHub → Install. Kiểm tra endpoint webhook từ máy local:

    curl -s -o /dev/null -w "%{http_code}\n" http://<jenkins-public-ip>:8080/github-webhook/

    💡 Kết quả 405 (Method Not Allowed – vì gửi GET thay vì POST) là bình thường, chứng tỏ endpoint tồn tại. Nếu bị timeout, kiểm tra lại Security Group.

  4. Bước 4: Tạo job CI/CD tự động

    Tạo New Item → Pipeline tên lab09-cicd-nodejs-auto:

    • Triggers: tick GitHub hook trigger for GITScm polling
    • Pipeline → Definition Pipeline script from SCM, SCM Git
    • Repository URL: git@github.com:<your-github-username>/nodejs-random-color.git; Credentials: github-ssh-key
    • Branch Specifier: */develop
    • Script Path: Jenkinsfile-auto
  5. Bước 5: Chạy job lần đầu bằng tay

    Build Now một lần để Jenkins ghi nhận repository/branch của job (webhook dựa vào thông tin này để biết job nào cần chạy). Kiểm tra pipeline chạy hết 5 stage và website trên ALB hiển thị code của nhánh develop.

  6. Bước 6: Tạo webhook trên GitHub

    Trong repository nodejs-random-color → Settings → Webhooks → Add webhook:

    • Payload URL: http://<jenkins-public-ip>:8080/github-webhook/ – bắt buộc có dấu / ở cuối
    • Content type: application/json
    • Which events: Just the push event; Active: tick

    Sau khi Add, GitHub gửi một ping event – tab Recent Deliveries hiển thị dấu ✔ xanh với response 200.

  7. Bước 7: Sửa code & push lên develop

    Sửa text thẻ <h1 id="welcome" ...> trong public/index.html thành Welcome to My Website – v3 from develop:

    git add public/index.html
git commit -m "feat: update welcome message v3 from develop"
git push origin develop

    Trong vài giây, job lab09-cicd-nodejs-auto tự chạy; log build bắt đầu bằng Started by GitHub push by <your-github-username>. Thử push một commit lên master: job không chạy vì chỉ theo dõi nhánh develop.

  8. Bước 8: Kiểm tra version mới qua ALB 
    curl -s http://<alb-dns-name>/ | grep -o "<h1[^>]*>[^<]*"

    Trên ECR, image mới nhất có 2 tag ver-N và latest.

Troubleshoot

GitHub Recent Deliveries báo We couldn't deliver this payload: failed to connect to host / timeout
Nguyên nhân: Security Group chưa mở 8080 cho IP của GitHub, hoặc Public IP của Jenkins đã đổi sau khi Stop/Start.
Giải pháp: Kiểm tra Bước 2; cập nhật Payload URL theo Public IP mới (hoặc dùng Elastic IP), bấm Redeliver.
Webhook trả về 302 hoặc 403 No valid crumb
Nguyên nhân: Payload URL thiếu dấu / cuối hoặc sai đường dẫn.
Giải pháp: Dùng đúng http://<jenkins-public-ip>:8080/github-webhook/.
Webhook trả về 200 nhưng job không chạy
Nguyên nhân: Chưa tick trigger GitHub hook trigger for GITScm polling, chưa build tay lần đầu, push vào nhánh khác develop, hoặc repository URL trong job khác repository gửi webhook.
Giải pháp: Kiểm tra lại Bước 4, 5; xem Manage Jenkins → System Log và trang job → GitHub Hook Log.
Hai build chạy chồng lên nhau khi push liên tục
Nguyên nhân & giải pháp: Jenkinsfile đã có disableConcurrentBuilds() nên build sau sẽ chờ build trước xong – tránh 2 deployment cùng lúc trên một ECS service.
