10. CI/CD sử dụng Jenkins / Lab 2: Làm quen giao diện & tạo job Freestyle đầu tiên

Mục tiêu

  • Làm quen giao diện Jenkins: Dashboard, trang job, Build History, Console Output.
  • Tạo job Freestyle đầu tiên lab02-hello-job chạy một đoạn shell script, build thử và đọc log.
  • Xem workspace của job trên giao diện và trên server, hiểu job chạy bằng user nào, ở thư mục nào.
  • Thử trigger job tự động theo lịch (Build periodically) – cú pháp giống cron (Section 6 – Lab 8).

Yêu cầu trước khi bắt đầu

  • Hoàn thành Lab 1: Jenkins server đang chạy, đăng nhập được bằng user admin.
  • Source code: sourcecode/section_10_cicd_with_jenkins/lab2_first_job/hello.sh.

Các bước thực hành

  1. Bước 1: Tìm hiểu giao diện Dashboard
    • Menu trái: New Item (tạo job), Build History (lịch sử build của mọi job), Manage Jenkins, My Views.
    • Danh sách job ở giữa: trạng thái build gần nhất (✔ xanh / ✖ đỏ), biểu tượng thời tiết (☀ ổn định → ⛈ hay lỗi), thời gian lần build thành công / lỗi gần nhất.
    • Build Queue / Build Executor Status: build đang chờ và build đang chạy trên từng executor của built-in node.
  2. Bước 2: Tạo job Freestyle

    Vào New Item với các thông số:

    • Item name: lab02-hello-job
    • Type: Freestyle project
    • Description: Job đầu tiên – Hello Jenkins
    • Build Steps: thêm Execute shell, nội dung Command như bên dưới
    echo "Build Step 01 - Hello world"
echo "DevOps on AWS for Beginner"
echo "Job đang chạy với user: $(whoami)"
echo "Thư mục làm việc (workspace): $(pwd)"
date
echo "Hello Jenkins - build ${BUILD_NUMBER}" > hello.txt
ls -la

    💡 Mỗi build step Execute shell được Jenkins lưu thành một file script tạm và chạy bằng /bin/sh -xe: -x in từng lệnh ra log (dòng bắt đầu bằng +), -e dừng ngay và báo FAILURE khi có lệnh trả về exit code khác 0.

  3. Bước 3: Build & xem Console Output

    Trong trang job, chọn Build Now. Một build #1 xuất hiện ở Build History → click vào → Console Output:

    Started by user admin

Building in workspace /var/lib/jenkins/workspace/lab02-hello-job
[lab02-hello-job] $ /bin/sh -xe /tmp/jenkins1234567890.sh
+ echo Build Step 01 - Hello world

  4. Bước 4: Xem workspace của job

    Trên giao diện: trang job → Workspace – thấy file hello.txt. Trên server (cửa sổ SSH):

    sudo ls -la /var/lib/jenkins/workspace/lab02-hello-job
total 12
drwxr-xr-x 2 jenkins jenkins 4096 ... .
-rw-r--r-- 1 jenkins jenkins   28 ... hello.txt
sudo cat /var/lib/jenkins/workspace/lab02-hello-job/hello.txt

    💡 Workspace được giữ lại giữa các lần build – file của build trước vẫn còn nếu không xoá. Các lab build sau sẽ có bước dọn dẹp (ví dụ xoá thư mục dist) để tránh dùng nhầm file cũ.

  5. Bước 5: Thử một build lỗi

    Vào Configure, thêm dòng sau vào cuối Command, Save rồi Build Now:

    cat file-khong-ton-tai.txt

    Build #2 báo đỏ, Console Output kết thúc bằng Finished: FAILURE. Xoá dòng vừa thêm, build lại để job xanh trở lại.

  6. Bước 6: Trigger job theo lịch (tuỳ chọn)

    Vào Configure → Triggers, tick Build periodically, Schedule:

    H/5 * * * *

    Job sẽ tự chạy khoảng 5 phút một lần; log ghi Started by timer. Ký hiệu H (hash) giúp Jenkins rải đều thời điểm chạy của nhiều job thay vì tất cả chạy cùng phút 0. Bỏ tick sau khi thử xong để tránh tạo nhiều build không cần thiết.

  7. Bước 7: Một số thao tác hữu ích trên job
    • Discard old builds (Configure → General): giữ tối đa N build gần nhất, tránh đầy ổ đĩa.
    • Rebuild / Replay: chạy lại build cũ (Replay dành cho Pipeline job, sẽ dùng ở các lab sau).
    • Copy job: New Item → ô Copy from nhập tên job có sẵn để nhân bản cấu hình.
    • Disable Project: tạm dừng job mà không xoá.

Kiểm tra kết quả

✅ Lab thành công khi

  • Job lab02-hello-job có ít nhất 1 build SUCCESS và 1 build FAILURE (Bước 5).
  • Console Output cho thấy job chạy bằng user jenkins trong thư mục /var/lib/jenkins/workspace/lab02-hello-job.
  • Thấy file hello.txt trong Workspace trên giao diện và trên server.

Troubleshoot

Build bị kẹt ở trạng thái Waiting for next available executor
Nguyên nhân: Built-in node có 0 executor hoặc mọi executor đang bận, hoặc node bị offline do ổ đĩa sắp đầy.
Giải pháp: Vào Manage Jenkins → Nodes → Built-In Node → Configure, đặt Number of executors = 2; kiểm tra dung lượng bằng df -h /.
Permission denied khi script đọc/ghi file ngoài workspace
Nguyên nhân: Job chạy bằng user jenkins, không phải ubuntu hay root.
Giải pháp: Chỉ ghi file trong workspace; nếu thật sự cần, cấp quyền thư mục cho user jenkins (Section 6 – Lab 4). Không cấp sudo không giới hạn cho user jenkins.

Dọn dẹp resource

Lab này không tạo resource trên AWS. Có thể giữ hoặc xoá job lab02-hello-job (trang job → Delete Project). Nhớ Stop Jenkins server nếu nghỉ học.
