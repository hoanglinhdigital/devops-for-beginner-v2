17. CI/CD sử dụng GitHub Actions / Lab: Sử dụng GitHub Actions để implement Blue-Green deployment

Mục tiêu

Chuỗi Lab 1 → Lab 6 hướng dẫn xây dựng quy trình Blue/Green deployment cho ECS hoàn toàn bằng GitHub Actions. Mỗi lab thêm một workflow mới, lab sau tái sử dụng thành quả của lab trước:

  • Lab 1: Tạo workflow build Docker image từ source code và push lên Amazon ECR (tự động khi push và thủ công theo Git tag).
  • Lab 2: Tạo hạ tầng Blue/Green bằng Terraform và workflow deploy version mới lên ECS Cluster đang không nhận traffic.
  • Lab 3: Tạo workflow switch traffic giữa 2 môi trường Blue/Green trên ALB.
  • Lab 4: Tạo workflow clear old resources (scale service cũ về 0 task).
  • Lab 5: Kết hợp cả 4 workflow trên thành một pipeline Blue/Green hoàn chỉnh có manual approval.
  • Lab 6: Thêm workflow chạy test tự động khi code được push / tạo PR vào nhánh develop.

GitHub Actions build image lên ECR, deploy vào cluster idle (không nhận traffic), sau đó hoán đổi listener của ALB để switch traffic và cuối cùng scale cluster cũ về 0.

Yêu cầu trước khi bắt đầu

  • Tài khoản GitHub và tài khoản AWS (region ap-southeast-1).
  • Fork repository mẫu: github.com/hoanglinhdigital/nodejs-random-color (ứng dụng Node.js/Express chạy ở port 3000).
  • Máy local: Git (Section 7), Terraform >= 1.5 và AWS CLI v2 đã cấu hình profile (Section 5).
  • IAM User có quyền cần thiết (bài lab dùng PowerUserAccess), có Access Key để cấu hình cho GitHub Actions.
  • Source code: sourcecode/section_17_cicd_using_github_action/.
Chi phí: stack chạy 1 ALB + 4 task Fargate (0.25 vCPU / 0.5 GB) + Public IPv4, tính phí theo giờ. Nên làm liên tục Lab 1 → Lab 6 rồi terraform destroy ở chương Tổng kết.

Lab 1: Build Docker image & push lên ECR

  1. Bước 1: Tạo ECR repository

    Trên AWS Console, vào ECR → Create repository với các thông số:

    • Visibility: Private
    • Repository name: nodejs-random-color
  2. Bước 2: Tạo IAM User và lấy Access Key

    Tạo IAM User có quyền thao tác AWS (bài lab dùng policy PowerUserAccess), sau đó tạo Access Key và tải về (lưu ý không commit key lên GitHub).

  3. Bước 3: Cấu hình GitHub Secrets

    Mở repository đã fork trên GitHub → Settings → Secrets and variables → Actions → New repository secret, tạo 2 secret:

    • AWS_ACCESS_KEY_ID
    • AWS_SECRET_ACCESS_KEY
  4. Bước 4: Tạo thư mục workflow

    Clone repository về máy, tạo thư mục .github/workflows ở thư mục gốc của project:

    git clone git@github.com:<your-github-username>/nodejs-random-color.git
cd nodejs-random-color
mkdir -p .github/workflows
  5. Bước 5: Tạo workflow build tự động (tag latest)

    Copy nội dung file sourcecode/section_17_cicd_using_github_action/lab1_build_docker_ecr/build-docker-v1.yml vào file .github/workflows/build-docker.yml. Workflow kích hoạt khi push lên nhánh master và push image tag latest:

    name: Build and Push Docker Image

on:
  push:
    branches:
      - master
  workflow_dispatch: {}

env:
  AWS_REGION: ap-southeast-1
  ECR_REPOSITORY: nodejs-random-color

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    steps:
    - name: Checkout code
      uses: actions/checkout@v4

    - name: Configure AWS credentials
      uses: aws-actions/configure-aws-credentials@v4
      with:
        aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
        aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
        aws-region: ${{ env.AWS_REGION }}

    - name: Login to Amazon ECR
      id: login-ecr
      uses: aws-actions/amazon-ecr-login@v2

    - name: Build, tag and push image to ECR
      run: |
        docker build -t ${{ env.ECR_REPOSITORY }}:latest .
        docker tag ${{ env.ECR_REPOSITORY }}:latest ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}:latest
        docker push ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}:latest

    💡 Action amazon-ecr-login vừa đăng nhập Docker vào ECR, vừa xuất ra output registry là URI của ECR registry — không cần khai báo Account ID thủ công.

  6. Bước 6: Commit & push để kích hoạt workflow

    Sửa nội dung trang public/index.html (ví dụ đổi text trong thẻ <h1>), rồi commit và push:

    git add .
git commit -m "modify index.html, test CICD"
git push origin master

    Mở repository trên GitHub → tab Actions, bạn sẽ thấy workflow Build and Push Docker Image tự chạy.

  7. Bước 7: Kiểm tra kết quả

    Đợi workflow hoàn thành (dấu ✓ xanh). Vào ECR → repository nodejs-random-color, kiểm tra image có tag latest đã được push lên.

  8. Bước 8: Chuyển sang build thủ công theo Git tag

    Copy nội dung file build-docker-v2.yml đè lên .github/workflows/build-docker.yml. Workflow này chỉ chạy thủ công (workflow_dispatch) hoặc được workflow khác gọi (workflow_call), và checkout source theo tag:

    name: Build and Push Docker Image

on:
  workflow_dispatch:
    inputs:
      version:
        description: 'Version tag to build'
        required: true
        type: string
  workflow_call:
    inputs:
      version:
        description: 'Version tag to build'
        required: true
        type: string

env:
  AWS_REGION: ap-southeast-1
  ECR_REPOSITORY: nodejs-random-color

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    steps:
    - name: Checkout code (theo tag)
      uses: actions/checkout@v4
      with:
        ref: refs/tags/${{ inputs.version }}

    - name: Configure AWS credentials
      uses: aws-actions/configure-aws-credentials@v4
      with:
        aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
        aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
        aws-region: ${{ env.AWS_REGION }}

    - name: Login to Amazon ECR
      id: login-ecr
      uses: aws-actions/amazon-ecr-login@v2

    - name: Build, tag and push image to ECR
      run: |
        docker build -t ${{ env.ECR_REPOSITORY }}:${{ inputs.version }} .
        docker tag ${{ env.ECR_REPOSITORY }}:${{ inputs.version }} ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}:${{ inputs.version }}
        docker push ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}:${{ inputs.version }}

    Tạo tag v1.0.0 và push lên GitHub:

    git add public/index.html
git commit -m "modify index.html, test CICD"
git tag -a v1.0.0 -m "Test v1.0.0 by Github Action"
git push origin master
git push origin v1.0.0

    Mở tab Actions → Build and Push Docker Image → Run workflow, nhập version = v1.0.0 và chạy. Kiểm tra ECR có image tag v1.0.0.

Lab 2: Deploy lên ECS Cluster

  1. Bước 1: Triển khai hạ tầng Blue/Green bằng Terraform

    Sử dụng code trong thư mục sourcecode/section_17_cicd_using_github_action/terraform/ (xem terraform/command.sh):

    cd sourcecode/section_17_cicd_using_github_action/terraform
cp terraform.tfvars.example terraform.tfvars
# Sửa ecr_image_uri thành image v1.0.0 vừa build: 123456789012.dkr.ecr.ap-southeast-1.amazonaws.com/nodejs-random-color:v1.0.0
terraform init
terraform plan --var-file "terraform.tfvars"
terraform apply --var-file "terraform.tfvars"

    Stack tạo ra: VPC, ALB (udemy-devops-alb, listener :80 → Blue, :81 → Green), 2 Target Group, 2 ECS Cluster (udemy-devops-cluster-blue / udemy-devops-cluster-green), mỗi cluster 1 service nodejs-service chạy 2 task.

    Kiểm tra truy cập ALB bình thường (port 80 và 81 đều hiển thị v1.0.0):

    terraform output
  2. Bước 2: Tạo workflow deploy lên ECS

    Copy nội dung file sourcecode/section_17_cicd_using_github_action/lab2_deploy_ecs/deploy-ecs.yml vào .github/workflows/deploy-ecs.yml. Workflow nhận 2 tham số version và cluster_name, lấy task definition hiện tại, đổi image thành version mới rồi cập nhật service:

    name: Deploy to ECS

on:
  workflow_dispatch:
    inputs:
      version:
        description: 'Version tag to deploy'
        required: true
        type: string
      cluster_name:
        description: 'ECS Cluster name'
        required: true
        type: string
  workflow_call:
    inputs:
      version:
        description: 'Version tag to deploy'
        required: true
        type: string
      cluster_name:
        description: 'ECS Cluster name'
        required: true
        type: string

env:
  AWS_REGION: ap-southeast-1
  ECR_REPOSITORY: nodejs-random-color
  TASK_FAMILY: nodejs-task-definition
  SERVICE_NAME: nodejs-service

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
    - name: Configure AWS credentials
      uses: aws-actions/configure-aws-credentials@v4
      with:
        aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
        aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
        aws-region: ${{ env.AWS_REGION }}

    - name: Update ECS task definition and deploy
      run: |
        ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
        FULL_IMAGE="${ACCOUNT_ID}.dkr.ecr.${{ env.AWS_REGION }}.amazonaws.com/${{ env.ECR_REPOSITORY }}:${{ inputs.version }}"

        TASK_DEFINITION=$(aws ecs describe-task-definition \
          --task-definition ${{ env.TASK_FAMILY }} \
          --region ${{ env.AWS_REGION }})

        NEW_TASK_DEFINITION=$(echo "$TASK_DEFINITION" | jq --arg IMAGE "$FULL_IMAGE" '
          .taskDefinition |
          .containerDefinitions[0].image = $IMAGE |
          del(.taskDefinitionArn, .revision, .status, .requiresAttributes,
              .compatibilities, .registeredAt, .registeredBy)')

        NEW_TASK_INFO=$(aws ecs register-task-definition \
          --region ${{ env.AWS_REGION }} \
          --cli-input-json "$NEW_TASK_DEFINITION")

        NEW_REVISION=$(echo "$NEW_TASK_INFO" | jq -r '.taskDefinition.revision')

        aws ecs update-service \
          --cluster ${{ inputs.cluster_name }} \
          --service ${{ env.SERVICE_NAME }} \
          --task-definition ${{ env.TASK_FAMILY }}:${NEW_REVISION} \
          --region ${{ env.AWS_REGION }} \
          --force-new-deployment \
          --desired-count 2

        echo "Deployed version ${{ inputs.version }} to cluster ${{ inputs.cluster_name }}"
        echo "New task definition revision: ${NEW_REVISION}"

    💡 Deploy lên cluster đang không nhận traffic (xem Resource map của ALB để biết cluster nào đang idle).

  3. Bước 3: Commit, push và chạy deploy

    Sửa public/index.html thành nội dung version mới, commit, tạo tag v1.0.1 và push:

    git add .
git commit -m "Add Deploy ECS Workflow"
git tag -a v1.0.1 -m "Test v1.0.1 by Github Action"
git push origin master
git push origin v1.0.1

    Mở tab Actions chạy workflow Build and Push Docker Image với version = v1.0.1 (build image mới), sau đó chạy workflow Deploy to ECS với version = v1.0.1 và cluster_name là cluster đang idle.

  4. Bước 4: Kiểm tra

    Truy cập ALB qua cổng 81 (test listener) để thấy version mới v1.0.1, trong khi cổng 80 vẫn hiển thị version cũ v1.0.0.

Lab 3: Switch traffic trên ALB

  1. Bước 1: Tạo workflow switch traffic

    Copy nội dung file sourcecode/section_17_cicd_using_github_action/lab3_switch_traffic/switch-traffic.yml vào .github/workflows/switch-traffic.yml. Workflow tìm ALB theo tên, lấy 2 listener theo port rồi hoán đổi Target Group của listener :80 và :81:

    name: Switch ALB Traffic

on:
  workflow_dispatch: {}
  workflow_call: {}

env:
  AWS_REGION: ap-southeast-1
  ALB_NAME: udemy-devops-alb

jobs:
  switch-traffic:
    runs-on: ubuntu-latest
    steps:
    - name: Configure AWS credentials
      uses: aws-actions/configure-aws-credentials@v4
      with:
        aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
        aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
        aws-region: ${{ env.AWS_REGION }}

    - name: Switch traffic between blue and green environments
      run: |
        ALB_ARN=$(aws elbv2 describe-load-balancers \
          --names ${{ env.ALB_NAME }} \
          --query 'LoadBalancers[0].LoadBalancerArn' \
          --output text)

        LISTENERS=$(aws elbv2 describe-listeners --load-balancer-arn "$ALB_ARN")

        L80_ARN=$(echo "$LISTENERS" | jq -r '.Listeners[] | select(.Port == 80) | .ListenerArn')
        L80_TG=$(echo "$LISTENERS" | jq -r '.Listeners[] | select(.Port == 80) | .DefaultActions[0].TargetGroupArn')
        L81_ARN=$(echo "$LISTENERS" | jq -r '.Listeners[] | select(.Port == 81) | .ListenerArn')
        L81_TG=$(echo "$LISTENERS" | jq -r '.Listeners[] | select(.Port == 81) | .DefaultActions[0].TargetGroupArn')

        echo "Before switch: :80 -> $L80_TG | :81 -> $L81_TG"

        aws elbv2 modify-listener \
          --listener-arn "$L80_ARN" \
          --default-actions Type=forward,TargetGroupArn="$L81_TG"

        aws elbv2 modify-listener \
          --listener-arn "$L81_ARN" \
          --default-actions Type=forward,TargetGroupArn="$L80_TG"

        echo "After switch:  :80 -> $L81_TG | :81 -> $L80_TG"
        echo "Traffic switch completed successfully!"
  2. Bước 2: Commit & push 
    git add .
git commit -m "Add Switch Traffic Workflow"
git push origin master
  3. Bước 3: Chạy và kiểm tra

    Chạy workflow Switch ALB Traffic thủ công. Sau khi xong, truy cập ALB qua cổng 80 sẽ thấy version mới v1.0.1. Kiểm tra trên EC2 → Load Balancers → udemy-devops-alb → Resource map thấy 2 listener đã đổi Target Group cho nhau.

    💡 Chạy lại workflow một lần nữa sẽ hoán đổi ngược lại = rollback.

Lab 4: Clear old resources

  1. Bước 1: Tạo workflow clear old resources

    Copy nội dung file sourcecode/section_17_cicd_using_github_action/lab4_clear_old_resource/clear-resources.yml vào .github/workflows/clear-resources.yml. Workflow scale service về 0 task:

    name: Clear ECS Resources

on:
  workflow_dispatch:
    inputs:
      cluster_name:
        description: 'ECS Cluster name to clear resources from'
        required: true
        type: string
  workflow_call:
    inputs:
      cluster_name:
        description: 'ECS Cluster name to clear resources from'
        required: true
        type: string

env:
  AWS_REGION: ap-southeast-1
  SERVICE_NAME: nodejs-service

jobs:
  clear-resources:
    runs-on: ubuntu-latest
    steps:
    - name: Configure AWS credentials
      uses: aws-actions/configure-aws-credentials@v4
      with:
        aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
        aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
        aws-region: ${{ env.AWS_REGION }}

    - name: Scale service down to 0
      run: |

          --cluster ${{ inputs.cluster_name }} \
          --service ${{ env.SERVICE_NAME }} \
          --desired-count 0 \
          --region ${{ env.AWS_REGION }}

Lab 5: Kết hợp tất cả trong một workflow

  1. Bước 1: Tạo Environment cho manual approval

    Trên GitHub → Settings → Environments → New environment, tạo environment tên production-approval, bật Required reviewers (thêm chính bạn hoặc người review) để bước switch traffic cần được duyệt.

  2. Bước 2: Tạo workflow tổng thể

    Copy nội dung file sourcecode/section_17_cicd_using_github_action/lab5_combine_all_actions/blue-green-deployment.yml vào .github/workflows/blue-green-deployment.yml. Workflow này dùng workflow_call để gọi lại 4 workflow của Lab 1–4, kèm bước manual approval:

    name: Complete Blue-Green Deployment

on:
  workflow_dispatch:
    inputs:
      version:
        description: 'Version tag to deploy'
        required: true
        type: string
      target_cluster:
        description: 'Target cluster for deployment'
        required: true
        type: choice
        options:
        - blue
        - green
      switch_traffic:
        description: 'Switch traffic after deployment'
        required: false
        type: boolean
        default: false
      cleanup_old_cluster:
        description: 'Clean up old cluster after traffic switch'
        required: false
        type: boolean
        default: false

jobs:
  build-and-push:
    uses: ./.github/workflows/build-docker.yml
    with:
      version: ${{ inputs.version }}
    secrets: inherit

  deploy-to-target:
    needs: build-and-push
    uses: ./.github/workflows/deploy-ecs.yml
    with:
      version: ${{ inputs.version }}
      cluster_name: ${{ inputs.target_cluster == 'blue' && 'udemy-devops-cluster-blue' || 'udemy-devops-cluster-green' }}
    secrets: inherit

  manual-approval:
    if: ${{ inputs.switch_traffic }}
    needs: deploy-to-target
    runs-on: ubuntu-latest
    environment: production-approval
    steps:
    - name: Manual Approval Required
      run: |
        echo "## Ready to Switch Traffic" >> $GITHUB_STEP_SUMMARY
        echo "Deployment to **${{ inputs.target_cluster }}** cluster completed." >> $GITHUB_STEP_SUMMARY
        echo "- Version: ${{ inputs.version }}" >> $GITHUB_STEP_SUMMARY
        echo "- Target cluster: ${{ inputs.target_cluster }}" >> $GITHUB_STEP_SUMMARY
        echo "Approve this deployment to switch traffic to the new version." >> $GITHUB_STEP_SUMMARY

  switch-traffic:
    if: ${{ inputs.switch_traffic }}
    needs: manual-approval
    uses: ./.github/workflows/switch-traffic.yml
    secrets: inherit

  cleanup-old-cluster:
    if: ${{ inputs.cleanup_old_cluster && inputs.switch_traffic }}
    needs: switch-traffic
    uses: ./.github/workflows/clear-resources.yml
    with:
      cluster_name: ${{ inputs.target_cluster == 'blue' && 'udemy-devops-cluster-green' || 'udemy-devops-cluster-blue' }}
    secrets: inherit

  deployment-summary:
    needs: [build-and-push, deploy-to-target]
    if: always()
    runs-on: ubuntu-latest
    steps:
    - name: Deployment Summary
      run: |
        echo "## Blue-Green Deployment Summary" >> $GITHUB_STEP_SUMMARY
        echo "- Version: ${{ inputs.version }}" >> $GITHUB_STEP_SUMMARY
        echo "- Target cluster: ${{ inputs.target_cluster }}" >> $GITHUB_STEP_SUMMARY
        echo "- Switch traffic: ${{ inputs.switch_traffic }}" >> $GITHUB_STEP_SUMMARY
        echo "- Cleanup old cluster: ${{ inputs.cleanup_old_cluster }}" >> $GITHUB_STEP_SUMMARY
        echo "- Build status: ${{ needs.build-and-push.result }}" >> $GITHUB_STEP_SUMMARY
        echo "- Deploy status: ${{ needs.deploy-to-target.result }}" >> $GITHUB_STEP_SUMMARY

    💡 needs ràng buộc thứ tự job; if quyết định job có chạy hay không tuỳ tham số đầu vào; environment tạo điểm dừng chờ người duyệt.

  3. Bước 3: Commit, push và chạy pipeline hoàn chỉnh

    Sửa public/index.html thành nội dung mới (ví dụ Version 1.0.2), commit, tạo tag và push:

    git add .
git commit -m "Add Blue-Green full workflow"
git tag -a v1.0.2 -m "Test v1.0.2 by Github Action"
git push origin master
git push origin v1.0.2

    Mở Actions → Complete Blue-Green Deployment → Run workflow, nhập:

    • version: v1.0.2
    • target_cluster: cluster đang không nhận traffic (vd green)
    • switch_traffic: true
    • cleanup_old_cluster: true
  4. Bước 4: Kiểm tra toàn bộ quy trình

    Theo dõi trên tab Actions: job build-and-push → deploy-to-target → manual-approval (chờ bạn bấm Approve) → switch-traffic → cleanup-old-cluster. Sau cùng, truy cập ALB port 80 thấy v1.0.2, và cluster cũ đã được scale về 0 task.

Lab 6: Thêm bước testing khi push lên nhánh develop

  1. Bước 1: Chuẩn bị nhánh develop

    Tạo nhánh develop từ master và push lên GitHub:

    git checkout -b develop
git push -u origin develop
  2. Bước 2: Tạo workflow test trên nhánh develop

    Copy nội dung file sourcecode/section_17_cicd_using_github_action/lab6_add_test_step/test-on-develop.yml vào .github/workflows/test-on-develop.yml (lưu ý push workflow này lên nhánh develop). Workflow chạy khi có push hoặc PR vào develop: cài dependency, khởi động server, chờ server sẵn sàng và kiểm tra HTTP 200:

    name: Unit test on Develop

on:
  push:
    branches:
      - develop
  pull_request:
    branches:
      - develop

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
    - name: Checkout code
      uses: actions/checkout@v4

    - name: Setup Node.js
      uses: actions/setup-node@v4
      with:
        node-version: '18'
        cache: 'npm'

    - name: Install dependencies
      run: npm install

    - name: Start development server
      run: |
        npm run dev &
        echo $! > server.pid

    - name: Wait for server to start
      run: |
        echo "Waiting for server to start..."
        timeout=60
        counter=0
        while [ $counter -lt $timeout ]; do
          if curl -f -s http://localhost:3000 > /dev/null 2>&1; then
            echo "Server is up and running!"
            break
          fi
          echo "Waiting for server... ($counter/$timeout)"
          sleep 2
          counter=$((counter + 2))
        done
        if [ $counter -ge $timeout ]; then
          echo "Server failed to start within $timeout seconds"
          exit 1
        fi

    - name: Test website availability
      run: |
        response=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:3000)
        if [ "$response" = "200" ]; then
          echo "Website is accessible - HTTP status: $response"
        else
          echo "Website test failed - HTTP status: $response"
          exit 1
        fi

    - name: Additional health check
      run: |
        content=$(curl -s http://localhost:3000)
        if echo "$content" | grep -q "<!DOCTYPE html\|<html"; then
          echo "Website returned valid HTML content"
        else
          echo "Website did not return valid HTML content"
          exit 1
        fi

    - name: Cleanup
      if: always()
      run: |
        if [ -f server.pid ]; then
          kill $(cat server.pid) || true
          rm server.pid
        fi
        pkill -f "npm run dev" || true
        pkill -f "node.*dev" || true
  3. Bước 3: Kiểm tra

    Push code lên nhánh develop (hoặc tạo PR vào develop). Mở tab Actions thấy workflow Unit test on Develop tự chạy và các bước test đều ✓ xanh.

Troubleshoot

Workflow không tự chạy sau khi push
Nguyên nhân: File workflow không nằm đúng thư mục .github/workflows/, hoặc push sai nhánh khác với nhánh khai báo trong on:.
Giải pháp: Kiểm tra đường dẫn file và tên nhánh (bài lab dùng master cho build, develop cho test).
Credentials could not be loaded / AccessDenied
Nguyên nhân: Secret AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY chưa tạo hoặc sai tên; IAM User thiếu quyền.
Giải pháp: Kiểm tra Settings → Secrets → Actions; kiểm tra quyền của IAM User (bài lab dùng PowerUserAccess).
Build lỗi pull access denied hoặc không push được lên ECR
Nguyên nhân: Thiếu bước amazon-ecr-login hoặc tên ECR repository không đúng.
Giải pháp: Đảm bảo workflow có step Login to Amazon ECR; kiểm tra ECR_REPOSITORY trùng tên repository đã tạo.
Deploy thành công nhưng truy cập ALB nhận 503 Service Temporarily Unavailable
Nguyên nhân: Task chưa healthy hoặc không pull được image.
Giải pháp: Đợi 1–2 phút; kiểm tra ECS Console → cluster → service → tab Tasks (stopped) xem Stopped reason.
CannotPullContainerError: ... not found
Nguyên nhân: Image tag chưa tồn tại trên ECR, hoặc ecr_image_uri trong terraform.tfvars sai Account ID/tag.
Giải pháp: Chạy lại workflow build để push image; sửa lại ecr_image_uri rồi terraform apply.
Job manual-approval bị kẹt mãi ở trạng thái chờ
Nguyên nhân: Environment production-approval có Required reviewers — cần người duyệt bấm Approve.
Giải pháp: Vào workflow run đang chờ, bấm Review deployments → Approve (đây là hành vi mong muốn của Lab 5).
terraform apply báo conflict / muốn thay đổi listener hoặc service
Nguyên nhân: Listener/service đã bị workflow GitHub Actions thay đổi.
Giải pháp: Đây là hành vi bình thường nhờ ignore_changes trong Terraform; không cần xử lý.
