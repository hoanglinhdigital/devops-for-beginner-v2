Checklist dọn dẹp resource

Các resource tính phí theo giờ cần xoá ngay: ALB udemy-devops-alb, 4 task Fargate, Public IPv4 của task. ECR và CloudWatch Logs tính phí theo dung lượng. Không xoá sẽ phát sinh chi phí kể cả khi không dùng.

  1. Terraform stack: xoá VPC, ALB, Target Group, 2 ECS Cluster/Service, IAM Role, log group:

    cd sourcecode/section_17_cicd_using_github_action/terraform
terraform destroy --var-file "terraform.tfvars"

  2. Task definition còn sót: các revision do workflow Deploy to ECS đăng ký không do Terraform quản lý — deregister nếu muốn danh sách sạch (không tính phí):

    aws ecs list-task-definitions --family-prefix nodejs-task-definition --region ap-southeast-1 --query 'taskDefinitionArns[]' --output text | tr '\t' '\n' | xargs -I {} aws ecs deregister-task-definition --task-definition {} --region ap-southeast-1 --query 'taskDefinition.taskDefinitionArn'

  3. ECR: xoá các image latest, v1.0.0, v1.0.1, v1.0.2 hoặc xoá cả repository nếu không dùng ở các section sau:

    aws ecr batch-delete-image --repository-name nodejs-random-color --image-ids imageTag=latest imageTag=v1.0.0 imageTag=v1.0.1 imageTag=v1.0.2 --region ap-southeast-1

  4. IAM User: nếu IAM User PowerUserAccess chỉ dùng cho bài lab, xoá Access Key hoặc xoá cả User để tránh lộ key (least privilege).

  5. GitHub: gỡ các secret AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY (Settings → Secrets → Actions) và xoá Environment production-approval nếu không dùng nữa; có thể xoá repository đã fork.

  6. Kiểm tra lại trên Console (region Singapore): EC2 → Load Balancers, Target Groups, Elastic IPs, NAT Gateways, Volumes không dùng; ECS → Clusters. Không còn resource có tiền tố udemy-devops.

Best practice

  • Không commit secret: Access Key chỉ lưu trong GitHub Secrets; trong workflow tham chiếu qua ${{ secrets.* }} và không in ra log.
  • Một artifact cho mọi môi trường: build một lần theo Git tag, cùng image đi qua các bước deploy; không build lại khi rollback.
  • Guardrail trong pipeline: chặn deploy lên môi trường đang nhận traffic, dùng environment + required reviewer cho production.
  • Least privilege cho IAM: thực tế nên viết policy hẹp (chỉ ECR/ECS/ELB cần thiết) thay vì PowerUserAccess.
  • Tái sử dụng workflow: tách các công việc nhỏ thành workflow riêng và gọi bằng workflow_call (như Lab 5) để dễ bảo trì.
  • Pin version action: dùng tag như @v4, @v2 (hoặc commit SHA trong production) để tránh bị thay đổi bất ngờ.
  • Hạ tầng là code: Terraform quản lý hạ tầng, workflow quản lý trạng thái deploy — dùng ignore_changes để 2 bên không ghi đè nhau.

Chủ đề nên tìm hiểu thêm

  • OIDC thay cho Access Key: dùng GitHub Actions OIDC provider để cấp quyền AWS tạm thời, không cần lưu Access Key dài hạn.
  • GitHub Actions + CodeDeploy: Blue/Green deployment bản "native" với task set, auto rollback theo CloudWatch alarm.
  • Matrix build: build cùng lúc nhiều phiên bản (vd nhiều Node.js version) bằng strategy.matrix.
  • Self-hosted runner & cache: cache npm/Docker layer để build nhanh hơn, runner tự quản cho môi trường riêng.
  • GitOps với Argo CD: hướng deploy theo khai báo (declarative) cho Kubernetes — một hướng tiếp cận khác với pipeline push-based.
